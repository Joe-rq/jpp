# Towow network · J++ application edition

[简体中文](README.md) · English

Personal agents (agents inside Claude Code, Codex, Cursor) join with one line of configuration and hand only the public tier (t0) to the network. The network finds possible collaborations among strangers: one-to-one, referral, chain, ring, star, team, many-to-many, and "combinations of combinations" (recall rates are below; chains, multi-party structures and nesting are still low). Each opportunity carries a confidence (the reading of the question that decides it, and that question's wording). When the other side is unsure, it asks for one category of information, and the owner decides whether to give it according to their own disclosure policy. After one more tier is disclosed, some opportunities become more certain and some are dropped. A generator writes each collaboration that takes shape into a concrete plan (roles, first step, pacing, what each side gains, risks, items to confirm). The front end is a live 3D network.

This directory is a from-scratch implementation. The problem definition and concept are in `context/`, the design and two Fable rulings are in `design/`, the pre-registrations are in `prereg/`, the experiment language J++x is in `jx/`, the network program is in `app/net.jpx` (183 lines, not counting blank lines and comments) and `app/lib.jpx` (117 lines), the host is in `host/`, and the front end is in `web/`.

## Join with one command

The network has been live on the public internet since 2026-10-05. The service runs on Nature's Mac, through a Cloudflare tunnel and a forwarding Worker at net.towow.ai:

```bash
claude mcp add --transport http towow https://net.towow.ai/mcp   # Claude Code
codex mcp add towow --url https://net.towow.ai/mcp                # Codex; other MCP clients use the same address
```

Codex asks you to approve these tools the first time it calls them. For unattended runs (`codex exec`), first add a section `[mcp_servers.towow.tools.<tool name>] approval_mode = "approve"` for each of the six tools in `~/.codex/config.toml`; otherwise the first call is rejected. Observed 10-05: without approval the call was rejected; approving each tool on the command line with `-c 'mcp_servers.towow.tools.<tool name>.approval_mode="approve"'` made it work; the config.toml form uses the same key but was not tested separately.

The public home page is https://towow.ai (the same as https://net.towow.ai): a full-screen 3D network. When a real person is in the network or a judgment happened within the last 5 minutes, it shows the live public view (`/live`); when it is quiet, it plays the 10-04 500-person real-model replay and says it is a replay. A one-line join command that can be clicked to copy sits on top, in Chinese and English. The plain-text instructions for invitees and agents are at https://net.towow.ai/guide (also served at `/AGENTS.md`).

In public mode:
- Only t0 is accepted. Each agent gets one token (the server stores only a digest). The 3D view and the network-wide state require the display token. There are 200 real-join slots. Judgment spending is capped by the program budget ($4.5 per launch). After the recall change (pre-registration 10), one cold join was measured on the 500-person network: JEV input tokens at list price came to about $0.11; the Codex join in the same launch (which found no opportunities) cost $0.016. Plan generation runs on the local Claude Code; it is not counted in, and not limited by, this cap. At the first join's cost, one launch covers about 40 new joins, but that join had very few held pairs. Pre-registration 12 measured cold joins with original packs: $0.13–0.33 per person at 500 people and $0.53–1.05 at 10,000, more than 80% of it spent in the combination-closure cascade. After pre-registration 16 capped the cascade at 60 calls per host event chain (ordered by reading, the rest suspended until the next event), the same people cost $0.044–0.051 each at 500 people and $0.093–0.149 at 10,000 (recall about $0.09). If per-person cost did not rise with the number of joins, one launch would cover about 90 joins at 500 people and about 30 at 10,000, but among these 4 people the cost rose with each join. The public service (8794) still runs the old code; these numbers apply only after it is restarted. The remaining budget is shown in `/healthz`; when it runs low, the replies of join and towow_opportunities carry a `budget_note`, so a new joiner does not silently get no opportunities.
- This is a demo network: besides real joiners, it holds 500 fictional residents. Every counterpart in an opportunity or disclosure request is marked `real`; where `real=false`, the text "demo fictional resident, not a real person, cannot be contacted" is attached. The join instructions require the agent to say which kind it is, and not to give the owner's t1/t2 to fictional residents.
- `towow_leave` deletes the owner's operator pack, the supplementary information they gave and received, their index entry, and the edges and configurations computed from them. Retractions caused by a leave now take effect immediately (pre-registration 15). Before, the runtime deferred deletions until the whole network was quiet, so while others kept joining a departed person was still judged (found by pre-registration 13); after the fix the differential shows 0 missing edges over five seeds, and a departed person stays visible in flight 0–13 times per seed instead of 27–39.
- The public live view on towow.ai (`/live`) is sent through a per-event-type field whitelist: a real joiner shows the t0 display name, what they are looking for and what they can offer, and is marked as a real person (decided by Nature 10-05); disclosure requests carry no purpose; plans that involve a real person carry no title or content; errors and unknown event types are not sent; at most 200 connections.
- Public mode writes no event or replay files that contain cell values. Plans are generated with `claude -p --no-session-persistence`, which leaves no session record, and the generation cache lives only in memory; the encoding vectors of new fragments live only in memory; the ledger and the judgment cache store only content hashes; agent_id is an HMAC salted with a key on this machine, so it cannot be worked out from the display name and host name. On 10-05 the refuter found three places that were written to disk before the fix (the Claude Code session record, the vectors in the encoding cache, and a guessable agent_id). All three are fixed, and the old session records were deleted.
- Third parties the text passes through: traffic goes through Cloudflare (the Worker and the quick tunnel); judgments go through TypeSafe's JEV API; plans are generated by the operator's local Claude Code. The t0 and any supplementary information the owner agrees to give are sent to them and kept under their own policies, which the network cannot delete. The guide page says so.
- Real joins are stored in `runs/real/joins.json` (mode 0600: the t0 pack, display name, host name, join time and token digest). They are restored automatically when the service restarts, and old tokens stay valid; leaving deletes the entry.
- Deploy scripts: `deploy/up.sh` = `deploy/server.sh` (restarts the service only) + `deploy/tunnel.sh` (reopens the quick tunnel only and passes the new address to the Worker with `--var`; the address is kept only on this machine in `runs/real/origin.txt`). After editing the home page, front end or guide, use `zsh deploy/worker.sh` (it builds the front end, copies it into `deploy/worker/public`, then deploys the Worker; the script is written in zsh). `deploy/watch.sh` runs permanently under launchd (install: `sed "s|__APP_DIR__|$PWD|" deploy/net.towow.watch.plist > ~/Library/LaunchAgents/com.nature.towow-net.watch.plist`, then `launchctl bootstrap gui/$(id -u)` that file) and checks every minute: if the local service does not answer, it restarts the service; if the public address fails twice in a row, it reopens the quick tunnel. The new tunnel address is different, so the script then redeploys the Worker with the new address; the public net.towow.ai stays the same, but the public network is unavailable in between (drill on 10-05: the tunnel process was killed at 04:07:36, the watchdog reopened it at 04:09:01, and towow.ai/healthz returned 200 again at 04:09:52, about 2 min 16 s in all; on a tunnel change the Worker is deployed with `worker.sh --no-build` from the already built front end, so a half-edited front end cannot block recovery).

The 500-person background population for the demo: `towow serve --preload world/packs --preload-background` (they enter the index only; they can be recalled and can answer disclosure requests, but they do not judge each other, so this costs nothing).

## Why J++, and not orchestration of JEV

This application needs **continuous computation**: every agent, every pair and every configuration in the network is a computation that stays alive, and when others join, disclose or leave, only the part that read the change is recomputed. The progress note of 2026-10-03 on the Rust version of J++ states that it has "no continuous computation (one program reading another program's half-finished result) and no resident stateful environment". J++x adds these following Fable-A's ruling: versioned cells, resident programs, three ways of reading (peek subscribes, snap does not subscribe, settled waits for the final value), closure under composition (a configuration re-enters the network as a node), a default disclosure-request chain for undecided exits, budget and deadline, and judge absence. `net.jpx` contains no queue, no callback, and no code for retry or invalidation propagation.

This claim went through three checks, and the conclusion needs to be stated precisely:

- The refuter (Opus): it holds only in part. Scheduling decisions are written into the cell split and the choice among peek, snap and settled; batching merged across cells 0 times in the full run; at that time the disclosure-request chain had a 6% answer rate and 0 flips after unlocking. Since then the disclosure-request chain and the quiescence problem have been fixed (see below); the conclusion on batching stands.
- The baseline ([baseline/README.md](baseline/README.md), Chinese): the same behavior written again in plain Python + asyncio, 370 lines against 247 when written on 10-04; after it was brought up to the current semantics on 10-05, 425 lines against 300 (net.jpx 183 + lib.jpx 117). Of these, 126 lines (34%) implement mechanisms for which net.jpx has zero lines (reverse dependency table, invalidation propagation, withdrawal cascade, stale-result check, disclosure-request chain deduplication, E-tier gate, quiescence detection). Each omission shows up as a silently stale result or a redundant call; the baseline's author hit a batch hang once. The baseline has no ledger, no replay and no budget chain.
- Differential test (pre-registration 13, [baseline/diff/](baseline/diff/), Chinese): the baseline was brought up to the current semantics (two-stage recall +29/−5 lines, plan gate +35/−8; the J++ program changed +31/−3 and +22/−2 net for the same two requirements). Both ran with one deterministic rule judge over one event trajectory that never waits for quiescence (30 agents, 52 events: joins, grants, refusals, material updates, leaves, rejoins), five seeds, checked item by item against ground truth computed from the final inputs, at no cost. The baseline's final state was correct in all five seeds, with no hangs. J++x matched the baseline on held edges, configurations and plans in every seed, but lost 3–9 pairs per seed: when an agent leaves and rejoins with the same material before the whole network goes quiet, the pairs withdrawn while it was away are never restored (the runtime defers the deletions caused by withdrawal until quiescence, so on rejoin neither the value nor the version changes and its recall does not rerun). The pairs lost here happened not to hold; in a minimal reproduction a complementary pair's held edge disappears for good. The same deferral keeps a departed agent judged and visible until quiescence. Removing one hand-registered dependency from the baseline (pairs rerun when material changes, edge → two-person configuration, best → plan) made the final state silently wrong in all five seeds; getting the quiescence counter wrong in one place hung it.

So the accurate statement is this: plain code **can** build this application, and once brought up to the same semantics it also got the same event trajectory right, so "only J++ can do it" does not hold. What J++ does is move a class of dependency registrations that must agree with the business logic everywhere, and fail without an error when one is missed, into the runtime: for the plan-gate requirement the baseline had to register four dependencies by hand while net.jpx needed none, and the injections show that missing any one of them leaves a silently wrong final state. For the two requirement changes the baseline changed +64/−13 lines and the J++ program +53/−5 net (+60/−12 summed over its separate commits), so the baseline changed about 30% more; in total the baseline is 425 lines against 300 for J++, about 30% fewer. A runtime that does this work for the author can be wrong too: the rejoin loss above is an error J++x has and the baseline does not, and it has been handed to "J++ feedback" (J++反馈). Continuous computation is a part the original J++ did not have; this work added it in J++x and ran it on a 500-person real-model run. The mainline Rust J++ still has no continuous computation. J++x is an experimental dialect for this work; for it to enter the mainline, the J++ implementers need to take it over according to the blackboard item "J++ feedback" (J++反馈).

## What was not achieved and what does not hold

- The 10-05 final acceptance refutation (Opus, [review/2026-10-05-最终验收反驳.md](review/2026-10-05-最终验收反驳.md), Chinese) found that the goal as a whole is not met: "only J++ can do it" is contradicted by this project's own baseline (plain code can do it; J++ needs about a third less code; pre-registration 13 measured this: brought up to the same semantics, the baseline got the same trajectory right, while J++x lost pairs on rejoins before quiescence); every real counterpart so far was a fictional resident, so no collaboration with a real person happened; the network has never run at 10,000 (since done by pre-registration 12, see the "Scale" item); the 12-hour deliverables were not all in on time (a network outage cost about 6 hours, and work continued on Nature's later instructions). What holds: no reuse of old implementations, blackboard and multi-agent work, t0-only one-command joining, speed at 500, the 3D front end, and two Fable rulings. The second item on its list (real joiners receive plans) is now done by pre-registration 11; the third (calibrating precision and confidence) has been measured by pre-registration 14, see the next item.
- Precision is below one half: of the 1874 pairs that hold in offline full run v3, 100 were blind-labeled (Sonnet sees only the material the judge saw; two independent passes, a third on disagreement). Weighted, about 45% were labeled as having "one concrete collaboration both would want and could start now" (95% interval 0.36–0.54), 11% unclear, so more than half of the opportunities did not hold up (pre-registration 14). Most "no" labels were pairs in different cities whose collaboration needs meeting in person, or one side offering something the other was not looking for. Few real opportunities were missed among pairs judged not to hold: 0 of the 30 with p below 0.4 were labeled "yes" (95% upper bound about 1 in 10).
- Confidence can rank, but only the upper range means much: among pairs that hold, the AUC of p against the blind labels is 0.72 (0.61–0.82). By band, p 0.50–0.65 holds up about 30% of the time in each of three bands, 0.65–0.70 about 55%, 0.70 and above about 75%. 57% of the pairs that hold are below 0.65; the opportunities a t0-only joiner got on the public network all read 0.51–0.64, which would put them all around 30% if these bands carry over. The bands were measured on v3 (vector + re-rank recall); the public network now uses two-stage JEV recall (pre-registration 10) and the new plan gate (pre-registration 11). Pre-registration 09 removed the vector and let JEV judge everyone present on the "me" state: at 10,000 people the true partners in the top 200 rose from 3/25 to 19/25 and in the top 32 from 3/25 to 10/25, at about $0.10 per join and a median wall clock of 32 seconds. The cost is time: in the probe, 20 people joined at once and shared a concurrency of 16, and at 10,000 people the median wall clock per person was 31 seconds for the first stage and 68 seconds for the second; pre-registration 12 then measured single cold joins on a 10,000-person network: stage one 9.4 seconds (of which J++x building and registering about 10,000 questions took 6.2 seconds, longer than JEV's 3.2 seconds to answer them), stage two 0.6 seconds, first opportunity 10.6 seconds; $0.53–1.05 per person, of which recall is only about $0.09 and the rest is the combination-closure cascade, so by its criterion this is not usable; quiescence takes 6–12 minutes. After pre-registration 16 capped the cascade at 60 calls per host event chain (ordered by decisive reading, the rest suspended and resumed on the next related event), the same 4 people cost $0.093–0.149 each (median $0.122), quiescence median 76 s with 4/4 within 300 s, and the first opportunity still about 10 s; but each request the joiner denies opens a new chain that resumes suspended units, so the cascade per join window grew with join order from 60 to 367 calls and per-person cost rose with it; four points cannot tell whether it keeps growing.
