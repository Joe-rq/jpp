# 03 产品与宣传片调研（联网）

调研日期 2026-10-04。本文回答五件事：现在的 personal agent 产品是什么、能不能接入、有没有发现与撮合；一行命令接入的写法；顶级宣传片怎样讲故事；实时 3D 网络的做法与性能；对通爻网的十条设计建议。

读法说明。每条事实后面带来源链接和日期；页面没有标日期的，写“访问于 2026-10-04”。厂商或项目自报的数字单独标“自报”。第三部分的片子我没有逐帧观看，镜头与节奏的描述来自已发表的拆解文章，导演规则是我在这些材料上的归纳，文中分开标明。

与现有材料的关系：实验世界规格见 `应用/通爻网/design/world-spec.md`（500 个 agent、t0/t1/t2 披露层、latent/relay/pair/chain/ring/team/star/m2m/meta 九类结构），Nature 对网络规模的口述是 500 到 1000 个主体（意图汇编第 28 条），本次按用户这次的要求同时给出 1 万节点的做法。跨主体结果流动的既有调研见 `地基/研究/15-跨主体结果流动的外部做法.md`，这里不重复。

## B. 接入体验：一行接入的范式

### B1. 四种范式

1. 远程 MCP 地址加 OAuth：用户只需粘贴一个网址，登录授权后完成。云端 agent 只能用这一种，因为它们访问不到你的 localhost：Muse 运行在 Meta 云端的 Linux 虚拟机上，需公网地址 [SealGate 文档，访问于 2026-10-04](https://sealgate.ai/docs/connect-clients/muse)；ChatGPT 要公网 HTTPS 端点或 Secure MCP Tunnel [OpenAI 文档，访问于 2026-10-04](https://developers.openai.com/plugins/deploy/connect-chatgpt)。
2. `npx` 或 `uvx` 启动的本地 stdio 服务：本地 agent 一行命令，例如 `npx -y 包名`。
3. 带检测的安装器：一条命令检查本机装了哪些 agent，替每个写配置。例子：Stacktree 的 `npx stacktree-install` [页面，访问于 2026-10-04](https://stacktr.ee/blog/muse-connector-platform)；Poke 的 `npx poke@latest mcp add <地址> -n 名字` [文档](https://poke.com/docs/mcp-servers)。
4. 把一段提示词或技能文件发给 agent，让它自己执行注册：Moltbook 的“把这段话发给你的 agent”[moltbook.com](https://moltbook.com/)；AI Neighbor 的邀请提示词，粘贴到任何 LLM agent，批准后 agent 自装协作技能并领取密钥 [aineighbor.net](https://aineighbor.net/)；Abund.ai 的 `npx skills add abund-ai/abund.ai` 加 `skill.md`。

### B2. 各家 agent 的命令（我核对过的写法）

| 客户端 | 命令或配置 | 来源 |
|---|---|---|
| Claude Code | 远程：`claude mcp add --transport http <名字> <地址>`，带令牌加 `--header "Authorization: Bearer ..."`；本地：`claude mcp add --transport stdio <名字> -- npx -y <包>`。`--` 之前是 Claude 的参数，之后原样传给服务；JSON 里有 `url` 却没有 `type` 会被当成 stdio 而报错；SSE 已弃用，优先 HTTP | [Claude Code 文档，访问于 2026-10-04](https://code.claude.com/docs/en/mcp) |
| Codex CLI | 远程：`codex mcp add <名字> --url <地址>`，可加 `--bearer-token-env-var 变量名`、`--oauth-client-id`、`--oauth-client-registration auto|cimd|dcr`；本地：`codex mcp add <名字> -- <命令> [参数]`；写入 `~/.codex/config.toml`；添加时若检测到 OAuth 会自动发起登录 | [openai/codex PR #4904，2025-10-07](https://github.com/openai/codex/pull/4904)、[mcp_cmd.rs 源码](https://github.com/openai/codex/blob/27c05a52/codex-rs/cli/src/mcp_cmd.rs) |

### B3. 对通爻的推导

云端 agent 数量在涨，远程 MCP 地址是各家唯一的公分母，所以通爻的第一入口应当是一个带 OAuth 动态注册（DCR）的远程地址；Codex 与 ChatGPT 还支持 CIMD（客户端 ID 元数据文档）注册 [OpenAI MCP 指南，访问于 2026-10-04](https://developers.openai.com/api/docs/mcp)，两种注册都实现最稳。本地 agent 用一行安装器覆盖。对 Muse 这类没有 MCP 设置页的 agent，准备一段可粘贴的提示词。需要警惕的是：Muse Code 文档明说 MCP 工具不在沙箱内 [dev.meta.ai](https://dev.meta.ai/docs/muse-code/extending/)，本地 agent 会信任你给的工具说明，所以工具说明、返回内容都要按“可能被当作指令执行”来设计。

### C2. 提炼：实时 3D 网页的导演规则（我的归纳）

1. 先一个点。开场只有一个会呼吸的点（OpenAI 的 Emotive Point 与 GitHub 的“活着”）。第一句字幕在 3 秒以后才允许出现。
2. 揭示顺序：一个点，拉远看到许多点（规模），点之间飞出信号（发现），个别信号收敛成结构（撮合），结构亮起并带出置信度（结果）。每一步只增加一种新信息。
3. 先露边缘，后露全貌（Apple 逆光语法）。新结构先显示轮廓线，接着填充亮度，最后才出文字。
4. 文字只在三个时刻出现：命名（这是什么）、转折（规模变化）、结果（匹配与置信度）。字数用 Apple 的度量：一两个音节的词、每词不少于 0.25 秒，整片正文字不超过几十个。
5. 一次破例。全片统一的摄像机语法（缓慢环绕加轻微推进）里，只留一次剧烈动作（例如整个网络瞬间同步脉冲），像 Don't Blink 的 z 轴突入。
6. 运动曲线：入场与靠近用指数趋近（每帧向目标走 6% 到 12%，GitHub 的做法），信号飞行用 ease-in-out 的三次曲线，瞬时反馈（点击、接受）用硬切无缓动（OpenAI 语音片的做法）。同一个画面里不超过三种缓动。
7. 色彩：近黑底，灰白文字，只留一种强调色用于“发现与置信度”，其他全靠亮度与透明度（Linear 的做法：强调色只表示状态变化）。不使用渐变色背景和装饰性发光，发光（bloom）只给“正在发生的信号”。
8. 字体：一款紧凑的无衬线体做叙述，一款等宽体做数据与 ID（Linear、OpenAI Sans 与 Mono 的组合）。画面里同时出现的字号不超过三档。
9. 声音：音效用来证明响应，不用来渲染气氛；每条信号到达对应一个干净的短音；高潮前允许 1 到 2 秒近乎静音，然后用安静的定格收尾（Don't Blink 的门铃）。
10. 呼吸而不是持续高速：交替“推进、停留、推进”，每个停留给 1.5 到 2 秒让观众读懂（Apple Life on iPad 的首尾长镜头）。
11. 证明活着：结果节点可悬停、可点击，展示真实的上下文片段与置信度来源（GitHub 的结论）。无法证明的东西不要画。
12. 失败也要画出来：难负例让信号靠近后消散，说明系统不会什么都连。这一条是我加的，来源是 Tobira 强调“没有匹配的结论也算结论”。

### C3. 一个 45 到 60 秒的时间线草案

| 时间 | 画面 | 文字 | 声音 |
|---|---|---|---|
| 0–3 s | 黑底，一个点缓慢呼吸 | 无 | 近乎静音，一个低音 |
| 3–8 s | 镜头拉远，点增殖成几百个，每点附一圈暗环（上下文层） | “每个人都有一个 agent。” | 低频铺底 |
| 8–16 s | 个别点向外发出细信号，信号相遇后折返；另一些信号靠近后消散 | 无 | 稀疏的短音 |
| 16–26 s | 信号收敛：两点成对、三点成链、一点对多点；轮廓线出现再填亮 | “它们本来不认识。” | 节奏渐起 |
| 26–36 s | 单个结构放大：环层逐级亮起（t0、t1、t2），置信度数字出现 | “只交出一点点，然后逐级。” | 层层加声 |
| 36–42 s | 全网同步一次脉冲（一次破例），随即静下来 | 无 | 静音 1.5 s |
| 42–52 s | 缓慢退远，网络持续有新的结构生成 | 产品名与一行命令 | 门铃式的单音收尾 |

### D2. 3d-force-graph 能不能直接上 1 万节点

我下载了 three-forcegraph@1.43.6 的发布文件核对：默认每个节点是一个独立的 `Mesh`（球体），每条连线是一个 `Line` 或圆柱 `Mesh`，每个飞行粒子又是一个 `Mesh`（`three-forcegraph.js` 中 `new three$1.Mesh()`、`CylinderGeometry`、`TubeGeometry`、`photonDataMapper` 一带）。因此一万个节点加连线和粒子等于上万次绘制调用，这由引擎按对象逐个绘制的方式决定，调参数解决不了。官方示例的“较大图”是约 4000 个元素；维护者回答过 6.3 万节点的用户：只能先在后台预跑布局，设 `warmupTicks(200)`、`cooldownTicks(0)`，示例中 7000 节点和 7 万连线能用 [issue #124，2018-10-01](https://github.com/vasturiano/3d-force-graph/issues/124)；文档也建议关闭指针交互来换取性能（`enablePointerInteraction(false)`）。

结论：500 到 1000 个主体、几千条边的阶段，用 3d-force-graph 做原型足够，也能直接打开泛光示例；做到 1 万节点，改用自写渲染：节点用一个 InstancedMesh，连线用一个线段几何，信号用着色器。布局计算与渲染分开。

### D3. 1 万节点保持 60fps 的做法

下列预算是我的工程估算，没有实测；建议第一个原型就做一个基准页测量（见 E 第 8 条）。依据的外部事实附在后面。

| 环节 | 做法 | 依据 |
|---|---|---|
| 布局 | 在 Web Worker 里用 d3-force-3d 手动 `tick()` 跑到稳定，只把 `Float32Array` 位置传回主线程；d3-force-3d 的多体力用八叉树和 Barnes–Hut 近似，复杂度 O(n log n)；新节点只对局部做小范围迭代，或直接给定预计算坐标 | [d3-force-3d 文档](https://github.com/vasturiano/d3-force-3d/)（文中建议大图静态布局放进 Worker） |
| 节点 | 一个 InstancedMesh（低面数二十面体或始终朝向摄像机的面片），位置、颜色、大小、出现时间放在实例属性里；入场动画在顶点着色器里按时间算 | 7000 个独立球体掉到 60fps 以下、改成实例化后同一台机器能到 10 万 [Velasquez 2020-03-08](https://velasquezdaniel.com/blog/rendering-100k-spheres-instantianing-and-draw-calls/)；一个 InstancedMesh 对应 1 次绘制调用，10000 个独立 Mesh 对应 10000 次 [IGC，访问于 2026-10-04，厂商自报](https://intelligentgraphicandcode.com/development/threejs-interfaces/performance) |
| 连线 | WebGL 线宽固定 1 像素，需要粗线就用 three 示例里的 `LineSegments2`（实例化的屏幕空间线）或自写“实例化四边形”；全部连线合成一个几何 | three 示例 `examples/jsm/lines/LineSegments2.js`（路径已验证存在，见 D4） |
| 信号 | 不为每个信号建对象；连线几何带“起点时间、速度”属性，片段着色器按全局 `uTime` 计算亮点位置；加法混合 | GitHub 弧线用 `setDrawRange` 同样把动画交给 GPU |
| 泛光 | 只对信号和被选中的结构发光；three 示例的 `UnrealBloomPass`，或 pmndrs 的 postprocessing（把多个特效合并到更少的绘制通道，库自述）；注意 postprocessing 6.39.5 要求 three 版本小于 0.187 | 版本信息见 D4 |
| 文字 | 只为被选中或在镜头中心的少量节点（20 个以内）生成文字，其余不渲染；用 troika-three-text（SDF 文字） | — |
| 交互 | 不对 1 万个对象做射线检测；用 GPU 拾取（把节点 ID 编码进离屏颜色）或在 CPU 里用空间哈希；仅在指针移动时计算 | IGC 称把每帧射线检测换成 GPU 拾取，耗时由 8ms 降到 0.1ms（厂商自报） |
| 质量分级 | 照搬 GitHub：监测帧率，掉到阈值就降像素比、降泛光分辨率、减少可见节点和信号数；像素比上限设 2；抗锯齿关闭，用光晕和轻量 FXAA 弥补 | [GitHub 博客](https://github.blog/engineering/engineering-principles/how-we-built-the-github-globe/)、[Stripe 博客](https://stripe.com/blog/globe) |
| 暂停 | 标签页不可见或画布出屏时停掉渲染循环；用 IntersectionObserver | [GitHub 性能篇 2021-01-29](https://github.blog/engineering/user-experience/making-githubs-new-homepage-fast-and-performant/) |
| 渲染器 | 以 WebGL2 为基线。WebGPU 渲染器自 r171 起可用并自动回退 WebGL2，在绘制调用多和计算多的场景可能快 2 到 10 倍，但部分移动端仍是 WebGL2 更快，需按自己的场景测 [IGC](https://intelligentgraphicandcode.com/development/threejs-interfaces/performance)；three 官方示例有 20 万到 30 万点的 GPU 计算粒子 [webgpu_compute_particles](https://github.com/mrdoob/three.js/blob/740dd76c/examples/webgpu_compute_particles.html)、[webgpu_compute_points](https://github.com/mrdoob/three.js/blob/477da614/examples/webgpu_compute_points.html) | 信号粒子数很大时再考虑 |

目标绘制调用数（估算）：节点 1、光晕 1、连线 1 到 2、信号 1、被选中结构的细节几个、文字几个，加后处理 5 到 8 个通道，每帧总计在 20 次以内。

## E. 十条可执行设计建议

1. **入口只做一件事：一个远程 MCP 地址，OAuth 同时支持 DCR 与 CIMD。** 本地 agent 另给一行安装器，检测已装的 Claude Code、Codex、Cursor、VS Code、Gemini CLI 并写入各自配置；对 Muse 等没有 MCP 设置页的 agent，页面上放一段可复制的提示词。发布到官方 MCP Registry（`io.github.*` 命名空间）。依据：B 节各家命令，云端 agent 只能走公网地址。

2. **工具面压到四个：`join`、`disclose`、`inbox`、`respond`。** `join` 只收 t0 层一句话与能力标签；`inbox` 返回候选结构和置信度；`disclose` 由服务端按层放行，不让 agent 自己决定放多少；`respond` 接受或拒绝。同时对外暴露 A2A 名片（`/.well-known/agent-card.json`）与认证后的扩展名片，t0 放在公开名片，t1、t2 放在扩展名片，直接借用 A2A 的分级形状。

3. **服务端强制四层披露与人工确认。** 照 world-spec 的 t0、t1、t2、never 做；联系方式只有双方主人都批准后才交换（Tobira 的做法）；agent 可以探索和资格审查，但不能代主人敲定。每次升级披露都留日志，页面上可见。

4. **撮合要限量，要宁缺毋滥。** 学 Tobira 的教训：首日出过一夜 1014 个匹配被当成攻击；设分数下限（Tobira 用 0.30），每个 agent 每次只推 3 个，加“反同行”过滤。把难负例也作为一等结果展示（信号靠近后消散），验收时单独统计误报率，与 world-spec 的 40 对难负例对应。

5. **把身份与注入当作第一天的问题。** Moltbook 泄露数百万令牌，爆款帖由真人冒充；OpenClaw 的技能仓库出现恶意技能；Muse Code 的 MCP 工具不在沙箱内。对策：每个 agent 由真人账户认领；服务端永远把来自其他 agent 的文字当不可信数据，返回结构化字段而非自由文本指令；不发布会在用户机器上执行代码的技能，接入只给 MCP 工具；对所有写操作限速。

6. **前端视觉词汇与结构类型一一对应。** 一对一是两点一线；链是带方向的接力；环是闭合回路；团队是各取一块拼合；一对多是星形；多对多是两团之间的桥；再组合（meta）是一个团队先坍缩成一个新节点再与第四方相连；转介（relay）是网络之外的暗淡节点；潜信号是连线之前的微弱闪烁。每种结构有固定的“成形动画”，演示时观众看动画就能认出类型。

7. **宣传片与实时页面共用一份导演时间线。** 采用 C3 的时间线，写成可重放、种子固定、固定时间步长的脚本；实时页面按它自动导览，另一路用同一脚本逐帧导出高分辨率序列做成片。这样宣传片和产品页面出自同一份脚本，也符合“Agent 做的一切都能在 3D 世界里看见”的方向（意图汇编第 27 条）。

8. **渲染从第一天按 1 万节点设计，原型先做基准页。** 路线：Worker 中算布局，InstancedMesh 画节点，线段几何加着色器画连线与信号，泛光只作用于信号；加 GitHub 式的帧率监测与四档降级。第一个交付物是一页基准测试：1000、5000、10000 节点下分别记录帧率、绘制调用数、GPU 时间，在一台低配笔记本和一部手机上跑。500 到 1000 主体的演示可先用 3d-force-graph 起步，但不要在它上面叠加定制，避免日后重写两遍。

9. **文字、色彩、字体按 C2 的纪律执行。** 近黑底；一种强调色只代表“发现与置信度”；置信度用亮度与线宽表示，数字只在结果出现时才显示；叙述用一款紧凑无衬线，数据用等宽体；整片正文字控制在几十个以内，每个词停留不少于 0.25 秒；音效只在信号到达时出现，高潮前留 1 到 2 秒静音。做具体视觉前，按全局设计方法先写简报和“绝对不能像什么”（例如不做紫色渐变加玻璃拟态的通用 AI 页面），本调研不替代那一步。

10. **画面里的一切要么真实，要么标明模拟。** 实验阶段的 500 个 agent 是合成世界，页面角落写小字“模拟数据”（Nature 2026-09-26 的口径：标一句“假结果”即可）。结果节点可悬停可点击，显示 t0 摘要、置信度来源和已披露的层级，这对应 GitHub 地球的“活着的证据”。Rabbit 与 Humane 的教训是：片子里的能力产品做不到，信任会整体崩塌。
