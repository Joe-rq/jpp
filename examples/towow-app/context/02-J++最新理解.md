## 1. J++ 是什么，理论上站在哪里

J++ 是一门编程语言，最底层的原语是一次语义判断：对一份材料回答一道题，返回校准过的概率分布。它要做到两件事：同等水平的程序写起来便宜、快（一句顶一百句）；以前写不出来的程序现在写得出来，例如数百道判断连环、数秒内数千次调用、判断与生成、执行、精确算法、问人协同工作（`00-定位与方法论` §一；R-001、R-003）。

它不定义在 JEV 这个产品上，定义在一份**能力画像**上：便宜、快、可成批调用、会错、带校准置信度、知道自己何时拿不准的语义判断器。JEV 是一号画像。画像字段描述成本、时延、并发、噪声、窗口、已知缺陷（比如不做算术）；语言规则只引用画像字段，不写死任何数值。换一个判断器，只换画像与接口，程序一个字不改（`00-目标与动机` §二；`12` §1.2–1.3）。降级规则逐行规定「某字段为假或未测时关掉什么」，未测时取保住守卫的一侧（B39）。

项目把自己定位为「在构建一套理论」：这类判断器的使用规则（一道题由什么构成、对哪些材料问、读数如何变成动作、拿不准去哪、深度受什么限制、预算与时延怎么分）。J++ 是这套理论的可执行形式。它有三个可检验的预言：判断器变强，程序不改效果变强；换任务不改语言；别人要单独设计的逻辑在这里是一条语句（`00-定位与方法论` §二）。

**任务无关是硬要求。** 语言只关于判断器自身的逻辑，像数学只关于数（`00-目标与动机` §五；R-005）。它不是工作流框架、Agent 框架或 JEV 的 SDK。为什么必须是语言：有一组调度与语义决定没法在局部做，只能由整个程序的分析与运行时接管，即下文第 4 节的八件事。判据是：如果作者能**无意中**绕过某件事（例如同一程序两种写法调用次数差十四倍），这件事就还没被语言接管（`00-定位与方法论` §三）。

各效应同级。判断的特殊之处只有一点：它是唯一产出读数的效应，读数必须过桥才能变成程序能用的东西（`00-定位与方法论` 术语表）。

## 2. 核心值与类型

### 2.1 材料与状态

`Mat` 是唯一的材料类型：`{content, addr, modality, origin, taint, derived_from, render_version}`。任何能渲染成文字或 JSON 的东西都能当材料，判断的结果本身也是数据（R-024）。宿主函数的返回值不能直接进判断槽，要经 `transform`（记账的宿主变换）才行，账本记输入输出哈希，同输入异输出判为不纯（`12` §2.1、§2.8）。

状态是一次判断的输入：`state(on, ctx, ref, over)`，四个具名槽。`on` 恰好一个判断对象（关系题用 `(a, b)` 复合对象）；`ctx` 是语境；`ref` 是参照（打分题必需的锚）；`over` 是候选集。n 个主体共享语境，就是 n 个状态共享 `ctx`、同层并发发出，不做「多主体状态」（B62，因为同状态多对象有串扰，H8）。候选在值上属于状态，在线上随题发出（B155）。

### 2.2 题

一道题有五件：**主体**（读哪个槽、几个对象，由槽形推出）、**谓词**（判断内容）、**划分**（二元 / K 元 / 有序）、**请求**（是非 whether、K 选一 one、打分 degree；子集请求 all 是 K 道是非一次发）、**前提**（可选声明，不进账本键，进校准键）（B1；`12` §2.2）。题的模块清单定为十项：五件、四个状态槽、校准引用（B46）。另有一份守则内嵌的「十模块」（材料、谓词、切法、请求、前提、语境、参照、预算、拿不准去向、完成条件），用于由目的组装题（裁定四）；两份清单用途不同。

三种题型是程序能被判断驱动的三种方式：是非题给一个位（`if`），K 选一给一个索引（`switch`），打分给一个数（`while` 的进度、排序）。三者对「驱动程序」完备且最少（`06` §6）。三者合起来是优化问题的三要素：约束、选择、目标（`06` §3）。语义操作与物理题型分开：作者写 test / select / measure，编译器按 K、候选长度、已测偏置决定下沉成哪种物理题（`06` §6；`12` §4 pass 4）。

题类（属性、关系、子集、充分性、比较、归类、提及、程度、决定）由 `op × 槽形` 推断，是只读字段 `Question.kind`，作者不可写，用于校准键分类与诊断（B46、B76）。

### 2.3 读数

读数是判断器对一道题返回的概率分布，是随机变量，不是值。跨题不可加、不可比（P(x)+P(¬x) ≠ 1），不再喂回判断器。读数只能经桥离开：`cut`，或跨题合成的 `fit`（`12` §1.1 I1–I3；J-01、J-04）。读数的合法去处是八类：守卫、材料上的标记、下一题、校准、预算与规划、交给外层或人、`fit`、题库维护（B22）。同题同锚、单独渲染的读数可以 `order` 排序（同尺才可比）；同题重复读数可以 `repeat` 取均值压抖动，对出口取多数表决是禁止的（B28）。

### 2.4 桥与三值出口

`cut(读数, 线?) → Exit`。出口形状冻结为 `Act | Ignore | Pick(k) | At(ℓ) | Unsure(cause)`（R15）。未决原因是封闭枚举，十六种：`band, tie, insufficient, fail, budget, depth, latency, deadline, noprogress, rejected_all, no_candidate, absent, infeasible, cold, claim_conflict, violation`（B197）。其中 `absent, budget, depth, latency, deadline` 是缺席类，表示「没观察到」，出口不能被放弃（B95、B197）。`untested`、`delta_unknown` 一族是读数上的正交位，不是原因（R14、R15）。

`cold` 的变化要注意：B187 一度删了它，B197（裁定四十三）又加回，含义只是「这一出口没有可信记录」，无线时照样按多数块走；GUIDE 里「原因里不再有 cold」是旧句。

### 2.5 线

线把读数映射为出口，三种来源（`12` §2.3；GUIDE「线从哪里来」）：

- **无线**（默认）：按读数的多数块走。是非题 p > 0.5 为 act、< 0.5 为 ignore；K 选一与打分取最大块；恰好并列出 `Unsure(tie)`。出口等级 `Answer`（B187）。
- **作者声明线**：`cut(r, {declare: {hi: 0.7, lo: 0.3}})`，按写的数切，中间为 `Unsure(band)`，等级 `Declared`。这是作者的策略，语言不剥夺、不替换（B128；意图汇编 11）。另有 `stat`（切在期望、概率和、自报置信度上）、`closed`（端点开闭）、`feasible`（代码谓词改选可行候选）。
- **认证线**：作者要语言担保错误率时才用，由带真值的标注经 `calib-import` 认证（固定序两侧检验，B24、B86），等级 `Certified/Trial` 等。手写的数不得冒充认证结果（J-03）。

### 2.6 账本

账本是追加日志，唯一的真相来源。每次判断、生成、执行、问人、缺席都记一条。三种键要分清（`12` §2.2、§2.4、§2.5、§2.10）：

- **账本键**定位一次效应：判断条目按状态与题的内容加站点（站点现为「定义路径加定义内序号」），`gen` 为 `(site, prompt_hash, ctx_hash, n, retry_seq)`，`do` 为 `(site, action, args_hash, iter_seq)`。同一份材料、同一道题从不同 `judge` 调用处发出，不按账本键复用（GUIDE「写法提醒」）。
- **缓存键**决定跨运行复用：只由方法身份与输入决定，不含调用位置（B20、B40）；单元图里判断单元按题与材料的内容键跨程序共用（R1）。
- **校准键**决定用哪条线：`(form_hash, slot_kinds, phys, render_version, literal_mode, model)`，题式为主键、填法为次键（B2、B30、B60）。

不可逆 `do` 发出前写意向、返回后写效应，逐行落盘（B55）。只凭账本重放不调判断器、不重触世界；缺键报 `E-replay`（B35）。账本头带画像哈希、模型 id、库版本等，不同即不承诺重放一致（J-18）。恢复只以账本为准，任何进程内续延（async、协程）不得成为恢复依据（`12` §2.6）。账本键现为「定义路径加定义内序号」，改注释不换键（账本第 6 版，`现状与交接`）。

### 2.7 方法作为值

方法（闭包）是一等值：可作参数、记录成员、列表元素、返回值。创建方法不执行函数体，函数体的效应属于未来的调用（`13` §1）。方法类型带效应上界：`Fn(A) -!{judge}-> B`，未标注的高阶方法在每个调用点按实参实例化效应（`13` §2；FRONTEND）。方法身份包括捕获的环境，用于缓存的键不能只取代码正文（`13` §4）。捕获了未决责任的方法若是该责任的唯一路径，就是 `Fn¹`，调用一次后再调用为错（B52）。

效应形式本身（`judge`、`cut`、`do`）不是一等值，只能出现在调用位置；要当参数传，包一层 `fn`（B56）。

### 2.8 题作为值

题与题式都是一等值：`test(题面, 校准键)`、`select(...)`、`measure(题面, 档位, 键)` 造题；`form(op, 模板, {...})` 造题式（带槽的模板），`fill(题式, 填法)` 填出具体题（`12` §2.2；GUIDE 内置表）。题能放进列表、按出口路由、由生成器生成、由上一轮出口派生（确定性派生为默认，`gen` 唤出为后备，B45；是非题某一块挂签名即可连环派生，裁定十九）。题面也能当另一道题的材料（诊断题读题面），J-02 只禁一道题的出口回喂同一道题（B4）。

### 2.9 题树

复杂判断靠结构拆开，不靠把题问浅（意图汇编 7b）。大模型在循环开始前一次生成整棵追问的题树，判断器沿每步出口往下判。库函数 `walk(tree, material, depth, opts)` 实现它：节点是是非题或 K 选一题，叶是结论；`grow` 在进入节点前把材料变成该节点要看的样子（如并入第三个人）；`keep` 是代码谓词，代码能定的节点不发判断；`enrich` 在节点拿不准时问缺哪类、取来、再判。缺省 `eval: "all"`：同一份材料上的整组节点一次发出，之后纯按出口下行，层数 = 材料变化次数 + 1（B185；GUIDE「题树」；B185 原文写的缺省 path、冷线未决已被后来的实现与 B187 取代）。叶出口是路径各出口的强 Kleene 合取。反事实归因用 `without_member` 逐个去掉成员、对同一道题的读数 `order`，按相对变化找关键人（GUIDE）。

### 2.10 契约值

每个单元与组合产物露出同一接口：`value`（产出）、`pending`（未决清单，带责任）、`evidence`（账本键）、续接方法、`spent`（已花预算）、`detail`。三条不变量：组合产物与基本单元同型，可再参与同类组合；未决责任随包转移；证据只存账本键（B17；`12` §2.12）。

## 3. 效应

| 形式 | 是什么 | 纯 / 效应 | 画像与要点 |
|---|---|---|---|
| `state` | 构造状态（四槽） | 纯 | 窗口检查（H6），超窗交裂变 |
| `judge` | 在状态上问一批题，得读数 | 效应，惰性 | 成本回归、p95 时延、并发、噪声 δ、窗口、类假设 H1–H9；同状态多题一次调用（H7「状态收费、题近乎免费」） |
| `cut` | 读数过线变出口 | 纯（内核桥） | 线来源三种；出口第一次被检视时才解析（B94） |
| `gen` | 生成候选、模板、题树等 | 效应，惰性、非阻塞 | 每候选成本、时延分布、空率；输出 taint 缺省 `untrusted`（生成器端口），确定性枚举器是零成本 `gen`；只在程序结构需要新东西时调用，产物按键缓存复用（B149、B151） |
| `do` | 执行器、精确算法、检索、渲染、世界步进 | 效应，惰性 | `Action = {name, cost, latency, reversible, fail_types, taint_out, mat_shape?}`；`Fail` 是值，走 `Unsure(fail)`；内置 `exec_py`、`exec_sql`、`check_tests`、`graph:*`（匹配、最短路、最大团、连通、集合覆盖、最大流）、`bm25_topk`、`embed_topk`、`env:step`（B150、B159） |
| `ask` | 问人 | 效应，异步 | 贵、小时到天、可能不答；答案是真值、taint trusted；返回 `Pending` 时程序整体挂起，恢复 = 从头重放账本（`12` §2.6） |
| `transform` | 宿主函数变换材料 | 记账的宿主效应 | 键 `(site, f_hash, args_hash)`；纯性由账本核出 |

五种效应各有画像分表；只有 `judge` 有类假设与降级规则，其余只有调度与预算输入（B37）。效应实例 = 效应种类 × 模型 id，三种键都含 `model`，IR 节点可带 `via` 指定实例；同一程序内两个读数实例的路由本版不裁（B60）。所有效应共用一个预算池，各按画像计价（B38）。

**执行模型。** 程序是普通宿主程序（数据结构、纯函数、有界循环），效应在任意位置出现。效应是惰性的：调用只登记，到程序真的需要出口时（刷新点：`cut` 结果被检视、`if`、`match`、读内容、函数返回）把已登记、输入就绪的效应按依赖分层，一层一次发出。判据是「凡结果依赖于出口的操作皆是刷新点」（`12` §0、§2.2；B94、B145）。这是同一直线段内判断自动合批的来源。

## 4. 运行时接管的八件事

术语按意图汇编 16 用机制名加定义。「已造」以代码与 `现状与交接` 为证；`20` §2.5 只说明计划由哪个模块负责，不作已造的证据。

| 机制 | 一句定义 | 已造 | 未造或缺口 | 关键裁定 |
|---|---|---|---|---|
| 批调度 | 哪些题挤进同一次调用、哪些同层发出 | 惰性登记与刷新点、惰性过桥（步 23c）；`lift`、`speculate`、`vectorize`、`fission` 四个 pass 加刷新时的融合（`flush.rs`，开关 `fuse`）；层内超预算时按价值密度排发出顺序（`select.rs`）；按材料哈希分组，同材料不同候选集的 select 合成一次；gen/judge/do 同层一次提交轮询取回 | `map` 里多个 `search` 串行；`if` 是刷新点，作者要先算齐材料再登记；递归逐题不保证合批；跨程序的共享刷新点未造 | B94、B145、B149、B155、B51-C1 |
| 深度与终止 | 何时再往下问一层、何时停 | 「何时停」在内核：步数上限、无进展、账本键在循环内重复三条终止线（`iterate`、`loop` 必带 bound） | 「何时再问一层」在库与作者手里，规划器只能少问不能多问（差距如实登记为 T7）；跨程序触发链深度只在原型 | B43、B132、J-06、R11 第 5 条 |
| 未决去向 | 每个拿不准的出口去哪 | 四类去向、责任按账本键记、返回前可达性核、`E-drop-unobserved`、默认链与伴随题、违规事件 | 跨程序读者承接未造；检查器静态面能被三层函数转手绕过，靠运行时兜底 | J-05、B31、B52、B95、B162、裁定六 |
| 预算 | 有限的钱与调用怎么分 | 计划期区间估计、可靠下界超预算才拒；层边界核、超额按价值密度挑本层子集；只停发不停程序；`--carry-in/--carry-out` 跨运行余额只收紧 | 用完是静默的，看起来正常结束；花费估计不看语境长度（第三靶子实花 2.3 倍）；整场共享账户未造 | J-07、B42、B93、裁定十六 |
| 缓存与增量 | 问过的不再问，材料变了只重算受影响的 | 同运行按键复用；`--cache` 跨运行；单元图 C1、C2（`--cells`，单程序经单元图求值，判断单元按内容键） | 单元存储持久化、由账本重建、多程序共享、按世界变更复用（C3 起）未造；缓存索引不收复用来的条目 | B20、B40、R1–R4、B193、B199 |
| 校准 | 概率怎么读成决定 | 无线按多数块、声明线、认证线三条路都在；`calib-import`、固定序两侧认证、题库 | 真实程序里有线题 0/1,634；题库靠真实程序长，方向待 Nature 定 | B24、B86、B128、B187、裁定六十七、六十八 |
| 判断力缺席 | 判断器掉线、超时、不可用怎么办 | `Unsure(absent)`；`budget.absent` 重试、退避、熔断；缺席不进答案表，可再问 | 隐式重试不分错误类型 | B32、B35、R1 |

## 5. 未决必须消费：J-05 的最新默认去向

J-05 的本义：每个 unsure 出口必须有明确去向，四类封闭——交给另一道判断或计算（`refine`、`enrich`、`reselect`）、交给人（`escalate`）、显式放弃并记账（`drop_accounted`）、随返回值或单元值转交（`handoff`）。没有「什么都不做」这个去向，不加第五类（B31；R13）。项目对它的定性是「深度的使能机制」：判断器知道自己何时拿不准，于是深度上的错可以被路由，而不是被传播（`00-目标与动机` §四）。

**谁来定去向。** 以前作者不写去向即错。现在作者写了按作者的；作者没写，语言按**默认链**给，语言给的去向算去向（裁定六；草案改法 1、2）。开 `--guard` 恢复旧行为。

**默认链的三步**（草案 (2)；实现 `crates/jpp-runtime/src/unsure_default.rs`）：

1. **问**：已有伴随题读数就直接用；没有就发一道 select 问「为什么拿不准」，候选是可能缺的信息类别，外加「不缺信息，事情本身两可」「题问得不清或前提不成立」。候选类别四级来源：作者 `unsure_source` 声明 > 题式槽表 `lacks` > 守则填的 `lacks` > `lib/unsure.jpp` 通用表（裁定五十一）。候选只有一类时不问，直接取（代码能定的不问判断器）。
2. **取**：从程序声明的来源取被选中的那类材料。顺序：作者 `unsure_source.fetch` > 程序料库 > 宿主取材料端口 > 无（裁定五十五）。只做可逆读取。**生成器不进默认链**：让模型替材料作证，判断器判的就成了模型的说法（裁定五十五，意图汇编 7c「不是去诱导它」）。
3. **再判**：同一道题、同一条线，在补过的材料上重判；新条目带 `from_key` 指回原判断，去向记「细化」。补来的内容只进这道题的输入，不改共享原材料。每个没给去向的未决都补，不挑关键的（Nature 2026-09-29「补肯定是全部补的」）；预算不够时按价值密度排先后。每个类别对同一道题至多取一次。

**伴随题**（草案 (0a)；实现 `companions.rs`）：一道题还没有可信记录时，语言在同一批、同一状态上并行发一组伴随题，按题的模块各问一道：前提成立吗、缺哪类信息、是否藏了两个判断或有两种读法、按更细划分落在哪格、参照与语境够不够。伴随题读数不参与原题出口，只用于两件事：原题拿不准时直接指路；写进报告「这道题怎样能更拿得准」一栏（`improve` 段）。依据是 Nature 2026-09-29：「拿不准本身是个信息……语言应该自带这个」（意图汇编 30）。

**两种触发。** 读数触发：出现未决出口，或无线判断的读数落在边界带内（带宽 = 画像 `delta.<phys>.mid`，裁定五十二）且程序声明了材料来源时，先补再判，出口按补完后最后一次读数定；补不了按多数块出口并记 `near_boundary`（草案改法 3；实现 `读数触发`）。结构触发：题树上标了可能缺信息的节点，同一轮并行问缺哪类。读数触发在部分路径上只走到第一步：派生前提的 `sieve` 不登记判断来历，前提读数落进带内时只记 `near_boundary`（`使用问题清单` 第七节，未处理）。

**末端（三方不一致，照实并列）：**

- 草案 (4)：仍未决的一律转交，语言不做丢弃。
- 裁定六：补不到或补了仍拿不准，记账放弃。
- 代码（按裁定六与后续裁定）：`band`、`tie` 补完仍未决 → 记账放弃；路 C（没有任何取法，问出了缺哪类）与 `insufficient` → 转交，缺的类别进报告 `needed`（裁定五十五）；缺席类 → 随值带走（B95）；过程入口的动作题 → 按最后一次读数的最大项行动，未决照样转交进 `pending`（裁定七十八）。

**未决值的传播**（草案 (5a)）：结果依赖未决值内容的运算，结果就是那个未决值；作 `if` 条件时两支都不执行；作效应参数时该效应不发出、记跳过。未决值不当假、不当空。现状：放进列表时整个列表变成未决，到 `concat` 才报一个不说修法的错（`现状与交接` 第三节第 10 条）。

**推翻条件**：真机上补信息后再判，读数离边界没有变远、判对率没有上升（预注册后测），默认链退为只有转交（草案）。

## 6. 默认相信判断器，与判断分工定律

**B187 四句原则**（Nature 2026-09-26 明令；`12` §0、`13` §7）：(1) 判断器的回答默认就是程序的走向；(2) 作者写的线是作者的策略，按写的数切；(3) 放行把关、认证、来源标记都是可选工具，放行把关是宿主开关 `--guard`，默认关；(4) 账本是记录，账本、意向先落盘、J-05、`bound`、`budget` 照旧，它们保证终止与可重放，不是防线。具体翻转：无线不再出未决；不可逆 `do` 默认按作者的条件执行；无沙箱只告警 `W-action-no-sandbox`；没给账本路径时自动写到源文件旁（B187 表 1–14 行）。B188 把 39 条机制分成删除 11、改可选工具 12、纯记录 16。

**B190 设计红线**（`00-定位与方法论` §八第 10 条）：以「不信任判断器」为前提的默认限制不得进语言。判据两问：规则不成立时程序会不会按判断器的回答走；理由里有没有「万一判断器错了」。命中即只能作使用者自己打开的工具或纯记录。Nature：「直接改掉，以后永远不允许出现这种『信任问题』。」B39 的「画像未测取守卫侧」不属信任类，那是判断器能不能读的问题。

**判断分工定律**（B181，取代原字面化定律；`08` §2）分两半：

- **材料半**：每道判断的材料必须已经含有决定性证据，一跳读出。要运行、取、算、渲染才知道的，先由确定函数把证据摆到判断面前（`do`、`transform`、`gen` 接地）再判。这一半只约束材料形态，不约束题的难度。
- **谓词半**：材料摆好后，凡能由确定算法得出的（相等、包含、字段存在、退出码、长度、计数、排序、算术）用代码，不进判断；判断只问材料到结论之间没有确定算法的那一段。意图汇编 7a：「写一个 Python 就能达到的事，为什么要单独用 JEV 来去判断呢？」

GUIDE 把它落成交给 JEV 的三条判据：无确定算法、证据已在材料里、一跳一命题（B182）。三条都满足的题，语义再深也直接问，不先拆浅；「这两个人适不适合合作」「透露这条信息会不会推进合作」都属此类（意图汇编 7b、7c）。命题多跳时拆成题树，每节点仍是一跳。语言里的落点：`keep`、`feasible` 代码谓词（B184、C-4），派生前提先过分工定律、能由代码定的直接作代码谓词、账本记 `by: code`（裁定六十八）。

**要效果，不省调用**（意图汇编 7c）：调用次数不作为设计约束；不把今天模型的弱点写进语言；深问题直接问，拿不准就问缺什么、补、再判。

## 7. 组合封闭性与搭配

**搭配是底层。** JEV 与生成器、执行器、精确算法（图算法）、检索、人的搭配是 J++ 的底层（意图汇编 3–5；R-082、R-084）。按 JEV 的四个缺口推：不生成、不触世界、不算术、不记忆。JEV + 生成器 = 搜索；JEV + 执行器 = 可审计的 agent；三者闭环「提出 → 接地 → 校准地判 → 再提出」，任两个都闭不上；第四样是人，未决升级给人、人的答案进校准集（`08` §4）。

**语言里的体现有三层**（GUIDE「搭配：元素 → 组合 → 嵌套」）：

- **元素**：一次判断、一次生成、一次执行、一次图算法、一次检索、一段确定性处理。输入输出都是普通值或材料，不夹带读数（数字不流，J-01）。
- **组合**：库函数（`lib/compose/*.jpp`），全部写在内核构造 `sieve`、`pair`、`compose`、`element`、`carry`、`iterate` 之上，不是新语言构造：`search`（提出 → 判 → 再提出，可行域题与目标题，`opts.ground` 接地）、`ground` / `verify`（执行后判）、`judged_graph` / `judged_bipartite` + `interval`（判断给边、图算法给全局解，已决与含未决两组都算）、`walk`（题树）、`ask_human`。内核构造只收必须用到内核能力的（直接读答案、签发内核值、责任表），四骨架与 `tally`、`first_k`、`iterate` 原则上都应是 `.jpp` 库（B57）。
- **嵌套**：组合产物与 `sieve` / `pair` 产物同形（契约值，元素带 `item`），能原样交给下一层：`search` 的 `opts.ground` 填一个接地闭包；判出的分工图的产物再判、再建第二张图；`map` 里跑多个 `search`；`walk` 的叶再 `sieve`；几次 `walk` 的叶出口 `compose`。跨层时未决去向、预算、账本与重放都由库与语言带着走，`pending` 用 `concat` 或 `carry` 汇总（GUIDE；B17、B81、B82）。

**分层要对**（R-086）：JEV 做发现层，在成千上万个主体里把值得细想的关系与材料送到大模型面前；大模型只协调三四个主体。旧实现把这两层做反过，被记为架构错误。这条对 agent 网络应用直接有用。

**组合封闭性的运行时形态**是 §2.13 的单元图：组合产物是代码单元或程序单元，与基本单元一样可被读、再参与组合；判断单元按内容键跨程序共用（R1）。这一层目前只造了单程序部分（见第 8 节）。

**作者只给目的的三种入口**（README「Three ways in」）：`purpose_run`（一批条目问同一批由目的派生的题）、`purpose_drive`（世界每拍出一道动作题，`--env` 接外部世界）、`modules_run`（作者自己填守则模块）。题由语言从目的派生，过诊断闸门，命中题库就用已认证题式。

## 8. 现有实现的已知缺口

**一句话现状**（`现状与交接`）：只给目的的真实程序在两个真实项目上真机跑通、效果与手写版相当；一个按步推进的游戏世界跑通但没到能用水平。地基还缺四件：持续计算的上层、常驻有状态环境、料库底座、检查器。

**持续计算：设计在 `12` §2.13，实现只到单程序。** §2.13（骨架 v1，裁定三十九选「单元图」作计算模型）的设计是：值有版本、可持久、可被别的程序读；材料变了沿反向依赖边标脏，有人读时才修复，两层截断（输入没变不重算、对外指纹没变上层不重算）；程序单元有四种状态（进行中、已定、已修正、未决），「进行中」可读并带 `progress {judged, total}`；两种读法——**等到读**只读定下的版本，**立刻读**读当前最新版本（可能是进行中）且所读版本进账本；多写者单元必须声明归约器，`Claim` 是全有或全无的占用，被拒得 `Unsure(claim_conflict)`；读者读到带记号的未决，按元素各接一份欠账；跨程序共用追踪编号、预算与截止只收紧、付钱方是第一个要求者、用完只停发不停程序；宿主只做三件事（送事件、供时钟、展示），持续计算逻辑不写在宿主里（R1–R16）。B195 定了写法（**设计写法，未进 `.jpp` 文法**）：`resident <名> on [事件来源…] { … }`、`cell <名> reducer <归约器>`、`Read{Settled|Peek}`、`Write{Put|Claim}`、`Spawn{program, args, budget?, deadline?}`。

实现：`jpp-cell` crate 做了单元图的单线程语义（C1），解释器经单元图求值（C2，`--cells`，缺省开、大输入明显变慢，`--cells off` 结果逐字节相同）。落地单之后的八步——事件写账本与存储持久化、多程序引擎与常驻入口、两种读、读者承接与多写者、宿主动作声明与世界读端口、计划期一列、截止时间、并发尝试——都没造（`规划/骨架v1-落地变更单.md` C3–C10；`现状与交接` 第一、二节）。§2.13 各条的「主语言」行几乎都写「未落地」。

**「长驻、事件驱动、进行中的计算参与其他计算」不支持的具体表现：**

- 一个程序是一次输入、一次返回。事件一到就反应的长驻程序（如几百个主体的网络）不能用 `.jpp` 写，长驻、排队、状态管理只能放进宿主（README「What it cannot do yet」；`使用问题清单` 第三节「持续计算」，两个不相关的实践线各自撞到）。
- 别的程序只能拿到最终答案，拿不到算到一半已得的结果；没有立刻读、等到读、进度字段的语法与运行时。
- 没有「每次调用完成」的实时观察钩子，界面无法实时显示「刚判了这一条」。
- 实时场景每拍要重新起一次运行，跨拍状态与缓存由宿主拼。
- `--env` 驱动的世界每步整份状态传进传出、每步起一个子进程，状态不能序列化的仿真接不进来（N-B1，要先请裁定）。
- `map` 里的子程序串行，多个独立计算不并发推进。
- 没有跨运行、按内容寻址的料库；材料只活在一次运行的账本里，`jpp store get` 不存在。
- 多个主体争同一组成员的互斥（占用）、多写者单元、跨程序刷新点合批都没有。

**与持续计算构想的差距。** Nature 的原始构想（`附注/2026-09-20-J++与通爻-持续计算形成动态关系.md`；R-066、R-067）是：动态画像来自持续进行中的计算，不是历史结果；正在变化的得分与中间构型本身能成为别的计算的输入；「计算改变可发现性，可发现性改变后续计算」；复合构型继续作为新的计算对象。R-068 要求语言补四样：(1) 进行中的计算能被订阅；(2) 多个子程序同时跑；(3)「下一步跟谁算」本身是一段可替换的程序（网络级路由）；(4) 跨节点组合带着题的身份走。对照现状：(1) 有设计（立刻读、进行中版本、读者被标脏重跑）没实现；(2) 有设计（多程序引擎、带种子调度器、并发尝试 C10）没实现；(3) 只有本地的 `order`、`allocate`，网络级路由没有设计；(4) 判断单元按内容键跨程序共用有设计，跨节点身份没有设计。另外 §2.13 的 v1 只有「等定下」一种等待，带条件的等待（如「得分超过某值时唤醒我」）留作以后（R5）。

**其他已知缺口**（`现状与交接` 第一、三节）：检查器设计的十三条静态规则没造，未决经三层函数转手检查器不报；题从目的派生，但有线题比例为 0；派生的是非题不带两端描述，读数偏低；跨运行缓存目录要放全部祖先账本；超窗读数只发 `W-window` 照常出值；验收侧能力对照、深度曲线（现两层，要五层）、消融都没做。

## 9. 「对 JEV 的简单编排」能做到的，与只有 J++ 才做到的

简单编排指：普通语言里写循环调 JEV API，手工拼请求、手写重试与阈值。判据见 `00-定位与方法论` §三：能在局部决定的事库就能做；必须看整个程序才能决定、或作者会无意中绕过的事，才是语言的活。最后一列决定新应用能不能直接依赖现有 J++。

| 能力 | 简单编排怎么做 | J++ 的机制 | J++ 现在 |
|---|---|---|---|
| 同一材料多题一次问完、互不依赖的判断同层发出 | 每个程序手工拼请求；换个写法（包进函数、逐题递归）调用数暴涨，实测同一程序两种写法相差十四倍 | 惰性登记、刷新点、提升与融合、按材料哈希分组；写法不影响调用数（B94、B155） | 已造（`map` 内 `search`、递归逐题除外） |
| 拿不准的结果不丢 | 靠作者记得；非设计者五份程序四份把未决丢了且都过了验收（B95） | 责任按账本键记、经闭包与容器可达性核、返回前核、`Fn¹`、违规事件 | 程序内已造；跨程序承接未造 |
| 拿不准时问缺什么、补、再判 | 每个项目手写重试与补料 | 默认链、伴随题同批、四级候选、取法层、读数触发（第 5 节） | 已造，部分路径停在第一步 |
| 题从目的出、沿题树快速验证 | 手写题面与分支 | 守则派生、诊断闸门、题库、`walk` 同材料子树一次发出 | 已造；有线题 0 |
| 判断 + 生成 + 执行 + 图算法嵌套组合 | 胶水代码，每层重写未决与预算处理 | 契约值同形、`search`/`ground`/`judged_graph`/`walk` 互相嵌套，未决与预算跨层自动带 | 已造 |
| 预算与深度全局分配 | 计数器，超了就停或静默截断 | 计划期可靠下界拒、层边界按价值密度挑、只停发不停程序、跨调用只收紧 | 单程序与跨运行余额已造；整场共享账户未造 |
| 换判断器程序不改 | 改提示、改阈值、改解析 | 画像字段 + 逐行降级规则 | 已造（证据偏弱，V1-4） |
| 读数不被误用（跨题算术、跨尺比较） | 无防护 | J-01、J-04 静态拦；跨题合成只经 `fit` | 已造 |
| 可审计、可重放 | 自己打日志 | 账本意向先落盘、只凭账本重放零调用、追踪编号拼树 | 已造 |
| 问过的不再问、材料变了只重算受影响的 | 自建缓存，键难定 | 判断单元按内容键共用、依赖边标脏、两层截断、增量与从零静止状态相同 | 单程序已造；跨运行持久与多程序未造 |
| 一段正在算的结果被另一段用上 | 做不到，或在宿主里自建消息与状态 | 立刻读 / 等到读、进行中版本与进度、读者被标脏重跑、修正记录 | 未造 |
| 多个主体争同一资源、多方写同一值 | 自写锁与协议，难以重放 | 多写者单元 + 归约器、`Claim` 全有或全无、合并顺序进账本 | 未造 |
| 跨程序合批、付钱方、深度链 | 不存在这个概念 | 引擎共享刷新点、第一个要求者付、触发链深度只收紧 | 未造 |
| 运行前担保所有路径 | 无 | 检查器静态规则 | 部分；可被三层转手绕过，靠运行时兜底。这是「为什么必须是语言」的核心论据，目前偏弱（`现状与交接` 第二节第 4 条） |

**对新应用的含义。** agent 网络应用里「只有 J++ 才做得到」的部分，集中在表的后四行：进行中的计算参与别的计算、多主体争资源与多写者、跨程序合批与预算链、按内容键在主体间共享判断并增量重算。这几行在现有 J++ 里都是有设计、没实现。实验版语言若要证明「只有 J++ 才能做」，需要自己把 §2.13 的这几条造出来，并以「宿主里不手写持续计算逻辑」（B1-6 硬验收）作为检验。

## 10. 现行 .jpp 语法速览

文法（FRONTEND）：`budget {calls, cost, depth}` 必须在程序开头声明；`let` 不可变绑定；`fn` 字面量与具名函数；`if … else`；记录 `{k: v}`、列表、下标、字段；块的最后一个表达式是值；`import "相对路径";` 导入库；类型标注 `Fn(A) -!{judge}-> B`、`Fn1`。没有可变变量，没有 `now` 与无种子随机（不确定性只经端口进来，B157）。

下面这段由 GUIDE 与 `examples/` 的片段拼成，展示了最常用的写法（`steps`、`可行`、`brief`、`known`、`tree`、`甲`、`乙` 在原示例里另有定义，这里省略；完整可运行版本见 `examples/guide/elem-judge.jpp`、`examples/feasible-pick.jpp`、`examples/guide/elem-gen.jpp`、`examples/unsure-default.jpp`、`examples/guide/comp-tree.jpp`）：

```jpp
import "../lib/compose/tree.jpp";
budget {calls: 30, cost: 0.02, depth: 64};
// 题是值：是非、K 选一、打分
let refund = test("这条客户留言是不是在明确要求退款？", "customer-refund-request");
let next   = select("下一道工序做哪一项？", "site-next");
let amount = measure("这次合作能做成的生意金额有多大？", ["小", "中", "大"], "collab-tree");
// 一次判断：state → judge → cut（作者声明线）→ handle 三臂
let r = judge(state(mat("用了不到一周就一直报警……钱退给我就行。")), refund);
handle(cut(r, {declare: {hi: 0.7, lo: 0.3}}), {
    act: fn() { "退款：升级处理" },
    ignore: fn() { "非退款请求" },
    unsure: fn(u) { consume(u, "drop"); "线附近，转人工" }});
// K 选一：候选进 over 槽；代码能定的可行性用 feasible
let s = judge(state(mat("地基浇好，墙体尚未开砌。"), {over: map(steps, fn(x) { mat(x) })}), next);
handle(cut(s, {feasible: fn(k) { 可行(k) }}), {pick: fn(k) { steps[k] }, unsure: fn(u) { consume(u, "drop"); unit }});
// 生成 + 判断：gen 非阻塞，sieve 对一批材料问同一题，返回契约值
let names = gen("提出 3 个候选店名", [brief], 3, 0);
let o = sieve(names, test("这个名字适合做社区咖啡馆的店名吗？", "fit"));
// 拿不准时的默认链取法；题树沿出口下行
unsure_source({need: keys(known), fetch: fn(q, need, m) { if has(known, need) { known[need] } else { fail("没有：" + need) } }});
let w = walk(tree, mat({a: 甲, b: 乙}), 6, {line: {declare: {hi: 0.7, lo: 0.3}}});
{chosen: map(o.value, fn(e) { e.item }), leaf: map(w.value, fn(e) { e.leaf }), pending: concat(o.pending, w.pending)}
```

**写法要点**（GUIDE「写法提醒」与各节）：`handle` 的 `unsure` 臂可以不写，没写的走默认链；写了就要交出责任（`consume(u, "drop")`、`escalate`、返回 `u`）。`if` 是刷新点，想让几次判断同层发出，先算齐材料与题，再在不含 `if` 的 `map` 里连续登记。外部动作用 `do("名字", [参数], 序号)`，返回 `Fail` 时用 `is_fail` 分支。契约值的取值用 `lib/outcome.jpp` 的 `accepted`、`ignored`、`undecided`。确定性处理（`split`、`regex_find`、`parse_json`、`sort_by`、`hash`、`date_*`）直接写在 `.jpp` 里，不记账、不是刷新点。

B195 定下的常驻程序写法（`resident`、`cell` 两种声明与 `Read`、`Write`、`Spawn` 三个 IR 节点）只有声明与节点，没有定成表层文法，`.jpp` 里写不出来；内容见第 8 节。
