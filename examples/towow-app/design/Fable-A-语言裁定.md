# Fable-A · J++x 的语言与运行时语义裁定

2026-10-04，Fable 5.1 依 Nature 2026-09-23 授权（`00-定位与方法论` §5.6）裁定，Nature 可逐条否决。范围只有一件：实验版语言 J++x 的语义。不裁网络程序的具体题面、材料来源、实验世界与前端。依据：`context/02-J++最新理解.md`、`context/01-通爻问题定义与构想.md`、`design/00-主会话草案.md`、`12` §2.13（R1–R16）、`规划/骨架v1-落地变更单.md` §一 D1–D9 与 §四 B0504。

**总的取向**：J++x 不是另一门语言，是 `12` §2.13 已经定下但主线没造的那一层，用最小文法写出来。凡 §2.13 已裁的（单元、版本、两种读、归约器与占用、欠账与承接、预算与截止只收紧、宿主三件事）这里不重裁，只定写法；§2.13 没给的（D1 粒度、D2 尝试结束、D3 写法、补信息请求的效应归属、跨主体合批的排序、构型的终止）这里定。每条按：决定、为什么、替代与放弃、依赖、推翻条件、代价。

## 一、常驻与增量：采用 B195 的语义内核，文法收成五个构造

**决定。** 内核只有五个新构造：`cell`（有版本的单元，可带归约器）、`resident … on [事件来源]`（常驻程序）、`peek` / `settled`（两种读）、`put` / `claim`（经归约器写、全有或全无占用）、`spawn`（派生下游，预算与截止只收紧）。没有 `live` 关键字：依赖边由运行时在读的那一刻收集（R3），作者不声明；常驻程序体内每个 `let` 自动是代码单元（D1 取「绑定即单元」），只有 `cell` 声明的才可被别的程序读写。单元族 `cell world[a]` 用键区分实例，一条声明覆盖一万个 agent。

最小文法（在现行 `.jpp` 表达式之上，EBNF）：

```
program   ::= budget {decl}
decl      ::= cell | resident | "fn" … | "let" … | "import" …
cell      ::= "cell" NAME ["[" NAME {"," NAME} "]"] ["reducer" reducer] ";"
reducer   ::= "single" | "union" | "by_key" "(" NAME ")" | "claim" | "override"
resident  ::= "resident" NAME "(" params ")" "on" "[" source {"," source} "]" block
source    ::= "event" "(" NAME ")" | "timer" "(" NUM ")"
            | "change" "(" cellref ")" | "settled" "(" cellref ")"
cellref   ::= NAME ["[" expr {"," expr} "]"]
expr      ::= …现行表达式… | "ev"
            | "peek" cellref | "settled" cellref
            | "put" cellref "<-" expr | "claim" cellref "<-" expr
            | "spawn" NAME "(" args ")" ["budget" record] ["deadline" expr]
```

求值规则（每条对应 §2.13 的一条）：

1. **尝试。** 宿主事件写源单元、纪元加一；运行时沿反向边标脏，不算；来源里含被标脏单元的常驻程序各排一次尝试。尝试取开始时的快照，跑整个 block，block 的值就是这次发布的版本。`source` 里引用了参数的（`on [change(world[a])]`，`a` 是参数），运行时对单元族里每个键各实例化一个程序单元，身份 = (常驻名, 实参内容哈希)；`spawn` 是同一件事的显式形式。
2. **两种读。** `settled c` 读最新定下的版本，上游没定下则这次尝试到此结束：发布「进行中」（带已得的部分值与 `progress {judged, total}`，由引擎填）、登记等待，上游定下后重来一次、取新快照（D2 取「重来」不取「续接」，因为恢复只以账本为准，续延不可序列化，`12` §2.6）；重来的代价由代码单元的记忆项吃掉（R4）。`peek c` 读当前最新版本，可能是进行中，所读版本进账本。`ev` 是触发这次尝试的事件值。
3. **写。** `put` 在尝试提交时经归约器合入，合并顺序进账本；多写者单元必须声明 `union`/`by_key`/`claim`/`override`，`single` 单元只许一个常驻程序写（R7）。`claim` 是即时的、由引擎串行化的占用，被拒当场得 `Unsure(claim_conflict)`，走未决去向；它不是提交时的写，因为占用的意义就是要在尝试途中知道结果。
4. **键。** 判断单元键 = (模型, 状态内容, 题内容)；代码单元键 = (定义路径与序号, 捕获环境哈希, 实参内容哈希)；程序单元键如上。两层截断照 R4：输入没变不重算；对外指纹（值 + 欠账摘要）没变上层不重算。

**哪些进内核、哪些是 `.jpx` 库。** 内核：上面五个构造，加现行 `state`/`judge`/`cut`/`gen`/`do`/`ask`、`budget`、默认链。库：`sieve`、`pair`、`walk`、`search`、`judged_graph`、`iterate`，以及应用层的 `recall`、`grow`、`node_of`。判据不变（B57）：只有要直接读引擎真相（版本、依赖、占用表、预算账户）的才进内核。

**为什么。** Nature 的要求是「进行中的计算能被订阅、多个子程序同时跑」（R-068 1、2），§2.13 已把它定成单元图而不是消息流（裁定三十九放弃甲）。`live` 定义 + 依赖追踪比这套少的只有名字：它仍要版本（否则没有「进行中」可读）、仍要多写者归约（否则两个构型抢同一人时丢贡献，R7）。少写一个关键字换不来少一条语义。

**替代与放弃。** 只用 `live` + 隐式依赖：放弃，它表达不了多写者与占用，撮合里两个构型争一人是主场景。消息流 / actor：放弃，轨迹里没有「上游已作废」，撤回要作者写（裁定三十九 §三）。等到读改为挂起后续接：放弃，账本就退化成缓存（`12` §2.6）。

**依赖。** R1–R7；D1、D2、D3 在这里定。**推翻条件。** 500 agent 实测中增量墙钟不低于从零的三分之一且归因在簿记（H1b 的归因规则），粒度退为「只有 `cell` 是单元、`let` 不是」。**代价。** 每个 `let` 成单元，簿记量按绑定数线性；一万 agent 时预计单元数在百万量级，Python 字典可承受但要测。

## 二、未决 → 补信息：不是新效应，是「向对方的收件单元写请求、等到读回复单元」

**决定。** 默认链第二步「取」的第三级（宿主取材料端口，裁定五十五）在 J++x 里就是**向持有方的多写者单元 `inbox[b]` `put` 一条请求，再 `settled reply[b, a, 类别]`**。这是 B0504 列的两条路里的「经多写者单元」一路。不加新效应，不用 `ask`，也不是纯的 `fetch`：

- 不是 `ask`：回答的是对方的程序（它的披露策略是一段 J++x，或真实 agent 的模型），不是人；答案 taint 是 `untrusted`，不进校准集（B102 把 `ask` 的来源钉死在人）。
- 不是可逆读取：回复取决于「谁问、为什么问」（R4：记录披露的内容、接收者、目的、拒绝），同一材料对不同请求者给不同层，这不是一个纯函数的键能表达的。
- 不是新效应：请求与回复都是单元写读，账本已有合并顺序与版本事件；加第五种效应要改 `12` §2，而这里一行都不用改。

请求挂起期间程序怎么继续：请求方的尝试在 `settled reply` 处结束、发布「进行中」，值里带已决的题（同一 state 上其他题的出口已经在）和这道题的 `pending`（原因 `insufficient`，`needed: 类别`）；下游（构型搜索）`peek` 它，拿已有的边先算。回复到达，请求方被标脏重跑，补过的材料只进这道题的 `ctx`，不改共享原材料，再判一次（默认链第三步）。被拒：`reply` 单元定下为 `{denied, category, by}`，这道题不再补，按裁定五十五走 C——转交进 `pending`，`needed` 写明「缺 X，持有者 b 拒绝」；这条「还缺」同时成为构型 `Node` 的 `lacks` 字段的一项（见第四条），用户看得见。不记放弃，不当假。

对方一直不答：等待带截止（R16），截止由请求方尝试的上游给（接入事件的截止，如首批 15 秒），到时引擎发布「未决（deadline）」并把欠账附在 `pending` 清单上，程序不停，下一次宿主事件再来。

持有方（模拟 agent）的披露策略就是 Nature 7b 举的那道题：

```jpp
cell inbox[b] reducer union;  cell reply[b, a, cat] reducer single;
resident 披露(b) on [change(inbox[b])] {
    let req = ev;                                   // {from, cat, purpose, q, deadline}
    let s = state(mat(layer(peek world[b], req.cat)), {ctx: mat(req.purpose)});
    let r = cut(judge(s, test("把这一类信息给对方，会不会推进这桩合作？", "disclose")));
    put reply[b, req.from, req.cat] <- handle(r, {
        act: fn() { layer(peek world[b], req.cat) },
        ignore: fn() { {denied: true, cat: req.cat, by: b} } })
}
```

真实 agent（MCP 接入）：请求作为 MCP 通知送到它那边，它的回复由宿主作为事件写进同一个 `reply` 单元。两种 agent 在语言里是同一个单元，发现程序不区分。

**为什么。** 渐进披露是通爻协议 R9 的要求，Nature 把「拿不准就问缺什么、补、再判」定为语言默认（意图汇编 7c、30）。两者接上的唯一要求是「补」的来源可以是另一个主体，而 §2.13 R1 已经把跨主体通道限定为单元。**替代与放弃。** 用 `ask`：放弃，taint 与真值资格错。新效应 `request`：放弃，理由同上，且它的画像（时延小时级、可能不答）与 `ask` 重叠会让两者长期分不清。生成器替对方补：放弃（裁定五十五 A）。**依赖。** 裁定五十五、R7、R10（读到带记号的未决按元素承接）、R16。**推翻条件。** 真机上补过一层再判，读数离边界没变远、判对率没升（预注册后测），默认链退为只转交，披露请求保留为作者显式写的库函数。**代价。** 每次补信息至少两次尝试（请求方重跑一次）；一万 agent 时 `inbox` 单元族的合并顺序是账本热点。

## 三、跨主体合批与调度：刷新点归引擎，批在「静止」时发

**决定。** 单个尝试里 `judge` 仍惰性登记；但刷新点不再是某个程序的 `if`，而是**引擎的静止点**：当前没有任何尝试能不等判断结果继续前进时，引擎把所有尝试已登记、输入就绪的题一次发出。规则：

1. **合题**：按状态内容哈希分组，同一 state 的所有题（来自不同尝试、不同 agent 的程序）合成一次调用；不同 state 不合（B62，不做多主体状态）。窗口超限交裂变。
2. **排序**：组间按（截止最近 → 触发它的接入事件最新 → 价值密度）排，前 32 组立即发，其余排队；每次宿主事件带的接入预算（如 `{calls: 64}`）从整场账户派生、只收紧（R11.2），付钱方是同一组题的第一个要求者（R11.3）。
3. **时延预算**：组按序出队，`latency_p95` 从画像来；超时的站点转 `Unsure(latency)`，缺席类，不能放弃。
4. **调度确定性**：单线程带种子的调度器，种子进账本头；换种子只换交错、不换静止状态。

作者能否无意中绕过：同一个两两判断程序写成「先算齐材料再 `map` 登记」与「每道题后面跟一个 `if`」两种写法，在 ≥ 32 个尝试同时在飞的网络里，调用数之比预测 **≤ 1.2**（主线实测是 14 倍）。原因是组是按 state 划的，一个尝试早刷新只是让它自己多等一轮，state 组里的题仍在同一次调用里。只剩一种真正的串行：每一步都造新 state 的递归（逐人加入的构型成长），那是数据依赖不是写法。

**为什么。** `00-定位与方法论` §三的判据：作者能无意中绕过的事就还没被语言接管。主线的 14 倍来自刷新点绑在程序文本的 `if` 上；§2.13 R11.7 已定「刷新点归引擎」，这里给出它的触发条件（静止）。**替代与放弃。** 定时刷新（每 100ms）：放弃，时延随定时器而不随画像，且重放要记时钟。推测执行两支都发：放弃，调用数翻倍换时延，与「要效果不省调用」不矛盾但与预算只收紧冲突。**依赖。** R11、B155、B62。**推翻条件。** 两种写法之比 > 2，或静止点让首批机会时延超过 15 秒目标的两倍——改为「静止或超过一层 p95 二者先到」。**代价。** 一个慢尝试（等生成器）不该挡批：`gen` 一登记就先发（B38），不参与静止判定。

## 四、组合封闭：构型与 agent 都是「发布契约值的程序单元」，不是类型接口

**决定。** `Node` 不是类型层的接口，也不是新单元种类；它是程序单元发布的值的形状，按 B17 契约值扩一组字段：

```
Node = {id, kind: agent|config, mat: Mat, offers: [Mat], needs: [Mat], lacks: [{cat, by?, denied?}],
        members: [id], roles: {…}, value, ignored, pending, evidence, spent}
```

agent 的端侧程序与构型的常驻程序都发布这个形状；召回与两两判断读的是 `peek node[x].mat`，不问 `kind`。构型成立（整体作材料判一次 `act`）即 `put node[cfg] <- …`，自动进入召回索引（索引是透明的 `do`，依赖 `node` 族的版本，R8）。

自指与增长的四道闸，全部是已有机制：

1. **身份即终止**：构型单元键 = 成员集合（排序后内容哈希）；同一组人再被提出是同一单元，不再判（R1 内容键）。
2. **无环由代码定**：候选构型若含某构型 X 且 X 的成员闭包含它自己，`keep` 代码谓词直接排除，不进判断（判断分工定律谓词半）。
3. **深度按触发链**：构型发布 → 触发它的召回 → 两两判断 → 新构型，都在同一宿主事件的链内，深度每级加一，上限随链只收紧（R11.5）；默认 `depth_cap_default = 3`（agent → 构型 → 构型的构型），进账本头。下一次宿主事件开新链，所以跨事件的成长是允许的、按事件分段的。
4. **成长用 `iterate` 的耐心线**：「加入此人会不会更紧密」作度量，连续 2 轮不升即停（B132 `{measure, patience}`）。

**为什么。** Nature：「城堡本身能成为更大乐高世界里的一个元素」（`00-定位` §六）；R1 已定「组合产物就是程序单元，与基本单元一样可被读、再参与组合」。类型接口会让「构型能做什么」写死在类型里，而撮合里构型多出来的字段（`roles`、`lacks`）正该随程序长。**替代与放弃。** 类型层 `interface Node`：放弃，J++ 没有接口，契约值就是接口。构型作单独单元种类：放弃，「改」R1 的五种单元。**依赖。** B17、R1、R8、R11.5、B132。**推翻条件。** 真实运行里构型的构型（meta）在三层内没有出现过 `act`，深度默认降为 2；若两层内就出现同人多构型互相包含的活锁（同一占用被拒 > 10 次，R7 推翻条件），占用改有序仲裁。**代价。** 每个成立的构型多一次编码与一次召回。

## 五、读数与置信度：给用户的是「这道题的出口与读数」，不是一个合成数

**决定。** 用户界面上不出现「置信度」这个字段。一个构型对外给四样：(a) 整体作材料那道题（「这几个人合作能成吗」）的出口 `Act/Ignore/Unsure(cause)` 与线的等级（无线 `Answer`、作者 `Declared`）；(b) 同一道题的读数 `p`，标明题面；(c) 每条成员边各自那道题的出口与读数，各标各的题面；(d) `lacks` 与 `pending`（还缺什么、谁拒了）。构型之间的排序只用 `order`，对象是同一道题、同一参照（B28）。方案文本里「置信度来源」一栏由 `evidence` 的账本键与 `lacks` 生成，不由生成器写数。

两两读数相乘、平均、投票得「构型置信度」：禁止（J-01、B28）。跨题合成只经 `fit`，要注册公式与校准，本期不做。作者要「错误率担保」时，先冻结真值、`calib-import` 认证线，界面才可以写「在 α 下错误率 ≤ …」。

**为什么。** 读数是随机变量，跨题不可加（`12` §1.1 I1–I3）；通爻侧的对应是「网络里流的是对这道题的判断，不是会被误加总的分数」（`context/01` §3.3）。**替代与放弃。** 用 `fit` 合成一个数：延后，没有校准的 `fit` 只是换个名字的相乘。两两边平均作构型分：放弃。**依赖。** J-01、J-04、B28、B187。**推翻条件。** 用户测试里没有「单题读数 + 缺什么」看不懂决定的比例超过一半——加 `fit` 并走认证。**代价。** 界面要展示题面，前端多一层文字。

## 六、归语言与归宿主

| 事 | 归 | 形式 |
|---|---|---|
| MCP `towow.join` / `disclose` / CLI `towow join` | 宿主 | 变成宿主事件，写源单元 `world[a]`、`reply[…]`；宿主不读任何构型逻辑 |
| MCP `towow.opportunities` | 宿主 | `peek node[a]`（或 `settled`，由调用方选）后渲染；读进账本 |
| 真实 agent 的披露回复 | 宿主 | 事件写 `reply[b, a, cat]`，与模拟 agent 的常驻程序写同一个单元 |
| 时钟、`timer(s)` | 宿主供、语言声明 | 每拍进账本，重放取账本的拍（R12） |
| JEV | 语言的 `judge` 端口 | 画像：4.2e-8 美元/输入 token、p95 ≈ 1.1s、并发 32、批不变性 δ ≈ 0.01、文字槽 1000 token 翻转——写进画像不写进规则 |
| `claude -p` | 语言的 `gen` 端口 | 非阻塞；产物按键缓存；只在构型成立后写方案、以及端侧编译算子时调用 |
| bge-m3 + HNSW | 语言的 `do` 动作 `embed_topk`，声明透明 | 依赖 `node` 族版本；无关变更不重算 |
| 事件流（`design/events.md`） | 派生视图 | 每种账本事件映射一种前端事件（发布 → `edge`/`config`，刷新 → `batch`，去向 → `unsure_route`，合并 → `disclose_request`），由账本推出，不另写状态 |
| 常驻、排队、失效、合批、预算、截止 | 语言 | 宿主里出现任何一项即 B1-6 不过 |

**为什么。** R12 宿主三件事；B1-6 硬验收。**替代与放弃。** MCP 端点直接调发现函数：放弃，那就是旧实现的「宿主拼状态」。**推翻条件。** 若发现真实宿主必须访问端口外的世界（裁定三十九 §六第二条），不透明为缺省。**代价。** 前端只能看账本推出的东西，想看「某个 agent 的内部变量」要先让它成为 `cell`。

## 七、消融开关：七个，各对应运行时接管的一件事

同一份网络程序、同一实验世界、同一事件序列，开/关各跑一次。预测写成数，落空即该项「只有 J++ 才能做」的主张不成立。

| 开关 | 关掉后运行时不做什么 | 可证伪预测（500 agent，一次披露事件后） |
|---|---|---|
| `--no-cells` | 不标脏、不截断；每个事件全部常驻程序从零重跑 | 判断调用数 ≥ 开着时的 50 倍；开着时重发集合恰等于读到该 agent 材料的判断 |
| `--no-fill` | 未决不问伴随题、不发披露请求，一律转交 | 隐含需求（t1/t2 层）的构型召回下降 ≥ 30%；`lacks` 全空 |
| `--no-batch` | 每个尝试各自刷新，不等引擎静止 | 两种写法之比从 ≤ 1.2 升到 ≥ 5；调用数 ≥ 3 倍；首批时延不降 |
| `--no-meta` | 构型不发布为 `node`，不进召回 | 含构型成员的构型（链、团队的再组合）召回为 0 |
| `--no-budget-chain` | 预算不随接入事件派生、不按新接入排序 | 第 101 个接入者的首批时延 > 第 1 个的 3 倍；整场花费不可预估（事后超预算 ≥ 2 倍） |
| `--no-absent` | JEV 掉线即报错，不降级到编码器相似度 | 模拟掉线 60 秒期间新接入者得到 0 个机会；开着时得到标 `Unsure(absent)` 的粗召回且恢复后被重判 |
| `--no-deadline` | 截止不传、不发布部分值 | 15 秒时可读的机会数为 0；开着时 ≥ 首批的 80% |

**为什么。** 意图汇编 14「最后做消融，没有可测贡献的部件删掉」；草案 §二要求判据先于设计。**代价。** 七个开关各是一条代码路径，实验语言里要维护两套行为。

## 八、实现语言：Python

**决定。** Python 3.12，`asyncio` 单线程带种子调度，解释器为树遍历。**一句理由**：瓶颈在 JEV 的 35 次/秒与 `claude -p` 的 12 秒，不在解释器；一万 agent 的簿记是字典操作，Python 够；编码器与 HNSW 已是 Python 生态；12 小时、多代理并行写，Rust 的编译期与 Go 的 ML 生态缺口都是净成本。**代价**：真并发（C10）做不了，按 §2.13 串行语义先成立；若簿记成为瓶颈（第一条推翻条件触发），单元图核心换 Rust 扩展。
