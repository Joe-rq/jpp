# 实验世界规格：500 个 personal agent 与预埋真值

2026-10-04，主会话。本文件定义实验数据怎么造、真值怎么冻结。系统（实验语言写的发现程序）只看得见各 agent 的本地世界，永远看不见 `world/gold/` 与 `world/plan.json`。

## 1. 每个 agent 是什么

每个 agent 代表一个真实感的人，由他的 personal agent（Dot、Muse、CUE、Claude Code、Codex 一类）托管。agent 手里有主人的**本地世界**：很大、很杂、大部分与合作无关。需求往往没有被主人说出口，只散落在最近的笔记、聊天、日程和项目里（「隐藏需求」）。

文件 `world/agents/aNNNN.json`：

```json
{
  "id": "a0042",
  "host_agent": "Dot",
  "lang": "zh",
  "owner": {"display_name": "林岚", "city": "杭州", "age_band": "30-35", "occupation": "独立插画师"},
  "world": {
    "bio": "公开自我介绍，100-200 字",
    "skills_assets": ["她拥有或会做的东西，具体到工具、作品、设备、场地、渠道、人脉", "..."],
    "projects": [{"name": "...", "status": "进行中/搁置/构想", "text": "100-300 字"}],
    "notes": [{"date": "2026-09-28", "text": "私人笔记/日记，60-250 字，口语"}],
    "messages": [{"date": "2026-10-01", "with": "妈妈/前同事老周/客户…", "text": "聊天片段，含双方原话"}],
    "calendar": [{"date": "2026-10-12", "event": "..."}],
    "relations": [{"who": "儿子小凯", "about": "不在网络里的亲友/熟人的情况，转介案例靠这里"}],
    "constraints": ["时间、预算、地域、价值观、不愿意做的事"],
    "sensitive": ["财务、健康、家庭、情绪等敏感信息，主人一般不愿外露"]
  },
  "disclosure_policy": {
    "t0_public": "主人愿意对任何陌生 agent 公开的一句话范围",
    "t1_after_signal": "有合作苗头（对方也相关）时愿意给的范围",
    "t2_after_trust": "置信度高、对方身份清楚后才给的范围",
    "never": "永远不外露的范围"
  }
}
```

量的要求：每个 agent 的 `world` 总长 3000–7000 字（英文 agent 2000–5000 词量级相当的字符）。笔记 6–14 条、消息 4–10 段、项目 1–4 个、日程 3–8 条，日期集中在 2026-09-10 至 2026-10-03。**大部分内容与合作无关**（日常、情绪、琐事、无关工作），合作线索要藏在里面，不要写成「我需要找一个 X」的广告句（少数主动型 agent 可以有一两句明说）。

语言：约 80% 中文、20% 英文（英文 agent 分布在各城市，跨语言配对单列）。

## 2. 预埋结构（真值）

结构是「如果这几个人的 agent 能互相发现，就能形成有价值合作」的组合。成员的本地世界里埋着使合作成立的**决定性事实**，每条事实标明它在哪个披露层（t0/t1/t2/never 之外）。

| 类型 | 数量 | 说明 |
|---|---|---|
| latent 潜信号 | 30 | 发起方只有模糊状态（「最近睡不好」「工作室房租又涨」「孩子暑假没人带」），没有表达需求；接收方从**自己的**世界判断出能帮上（规范案例：缺钱的人 ↔ 心理咨询师）。 |
| relay 转介 | 20 | A 需要的东西 B 没有，但 B 的 `relations` 里有不在网络里的人能提供（规范案例：奶奶的儿子善于照顾人）。真值是 A–B 转介关系。 |
| pair 互补 | 40 | 双方需求与能力互补，可明说可暗含；其中 10 对跨语言（一中一英）。 |
| chain 链 | 10 | 3–4 人的单向链：A 的产出是 B 的输入、B 的产出是 C 的输入，两两之间单看价值弱，整条链才成立。 |
| ring 环 | 8 | 3–4 人的互助环：A 帮 B、B 帮 C、C 帮 A，任两人之间没有互惠（易物、互换服务）。 |
| team 团队 | 15 | 一个项目需要 3–5 种角色，发起人 + 成员，每人恰好补一块；缺一块项目不成。 |
| star 一对多 | 10 | 一个中心对 3–5 个外围（场地方对多个活动组织者、导师对多个学员、批发商对多个小店）。 |
| m2m 多对多 | 5 | 两组各 3 人（如三家小农场 × 三家社区餐厅的联合供货）。 |
| meta 构型再组合 | 6 | 先由 2–3 人构成一个团队，**这个团队整体**才匹配第四方（投资人只投完整团队；渠道方只接有成品的组合）。单个成员与第四方两两不相关。 |
| hard_neg 难负例 | 40 对 | 同话题、表面相关但不成立：双方都在找同一种人、时间地点冲突、价值观相斥、对方已经解决、方向相同。 |

深层要求：约 30% 的结构，其决定性事实只在 t1 或 t2 层出现（检验渐进披露是否必要）。一个 agent 可以属于至多 2 个结构。其余约 100 个 agent 是背景人物，没有预埋结构，但有正常生活与零散需求（系统在他们身上找出的合作由独立评审判质量，不计入召回）。

`world/plan.json`：`slots`（500 个槽：id、lang、host_agent、城市、职业、所属结构及要埋的事实与层）与 `structures`（id、type、members[{id, role, brings, needs}]、why（为什么成立）、key_facts[{agent, fact, tier}]、plan_sketch（合作方案要点））。`world/gold/` 由脚本从 plan 抽出并冻结（sha256 写进预注册提交）。

## 3. 隔离

- 生成人物的代理看得到自己负责的槽与结构说明，必须把事实**自然地**写进世界，不得写结构编号或「我和 a0123 适合合作」。
- 发现系统、出题、评审打分之前都不读 `world/plan.json`、`world/gold/`。
- 独立评审（判系统找出的非预埋合作是否有价值）用 Opus，读双方世界，不读系统的理由文本以外的东西。
