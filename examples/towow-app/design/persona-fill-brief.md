# 人物填写任务书（给每个填写代理）

你负责把实验世界里的若干个 agent 槽写成完整的本地世界文件。先读 `design/world-spec.md` 第 1、3 节（格式与隔离规则），再读 `world/plan.json` 里**分给你的槽**以及这些槽所属结构的说明（`structures` 中 id 对应的条目）。

## 每个槽写一个文件

路径 `world/agents/<id>.json`，严格按 world-spec 第 1 节的 JSON 格式（字段名一字不差，`world` 下九个键齐全，`disclosure_policy` 四个键齐全）。用 Python 写文件（`json.dump(..., ensure_ascii=False, indent=1)`），写完用 `.venv/bin/python -c "import json;json.load(open(path))"` 校验。

## 写法要求

1. **像一个真实的人的电脑/手机里的东西。** 笔记是口语、跳跃、带情绪；聊天片段要有双方原话；日程有具体时间地点；项目有进度和卡点。名字、城市、店名、产品名要具体（可以虚构但要像真的）。
2. **大部分内容与合作无关。** 按 `background_noise_hints` 写日常、家事、健康、爱好、抱怨、无关工作。合作线索占全部文字的 15–30%。
3. **决定性事实自然地埋进去。** `facts_to_embed` 里每条事实都要出现，放在它标的层对应的位置：
   - t0 的事实：可以出现在 `bio` 或 `skills_assets`；
   - t1 的事实：放在 `projects`、`calendar` 或不太私密的 `notes`；
   - t2 的事实：放在私密 `notes`、`messages`、`relations` 或 `sensitive`。
   不要写成「我需要找一个 X」的广告句（除非 persona_hint 说此人是主动型），不要写结构编号，不要提别的 agent 的 id 或名字。潜信号类（latent）的发起方只写模糊状态，不写需求。
4. **披露策略要符合此人。** `disclosure_policy` 用一两句话写这个人愿意在各层给出什么（例如 t0「职业和城市、正在做的项目名」，t1「项目进展、时间安排、预算区间」，t2「家庭情况、真实困难」，never「病史、具体收入」）。决定性事实所在的层要与策略一致（t2 的事实不能落在策略里写着 never 的范围）。
5. **长度**：`world` 总文字 3000–7000 字（英文 agent 写英文，长度相当）。笔记 6–14 条、消息 4–10 段、项目 1–4 个、日程 3–8 条，日期在 2026-09-10 至 2026-10-03。
6. **难负例**里的成员：照常写，让他们与对方在话题、城市、关键词上高度重合，但把使合作不成立的事实（都在找同一种人、时间冲突、价值观相斥、已经解决）也写进去。

## 交付

写完你负责的全部文件后，回复：写了哪些 id、总字数区间、哪几条事实你觉得埋得最隐蔽。不要改别人的文件，不要读 `world/gold/`。
