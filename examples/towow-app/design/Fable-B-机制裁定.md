# 通爻网 · 发现机制裁定（Fable-B）

2026-10-04，Fable 5.1 依 `地基/00-定位与方法论-v1.md` §5.6 授权裁定，Nature 保留事后否决权。本文只裁一个问题：发现机制本身在 N=1 万下怎样仍然高效。依据：`context/01`（公理 A1–A7、裁决 D1–D6、规范案例、P018/P019、#274）、`context/02` §4、§5、§7、`design/00-主会话草案.md`、`design/world-spec.md`、`context/03` A/B/E 节、`地基/00-Nature意图汇编.md` 7a/7b/7c/11a/30。JEV 实测数字按任务书。

每条裁定按：裁定、为什么、考虑过的替代、推翻条件、代价。伪代码用现行 `.jpp` 风格，不新增文法；需要语言补的能力集中在第 8 条。

贯穿八条的一个总判断先写在前面：**网络里流动的基本单位不是「需求」和「能力」，而是「信号」与「接住信号的方式」。** 发出方只说自己的状态（可以很模糊），接收方事先编译好「什么样的来信我接得住、接住后能做什么、怎么确认」。价值在接收方世界里构成（规范案例），路由在同一个语义空间里做（信号对信号，而不是需求对能力），判断沿接收方自己写的题走。下面每一条都是这个判断的展开。

## 1. 端侧算子：编译什么、谁编译、披露层怎么挂

**裁定。** 每个 agent 的端侧把本地世界编译成一份「算子包」，四类片段，每条片段带披露层（t0/t1/t2/never）和来源（哪条笔记、哪段聊天）：

| 片段 | 内容 | 方向 | 例 |
|---|---|---|---|
| `signals` | 主人最近的状态，不要求成需求；含潜信号 | 发出 | 「最近手头紧」「工作室房租又涨」 |
| `offers` | 能给出的东西，具体到工具、作品、场地、渠道 | 发出 | 「有 60 平画室，工作日白天空着」 |
| `catchers` | 假想来信 + 接住后能做什么 + 一道确认题；含转介（来自 `relations`） | 接收 | 来信「有人说最近孤立、钱紧」→ 我能提供低价咨询 → 确认题「这个人的状态是不是孤立引起的、而不是单纯缺一笔钱？」；来信「有人需要出门有人陪」→ 我儿子开车、会逗人 → 确认题「这个人要的是陪伴而不是专业护理？」 |
| `forbids` | 时间、地域、价值观、不做的事 | 代码谓词 | 「10 月中不接活」「不做加密货币」 |

编译读整个本地世界（含 never 层），每条产出片段的层默认取其来源的最高层；agent 可以把高层来源**抽象**成低层片段（never 层的「自己得过抑郁症」可以抽象成 t0 的 catcher「有人情绪低落我能聊」），这个抽象由 agent 自己做，网络不管。never 层材料本身永不出端。

谁编译：真实 agent 由它自己的模型编译。MCP 服务只提供两个工具：`towow.spec` 返回算子包的 schema 与编译说明（这段说明是唯一的提示词），`towow.join(pack)` 收包。agent 读说明、读自己的世界、填包、调 join；网络不碰它的本地世界。模拟的 500 个 agent 用 `claude -p` 按同一份说明批量编译，键为世界文件哈希，缓存；每条片段记来源，世界某条笔记变了只重编译引用它的片段。

「价值在接收方的私有世界里被构成」落在两处：第一，catcher 的假想来信与确认题是接收方从自己的世界写出来的，网络不预设任何维度（D4）；第二，两两判断的状态里除了接收方的 catcher，还挂一道开放题「读 B 的世界，B 能对 A 的状态做点什么吗？」，材料是 B 的 t0 原片段，不经 catcher 枚举，接长尾。两道题在同一状态、同一次调用，不另花钱。

**为什么。** 规范案例要求咨询师和奶奶两个候选都能出来，它们都不是从「我缺钱」这条需求推出来的，是从接收方世界推出来的；SPEC 说任何设计者的维度枚举都产不出它们。把枚举权交给每个端侧自己（它读得到自己的世界，A1、A5），网络只定片段的边界和层（D4）。Nature P018：「这个意图本身是没有办法形成构型的，但它跟其他上下文结合，然后发生计算以后，它就会可能会形成一个构型。」

**替代与放弃。** (a) 只编译 needs/offers：产不出规范案例，放弃。(b) 不预编译，每对候选都让 JEV 读双方原始世界：状态 3–7 千字 × 两方，每对一次调用 1.5 万 token 以上，而且路由没有抓手，放弃；保留为开放题那条副路。(c) 让网络的生成器替所有 agent 编译：违反 A1（端侧自带最强模型）和一条命令接入，真实 agent 不会交出整个世界，放弃。

**推翻条件。** 500 世界里 latent 与 relay 两类的召回，开放题副路贡献的命中超过 catcher 主路的一半，说明预编译没有抓住主要价值，改为以开放题为主、catcher 退为路由提示。

**代价。** 编译在端侧，对网络成本为零；模拟世界 500 × 12 s，6 并发约 17 分钟，一次性。每 agent 片段约 30–60 条、t0 层约 300–600 token。

## 2. 路由与召回：成本与 N 无关

**裁定。** 只有 t0 片段进网络索引；t1、t2 永不进索引，只在披露后进入具体一对的状态。索引是 bge-m3 1024 维上的 HNSW，片段按类型分四个子索引（signals、offers、catchers、derived）。

每次接入或披露变化，对变化的片段做四路查询，每路 top-20，按对方 agent 汇总命中分，取前 M=32 个对方：

1. 我的 signals → 对方 catchers 的假想来信（谁接得住我）
2. 我的 catchers → 对方 signals（我接得住谁）
3. 我的 offers ↔ 对方 signals、我的 signals ↔ 对方 offers（经典互补）
4. 我的 signals/catchers → `derived`（进行中的关系与构型，见下）

接收方侧过滤分三层，前两层不花判断：`forbids` 代码谓词（时间冲突、地域、明确不做），对方 policy 程序决定是否参与（第 4 条），然后才是 JEV 沿接收方的确认题判（第 3 条）。城市、语言不做硬过滤（D3 不漏优先；跨语言配对是真值的一部分）。

「计算改变可发现性」的落法：agent 在索引里的表示 = 自己的 t0 片段 ∪ **派生片段**。派生片段由运行时从判断结果生成，有三种：(i) 一对关系判为 act 时，双方各得一条「正与〈对方 t0 摘要〉形成〈形式〉关系」；(ii) 构型判定成立时，构型作为节点得到自己的 `offers`（整体能提供）与 `signals`（整体还缺）；(iii) 强关系的一跳传递：A 与 B 的关系判为 act 后，B 的 catchers 以降权复制进 A 的查询集（「我接不住的，我身边的人可能接得住」，这是网络内的转介）。每条派生片段带来源判断的账本键；该判断失效，片段随之撤销。于是一个 agent 的可发现表示随进行中的计算移动，正是 P018 说的「动态坐标」。

私有信号的召回：t1/t2 的 signals 不进索引，但端侧可以用它们的向量查公共 catchers（只有向量出端，文本不出）。命中后的第一次判断在**端侧范围**内做：状态含我的私有信号与对方的公共 catcher，读数只有我的 policy 程序能读；判为 act 即构成「有苗头」，端侧主动向该对方披露这条信号（第 4 条）。

```jpp
fn recall(me, delta_frags) -!{do}-> [Candidate] {
  let hits = concat(map(delta_frags, fn(f) {
    do(embed_topk, {index: route_of(f), query: f.vec, k: 20})
  }));
  let by_peer = group(hits, fn(h) { h.owner });          // 代码聚合
  let kept = filter(by_peer, fn(p) { forbids_ok(me, p) }); // 代码谓词
  top(kept, 32, fn(p) { p.score })
}
```

**为什么。** 终点句要求成本与规模和信息量解耦（R10、P4）；HNSW 查询 O(log N)，每次接入查询数由自己片段数决定，与 N 无关。Nature #274：发现层的强处就在 1 万个主体时仍能把值得想的关系送到大模型面前。只索引 t0 既是 A2（投影有损是物理的），也让索引体积有界。派生片段对应 P019「画像本身就是无数计算的结果」，以及 Codex 附注 §4 的「计算改变可发现性」。

**替代与放弃。** (a) 全库两两判断：500 时 12.5 万对、1 万时 5 千万对，与 N 平方，放弃。(b) 只用一路 needs→offers：错过规范案例两类候选，放弃。(c) 把派生片段做成分数（关系强度）而非文本片段：分数跨题不可加（J-01），也无法被别人的 catcher 接住；文本片段能被同一套索引比较，放弃分数版。(d) 定期全局重聚类：与 N 相关，放弃；所有全局结构只允许增量维护。

**推翻条件。** 梯度实验（第 7 条）中真值对方在前 32 的命中率从 N=500 到 10000 下降超过 10 个百分点，说明 top-M 被稀释，改为按类型分配配额（每路保底）并把 M 升到 64 重测；再不成立，表示层需要换（D5 允许）。

**代价。** 每次接入：本地编码 30–60 条约 0.3 s；40 次 ANN 查询，1 万规模 50 万向量 fp16 约 1 GB，单查询毫秒级；判断调用 0 次。披露变化只重编码、重查变化的片段。

## 3. 两两判断的题组

**裁定。** 一对候选一个状态：`state(on=(A_mat, B_mat), ctx=network_ctx, ref=value_anchor)`。`A_mat` 是 A 对 B 已解锁层的片段加命中的 catchers，`B_mat` 同理，均带 `forbids`。状态上一次挂齐根层全部题，运行时合为一次调用（`walk` 的 `eval:"all"`）：

| 题 | 题型 | 来源 |
|---|---|---|
| 「B 的 catcher k 的确认题」× 命中的前 3 条，两个方向各一组 | 是非 | 接收方编译时写好，作为题值随片段进状态 |
| 「读 B 的世界，B 能对 A 的状态做点什么吗」（反向同） | 是非 | 开放题，网络题树 |
| 方向：A 帮 B / B 帮 A / 互相 / 都不 | K 选一 | 题树 |
| 形式：直接互补 / 单向帮助 / 经 A 的关系转介 / 经 B 的关系转介 / 需第三方才成立 / 不成立 | K 选一 | 题树 |
| 价值：小 / 中 / 大（参照 `ref` 给的锚例） | 打分 | 题树 |
| 时机是否吻合 | 是非 | 题树 |
| 难负例族：在找同一种人、方向相同、对方已解决、价值观相斥 | 是非 ×4 | 题树；它们的读数不进出口，只解释 ignore |
| 伴随题：缺哪类信息（候选：时间安排、预算、具体技能、地点、意愿、身份、不缺）、前提是否成立、是否两种读法 | K 选一 / 是非 | 语言默认链（J-05） |

出口规则：方向题的多数块定方向；成立 = 对应方向上任一确认题或开放题 act；形式题定 `form`；价值题定 `value` 分布。无线按多数块走（B187），作者不手写线。未决按第 4 条。

题树由生成器事先生成一次，不是每对生成：按构型类型（pair、relay、chain、ring、team、star、m2m、meta、growth、disclose）共约 10 棵，带槽的题式，代码填名字与片段；版本化缓存。深一层只在材料变化时（披露、加第三人）触发同一子树重判（B185：层数 = 材料变化次数 + 1）。

**为什么。** 意图汇编 7b：「这些问题本身其实是由在这个循环开始之前的生成器就已经全部生成完了，它只不过是快速地验证而已。」7c：深问题直接问，不因今天读数改写成浅题。接收方的确认题作为题值进状态，是「题作为值」（`12` §2.2、B45）在网络里的用法；也是第 8 条消融点之一。难负例族单列而不并入成立题，是因为 world-spec 把 40 对难负例当一等验收项，要能解释「为什么不成」。

**替代与放弃。** (a) 一个方向一个状态：B62 说关系题用 (a,b) 复合对象，双向题共享同一材料，分两个状态白付一份状态费，放弃。(b) 用打分题一次给「合作可能性 0–10」：读数是一个无法解释的数，且把方向、形式、价值三个独立判断压成一个，违反 7b 的「结构消解」，放弃。(c) 每对由生成器现生成题：500 × 32 × 12 s，放弃。

**推翻条件。** 真值配对上，开放题的判对率显著高于 catcher 确认题（差 15 个百分点以上），说明接收方编译的题比通用题差，确认题退为路由用、出口以开放题为准。

**代价。** 一个状态约 1.5–2.5 千 token（双方 t0 各 400–600，题 15–20 道 × 40），单次约 1e-4 美元，时延约 1 s。每次接入 ≤32 个状态，32 并发一波约 1 s。同一对在双方各自接入时内容键相同，判断单元按内容键复用，第二次免费。

## 4. 渐进披露的协议

**裁定。** 四层语义：

- **t0**：进索引，网络内任何 agent 可见；接入即给。
- **t1**：不进索引；对**具体一对**、按**类别**释放。触发条件二选一：该对的根层判断出未决且伴随题指出缺的类别；或任一方向判为 act 但价值/形式题未决（有苗头）。
- **t2**：该对成立读数经 t1 重判后 ≥ 0.7（作者声明线，`declare`，等级 Declared，在报告可见），且对方是已认领的身份。
- **never**：不出端，只供端侧编译抽象。

谁发请求：**运行时**，沿 J-05 默认链：未决 → 读伴随题「缺哪类」→ 向持有方的宿主端口发 `disclose_request{pair, category, purpose}` → 取回 → 同题同线重判。持有方是「宿主取材料端口」（裁定五十五的第三顺位），只做可逆读取，生成器不进链。每个类别对同一道题至多要一次；拒绝即 `Unsure(insufficient)` → `handoff`，机会照样交给 agent，标「待对方披露〈类别〉」，不丢（D3）。

给不给：持有方的 **policy 程序**是一段 J++，材料是请求（对方 t0 摘要、目的、类别）与主人用自然语言写的 `disclosure_policy`，一道是非题「这个请求落在主人『有苗头时愿意给』的范围内吗？」加一道 K 选一「给全部 / 给摘要 / 不给」。policy 是自然语言，所以是判断，不是查表；主人可以在 policy 文本里写得随意。真实 agent 的 policy 由它自己的模型在端侧跑（MCP 推送 `disclose_request`，agent 回 `grant/deny`）；模拟 agent 由网络代跑同一段程序，材料隔离由运行时保证：任何状态只能装入该对已解锁层的片段，装入越层片段是运行时错误 `E-tier`，不是检查建议。

```jpp
fn policy(req, my_policy) -!{judge}-> Grant {
  let s = state({on: req, ctx: my_policy});
  let ok = cut(judge(s, test("请求落在主人写的 t1 范围内吗？", "disclose-t1")));
  let how = cut(judge(s, select("给全部 / 给摘要 / 不给", "disclose-how")));
  handle(ok, {act: grant(req.category, how), ignore: deny(), unsure: ask_owner(req)})
}
```

披露与置信度互相推进：t0 判断 → 未决或有苗头 → 一个类别的 t1 → 重判 → 读数升到 0.7 → t2 → 重判 → 方案。每一步只多给一类，每类只要一次，t2 有线卡着，所以不可能一次性全交出；但 t0 的宽窄由主人自己定，网络不限制（D2 暴露最大化）。

**为什么。** SPEC S3/R9：粗信号远传，需要时 quest 要更多，深到足够转入协商；每一步由端侧决定。意图汇编 7c 与 30：「拿不准就想到底增加什么信息才能更明确」「补肯定是全部补的」。J-05 默认链已有的三步正好是这个协议，不另造。D1 可学习性高于隐私，所以不加任何默认的额外限制，只按主人写的政策判。

**替代与放弃。** (a) 披露由对方 agent 直接向对方 agent 谈（agent 对话）：6–8 轮大模型对话，每对数十秒、数美分，与 #274「大模型不要每次自己思考」冲突，放弃；只在方案阶段允许。(b) 服务端定死规则表（有 act 就自动给 t1）：剥夺主人的策略（意图汇编 11），放弃。(c) 未决不请求、直接丢：违反 D3，且第 7 条预测 t1/t2 依赖结构召回会塌，放弃。

**推翻条件。** 补信息后重判，读数离边界没有变远、真值对上判对率不升（预注册后测），默认链退为只转交（草案已有的推翻条件）；本协议随之退为「只在 act 后请求 t1」。

**代价。** 每对至多 2 次额外重判（t1、t2），每次约 1e-4 美元；policy 判断每请求 1 次调用，材料短，约 3e-5 美元。时延：请求到回复在模拟世界内约 1 s，真实 agent 取决于它在不在线，是异步的，`ask` 式挂起。

## 5. 多方构型

**裁定。** 在 act 边构成的有向带类型图 G 上，候选只从**刚变化的节点**局部找，每种构型一个精确算法，候选上限写死在程序里：

| 构型 | 候选算法（代码） | 剪枝 |
|---|---|---|
| chain | 从新节点出发沿 `form=供给` 边的有向路径，长 2–3，`graph:paths` | 出度上限 8，`forbids` 代码谓词 |
| ring | 经新节点、长 3–4 的有向环，`graph:cycles` 局部 | 同上；要求任两人之间无互惠 act 边（代码可判） |
| team | 发起人的项目片段在编译时已带 `roles_needed`；每角色向 offers 子索引取 top-5，JEV K 选一每角色挑一人，再整体判 | 角色 ≤5 |
| star | 新节点有 ≥3 条同形式 act 边，或新节点接到已有中心 | 外围 ≤6 |
| m2m | 两个 star 共享 ≥2 个外围，`graph:biclique` 局部 | 两侧各 ≤4 |
| meta | 已判定成立的构型作为节点进索引（第 2 条派生片段 ii），走两两流程 | 与 agent 同一条管线 |

每个候选构型整体做一次判断：一个状态装全体成员的已解锁片段与构型的形状、角色，根层一次挂：「整体成立吗」（是非）、「最弱的一环是谁」（K 选一）、价值（打分）、「去掉成员 X 还成立吗」（每成员一道，`without_member` 变式，同状态同批）。不做两两读数相乘。

成长循环：对判定成立的构型 C，从 C 的「还缺」派生片段向 offers 子索引取 top-5 候选 X，每个 X 一个状态 (C, X)，题组是 Nature 举的那串：「X 加入会不会让合作更紧密」（是非）、「金额变大还是变小」（K 选一）、「在哪个地方变」（K 选一，候选是成员与「新领域」）、「概率多高」（打分）、「主要因为谁的加入」（K 选一）。取最紧的一个加入，`iterate` 上限 3 轮，一轮里没有 act 即停（无进展终止）。

交给大模型：构型 `stage=judged` 且成立读数 ≥ 0.6、成员 ≤5 时，调 `claude -p` 写方案（分工、谁出什么、节奏、风险、置信度来源）；每次接入只写前 3 个，网络每分钟全局上限 10 篇，异步非阻塞。star 外围超过 5 时按中心—外围分篇写。

组合爆炸的控制共六道：候选只从 act 边出（不是全图）；只在变化节点局部找；路径长与度上限；代码谓词先剪；每候选整体一次调用而不是子集枚举；成长有界并按无进展终止。整体预算：每次接入构型判断 ≤20 次调用。

**为什么。** Nature P018 的连锁（奶奶 → 儿子 → 投资人 → 创业者）与「500 个城堡拼成新东西」要求构型是一等值、能再组合；意图汇编 7b 把成长题组逐字给了出来；#274 定了大模型只在筛选后协调三四个主体。图上找环是 Nature 确认过的方向（E-12）。「读数跨题不可加」（J-01）禁止两两相乘得构型分，所以整体必须再判一次。

**替代与放弃。** (a) 构型由大模型从候选池里「想」出来：每次数十秒、不可重放、与 N 挂钩，放弃。(b) 用两两读数做图权重跑最大权团：读数跨题不可比，放弃；图算法只用 act/ignore 出口定边，权重不进。(c) 全图定期找所有环与团：与 N 相关，放弃。

**推翻条件。** chain/ring 真值的召回中，整体判断把两两判为 act 但整体不成立的候选筛掉的比例低于 10%，说明整体再判没有增加信息，改为只做局部图算法加一道价值题；或成长循环三轮内从未提升过价值读数，去掉成长循环。

**代价。** 每次接入候选构型 ≤20 个，每个一次调用，状态 2–4 千 token，约 1.5e-4 美元，一波 1 s；成长 ≤15 次调用；方案 1–3 篇 × 12 s 异步。

## 6. 置信度

**裁定。** 交给 agent 的每个机会带一个三元组，不是一个数：

1. **成立读数** `p_hold`：成立题在**当前已解锁材料**上的最新读数（对两两是对应方向的确认题或开放题中最大者所在那道题的 p；对构型是「整体成立吗」的 p）。只取一道题的读数，不跨题合成。
2. **已看到的层与还缺的**：`tier_reached ∈ {t0,t1,t2}`，`needed`（伴随题指出、尚未补到的类别）。
3. **等级**：`Answer`（无线，默认）；t2 解锁用的是作者声明线，标 `Declared`。实验里不用真值校准任何线；真值只在事后画可靠性图（第 7 条），产品不碰。

随披露更新：每次重判产生新的 `p_hold`，旧值留在轨迹里；前端用轨迹画线的亮度与宽度变化（事件 `edge.state=up/down`）。向用户解释用四样东西：哪几道题说了是（题树出口路径）、看了对方哪一层、还缺哪类、伴随题给的「怎样能更拿得准」（报告 `improve` 段）。价值（小/中/大）单独显示，不并进置信度。

**为什么。** J-01、J-04：读数跨题不可加不可比；把十几道题的 p 乘起来得到的数既没有概率含义，也无法解释。B187：判断器带校准置信度，它的回答就是答案；所以置信度就是那道决定性题的读数，不另造一个指标。意图汇编 30：拿不准本身是信息，语言自带「改哪里能更拿得准」，这正是 `needed` 与 `improve` 两栏。

**替代与放弃。** (a) 乘积或加权和：放弃，理由同上。(b) 再问一道「主人该多相信这个机会」的打分题：仍是一道题的读数，但它把其他题的结论当作材料回喂（J-02 边缘），且比成立题更不可解释，放弃。(c) 用真值校准出认证线再展示：实验系统不得看真值（world-spec §3），放弃；留作事后评价。

**推翻条件。** 事后可靠性图上 `p_hold` 在真值对与难负例上的分离（AUC）低于 0.7，说明单题读数不足以当置信度，改为 `fit` 跨题合成（语言已有的唯一合法合成路径），并重做本条。

**代价。** 零额外调用；每次重判照常计价。

## 7. 规模证明与 500 世界的测法（≤5 美元）

**裁定。** 分三块，真机只花在系统假设上。

**离线块（0 美元）。** (i) N 梯度索引：500 个真实世界之上，用已编译片段池按类型重组、换名、换城市合成背景 agent 到 N=2000 与 10000（背景只用于索引稀释，不进真值）。测每次接入的 ANN 时延、候选数、真值对方的命中率@32 随 N 的曲线。(ii) 全管线 1 万次接入干跑：判断器按画像的「判断力缺席」降级到编码器相似度，计数本应发出的调用、状态数、失效重算数、构型候选数，出「每次接入调用数—N」曲线与 p50 时延（去掉 JEV 的部分）。(iii) 消融里能靠账本重放的（合批、增量失效、构型为节点）只重放计数，不花钱。

**真机抽样块（约 0.4 美元）。** 在 N=500/2000/10000 三档各取同一组 20 个真值成员接入，跑完整管线，记每次接入的调用数、时延、花费。

**真机全量块（约 2–3 美元）。** 500 世界按随机顺序全部接入一遍（接入顺序进预注册），再做 30 次随机披露变化与 20 次离开。召回按真值结构算：全体成员接入后 10 次接入内，该结构以 `stage≥judged` 出现即命中；按类型、按决定性事实所在层（t0 / t1–t2）分列。难负例：判为 act 的比例，单列、按算力计价。质量：系统找出的非预埋构型随机抽 50 个，由 Opus 读双方世界与系统给的理由文本评「有价值 / 说得通 / 不成立」，评审不读 plan、不读真值。

每次真机运行各自 <5 美元；三块合计约 3–4 美元。预注册（提交号早于任何花费）至少写这些预测：

- P1 两两 / latent / relay 中决定性事实在 t0 的，召回 ≥ 0.8；在 t1–t2 的，披露开 ≥ 0.6、披露关 ≤ 0.3。
- P2 chain + ring 召回 ≥ 0.5；meta 在构型为节点开时 ≥ 0.5、关时 = 0。
- P3 每次接入的判断调用数在 N=500/2000/10000 之比 ≤ 1.3；ANN 单查询在 1 万时 < 50 ms；接入到首批机会 p50 ≤ 15 s。
- P4 难负例 act 率 ≤ 0.3，真值对 act 率 ≥ 0.7。
- P5 真值对方命中率@32 从 500 到 10000 下降 < 10 个百分点。
- P6 事后可靠性：`p_hold` 在真值对与难负例上 AUC ≥ 0.7。
- P7 开放题副路对 latent/relay 命中的贡献 < catcher 主路的一半（第 1 条推翻条件的对偶）。

**为什么。** 定位与方法论 §5.2：稀缺验证只花在系统假设上，先建免费代理、真机只用来标定代理。这里的系统假设是四个：信号—catcher 同空间路由不随 N 稀释；渐进披露对深层结构是必要的；构型为节点对 meta 是必要的；每次接入成本与 N 无关。细节假设（某一对判没判对）不单独花钱。SPEC 的真值规则（独立评判、冻结、被测看不到）照搬；Nature 2026-09-29 定了 500–1000 的模拟世界可用于内部验证。

**替代与放弃。** (a) 1 万个真实世界全真机：编译 1 万 × 12 s 与判断约 60 美元，且只回答细节，放弃。(b) 不做梯度、只做 500：无法证明「1 万仍高效」，放弃。(c) 用真值校准线后再测召回：被测看到标签，放弃。

**推翻条件。** 预测是推翻条件本身：P3 或 P5 落空即第 2 条机制有错；P1 的披露关组不塌即第 4 条不必要；P2 的 meta 关组不为零即第 5 条的「构型为节点」不必要。

**代价。** 真机合计约 3–4 美元；离线部分本机 CPU 数小时。

## 8. 「只有 J++ 才能做」在机制层的落点

**裁定。** 本机制里下面六处由语言或运行时接管；每处写成同一份程序开/关各跑一次可观察的预测。没有语言时，这六处要么由应用手写（每个网络一遍），要么直接做不到。ANN、HNSW、图算法本身不在此列，它们是 `do` 效应；语言的贡献是把它们与判断嵌套、并把未决、预算、账本带过每一层。

| 落点 | 运行时机制 | 关掉后的可观察预测 |
|---|---|---|
| 1 增量失效 | 派生片段、两两判断、构型判断都是带依赖边的单元；一次披露或离开只让依赖它的单元失效（缓存与增量） | 每次披露事件的重判调用数从 ≈1–3 升到 ≈32（该 agent 全部候选对）；离开后含该成员的构型不解散（出现「幽灵构型」） |
| 2 未决默认去向 = 向持有方要材料 | J-05 默认链第二步的取材料端口指向对方 agent，不写在应用里 | t1–t2 依赖结构召回 ≤ 0.3（P1 关组） |
| 3 跨主体合批 | 一对的状态上，来自两个接收方的确认题、题树根层、伴随题、policy 题由运行时合为一次调用；发出顺序按时延预算（新接入者优先） | 调用数 ×（每状态平均题数 ≈15）；并发接入时 p50 时延随并发数线性增长 |
| 4 构型是一等值 | 构型与 agent 同契约值（`value / pending / evidence`），派生片段带账本键进索引 | meta 召回 = 0（P2 关组）；构型没有自己的 `needed`，成长循环无法启动 |
| 5 题作为值从端侧流入 | 接收方编译的确认题随片段进状态，与网络题树同批 | 改用通用题「B 能帮 A 吗」后 latent/relay 召回下降（P7 的反面） |
| 6 读数不裸传 | 置信度是一道题的出口与读数；跨题只能经 `fit` | 用乘积排序的 AUC 低于单题读数（P6 对照） |

另有两件在运行时但不做开关：判断力缺席降级（第 7 条离线干跑就是它的用途）与预算只收紧（每次接入调用数上界）。

本机制对语言提出的、现有 J++ 没有的能力，按 `context/02` §8 对照，有四条，交语言侧裁定与施工：(a) 常驻单元与依赖失效（`12` §2.13 C3 起）；(b) 材料的所有者与层作为运行时不变量（`E-tier`）与状态的可见范围（端侧范围的判断只有端侧 policy 能读）；(c) J-05 取材料端口可以是异步的另一个主体；(d) 跨程序按内容键共用判断单元（同一对在双方接入时免费）。前三条没有，上表 1、2 两处就要退回宿主手写，「只有 J++ 才能做」的证明随之失效。

**为什么。** 定位与方法论 §三：必须由整个程序的分析与调度决定、无法局部决定的，才是语言的活；`context/02` §9 把「进行中的计算参与别的计算、跨程序合批、按内容键共享判断并增量重算」列为简单编排做不到的后四行，本表 1、3、4 正是它们在网络里的形态。Nature 2026-09-26 #242 确认的四项语言新能力（订阅、并发、路由可替换、题的身份跨节点）分别落在表 1、3、第 2 条的 recall 程序、表 5。

**替代与放弃。** 把这六处写进宿主：能跑，但每个网络一遍，而且写法会无意绕过合批（`16` §1 的十四倍）；主会话草案 B1-6 硬验收「宿主里不手写持续计算逻辑」即为此而设。

**推翻条件。** 消融开关关掉后预测不出现（调用数不升、召回不降），该处就不是语言的贡献，按意图汇编 14 从「只有 J++」清单里删掉；六处全不出现，本应用就只是对 JEV 的编排，不能作为目标场景交付。

**代价。** 消融里 1、3、4、6 四处靠账本重放计数，零花费；2、5 两处要真机，放在 150 个含深层结构的子集上跑，各约 0.5 美元。
