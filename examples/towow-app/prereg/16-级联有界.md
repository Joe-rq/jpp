# 预注册 16 · 每次接入的级联有界：按读数排序、用不完就挂起（先于代码与运行）

日期：2026-10-05，写于代码与运行之前。裁定：Fable（预注册 12 结果之后），原文见本文「依据」。

## 已经看过的结果

- 预注册 12（1 万人真跑）：4 位单人冷接入（a0125、a0294、a0383、a0401）每人 JEV 花费 $0.53–1.05，中位 $0.74；召回只占 $0.090，与模型相符；其余 83–91% 在召回之后。按程序分（`runs/scale10k/summary-10k.json`）：构型节点的召回每人 513–1111 次调用、$0.31–0.70；成长 736–1701 次；两两 274–556 次；整体 244–591 次；披露 114–310 次。召回之后的调用中位 2967 次。静止中位 478 秒（300 秒内 0/4）；窗口结束时机会中位 68 个；每人可见方案 2 份，另写了 73–187 份接入者看不到的方案（账本 gen 行 180–423）。真伙伴 4/5 进前 32、边都成立。
- 同一程序的 500 人对照（同机冷缓存）两位：$0.335（2509 次调用）、$0.128（899 次），中位 $0.23。
- Fable-B §5 与附表给的预算是每次接入构型判断 ≤20 次、成长 ≤15 次、合计 60–90 次调用；程序里没有执行这条预算，每次接入的级联只受整场 `budget` 约束。
- 构型节点的召回（向量 40 → 重排 → 8）召回的「构型对构型」「二层构型对人」，两两判完之后都被 `invalid_candidate` 否掉（含两个构型、或嵌套到第二层）：钱先花了，代码能定的放在了判断之后。
- 方案门「每位成员都排进前 2」按直接成员算；构型节点作为成员时有自己的前 2，所以「组合的组合」不断出方案，接入者却看不到。
- 预注册 14：决定性读数 < 0.65 的成立边盲标精度 0.28（17/60），≥ 0.65 的 0.67（26/40）；这条分界是看过结果后的观察，未在另一份样本上复核。
- `runs/raw/` 里预注册 12 的原始账本已经不在，按程序分的调用只剩上面摘要里的数，分不出接入者自己的两两和构型节点的两两各占多少。

## 依据（Fable 裁定原文）

> 花费主因：1. Fable-B §5 定了每次接入构型 ≤20 次、成长 ≤15 次、合计 60–90 次调用；程序没有执行链预算（实测 1688–2967 次）。2. 构型节点召回（route 40→8）命中的构型对构型、二层构型对人，随后都被 invalid_candidate 否掉，两两的钱白付；代码能定的放到了判断之后（意图 7a）。3. 方案门『每位成员前 2』按直接成员算，构型节点作成员时各有自己的前 2，每次接入写 73–187 份没人读的方案。
>
> 决定（不改 Node 形状、索引、成立规则）：甲 恢复链预算：每次接入的级联（构型节点召回、两两、整体、成长）合计 ≤60 次调用；用尽后剩余单元挂起而非跳过，下一次宿主事件（成员披露、有人读到该构型、新接入者命中它）续算。乙 链内按决定性读数降序；declare 0.65（Declared，依据预注册 14：<0.65 精度 0.28、≥0.65 为 0.67）以上先走；线下构型照样发布、进索引、给成员看，只是排后——是预算排序，不是把关。丙 构型节点召回前先用代码判它再组合是否还合法（现行 nest_depth、n_cfg 规则），不合法的不召回；召回池排除其他构型节点。丁 方案门的『每位成员』按展开后的 agent 算；组合的组合只在有真人把它排进前 2 时生成。戊 成长归入甲乙。代价：低读数构型的再组合要等事件；运行时需要『预算尽即挂起、事件到再续』；J++x 若只会跳过记 unobserved，先登 J++反馈。预测（1 万背景、4 位冷接入、≤$4，调用数按 resident 分列）：每人花费中位 ≤$0.25（召回仍 ≈$0.09）；第一个机会 ≤13 秒；可见方案 2 份/人，gen 行每人 ≤10；静止中位 ≤120 秒、4/4 在 300 秒内；召回后调用 ≤300/人；真伙伴进前 32 保持 4/5。推翻条件：花费中位 >$0.40 或 2/4 未在 300 秒内静止，则主因在披露请求链而非构型级联，按分列账再拆。

## 假设（系统级）

H：每次接入的花费与静止时间由组合封闭的级联决定，而级联的大小可以由运行时按事件链限住，不必删掉任何一层组合。给级联一个按事件链计的调用预算、按读数排序、用不完的单元挂起到下一次相关事件，每人花费降到召回加一个常数（与在场构型数无关），静止落到两分钟内；「组合的组合」照样能形成，只是低读数的排后、可能要等下一次事件。

若成立，单人接入的花费模型变成「召回（随 N 线性）+ 有界级联」，可以直接外推；若不成立（花费或静止仍超线），按 Fable 的推翻条件看分列账：主因在披露请求链，不在构型级联。

## 改动（不改 Node 形状、索引、成立规则）

### 运行时（jx/，语言层）

1. **事件链的级联预算**。程序头的 `budget` 加一项 `cascade: {calls: 60, line: 0.65}`：每条宿主事件链（一次接入、一次披露回复、一次离开各开一条）里，参与级联的常驻程序合计至多 `calls` 次判断调用。记账按调用：参与级联的尝试登记的题（含伴随题与补信息后的重判）发出时记到它所在链的级联账上；命中缓存与同键去重不记。
2. **哪些程序参与、按什么排**。常驻程序加可选子句 `rank <表达式>`（形参在作用域内，读单元只用 `peek`，读到的不记为依赖）：值是数时，这个实例参与它所在链的级联、按这个数排序；值是 `unit` 时不参与（照旧立即跑）。`spawn 名(实参) rank <表达式>` 给被派生的实例一个排序值（同一实例被多次派生取最大）。没有 `rank` 子句、也没有派生排序值的程序不受影响。
3. **准入**。参与级联的实例被标脏后，尝试先做第一层截断（输入都没变就跳过，同现行），然后不跑程序体，进本链的待准入表。引擎静止时（不等生成器）按序准入：排序值 ≥ `line` 的先走，同档按排序值降序、再按登记先后；本链还有线上的待准入单元时，线下的不准入。每准入一个，从本链级联账预留「这个程序以往单次尝试的最多调用数」（没跑过记 1），尝试结束后按实花替换预留。预留加已花到 `calls` 为止。
4. **挂起与续算**。本链级联账用完时，剩下的待准入单元挂起：不跑、不写、不撤回它以前写过的值，也不记为未观察。它仍然挂在自己读的单元上。之后任何一条**别的**事件链让它变脏（成员披露写了 `unlocked`/`reply`、新接入者的两两改了它读的 `material`/`adj`、新接入者的召回再次派生它），它就转到那条链的级联账上重新排队。宿主另有 `engine.resume(ids)`：开一条新链，把挂起单元里实参含这些 id 的（不给 id 就是全部）重新排队。挂起单元不进静止判定，网络照常静止。账本：首次在某条链上挂起记一行 `park`，准入记一行 `admit`；同一条链上重复挂起不再写账本（免得账本一直有新行、驱动判不出静止）。
5. **消融开关** `no_cascade`：关掉 3、4，回到现行行为（用于差分与「给足事件后终态一致」的对照）。

### 程序（app/）

6. **甲、乙、戊**：`budget` 加 `cascade: {calls: 60, line: 0.65}`。排序值：
   - 构型节点的召回：这个构型的决定性读数（`hold.p`）；agent 的召回 `rank unit`（接入者自己的两段召回不在级联里）。
   - 两两：由召回派生时给排序值。接入者自己召回的前 32 对（根上的两两）给 1，即先于一切派生工作：这些对还没有决定性读数，召回的读数是另一道题，与 `hold` 跨题不可比（J-01），所以不拿它排。构型节点召回派生的对，给这个构型的 `hold.p`。这是本文对「乙」的读法。
   - 整体：候选里各成员之间已成立边的决定性读数取最小（最弱的一环）。
   - 成长：这个构型的 `hold.p`。
7. **丙**：构型节点召回前，代码先判它再组合是否合法：`nest_depth` ≥ 2 的构型节点不召回；召回池去掉其他构型节点、去掉它展开后的成员、去掉与它组成候选时 `invalid_candidate` 为真的对方。不再派生必然被否掉的两两。
8. **丁**：整体写 `best[m]` 时 m 取展开后的全部 agent（`closure`），方案门「每位成员都排进前 2」也按展开后的 agent 判。于是构型节点没有自己的前 2，「组合的组合」只在它展开后的每个人都把它排进前 2 时才生成方案。
9. 基线 `baseline/net_py.py` 同步丙、丁，差分在 `no_cascade` 下跑一遍、在开着预算时再跑一遍。

## 已知的偏差

- 只跑一次、一个时段，JEV 时延随时段变；与公网服务共用一把 JEV 密钥。
- 本机直连，不经隧道。生成背景没有真值。接入者一律拒绝补信息请求。方案生成走本机 Claude，不计 JEV 花费。
- 挂起的单元若在下一位接入时被续算，`analyze` 按时间窗切账会把它记到下一位名下。
- 本次宿主不在「有人读到该构型」时续算：驱动每秒读一次机会，读即续算会让每次轮询开一条新的 60 次预算链，等于没有预算。续算只经依赖通知（披露、新接入者的写与派生）和测试里的 `resume`。
- `views.opportunities` 只列接入者是直接成员的构型。丁把展开后的 agent 计入前 2，「组合的组合」可能占掉接入者前 2 的一个名额：那份方案照样生成，接入者却看不到，可见方案会少于 2 份。发生了就是结果，不事后改。
- 根上的两两排在最前：如果接入者自己的 32 对加补信息重判就用掉大半预算，构型、成长、构型节点召回会大量挂起。真机前用 fixture 量一次根上两两每次接入用多少次调用，写进补注（补注写于真机检验之前）。
- `line: 0.65` 是作者声明（Declared），依据是预注册 14 看过结果后的观察，未复核；它只决定先后，不决定成立与否。

## 补注（2026-10-05，实现与零花费演练之后、真机检验之前）

本节写于看过 fixture 测试、差分与零花费演练之后，真机检验之前。预测表与判据一字不改。

**更正。** 「已经看过的结果」最后一条写错了：预注册 12 的原始账本还在本机 `runs/raw/`（`serve-1005-074220.*` 1 万、`serve-1005-072457.*` 500 对照），当时是我列目录时输出被截断。用它把两两按「根上（接入者自己召回的前 32 对）」和「构型节点的对」拆开（零花费）：1 万档每次接入根上两两 32–51 次调用、构型节点的对 223–520 次；500 对照根上两两 88–127 次、构型节点的对 237–680 次。所以 60 次预算里根上两两在 1 万档就要用掉 32–51 次，500 档单靠根上两两就会碰顶。

**实现与「改动」节的出入。**

1. **挂起点**：改为「要发出第一道新题时」而不是「尝试开始时」。没准入的级联尝试照常往下算，碰到第一道要真发出去的题（不是缓存命中、不是并到在飞的同一道题）才作废这次尝试（不写、不撤回旧值）并挂起。原因：fixture 离开测试里，成员离开后的撤回（两两、整体重算、不发题）被排在已用尽的预算后面，离开者的边留在网里。改后不发题的尝试不受预算影响。
2. **上限是硬的**：准入的尝试每开一次新调用（新的 state）时，若本链「已发出 + 已登记未发出」已到 60，也作废挂起（已发出的题答完进缓存，续算时命中）。准入预留只决定一波放几个。
3. **整体的排序值**：成长派生的候选（成员之间没有成立边）按它所长自的构型的 `hold.p`；既没有成立边也不是成长来的排 0。
4. **另修一处运行时缺陷**（差分开预算后 seed 3 暴露）：已撤回单元的在途尝试仍会执行有副作用的 `do`（`发布` 在离开前起、离开后才 `index_put`，离开者被写回索引）。现在撤回单元的尝试跳过非透明动作。关预算时五个种子没碰到这个时序。
5. 续算只经依赖通知与 `resume`，宿主不在读机会时续算（同「已知的偏差」）。

**fixture 与差分（看过）。** 稀疏的哈希读数下，预算 10、反复 `resume` 后，成立边、构型、方案与关预算一致（两个种子）；「什么都说成」的稠密小网在关预算时换种子终态就不同（构型的 `take(novel, 6)`、每条链的重跑上限、构型节点召回读的索引随时间变），不能拿来比。差分 `--seeds 0-4 --inject I1`：关预算、开预算两边终态都与基线逐项一致（15/18/15），开预算 J++x 判断调用 891–991（关预算 1029–1106）。

**零花费演练（看过）**：`--judge fixture`，500 人，端口 8796，a0125、a0294 两位，伪读数、不调生成器。
- 每次接入自己那条链的级联调用正好 60 次；但接入者拒绝补信息请求是宿主事件（成员披露），各开一条新链、各有 60 次，会把挂起的单元续算掉：a0125 的窗口里另一条拒绝链又用了 60 次，a0294 另有 22 次。按窗口算每人级联 120、82 次。这符合裁定原文「下一次宿主事件（成员披露…）续算」，所以「每人 ≤ 60」在按窗口切的账上可能不中。结果节同时报「接入链」与「窗口合计」两个口径（`analyze` 的 `cascade_calls_join_chain` 与 `cascade_calls`）。
- 丁的风险在演练里出现了：a0294 的前 2 被两份「组合的组合」占了（他经构型节点间接在内，不是直接成员），他直接参与的 3 个构型都没出方案，可见方案 0 份（a0125 2 份）。照预注册不改。
- 静止 18–22 秒；窗口结束时网络里仍挂起 21–31 个单元；4 个以内的组合的组合。

### 判据

- **全中**：花费中位 $0.122 ≤ $0.25、4/4 在 300 秒内静止（中位 76 秒）、第一个机会中位 10.2 秒 ≤ 13 秒。保留改动；README 关于 1 万人花费的句子按实测改；公网服务重启后生效。没有触发推翻条件（花费中位 > $0.40 或 2/4 不静止）。
- 预注册写的是「级联调用每人 ≤ 60」。按接入链读，3/4 中；按接入窗口合计读（每人的字面意思），1/4 中，而且 3/4 越过了「> 60 × 1.2 记实现问题」那条线（140、258、367）。越线的原因不是准入预留不紧：每条链各自没有超过 60（除下一条），多出来的是接入者每拒绝一次补信息请求开的新链，各有 60 次，把挂起的单元续算掉（补注在真机前已记下）。所以按窗口算不中，原因归到「续算记到哪条链」这一设计问题，交 Fable，不算实现错。
- 级联接入链 a0294 66 次：一个 state 的题因 token 上限被拆成两次调用（这条链有 6 个 state 各发了两次），运行时按「一个 state 约一次调用」记未发出的账，拆分多出来的那次没算进去。在 60 × 1.2 以内，记为已知的不精确，不改判据。

### 没中的与新看到的

1. **可见方案少了**：2/4 人只看到 1 份（500 对照 0、1 份）。这是补注里预先写下的丁的风险，真机上也核过（零花费，回放 `serve-1005-101233.events.jsonl` 里的 best，取运行结束时的状态）：a0294 前 2 的第二份是 `cfg:a0106+cfg:a0140+…`、a0401 的第二份是 `cfg:cfg:g01016+…+g04717`，都是他只间接在内的构型；他直接参与的构型多数又不在对方的前 2 里（对方的前 2 也被组合的组合占了）。前 2 按展开后的 agent 算以后，接入者自己或他的对方把「组合的组合」（接入者经构型节点间接在内）排进了前 2，那份方案照样生成，接入者却看不到（`views.opportunities` 只列直接成员）。是不是让接入者也看到他间接在内的构型、还是前 2 只按直接成员排，交 Fable。
2. **gen 行仍多于 10**（中位 31，预注册 12 是 180–423）：前 2 随新构型不断变动，方案被生成、又因不再在前 2 而撤掉。这次没有拆开「重生成」与「首次生成」各占多少。
3. **按窗口算的级联随接入顺序变大**（60 → 140 → 258 → 367），每人花费也随之 $0.093 → $0.149：接入者拒绝补信息请求是宿主事件（成员披露），每次各开一条 60 次的链，把网络里累积的挂起单元续算掉；挂起的单元从 115 涨到 597。四个点不够判断它会不会一直涨；若一直涨，「每次宿主事件 60 次」就只是限了单条链，没有限住每人。交 Fable：续算是否要记到原接入链、或给续算单独一个预算。
4. 组合封闭没有被取消：4 位里 3 位的窗口里发布过成立的组合的组合（7、64、40 个，含早已存在、重新发布的），排后的构型在后续事件里继续长。
5. 「静止」现在的意思是预算内的工作做完了，不是全部做完：最后一位接入后网络里还挂着 597 个单元，等下一次相关事件。
