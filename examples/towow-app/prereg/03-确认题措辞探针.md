# 预注册 03 · 确认题措辞（探针，先于改 catcher_q）

日期：2026-10-04，写于运行之前。

## 已经看过的结果

- 全量 v1：4209 条成立边里 2369 条由确认题（catcher）决定，1840 条由开放题决定。
- 真实接入（Nature 的 agent 经 MCP 接入 500 背景人口）：置信度最高的机会 0.73 来自 a0314 的确认题「你要处理的是抓取公开网页或接口数据的稳定性问题，而不是需要官方授权的商业数据对接吗？」——Nature 并没有这个需要，agent 判为误报。现行 catcher_q 只问 confirm（限定句），不问 hypo（设想中的来信，即「对方真有这个需要吗」）。

## 假设（系统级）

H：确认题只问限定句时，判断器在回答「是 X 而不是 Y」，对毫不相干的人也常答是；把 hypo 一起放进题面（「对方真会发出这样一封来信吗，并且满足限定」）后，随机对的确认题成立率明显下降，真值对基本不降。若成立，确认题的措辞就是精度的主要杠杆，以后所有接收方题都按这个结构写。

## 设计

- 样本：真值 pair/latent/relay 58 对、难负例 29 对、全量 v1 里判过且不在任何真值结构中的随机 60 对（固定种子 0 抽取）。
- 每对每个方向取接收方前 2 条 t0 确认题，两种题面各问一次（同一状态：双方 t0 文本）：
  - 旧：现行 catcher_q（只问 confirm）；
  - 新：「把 S 当作来信的人。R 设想过会有人这样来找他：『hypo』。S 现在真有这样的需要、会发出这样的来信吗？并且：confirm」。
- 指标：每对「任一确认题 act（p>0.5）」的比例。
- 花费上限 $0.10。

## 预测

| 样本 | 旧题面 | 新题面 |
|---|---|---|
| 真值对 | 0.80 | 0.70 |
| 难负例 | 0.85 | 0.65 |
| 随机对 | 0.45 | 0.15 |

## 判据

- 随机对下降 ≥ 0.20 且真值对下降 ≤ 0.15：改用新题面，写进 lib.jpx，之后的运行都用它。
- 否则保留旧题面，确认题的误报写进报告。

## 结果（运行后追加；runs/probe-catcher/result.json，294 次调用，$0.0221）

| 样本 | 旧题面 | 新题面 | 预测（旧 / 新） |
|---|---|---|---|
| 真值对 | 50/58 = 0.86 | 16/58 = 0.28 | 0.80 / 0.70 |
| 难负例 | 24/29 = 0.83 | 3/29 = 0.10 | 0.85 / 0.65 |
| 随机对 | 30/60 = 0.50 | 2/60 = 0.03 | 0.45 / 0.15 |

随机对下降 0.47（≥0.20），但真值对下降 0.58（>0.15）：按判据**不改用新题面**。旧题面对随机对一半答「是」，这一条预测基本对了；新题面把真值对也砍掉了大半，比预测狠得多。
看后备注：旧确认题的成立率在真值、难负例、随机三组是 0.86 / 0.83 / 0.50，几乎不分辨；它是全量里过半成立边的决定性题。下一步检验「成立只看开放题」，另写预注册 04。
