# 预注册 14 · 盲标校准：成立机会的精度，与置信度能不能分开真假（先于代码与标注）

日期：2026-10-05，写于抽样代码与任何标注之前。回答 10-05 最终验收反驳第 3 条与 Nature 10-04 的追问「那你怎么判断质量呢？」。

## 已经看过的结果

- 离线全量 v3（`runs/full-500/result.json`，停在第 429 人接入后）：两端都在场（`present` 429 人）的边 13169 条，其中判成立 1874 条（与 README「成立对 1874」同一口径）；判不成立 11295 条，出口 ignore 10885、出口 act 但形式题为「不成立」405、并列 5。两端有一方不在 `present` 的边不进抽样框。
- 成立边按决定性读数 p 分档（p 取决定性那道题说「成立」的读数，出口 ignore 时取 1−p，与 `host/eval.py` 的 `p_yes` 相同）：0.50–0.55 有 361 条，0.55–0.60 有 355，0.60–0.65 有 355，0.65–0.70 有 314，≥0.70 有 489。全体中位约 0.63，最高 0.91。
- 不成立且出口 ignore 的边按 p 分档：<0.20 有 2666，0.20–0.30 有 4147，0.30–0.40 有 3302，0.40–0.50 有 770。
- 成立边看到的层（tier_seen）：只有 t0 1696 条，t0+t1 71，t0+t1+t2 106，t0+t2 1。
- 成立边与真值结构的关系：同属一个 pair/latent/relay 真值结构的 58 条，同属一个多人真值结构（团队、链、星等）的 162 条，属难负例的 18 条，其余 1636 条两人不在同一个真值结构里。不成立边里对应的数是 8、49、4。这个世界每人都写了很多条信号，真值结构之外的对也可能是好的合作，所以真值结构不能直接当精度的标准答案。
- 已知：难负例 22 对里 18 对判成立，p 区分真值对与难负例的 AUC 0.596（v3）；预注册 02 里 t0 下开放题读数 AUC 0.57、t0+t1 下 0.78；预注册 07 三选一题 t0+t1 下 AUC 0.84。
- 标注环境的隔离检查（一次调用，不涉及任何样本内容）：`claude -p --no-session-persistence --model sonnet --system-prompt … --tools "" --setting-sources "" --strict-mcp-config` 的输入只有 516 个 token，没有带进全局或项目的 CLAUDE.md；实际模型 claude-sonnet-5-5，单次约 7 秒。

## 假设（系统级）

H1：判成立的边多数经得起旁人核对。标注者拿到判断器当时看到的同一份材料，认为「有一件具体、双方都愿意做、现在就能开始的合作」的比例，就是这个网络给出的机会的精度。

H2：决定性读数 p 在成立边内部能排出好坏，也就是 p 越高，标注为「是」的比例越高。这决定界面上的置信度数字该怎么说。

H0（标注者本身）：Sonnet 盲标能当这个问题的参照。检验办法是在真值已知的对上看它能不能分开真值对与难负例；难负例的否定理由大多在 t1（预注册 02），所以同一批对分 t0 与 t0+t1 两种材料各标一次。

## 设计

### 抽样（种子 14，抽样框见上）

- 主样本 150 条。成立 100 条：五个 p 档各 20 条。不成立 50 条作对照：出口 ignore 的四个 p 档各 10 条，出口 act 但形式题为「不成立」的 10 条。档内按 (a, b) 排序后用 `random.Random(14)` 无放回抽。
- 校验集：抽样框里所有属于真值 pair/latent/relay 的边（66 条）与所有属于难负例的边（22 条），共 88 条。先抽主样本，校验集取全部 88 条；与主样本重合的条目，t0 条件直接沿用主样本的标注，不另标。
- 每条记下：a、b、p、决定性出口、是否判成立、形式题、tier_seen、真值类别（同属 pair/latent/relay、同属多人结构、难负例、无）。

### 给标注者的材料

- 主样本与校验集的「t0 条件」：双方的材料与判断器当时状态里的相同，即 `side()` 给出的展示语、t0 的在找、能提供、在做的事、接得住的来信（catcher 的 can 字段）；加上该边最后一次两两判断之前已放行的片段。放行片段从 `runs/full-500/engine-events.jsonl` 的 `unlocked` 发布事件复原，以 `events.jsonl` 里这一对最后一次 judge 事件的时间为界。片段在材料里叫「补充信息」（不叫「已解锁」）。
- 校验集的「t0+t1 条件」：在 t0 材料上加双方算子包里全部 t1 片段（在找、能提供、在做的事、接得住的来信），不加 t2。
- 不给：读数、出口、形式题、决定性题题面、是否成立、真值、对方称呼以外的任何系统字段。两人分别称「甲」「乙」。系统提示不提这是在核对一个撮合系统的输出，也不提任何比例。

### 标注题（写死）

系统提示：「你是一名标注员。你会读到两个人各自写下的一些信息。按题目作答，只输出一行 JSON。」

题目：「这两人之间有没有一件具体、双方都愿意做、现在就能开始的合作？一方帮另一方也算，只要帮的一方有理由愿意做。」选项：是 / 否 / 说不清。输出 `{"label": "是|否|说不清", "reason": "一句话理由"}`。

「一方帮另一方也算」这半句的理由：网络的成立规则是两个方向的开放题任一为 act（`net.jpx` 两两），单向帮助本来就算一个机会；不写这半句，单向的机会会因题面被标成「否」，精度被题面压低。

### 两次独立标注与裁决

- 第一遍：甲 = a、乙 = b，选项按「是 / 否 / 说不清」列。第二遍：甲 = b、乙 = a，选项按「说不清 / 否 / 是」列。每条每遍独立调用 `claude -p --no-session-persistence --model sonnet`（参数同上），并发不超过 4。
- 两遍一致即为最终标注。不一致的再做第三遍（甲 = a、乙 = b，选项按「否 / 是 / 说不清」列），三遍取多数；三遍各不相同记「说不清」。
- 一致性：两遍之间的原始一致率与 Cohen's κ（三类）。
- 输出解析失败的调用重试一次，仍失败记「说不清」并单列个数。

### 指标

- 精度：成立边里最终标「是」的比例。主口径「说不清」算作不是「是」；敏感性口径去掉「说不清」再算。总体精度按五档在 1874 条里的份额加权；95% 区间用档内有放回自助法（10000 次）。各档单独报比例与 Wilson 区间。
- AUC：p 对「是」的区分力。主口径在 100 条成立边内算，每对样本按两者抽样权重（档内总数 ÷ 档内抽中数）之积加权，档内自助法给区间。副口径在全部 150 条上按同样的权重算（代表全部已判断的边，分母以 ignore 为主）。也报未加权的样本 AUC 作对照。
- 精度曲线：五个 p 档各一个点。
- 对照：不成立各档标「是」的比例（漏掉的机会）。
- 真值：主样本按真值类别分列「是」的比例；校验集两种材料下，真值 pair/latent/relay 与难负例各自标「是」的比例，以及它们之间标注的分辨（是率之差）。
- 按 tier_seen 分列成立边的精度（只看 t0 / 看到 t1 或 t2）。

## 判据

先看标注者能不能用（H0），再看置信度怎么说（H2）。

- 标注者可用：校验集 t0+t1 下真值对「是」率 ≥ 0.60，且比难负例高 ≥ 0.30；两遍 κ ≥ 0.40。不满足时，精度与 AUC 只作描述，不据此改界面说法，README 照实写「标注者本身没过校验」。
- 标注者可用时，界面上置信度的说法三选一（只改说法，不加门、不藏机会，不改代码）：
  - **显示分档精度**：成立边内加权 AUC 的 95% 区间下限 > 0.60，且 ≥0.70 档与 0.50–0.55 档的精度区间不重叠。界面在数字旁写「同档实测约 X 成成立」。
  - **只作排序**：AUC 点估计 ≥ 0.60 但不满足上一条。数字只用于排序，界面写总体实测精度（「这批机会经盲标约 X 成成立」），不把 p 当成概率展示。
  - **不作质量信号**：AUC 点估计 < 0.60。界面不把 p 当质量信号，只写总体实测精度；下一步改排序依据（预注册 07 的三选一题或披露后重判），另写预注册。
- 精度：加权精度点估计 < 0.50 时，README 写明「多数机会经核对不成立」；≥ 0.50 时写实测值与区间。

功效的限度事先说明：每档 20 条，单档精度的 95% 区间宽约 ±0.20；成立边 100 条时 AUC 的标准误约 0.06，0.60 与 0.70 之间分不太开，所以判据用区间而不是点估计。

## 已知的偏差

- 标注者只看判断器当时看到的材料，测的是「同样的信息下这次判断说得过去吗」，不是「两人现实里真能合作吗」。校验集的 t0+t1 条件用来估计两者的差距。
- 模拟 agent 只在这一对判成立后才给 t2（`net.jpx` 披露），t2 的出现本身带着判断结果。按 tier_seen 分列，看到 t2 的边单独报，不据此下结论。
- 标注者是另一个大模型（Sonnet），世界本身也由大模型写成，两者可能有同样的偏好；它和 JEV 的错误是否相关，本次测不出。
- 主样本按 p 档等量抽，高 p 档被多抽；总体精度与 AUC 都按抽样权重还原到 1874 条。不成立的 50 条只作对照，不还原到 11290 条的总体精度。
- 全量 v3 跑在 $4 上限处停下，进程被停，快照可能含还没重判完的边。

同一批 88 对上，p 区分真值对与难负例的 AUC 是 0.596，与全量 v3 的已知值一致。

### 按判据

- **置信度：显示分档精度。** 成立边内加权 AUC 区间下限 0.614 > 0.60；≥0.70 档区间 0.53–0.89 与 0.50–0.55 档区间 0.15–0.52 不重叠。两条都只是勉强过线。
- **精度：加权 0.45 < 0.50**，README 写「过半的机会经盲标核对不成立」，并写实测值与区间。

### 怎么读这些数

- 判成立的边大约 45% 经得起旁人核对，11% 说不清，其余约 44% 被标「否」。抽看「否」的理由，最常见的是两人不在一地而合作要当面做，其次是一方能给的东西对方并没有在找，或者找不到帮的一方愿意做的理由。
- 判不成立的边少有漏网：p 低于 0.4 的 30 条里 0 条被标「是」（95% 上限约一成，这三档合计约 1 万条边）。漏掉的机会集中在 0.4–0.5 的近线带（2/10）。
- p 在成立边内部确实能排出好坏（AUC 0.72），但曲线不是平滑上升的：0.50–0.65 三档都在三成上下，0.65 以上才升到五成半到七成半。成立边里 57%（1071/1874）落在 0.65 以下这一段。公网上只交 t0 的接入者拿到的机会读数都在 0.51–0.64（验收反驳与预注册 11），若沿用这组分档，全在三成上下的那一段。这组分档测自 v3（向量 + 重排召回）；公网现在是两段 JEV 召回（预注册 10）加新方案门（预注册 11），两两题没变，但进到两两判断的对不同，分档精度不一定照搬，放进界面前要在现行程序上重测。
- 两处限度：标注者只看判断器当时看到的材料，它和 JEV 在难负例上同样宽松（t1 下仍有 64% 标「是」），所以 0.45 衡量的是「同样信息下这次判断说得过去吗」，对设计好的难负例偏高；p 对真值对与难负例的区分仍是 0.596，这次没有改善。看到 t1 或 t2 的边精度更高（0.59 对 0.40），但模拟 agent 只在判成立后才给 t2，这一差别带着判断结果，不作结论。

看过结果后的观察（未预注册，只作下一步假设）：把五档并成两段，p < 0.65 加权精度 0.28（17/60），p ≥ 0.65 为 0.67（26/40）。若界面要用两段的说法，需要在另一份样本上复核这条 0.65 的分界。
