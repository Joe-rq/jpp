# 通爻网 J++ 应用版 · 最终验收反驳（Opus）

2026-10-05。只读核查加一次真实接入，没有改代码、文档或黑板，也没有提交或部署。这次 JEV 花费 $0.0231：healthz 的 cost_used 从 0.0 升到 0.0231，接入期间网里只有我这一个真实接入者，离开后 120 秒没有再涨。

总的结论：应用的工程主体是真做出来的，测试 81 个全过，公网接入也能在 10 秒内给出机会。但有四个原始目标没有达到：「只有 J++ 才能做」、给真实接入者详细合作方案、1 万人高效、创造真实价值。12 小时内没有交齐必交项；之后的工作是在 Nature 继续指示下延伸的。README 对多数短板写得照实，下表的主要作用是把「已经承认的短板」和「目标是否达成」对上。

## 二、真实接入记录（本次）

做法：用宿主自带的 MCP 客户端函数（`host/cli.py` 的 `call`）直接连 https://net.towow.ai/mcp。token 只放在进程内存里，没有写进 `~/.towow`。算子包是我编的测试包，只有 t0：6 条 signals、4 条 offers、4 条 catchers、1 条 forbids，每条都带「【测试】」前缀，称呼是「验收测试（非真人）」，包文件在 scratchpad 的 `refute/test-pack.json`。

| 时刻（自 join 起） | 事件 |
|---|---|
| 接入前 | healthz：500 位居民，真实接入 0，configs 0，cost_used $0.0 |
| 2.4 秒 | join 返回，`t0_fragments: 14`，`dropped_non_t0: 0` |
| **9.6 秒** | **第一批 6 个机会**，都是 pair，置信度 0.51–0.64，对方都标 `real=false`（虚构居民） |
| 14.0 秒 | 第 7 个机会（悉尼退休渡轮船长，0.63） |
| 52 秒前 | `discovery`：本轮发现已完成，细判 32 对，3 个机会，9 个在披露后放下，和真人的机会 0 个 |
| 约 150 秒 | 收件箱 23 条补信息请求，全部来自虚构居民，我逐条拒绝 |
| 离开 | `towow_leave` 返回删掉了 pack、索引、52 个披露单元和已存的接入记录；10 秒内 real_agents 回到 0；之后 120 秒花费不再增长；再用旧 token 读机会，返回「需要 token」 |

最后留下的 3 个机会是：悉尼退休渡轮船长（他想讲旧渡轮的故事，正好上播客，0.63）、柏林独立游戏开发者（可以来做访谈，他也缺配乐，0.61）、Newtown 爵士吉他手（需要录音和场地，0.62）。从语义上看三个都说得通。初始批里的「泉州乌龙茶批发商」「南京博物馆讲解员」后来被放下，这一点符合渐进披露的设计。

本次接入暴露的问题：

- 观察窗口内没有构型和方案（23 条请求当时都还没答，混杂见 4d）。3 条成立边是 1 条单向（对方帮你）加 2 条互惠（互相帮）：互惠边不进链，凑不出以我为中段的链；也够不上星要求的「中心至少 3 条同向边」；居民之间没有边，所以环和多对多不可能出现。
- 置信度挤在 0.61–0.64 一个窄带里，看不出这几个机会谁比谁强。
- 题面里把对方称呼截到 12 个字符，例如「能对 Retired Sydn 现在的状态……」「Indie game d」，读起来不通顺。
- 2 分钟内收到 23 条请求，真实主人会觉得被打扰。

## 三、总判定

**整体没有达到目标。** 达成的部分有：语言实验做成了（J++x 加 net.jpx，81 个测试全过）；只交 t0 的一条命令公网接入可用，并且很快（9.6 秒出第一个机会）；黑板与 Fable 流程合规；README 对短板的表述基本照实。没达到的部分是 Nature 目标里最重的三件：「只有 J++ 才能做」被自己的基线否定；现存的真实接入报告里没有一份拿到方案，公网结构上也出不了环和多对多；没有产生一次真人之间的价值。1 万人高效没有实测。12 小时必交项没在时限内交齐，不过有断网，而且 Nature 之后继续下了指示。

剩余工作里最值得做的五件事，按价值排序：

1. **让真人和真人在网里相遇。** 请 3–10 位 Nature 圈子里的真人，让各自的 agent 接入公网，记录有没有真人之间的机会、对方是否确认有用。这是第 9 条「创造价值」唯一的检验方法，其他工作都不能替代它。
2. **打通「真实接入者的成立边 → 构型 → 方案」这条路。** pair 本来就是会生成方案的构型形状（v3 有 410 个 pair 构型、346 个方案事件），缺口在真实接入者这一侧。先查清楚接入者的成立边为什么没有变成构型：是「整体」判了不成立，是在等补信息，还是根本没有触发。查清后改到一次冷接入就能拿到至少一份方案。另外，要让环和多对多在公网上出现，就得让召回到同一位接入者的那批居民之间也做两两判断，至少在这个邻域里做。
3. **标定精度和置信度。** Nature 10-04 也问过「那你怎么判断质量呢？」。抽 100 条成立边做盲标（人工或 Sonnet，先预注册），测出精度，以及置信度对真假的区分力。现在 AUC 约 0.6，本次接入的读数又挤在 0.61–0.64，「带置信度」实际上没有提供多少信息。如果区分力确实弱，就把预注册 07 的三选一题或披露后重判当作排序依据。
4. **把「只有 J++」从主张变成证据。** 按改召回后的程序更新基线，在同一条 500 人事件轨迹上让基线和 J++x 做差分测试，数出基线的陈旧结果、挂死和多余调用。同时把 J++x 的持续计算（cell、resident、三种读、union 只增、深度沿触发链携带）按「J++反馈」板交给主线。只有进了主线，「用 J++ 构建」才名副其实。
5. **在 1 万人上真跑一次网络。** 单人冷接入，测时延、花费，看能否静止。然后决定召回「判断在场全体」是否要改成增量或缓存，比如第一段读数按内容键跨接入复用。顺手补三处小修：给真实 agent 加主动披露工具、题面不再截断称呼、统一 README:79 和 X28-0026 的披露数字。
