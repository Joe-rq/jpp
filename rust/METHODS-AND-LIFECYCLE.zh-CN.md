# 方法、源码库与可恢复运行

这一包让方法的效应契约能写进类型，并让多份 `.jpp` 文件复用同一套方法；CLI
接入固定生成、回应记录和 JSON 文件动作。所有程序仍交给原 Rust 内核执行，没有新增运行时。

## 现在可以怎样写

```jpp
import "../lib/methods.jpp";
budget {calls: 0, cost: 0, depth: 256};
fn increment(x: Int) -> Int !{} { x + 1 }
map_ints([1, 2, 3], increment)
```

库里的参数类型是 `Fn(Int) -!{}-> Int`，表示无外部效应的整数方法。
`Fn(Mat) -!{judge}-> Record` 则带有判断效应上界，lower 后进入共同检查器。
旧式 `Fn(Int) -> Int` 继续保留未知／推断效应的含义。`Fn1` 传递捕获未决责任的
标记，不代表完整线性类型证明。方法的创建、保存、返回不会执行其函数体。
未标注的高阶助手按调用点推断；函数定义明确写下的效应集合始终是对调用者声明的上界。

公开快照使用第四包 core（`d021f33`）：声明的方法效应能参与检查，但尚不能拦住所有
“实际传入方法超出形参效应上界”的情况。core 归口已在后续包补充实参契约检查，
未纳入本快照；不能把当前类型标注当作完整静态保证。

`library-methods.jpp` 返回组合后的方法，把它放进记录再调用，得到 `[4,6,42]` 和
`42`。`lifecycle.jpp` 引用同一个方法库，并引用观察／请求回应库。
导入相对当前源码文件解析，写在 budget 前面；同一个依赖只加载一次，声明按依赖顺序
进入同一作用域。跨文件重名、循环导入会报错。库只有声明，没有自己的预算、独立语句
或最终结果；顶层绑定仍会求值。本包尚无命名空间、选择性导出和包管理器。

## 完整运行效果

按[英文页的可复制命令](METHODS-AND-LIFECYCLE.md#one-complete-lifecycle)在临时目录运行：

1. 读取 `input.json`，生成候选，再判断是否符合要求，执行到请求回应时暂停。
2. 用 `--resume pending.json` 和回应记录继续：复用输入、生成与判断，只完成回应及输出。
3. 用 `--replay complete.json` 重放：得到同一结果，不重新调用客户端，也不再次写文件。

贯穿测试在恢复前删除原输入文件，确认仍使用已记录的输入；重放前把输出改为标记，
确认没有再次覆盖。算法和组合写在源码里，CLI 只连接已有客户端、动作表和账本。
这一组生成、判断和校准均为固定测试数据，不使用新的付费调用，也不代表模型准确率。

导入文件路径相对源码；`read_json`、`write_json` 的文件路径相对进程工作目录。
`do("read_json", [path], seq)` 的返回值由内核包成带动作来源的不可信材料；
`do("write_json", [path,value], seq)` 写入源码计算出的 JSON，覆盖目标文件。
失败返回 `Fail`，可用 `is_fail` 处理。超过有符号 64 位范围的 JSON 整数会被拒绝。

恢复允许尚未完成的调用和动作；重放拒绝新增调用和动作。两者都使用原内核账本，
按未改变的源码重建方法环境，不是任意闭包跨进程序列化。保持入口、导入库和校准稳定；
读文件的完成记录代表当时的快照，处理新输入应使用新账本，或明确改变动作身份。
外部动作完成与账本文件落盘没有组成事务，因此不承诺崩溃条件下普遍的“恰好一次”。

原 fixture 格式兼容。新增可选 `generations` 数组，包含 `prompt`、`retry_seq`、`output`；
`responses` 沿用观察的材料／问题／答案字段。不提供回应就保持待回应状态。
固定生成器沿用 core 的 prompt／重试序号匹配，不模拟随上下文变化的真实生成能力。

## 怎样证明沿用了同一语言

[等价用法对照](COMPARISON.md)的测试同时执行旧式源码、显式纯方法类型源码和直接
构造 core AST 的程序，三者都返回 `{expected:43,result:43}`。多文件加载只负责合并
声明和保留来源位置，lower、检查、执行仍走共同路径。类型位效应与责任标记的检查、
库中静态／运行错误的位置，以及旧三个完整程序，都有相应回归。

真实 JEV CLI 适配、更多算法库迁移、未决责任生命周期与优化继续归原计划和归口推进。
本包没有把这些未完成项宣称完成，也没有增加全面审查的发版门槛。
