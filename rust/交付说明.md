# J++ 原生源码整包

这次把“组合方法”落实成了可以直接编写和运行的 J++ 源码。开发者写 `.jpp`
文件，原生 `jpp` 命令负责解析、检查，再交给唯一的 Rust 内核执行。算法不再需要
写进 Python 宿主程序里。

## 已经看到的效果

**方法可以组合，组合出的新方法还能再次组合。** `composition.jpp` 把“加一”和
“乘二”组合成一个方法，再把这个方法与“加一”组合。输入 20，得到 43。测试还
直接用 Rust 构造同一个内核程序，两种写法经过共同检查和执行，返回值完全一致。

**程序自己决定下一道问题。** `adaptive.jpp` 根据上一题答案改变区间、构造新题，
用十次固定判断，在 1,000 个候选里定位 731。题目和求解方法都是源码中的值；
命令行没有一个隐藏的“寻找 731”程序。

**有一部分不知道，仍能先用已知结果，再换方法继续。** `partial.jpp` 先找到
A+B，成本 9；此时 C、D 仍未决。它返回可用结果和一个继续求解的方法。随后换成
优先处理便宜候选的策略，补 C 后得到成本 2；再换策略处理 D，完成剩余部分。
整个过程保留旧证据，共六次观察，A、B、C 各检查一次。候选组合和约束计算都在
J++ 源码里，不是 CLI 偷做的业务算法。

重放相同源码和账本，会得到同样的返回值，而且没有新增判断调用，也没有重复
执行记录动作。停止条件、未决候选、完成的观察各自有明确表示。

## 怎么使用

本机已经安装的原生程序：

```sh
/private/tmp/jpp-native-install/bin/jpp run /private/tmp/jpp-native-install/examples/composition.jpp
```

完整源码与构建说明见 [README](README.md)，实际文法见 [FRONTEND](FRONTEND.md)，
两种表达方式的等价对照见 [COMPARISON](COMPARISON.md)。

已验证在项目目录以外、PATH 为空的环境运行两个完整算法。安装后的原生程序不用
再启动 Python 或 Cargo。固定观察样例不需要账号、密钥，也不产生模型费用。

## 本轮范围与收尾

这些例子证明语言怎样构造和执行组合程序；固定观察不证明真实模型准确率。
方法返回的继续计算由源码闭包表达，账本保存效应记录，不能把账本等同于任意闭包的
跨进程序列化。保留的 Python 优化也没有被一概算作 Rust 已完成。

共同检查器已经提前拒绝明显的参数类型错误，并区分“保存方法”和“执行方法的效应”。
