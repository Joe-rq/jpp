# 完整方法可以被修改，也可以在运行中构造另一套方法

本包完成“完整及动态组合进入共同语言结构”，交回总控验收。上一包仍为已验收。本包没有宣布整门语言完成。

**作者现在可以打开一个完整求解方法，替换里面的检查步骤，再将它交给上层继续组合；程序也能按输入构造新方法，执行记录会保存这次究竟构造了什么。** 过去这些过程藏在闭包里，共同计划器只看到 opaque。

## 一个完整程序及实际效果

完整源码：[jev_compose/method_example.py](jev_compose/method_example.py)。它复用已有表达式候选、检查器和 feedback。固定观察用于验证语言行为，实际本地检查执行了每个声明输入；不代表真实 JEV 精度或速度提升。

运行：

```sh
cd /Users/nature/个人项目/jev/地基
.venv/bin/python -B 扩展/codex_composition/run.py methods
```

输入是要满足的有限范围及其绝对值结果。同一个工厂收到输入后，构造完整反馈求解方法；大范围的求解方法内部，再按每轮候选构造检查方法。外层继续组合报告和表达式提取，使用整个方法的输出。

| 输入范围 | 构造与执行结果 | 固定观察调用 | 实际检查动作 |
|---|---|---:|---:|
| `[0]` | 构造直接检查的反馈方法，1 轮得到 `x` | 0 | 1 |
| `[-4,…,4]` | 构造含动态检查步骤的反馈方法，3 轮得到 `x if x >= 0 else -x` | 4 | 3 |

第一种结果只满足声明的 `[0]`，不能推成所有整数的绝对值。第二种也只验证声明的九个输入。

大范围程序实际检查顺序为 `0`、`-x`、`x if x >= 0 else -x`。它有一次完整方法的动态构造和三次内部检查方法的动态构造。每个 bind 事件带本次调用编号、真实生成结构、后续事件范围和执行结果；生成结构不回写原组件。

程序还直接修改已封装的反馈方法：

```python
original = make_synthesis().then(report_solution)
changed = original.replace_at((0, 0, 0, 1, 1), inspect_without_semantics)
```

同样九个输入，原方法调用固定观察 5 次，替换后 0 次，再运行原方法仍为 5 次；都得到同一个已检查表达式。这里证明方法内部可编程且原对象不变，不把减少观察次数宣传为普遍算法优势。

实际完整输出及动态结构：[out/method-construction.json](out/method-construction.json)；终端输出：[out/method-output.txt](out/method-output.txt)。

## 共同结构与执行规则

`Component` 的 `children` 同时用于执行、结构描述、受控替换和共同 `jv.plan`。仍通过已有 `jv.program`、Runtime、动作及预算执行，没有另建运行时，也没有新增 inquiry/feedback 专用指令。

| 组合 | 执行规则 | 静态计划 |
|---|---|---|
| product | 同一输入，按子节点顺序全部执行 | 成本相加 |
| iterate | 先查 done，最多 N 步，返回 done/limit | N 次 step + N+1 次 done 上界 |
| bind | 前段结果传给工厂，执行返回的方法 | 分析已知前段与工厂；后续为未知符号，不执行工厂 |

inquire 的一步是 `product(identity, prepare.then(observer)).then(update)`；feedback 的一步是保留状态、构造候选、检查、更新的通用组合，两者外围都使用 iterate。数据处理仍为普通叶。

`execute()` 返回本次 trace；其中 `generated_structure` 保留可调用对象的只读共同结构，`generated_description` 可导出展示，`result` 是执行结果。JSON 演示保留描述、事件范围与结果类型；不尝试序列化任意闭包。直接调用组件时保持原有行为；要取得这份组合事件记录，使用公开 execute 入口。

返回 Component 作为数据不执行它；bind 才执行。factory_effects 与 continuation effects 的既有声明契约保留，空声明不证明纯净。未知保持未知；本包未增加对任意 Python 黑盒的分析。
