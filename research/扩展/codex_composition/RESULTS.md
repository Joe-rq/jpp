# 初版记录：组合标准库的三个使用样例

定位校正：按原设计任务复核，本包是“组合标准库初版”。下面保留初次交付的样例和实测事实；后续方向以 [IR贯通验收.md](IR贯通验收.md) 为准，暂不扩展为完整程序修复应用。

2026-09-20。`jev-compose 0.1` 已实现并接入 Claude 的 `foundation.jv`：一个问题可以保存、传递、动态构造；一个完整方法可以接收另一个方法、返回新的方法，再被更大的程序调用。组合库、两类算法构造器、三条完整程序、使用说明和独立扩展验证均已交付。

我们之前约定的三个结果已经实际跑通：**封装后仍保持行为；更换组件后公共算法继续工作；未参与实现的作者能构造此前没有预置的方法。** 本轮交付的是语言的组合与复用层。现有源码入口仍然使用 Python 构建器，独立文本语法、完整编译器和整门语言的通用性目标继续沿用项目原规划。

## 先看效果

从项目的 `地基` 目录执行：

```sh
.venv/bin/python 扩展/codex_composition/run.py demo
```

打开 [演示页面](out/demo.html)。拖动第一条程序的步数滑块，看候选如何收缩；拖动第三条程序的预算滑块，看实际分配如何变化。所有显示数据来自这条命令运行的程序，完整数据在 [results.json](out/results.json)。

| 完整程序 | 输入 | 实际结果 | 能继续复用的部分 |
|---|---|---|---|
| 自适应提问 | 128 个候选，固定观察器知道目标 93 | 平衡划分用 7 次判断；只替换划分策略，顺序查找用 94 次 | 问题准备、观察、结果更新和完成条件；整个求解器能作为返回值并再次调用 |
| 根据反例构造表达式 | 有限候选语法，指定输入 −4…4 的绝对值要求 | 3 轮得到 `x if x >= 0 else -x`；检查器实际执行全部 9 个指定输入 | 生成候选、选择策略、实际检查、吸收反例；换成平方要求得到 `x * x` |
| 未决保留与最优分配 | 5 个项目的资格观察，预算 10 | 选择 B+C，成本 10、收益 21；保留 D 未决，A 合格未获预算，E 不合格 | 独立作者新写的动态规划可以替换；整个分配方法又被报告方法调用 |

**模型观察来自明确标记的固定数据，模型外呼费用为 $0。** 候选更新、表达式计算、精确验证、预算分配和记录重放实际执行。7 / 94 是固定可靠观察下的策略比较；三轮合成是有限输入验证，均不表示真实 JEV 的准确率、通用提速或无限整数上的证明。

第三个方法最初使用本地合成资格数据。独立作者提出文档缺口后，我们补齐了原生观察入口示例；作者随后把 15 个原生 `Observation` 接入同一个方法，结果保持不变，外层报告保留全部原始观察及请求身份。

## 你提出的想法，分别落到了哪里

| 你的想法 | 这次已经实现的对应物 | 往更大能力发展的连接点 |
|---|---|---|
| 最小单元、组合、组合的组合 | `Component` 有输入输出、能力声明及结构；叶方法和复合方法使用同一个接口 | 新算法继续返回 `Component`，不增加专用执行器 |
| 问题本身可以输入、传递、保存 | `Request` 使用原生问题值；三种题型可以序列化、恢复，构造时不会执行 | 把选题器作为组件，生成的问题交给现有观察入口 |
| 程序决定应该问什么 | `inquire` 根据本轮结果构造下一题；策略可以返回整个求解器 | 加入信息收益、采样或领域约束策略，只替换相应组件 |
| 是非、选择、度量参与同一程序 | 三种题共用 `Observation`；封装与嵌套后保持出口与来源 | 题型的后端实现与算法连接分开演进 |
| 把不确定性定位在一小块 | 未决有请求身份和原因；`at_least` 计算确定上下界，`refine` 只更新指定未决 | 更大的约束求解器可接收局部未决及其影响范围 |
| 其他确定部分继续强力推算 | 分配程序在 D 未决时，继续求解已合格集合的最优子集 | 结果明确是当前已合格集合的最优解；补全 D 后可用同一方法重新求解 |
| JEV 加经典算法，让原来做不到的事做到 | 提问接候选划分，判断接动态规划，候选建议接实际验证与反例反馈 | 生成器、求解器、测试器都用同样的方法接口接入 |
| 调用者决定完成标准 | `done: S→bool` 由调用者传入；成功、未决、耗尽等业务状态保留在结果中 | 更复杂方法定义自己的可检查完成标准 |
| 复杂判断打包后只写少量连接代码 | `.then`、`product`、`branch`、`bind`、`iterate` 与两个算法构造器 | 使用者复用已有方法，只写新的领域操作与连接 |
| 从问题到可运行程序 | 表达式示例实际经历候选、反例、重新生成、验证、输出代码 | 扩展候选生成器与验证器；公共反馈算法无需改写 |
| 固定、可组合、可恢复 | 固定输入下的组合等价、嵌套预算、材料来源及执行重放均有运行验证 | 真实模型观察仍可能有误；模型校准与固定执行语义分别处理 |
| 模型能升级，不被今天的 JEV 锁死 | 库只接公开 `jv` 能力入口，Runtime 由调用者提供 | 更换模型需要相应适配、档案和校准，组合接口可以保留 |
| 独立作者构造我们没预置的方法 | 新作者只读文档，构造未决预算分配并继续嵌套，没有修改库核心 | 这是一次实际开放复用；项目的更多任务类别继续按原目标推进 |
| 架构要极简，贡献要能拆开看 | 三个消融条件替换组件后仍用同一个反馈构造器 | 能删的策略就删；新增能力应贡献可测量的求解效果 |

对于“200 个选择是否逻辑完备”，目前程序要求调用者显式给出候选集合及划分规则。集合内的算法可以精确处理；自然语言选项是否覆盖现实，要另由领域构造或检查方法提供依据。本轮没有把概率归一化视为逻辑完备。

## 消融告诉了我们什么

保持同一绝对值问题、候选集合、精确检查器和停止上限，只替换策略：

| 条件 | 迭代轮数 | 实际候选检查 | 固定模型请求 |
|---|---:|---:|---:|
| 完整程序 | 3 | 3 | 6 |
| 去掉语义选择与度量 | 3 | 3 | 0 |
| 去掉反例过滤，保留已尝试候选去重 | 13 | 13 | 26 |

这个案例的收益来自反例过滤，减少了 10 次候选检查；语义选择和度量没有减少检查工作。因此它们是可替换策略，精确算法可以直接运行。这说明组合层能够把算法贡献拆开测量；当前案例没有给出 JEV 增益或语言自身加速的证据。

源码：[ablations.py](jev_compose/ablations.py)。完整记录已包含在演示数据中。

## 对语言本身新增了什么

直接写 jv 程序时，作者要自己组织循环、停止、接线、未决携带和整个方法的复用。这一层提供了可传递的统一方法对象、构造时的接口检查、公共算法骨架、来源完整的观察，以及封装后继续调用的契约。精确算法与语义判断共享这些构造。

底层仍然使用原生 `jv.program`、`judge/cut`、`gen`、`do` 和 `transform`。执行、预算、融合、效应记录及重放继续由同一个内核负责。`describe()` 可以查看库的组合结构；它还不是任意 Python 程序的完整静态 IR，也不会自动证明隐藏的效应。

我们没有用任意代码行数倍率来量化价值。实际减少的是新算法反复实现公共组合流程的工作；实际证明是新作者在不修改库核心的情况下，新增并复用了第三个方法。

## 实现语言和与 Claude 的接入

**本轮使用 Python 3.12。** 原因是现有语言内核公开入口已经在 Python 中；本轮把组合语义接进这个入口，直接获得既有执行能力。我们没有新增 Rust 或 OCaml 内核。独立语法前端、完整类型系统及运行时的实现语言，保留到相应接口和性能要求明确时再决定；本次没有把长期语言目标改成只能写 Python 库。

默认演示固定使用只读源码快照，36 个文件均核对 SHA-256。合并指纹为 `be68c783b4b2475174a5efc366986a4b05c230bbba39a0927a85f8208b9a2bcf`。

另一次完整演示使用了 Claude 正在维护的工作目录内核。接入中修复了报告代码对 `Mat` 的隐式真假判断，并接上当前公开的可信动作登记入口。三条程序与重放均通过，实际载入模块的路径和指纹保存在 [工作内核接入记录](out/working_kernel_check.json)。我们未修改 Claude 的核心源文件或权威规范。

## 初版提出的应用建议（本轮暂停）

把这套组合用于一个“检查器能精确确认，但查找过程无法直接算出答案”的真实问题，例如带自然语言约束的程序修复。复用本轮的候选构造、反例反馈和可替换检查器，给 JEV 一个明确岗位：在多个可执行候选之间选择下一项值得验证的方案。

下一项的完成物应是可应用的补丁及其实际测试结果。比较三种策略：无语义排序、JEV 排序、其他后端排序；在同一批问题上测解决率、实际验证次数、时间和费用。这样能回答“模型在哪些条件下让复杂算法更有用”，也能继续扩充通用组合库。它属于后续能力包，本轮的组合层已经完整交付。
