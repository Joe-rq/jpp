# `conformal-proto` 与 `jpp-core::conformal` 的逐项对照

2026-09-21。**起因是一处静默分叉**：这份原型先于内核写成，内核落地后两边并存了八个同名项，而它们**已经分叉过一次**，并且那次分叉**永远不会断编译**。

```
proto:  binomial_upper(k, n, delta)        certify(samples, alpha, delta)
core:   binomial_upper(k, n, conf_delta)   certify(samples, alpha, conf_delta)
```

## 那次改名不是整理，是一条判断

**保形的 `δ` 是置信水平**（「这个上界有多大把握成立」）；**档案里的 `δ` 是迟滞带宽**（「读数抖多少不算变」，`profile.delta.noul.immediate.p99` 那一族）。**两个完全不同的保证，不许共用一个名字。**

这条判断在内核里做了，而**拷贝这边没有跟上，也不会有任何东西提醒它**：同一个 crate 两小时内被内核字段变更打断编译两次（`Sample` 加必填 `cluster`、`cert` 变 `certs`），那两次都是**响亮**的、当场修掉的；**这一处是静默的，它在同一个文件里躺了一整轮没人看见。**

**这是「两件正交的事不许挤进一个名字」的又一个实例**，与 `mode_share` 不许离开 `perms`、`calib_key` 不许缺 `literal_mode`、`untested` 不许挤进 `cause` 同族。

## 逐项判过的结果

**判法**：把内核那份里的 `conf_delta` 归一化回 `delta`，再与原型那份**逐字节比**。「两边一样」也写下来，否则下一个人还得再对一遍。

| 项 | proto | core | 归一化后逐字节 | 判定 |
|---|---|---|---|---|
| `binomial_upper` | 有 | 有 | **相同** | 引用内核。分叉只在参数名 |
| `n_needed_zero_error` | 有 | 有 | **相同** | 同上 |
| `enum Certificate` | 有 | 有 | **相同** | 内核另加 `Serialize, Deserialize` 派生——**它要进记录，必须可序列化**，原型不需要。内核对 |
| `impl Certificate` | 有 | 有 | **相同** | 引用内核 |
| `certify` | 有 | 有 | **相同** | 引用内核。三道「空放行区不算解」的保护两边都在 |
| `struct DriftReport` | 有 | 有 | **相同** | 内核另加 serde 派生，同上 |
| `drift` | 有 | 有 | **相同** | 引用内核 |
| `cluster_subsample` | 有 | 有 | **相同** | 引用内核 |
| `cost_line` / `CostLine` | **无** | 有 | — | 内核独有，原型从来没写过 |
| 原型独有的实现 | **无** | — | — | **一项也没有** |

**结论：八处实现逐字节相同，唯一带判断的差异是参数名，而内核那边是对的。** 没有出现「原型才对」的格子——这一点是逐项查过的，不是默认内核对。

## 改完之后 proto 还剩什么

`src/lib.rs` 现在只有两样：

1. `pub use jpp_core::conformal::*;`——**凡内核里已经有的，一律引用不复制。**
2. 原型独有的 **E-CAL 真读数装载**：`ecal()` / `ecal2()` / `装进()`。五个测试文件里原本各有一份装载器，现在都委托到这一份，**逻辑只剩一处**。

外加 `tests/` 里的回归保护与三个 `analyze*.py`（不需要 Rust 就能跑）。

**实测：`cargo test` 11 passed / 0 failed / 0 warning**，在 `jpp-core` 的当前 HEAD 上。

## 留给下一个人的一句

**这个 crate 依赖内核的内部结构，而这条依赖只活在 `Cargo.toml` 的一行 `path` 里。** 内核改字段时**没有任何东西会提醒它**——断编译那种会当场发现，**改名那种不会**。引用不复制之后，改名也会断编译了，**这正是把它从注解变成承重件**：删掉它（即再复制一份）就不再有东西坏掉，而这正是要避免的。
