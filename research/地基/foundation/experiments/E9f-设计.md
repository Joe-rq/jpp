# E9f · 设计稿：在昂贵执行器下量 Jev 的增益（不跑，只设计）

日期 2026-09-21。起点：独立顾问（设计/H §7、§12.8）指出 E9b–E9d 的执行器是毫秒级沙箱，
比一次 Jev 调用（≈1 s、≈$0.00005）还快还便宜，在这个区间任何便宜的排序器都无增益，
所以三次实验测的是「执行免费时 Jev 有没有增益」，不是「Jev + 生成」本身。
E9f 把执行器换成真正昂贵的一步，量「固定召回下省掉多少次昂贵步骤」。

本文只做定义、场景比较、预注册草案与一次基线测量；未发一次 Jev 调用。

---

## 1. 增益公式的可操作定义

设一批候选 x₁…x_N，每个候选都可以走一次**昂贵步骤** E（跑全量测试、人工核对、部署观察），
E 的单位成本 C_E（秒 / 美元 / 人分钟，三种都记）。E 的输出是一个二值真值 y ∈ {阳, 阴}：
阳 = E 发现了问题（测试挂了、人工核对发现真矛盾、上线出事故）。

**筛选器** S（Jev、启发式、或组合）给每个候选一个分数 s(x)，并按阈值 τ 决定「送 E」或「跳过」。
筛选器自身的单位成本 C_S（同样三种口径）。

- **召回** r(τ) = 被送 E 的阳性数 / 全部阳性数（真值来自全跑）。
- **省掉的昂贵步骤数** N_saved(τ) = N − |{x : s(x) ≥ τ}|。
- **固定召回下的省掉数** N_saved(r₀) = max_τ { N_saved(τ) : r(τ) ≥ r₀ }，r₀ 预注册为 0.95。
- **增益（顾问公式）** G = (C_E / C_S) × N_saved(r₀)。
- **净收益**（更直接）：Net(r₀) = N_saved(r₀) × C_E − N × C_S。Net ≤ 0 即无增益。
- **增益比** G′ = N_saved(r₀) × C_E / (N × C_S)。G′ ≤ 1 即筛选不如全跑。

零点条件：C_E ≤ C_S 时 Net < 0 恒成立，无论 AUC 多高。E9b–E9d：C_E ≈ 0.01–0.5 s（沙箱）、
C_S ≈ 1.2 s，正落在零点，与观察一致（测试能分时 Jev 复述，不能分时 0.62）。
E9f 要求 C_E / C_S ≥ 100。

阈值 τ 的选法（与账本「阈值 = 代价 + 标注集经风险控制」一致）：在**标定切分**上取使召回 ≥ r₀ 的
最宽阈值（经验分位数），在**测试切分**上报告实际召回与 N_saved；两个切分按候选 id 随机切、不重叠。
另报整条 召回–省掉 曲线（τ 扫描），因为不同用户的 r₀ 不同。

对照的定义：任何对照臂也走同一套 τ 选法与同一个 r₀，只比 N_saved(r₀) 与成本。

## 2. 三个候选场景

### 2a. 真实开源仓库的慢测试套件（推荐）

**昂贵步骤 E**：对一个补丁跑 networkx 3.3 的全量 pytest。基线实测（本文 §4）：**230 s 墙钟**，
4,579 通过 + 302 跳过（无 numpy/scipy 时）。C_E = 230 s ≈ 190 × C_S（一次 Jev ≈ 1.2 s）。

**候选来源**（两类混合，N ≈ 120）：
- 变异体 80 个：对 `networkx/algorithms`、`classes`、`generators` 里的函数做单点 AST 变异
  （比较运算符翻转、边界 ±1、`return x` → `return None`、`and`/`or` 互换、删掉一个分支）。
  变异体的阳/阴（被杀 / 幸存）就是真值；幸存里含等价变异，按定义算阴（E 发现不了问题）。
- 写手补丁 40 个：haiku 对随机挑的 40 个函数各写一条「小重构或修一个你认为的 bug」的补丁
  （$0），真值同样由全跑给。这类更像真实提交，防止结论只对变异体成立。

**字面化 S（宿主，秒级，全部确定性）**：对每个补丁产出一个 JSON state：
`{diff, 触及函数补丁后全文, 触及符号列表, 直接引用这些符号的测试文件与用例名（grep/AST）, 改动行数, 是否改了测试}`。
不跑任何测试（否则又回到零点）。

**Jev 题组**（一状态一次调用，全部一跳字面，按 06 §6 的三种语义操作）：
- test「这个改动会让函数在某些输入上返回不同的值或产生不同的副作用吗」
- test「补丁后的代码里有明显的逻辑错误吗（越界、条件反了、漏返回）」
- test「列出的测试用例里有直接检查被改动行为的吗」
- measure「这个补丁破坏现有测试的可能性」5 档，锚每档 1 条（从标定切分里抽）
- 置换/重跑：noul 3 次均值；state 单对象（P22）。
筛选分数 s = 拟合聚合器（逻辑回归，在标定切分上训，特征 = 三道 test 读数 + 档位 + 改动行数），
另报「只用 measure 档位」与「只用第二道 test」两个不拟合的简单分数，防止增益全来自拟合。

**对照臂**（全部走同一 τ 选法与 r₀ = 0.95）：
1. 全跑：N_saved = 0，召回 1。基线。
2. 随机筛：同 |送 E| 数下的期望召回。
3. **确定性 TIA（测试影响分析）**：只跑直接引用触及符号的测试文件（宿主 grep/AST 得到，秒级），
   挂了才送全跑。它自己也是筛选器：C_S(TIA) ≈ 5–20 s，报它的召回与 N_saved。这是最强的免费基线，
   Jev 必须与它比、与它合。
4. Jev + TIA：TIA 通过的候选再由 Jev 打分决定送不送全跑。
5. **一致性投票（CodeT / MBR-exec）**：只对「同一函数多候选」的子集适用（写手补丁每函数可多写 3 条），
   量的是「选一条不破坏的」而不是「筛送不送 E」，单独报，不进主表。
6. haiku 当筛选器：同一 JSON state、同三道题，只答字母；记每候选秒数与 token 折算成本。
7. 静态启发式：改动行数、是否触及公共 API、是否改了测试，各单独作分数。

**指标**：每臂 召回(τ*)、N_saved(τ*)、Net（秒、美元、以 230 s/次 折算）、G′、AUC、
在本域的 ECE（并入 E-CAL 的字面化模式「判代码字面」）、每候选 C_S。
主结论只看一格：**同召回 ≥ 0.95 下，Jev+TIA 的 N_saved 比 TIA 单独多几个**。

**预算**：Jev：120 候选 × 1 状态 × 3 次 ≈ 360 次调用，每次 ≈ 271 + 900 + 4×40 ≈ 1.3k token
→ ≈ 0.47M token ≈ **$0.02**；再加 measure 锚样例 ≈ +30%，上限 **$0.03**。
真值计算（不花钱但花机器）：120 次全跑 × 230 s，4 路并行（每路 CPU 85 s，10 核够）≈ **1.9 小时墙钟**；
先跑 40 个变异体（40 分钟）看阳性率，再决定是否补满 120。TIA 臂 120 × ≤20 s ≈ 40 分钟。
haiku 臂 120 × ≈40 s，并发 4 ≈ 20 分钟，$0。

**预注册预测（赌）**：
- 变异体阳性率 ≈ 0.70（networkx 套件覆盖高）；写手补丁阳性率 ≈ 0.35。
- Jev 拟合分数 AUC ≈ 0.72（静态、无执行，介于 E9b 字面 0.79 与 E9c 0.62 之间）；只用 measure 档位 AUC ≈ 0.65。
- 召回 ≥ 0.95 下：Jev 单独 N_saved ≈ 25% × N；TIA 单独召回 ≈ 0.85（间接破坏漏掉）且 N_saved ≈ 80%；
  **Jev + TIA 在召回 ≥ 0.95 下 N_saved ≈ 55–65% × N**，即比「为保召回而全跑」省一半以上。
- Net（Jev+TIA，N=120）≈ 70 × 230 s − 120 × (1.2 + 15) s ≈ 4.2 小时省下 vs 0.5 小时筛选。
- haiku 筛选器 AUC ≈ 0.68，每候选 ≈ 40 s（比 Jev 慢 30 倍）。
- 本域 ECE：变异体上 ≈ 0.10，写手补丁上 ≈ 0.18（同 E-CAL-0 的字面化规律）。

**证伪判据**：
- 召回 ≥ 0.95 下 Jev 单独 N_saved < 10% × N → 在此昂贵区间 Jev 单独无增益。
- TIA 单独召回 ≥ 0.95 → Jev 冗余，此格标「确定性方法已够」。
- Jev+TIA 比 TIA 单独在同召回下 N_saved 多不到 10 个百分点 → 组合无增益。
- 三条都不触发且 Net > 0 → 增益公式在此区间成立，数字入能做域表。

**怎么才能对（若证伪）**：把 S 再往字面推一步——让 TIA 的**部分测试输出**渲染进状态再判（E9d 的路，
但只跑秒级子集，不回零点）；或换更慢的套件（装 numpy/scipy 后 networkx 套件更长；或 sympy，小时级）。

### 2b. 交付前文档自检

**昂贵步骤 E**：Nature 人工核对一处被标出的疑似矛盾/承诺不一致，C_E ≈ 2–5 人分钟。
**候选来源**：本项目自己的交付文档（地基/ 与 语言/ 下的 md），已抓到过两处真矛盾；候选 = 同一文档集内
「都有主张的段落对」，先用注意题（这 K 段里哪段与 a 相反，K ≤ 16，E10）压缩，再对命中对问关系题。
**字面化 S**：切段、装槽（对象 + 对手段单独占位）、去掉引用与代码块。
**Jev 题组**：test「两段对同一件事的说法相反吗」、test「两段说的是同一件事吗」、measure「矛盾的严重程度」3 档。
**对照臂**：全读（Nature 读全部，C_E × 段数）、随机抽同样数量给 Nature、关键词重合启发式（同名实体共现）。
**标注流程**：三批，每批 50 条 Jev 标出的对（按分数降序）+ 10 条未标出的随机对（估漏放），
Nature 每条标「真矛盾 / 不是 / 看不出」；每批约 40 分钟，三批 2 小时。
**指标**：标出集合的精度、由随机未标出对估的召回、人分钟省下 = 全读时间 − 核对时间；G′ 用人分钟算。
**预算**：Jev ≈ $0.05（几百对）；人 2 小时。
**预注册预测**：精度 ≈ 0.4，召回 ≈ 0.7，人分钟省 ≥ 70%。
**可行性**：真值最真（人）、场景与使命直接相关，但不能自主跑，**要等 Nature 的 2 小时**。
