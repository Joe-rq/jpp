## 0. 一句话

程序是普通的宿主程序（数据结构、纯函数、有界循环），里面在任意位置出现四种带类型的效应：`judge`（问模型）、`gen`（生成候选）、`do`（触世界）、`ask`（问人）。
`judge` 的输出是读数，读数只能经 `cut`（过线）或 `fit`（拟合聚合）变成程序能用的出口。规划器按效应画像把判断融合、裂变、下沉、调度，并在计划期算钱与层数。
语言的原创部分全在效应与类型纪律；其余是无聊但好的宿主。

**为什么。** 「判断语言」把判断放在语法根上，一切程序成了「判→做」序列，写不出「普通程序中途用一次判断做分支」；Fable 顾问 §12.1 列出的四处文法缺口（无 lambda、无有序序列、赋值位置受限、22 个关键字）都是这个选择的代价。判断是效应不是语法，通用性才成立（清单 A0、G2）。

## 1. 类契约（对「Jev 这类模型」成立的，一页）

契约只写类级性质。凡是数字，都是模型档案（`foundation/profile/profiles/<model>.json`）里的字段，程序与编译器只引字段名。

```
Model : State × [Q] → [Reading]                  一次调用：一个状态，一批题，每题一个读数
```

| # | 契约条款 | 依据 | 由档案参数化的字段 |
|---|---|---|---|
| C1 | 状态是文字或 JSON 对象；题面可按路径引用 JSON 字段 | D1（api：state string/object/array） | `state_representation_default`、`modalities_accepted` |
| C2 | 题有三种输出结构：{真,假} 上一个数（test）、K 个给定选项上的分布（select）、L 个锚定档位上的有序分布（measure）。模型只在**给定集合**上分配概率，从不产生集合 | D2；H §1.4 | `question_types`、`k_limit.hard_max_options` |
| C3 | 读数是**单调分数**：同题同状态可比、可排序。概率含义只在该校准键经可靠性检验（ECE 量在跨阈值箱、n ≥ 100）后成立 | E-CAL-0（P21：校准是字面化程度的函数） | `calibration.ece_by_source`、`calibration.zh_reliability_curve` |
| C4 | 跨题读数不成恒等式：P(x)+P(¬x) ≠ 1，跨题算术无定义 | 官方文档；v0 §1.3 | — |
| C5 | 一跳字面：模型读面前的字面，判不出要运行、要算、要多跳才知道的事 | P1、P10 | — |
| C6 | 算术在宿主。模型不做算术，不做计数 | D2、P10 | — |
| C7 | 重跑非逐位确定；同一（状态，题，运行序号）的结果由账本定义为确定 | P2、P3 | `delta.*`、`flip_rate.*` |
| C8 | 状态有窗口：超过某个量的带主张材料会带偏读数；窗口随表示（文字/JSON）不同 | P4、P24 | `window.text_slots.*`、`window.json_slots.*` |
| C9 | 状态收费、题近乎免费（时间不随题数增长；token 每题边际固定） | P5 | `cost.regression`、`cost.tokens_per_question`、`cost.latency_median_by_n` |
| C10 | 同状态多对象逐对象判存在串扰；一状态一判断对象 | P22（E16 证伪多对象） | `batch_invariance.*` |
| C11 | 每个结果记模型版本；换版本 = 重跑档案测试组 + 迁移报告，程序不改 | 审核 A | `model_version` |
| C12 | 带主张的自述文本会推动读数（不可信材料是攻击面） | P23（E-ADV） | — |

不在契约里的（是这一版模型的档案，不是类性质）：500 / 1,800 token 的具体窗口、K ≤ 16 / ≤ 4、置换 2 次、δ 0.05 / 0.15、首位偏置 33%、锚每档 1 条、并发 32。程序若引「未测」字段，编译期报错（SCHEMA 约定）。

**为什么。** 清单 G3：为这类模型设计，不为一个版本；模型更新极快。分开契约与档案，语言才能在换模型时不改（审核 A）。C3 把「校准」从默认前提降为可验证的条件，是 E-CAL-0 的直接结果：语言的正确性不押在校准上，校准好只是让线更靠谱、样本更少（H §9(2)）。

## 2. 六形式 IR

宿主之外只有六种形式。每种给类型签名、画像、账本键。`Mat` 是唯一材料类型：`{content, addr, origin: [Mat|Q|do|gen|ask], taint ∈ {trusted, untrusted}, derived_from: Set[Q_hash], render_version}`。

### 2.1 `state`（槽构造子，纯）

```
state(on: Mat | [Mat], ctx: [Mat] = [], ref: [Mat] = [], over: [Mat] = []) → State
State = {slots: JSON, size_tokens, taint = ∨ slots.taint, derived_from = ∪ slots.derived_from, repr ∈ {json, text}}
```
- JSON 具名槽渲染，题面按 `on` / `ctx[i]` / `over[k]` / `ref[ℓ]` 路径引用 [C1、P24]。
- 窗口检查：`size_tokens ≤ profile.window.<repr>.usable_lower`，材料静态已知时编译期查，否则调用前查，超窗交裂变 pass。
- `on` 恰一个判断对象（C10）；`over` 是候选集，`ref` 是锚样例或参照，`ctx` 是语境。
- 关系是 `on=(a, b)` 的复合对象：配对是状态构造，不是题型 [P8]。
- 账本不记 `state` 本身；它只出现在 `judge` 的键里。

### 2.2 `judge`（效应）

```
Q = {op ∈ {test, select, measure}, slot_shape, text, calib_key, phys?: {noul, choice, score, k_noul}}
judge(s: State, qs: [Q]) → [Reading]
Reading = 不透明 {q_hash, state_hash, run_seq, model_version, phys, perm_seed}     # 语法不可写，只能被 cut / fit 消费
```
- 画像：成本 = `profile.cost.regression`（每次调用 ≈ 固定 + 状态字符 + 题字符），时延 ≈ `profile.concurrency.latency_s.p95`，几乎不失败，噪声 `profile.delta`。
- **账本键**（程序局部，确定性重放）：`(model_version, canon_json(state), q_text_hash, slot_kinds, phys, perm_seed, run_seq)`。按题不按题组：融合不改键 [P3]。
- **缓存键**（跨程序）：`(materials_hash(state), q_text_hash, slot_kinds, phys, model_version)`。读数与程序无关 [推导 ← P3 + 材料不可变 + 题字面]。这就是「目的无关的中间状态」：预览层从命中统计里长出来，不是固定谓词表（账本 #24 的替代）。
- `calib_key` = `(q_text_hash, slot_kinds, phys, render_version, literal_mode)`；`literal_mode` ∈ {判执行输出, 判代码字面, 判文档段落, …}，题级样本不够时用模式级校准做先验收缩（jev-f6 细化 2）。
- 题式（属性/关系/子集/充分性/比较/归类/提及/程度/决定）不是 IR 形式：由 `op × slot_shape` 推断，只作校准键分类与下沉提示（H §12.2）。

### 2.3 `cut`（桥，纯）

```
cut(r: Reading, c: CalibRef, cost?: {fp, fn}) → Exit
Exit = Act | Ignore | Unsure(cause)               # test
     | Pick(k) | Unsure(cause)                    # select
     | At(ℓ)   | Unsure(cause)                    # measure
cause ∈ {band, tie, cold, insufficient, fail, budget, noprogress, drift, taint}
```
- `CalibRef` 指向校准记录：`{lines | conformal_quantiles, n, coverage, δ, status ∈ {冷, 上岗, 停岗, 待真值}, drift_stat}`。线**只**从记录来；若给 `cost`，线由保形风险控制在标注集上按代价求出，校准好时收敛到贝叶斯代价比线（jev-f6 细化 1）。字面量线是类型错。
- 顺序：先查 `insufficient`（状态里没有决定性证据 → 不信任 p），再查 `taint`（不可信材料且下游是 `do`），再过线，再查 `band`（线附近 ±δ）。
- `select` 的 `Pick` 要求置换众数一致（`profile.position_bias`）且有证据（先验策略是库参数，见 §5）；不一致 → `Unsure(tie)`。
- 出口是 `Mat` 的子类型，可渲染回状态，但带 `derived_from ∋ q`（§3 J-02 禁自指）。

### 2.4 `fit`（桥，纯，第二个读数消费者）

```
fit(m: FitRef, rs: [Reading]) → Score ;  然后 cut(Score, c)
FitRef = {trained_from: 标注集 id, features: [calib_key], error_rate, n, version}
```
- 只能由标注数据训练产生（逻辑回归级；样本几十时退化为投票）；程序里不可手写算术。合成后**再保形一次**得出口（H §9(2)）。
- 这是跨题读数唯一合法的算术。

### 2.5 `gen`（效应）

```
gen(prompt: Str, ctx: [Mat], n: Int, retry_seq: Int = 0) → [Mat]      # 可能为空
```
- 画像：成本 `profile_gen.cost_per_candidate`，时延分布（LLM 秒到分钟；枚举器 0），失败 = 超时/空（E9b 30%），首候选常是强基线 [P20]。
- 键：`(site, prompt_hash, ctx_hash, n, retry_seq)`。`regen` 去向必须递增 `retry_seq`，否则命中账本返回同一批（H §12.4）。
- 确定性枚举器（正则、解析器、语法、k-子集、全配对）是 `gen` 的零成本实现，同签名。

### 2.6 `do`（效应）

```
do(action: Action, args: [Mat], iter_seq: Int) → Mat ⊎ Fail
```
- 画像由动作声明：成本、时延（毫秒到小时）、可逆性、失败类型。`Fail` 是值，进账本，走 `Unsure(fail)` 流。
- 键：`(site, action, args_hash, iter_seq)`；重放取账本，不重触世界。
- 执行器、渲染器（OCR、可访问性树、结构化抽取）、求解器/检查器都是 `do` 的实例；返回的 `Mat` 已是渲染后材料，不需再渲染。

### 2.7 `ask`（效应，异步）

```
ask(s: State, q: Q) → Exit ⊎ Pending
```
- 画像：贵、小时到天、可能不答；答案是真值，进校准集。
- 有预算（`budget.escalate`）与去重（同键只问一次）；`Pending` 使程序挂起，恢复时账本重放不付费。
- 键：`(state_hash, q_hash)`。

### 2.8 宿主

纯函数、数据结构（列表、映射、集合、记录、优先队列）、有界循环 `loop(bound, variant)`。变式：宿主计量严格单调，或打分出口带耐心（连续 p 轮无提升即停），或账本键在本循环内重复即停 [P6]。纯性由 IR 判：不含六种效应即纯。

**为什么。** H §4：四种效应成本、时延、失败、不确定性各不同，都叫 S 会抹平画像，规划器无法把 21 s 的 `gen` 移出关键路径、无法给 `regen` 换键（可直接触发的重放缺陷）。`cut` 与 `fit` 是读数仅有的两个消费者（审核 §4.2 T-fit），把「读数不可表达」从绝对禁令改成两座桥。`state` 是一等构造而不是库函数，因为对象绑定（P4/A7）、窗口、taint 三条都是语言级保证，落在拼状态这一步（红队 03 B8）。

## 3. 类型纪律（IR 检查器规则）

| 编号 | 规则 | 依据 | 可判性 |
|---|---|---|---|
| J-01 | 读数只经 `cut` 或 `fit` 离开；放到要 `Mat` 的位置、做算术、做比较都是错 | C4、C5、P1 | 静态 |
| J-02 | 读数派生材料（出口、摘要）带 `derived_from`；由题 q 派生的材料不得进入再问 q（或同 `calib_key` 前缀）的状态——禁自指 | P4 自我锚定；H §12.9 | 材料静态时编译期，否则运行期 |
| J-03 | 线不可字面；`cut` 的第二参数必须是 `CalibRef` | E4 纪律 | 静态 |
| J-04 | 跨题、跨候选集（`over` 指纹不同）、跨刻度或异锚（`ref` 指纹不同）的读数不可比；同题同锚同单独渲染的 `At(ℓ)` 可偏序（相邻档并列）与按档计数 | P2、P13 | 静态（指纹在类型里） |
| J-05 | 每个 `Unsure` 必须被某个 handler 消费；程序返回类型不含 `⊎ Unsure` 时，出口前所有 unsure 流已被 handler 处理（升级、丢弃并记账、进返回类型） | 研究 §5.2；零上下文读者 G2 | 静态（match 穷尽性） |
| J-06 | `loop` 必带 `bound` 与 `variant`；变式为宿主计量时须严格单调；键重复即停 | P6、P2 | 静态（存在性），运行期（进展） |
| J-07 | 预算：每个含效应的函数带符号成本签名（调用数、层数、gen 时延 = 输入规模的函数）；调用点实例化；`program` 的 `budget` 是对实例化总和的断言 | P5；H §12.5 | 静态（规模已知时），否则计划期 |
| J-08 | T-taint：`taint = untrusted` 的状态上得出的出口不得**单独**放行 `do`（不可逆动作）；须与 trusted 证据合取或经 `ask`。不做逐字标签传播（融合会被拖垮，研究 04） | P23 | 静态（`do` 的守卫来源可追） |
| J-09 | `insufficient` 在信任 p 之前检查：`cut` 先看状态是否含该题的决定性证据槽（由 S 声明），再过线 | E-CAL-0（证据不在状态里时过度自信） | 运行期 |
| J-10 | unsure 乘性预算：编译器从校准记录取每题 unsure 率 u，估组合表达式（AND 串 k 题 ≈ 1−(1−u)^k）的期望 unsure 率，超 `budget.unsure` 即报 | H §13.2 | 静态（估计），运行期（实测） |
| J-11 | `for/map` 传入的函数必须纯（不含六种效应或只含 `judge`）；要顺序与写外层用 `loop` | E8 融合前提 | 静态（IR 纯性） |
| J-12 | `Fail` 传播：任一子表达式 `Fail` 则整体 `Fail`（短路）；集合逐元素；`judge` 与聚合对 `Fail` 元素按 `Unsure(fail)`；程序边界不含 `⊎ Fail` 时必须 `on_fail` 处理 | 红队 05；v1.1 §4.11 | 静态 |
| J-13 | `regen` 必须递增 `retry_seq`；`do` 的 `iter_seq` 由循环给 | H §12.4 | 静态 |
| J-14 | 状态 `on` 恰一个判断对象；`ctx` 中带主张材料的总量按档案窗口检查；`ctx` 只收 trusted（不可信材料只能进 `on`） | C10、P23（语境槽注入更强） | 静态（槽形状），运行期（窗口） |
| J-15 | 引用档案「未测」字段即错；引 `upper` 界须留余量 | SCHEMA 约定 | 静态 |

**为什么。** 每条都能追到一条公理或一次失败：J-01/03/04 是 Move 式「对读数你不许做什么」的纪律（H §2）；J-02 解开「读数无渲染」与分治骨架的矛盾；J-05 是三轮零上下文读者与 SQL NULL 教训的共同结论；J-08/09/14 来自 E-ADV 与 E-CAL-0 两条实测；J-10 是 H 推出的、两份文档都没有的墙。

## 4. 编译 pass（每个一个开关，给消融留门）

| 序 | pass | 做什么 | 依据 | 不做会坏什么 |
|---|---|---|---|---|
| 1 | 提升 `--lift` | 不依赖前面**效应**结果的 `judge` 提前到同一轮，分支条件变成对出口的查表；跨 `if` 分支也提 | P3 批无偏；审核 §4.3-a | 成本回到逐层 |
| 2 | 融合 `--fuse` | 同 `canon_json(state)`、同层的题合成一次调用；键按题不变 | P5 | E8：成本 +45% |
| 3 | 裂变 `--fission` | 超 `profile.window.<repr>` 的状态按窗切开，对象单独占位；合回按 op：test → exists/all，select → 分块选再决（K-noul 优先，锦标赛只在 cmp 判据相对时），measure → 按出口计数 | P4、P24 | 带偏读数 |
| 4 | 下沉 `--lower` | `select` → choice（候选 token ≤ `profile.k_limit` 档、K 在档内，置换 ≥ 2 取众数）或 K-noul argmax（长候选）；`measure` → score（锚 ≥ `anchors.default_per_level`，对象单独渲染）；`test` → noul | E9b、E10 | 首位偏置直接进结果 |
| 5 | 调度 `--schedule` | 效应 DAG；`gen`/`ask` 移出关键路径提前发；`judge` 按层批发、并发按状态大小自适应（`profile.concurrency`）；宽优先于深 | H §6.8；E10 SSL EOF | 时延与限流 |
| 6 | 预算干跑 `--plan` | 按 J-07 实例化成本签名：调用数 ×（`cost.regression`）→ 钱；层数 × p95 + gen 时延 → 秒；unsure 乘性估计；与 `budget` 比对，超即拒；报 W-cost（笛卡尔积）、W-taint、W-window | P5 | 平方项在运行时炸 |
| 7 | 键与重放 `--ledger` | 生成账本键与缓存键；重放不付费；`ask` 挂起后恢复 | P3 | 不确定 |

下沉阈值不是常量：`jv lower` 打印每题命中的档案字段与依据。

**为什么。** 提升与融合直接来自 P3、P5；裂变来自 P4/P24；下沉来自 E9b 与 E10 两次相反的实测（同一逻辑算子，长短候选最优物理形式不同）。这四个 pass 是这门语言的编译器区别于任何现有编译器的地方（06 §6）。开关是为建造第 8 步的实跑消融留的。

## 5. 库（不是语言）

| 层 | 内容 | 说明 |
|---|---|---|
| 题式 | 属性、关系、子集、充分性、比较、归类、提及、程度、决定 | 校准键分类与下沉提示；由 `op × slot_shape` 推断，不进 IR |
| handler 库 | 按 `cause` 路由：`band → 重跑/置换收窄`，`tie → 逐候选 noul`，`cold → 保守线 + 标记`，`insufficient → 补证据槽（S）/ escalate`，`fail → on_fail`，`budget → 保留并标注`，`noprogress → 退出记账`，`drift → 停岗 + ask`，`taint → 要求 trusted 证据` | 每个 handler 两个有序去向带上限；`refine` 的判据用字面前提题，不用元题（`enough` 待 E-ENOUGH） |
| 组合子 | `gate`（位→槽）、`pick`（索引→槽）、`threshold`（档→槽），槽 ∈ {材料, 语境, 参照, 问题, 候选集, 刻度, 动作, 循环} | 三原语 × 槽参数（10 §3.2、红队 04 §6.2），体内实现一次 handler |
| 聚合子 | 位：exists/all/count 区间；索引：mode/hist；档：dist/median/top-k（含 unsure 标 unsure）；混合由宿主写 | Kleene 与 Mostowski 量词 |
| 骨架 | 筛、配对、分治（出口摘要打标）、搜索（已访集合、不可逆闸门）、锦标赛（unsure 组晋级前二）、选型（预测 + 回填）、group_by（关系 + 并查集）、derive（二阶：`gen` 出题 → 校准 → 用） | 全是普通函数；去掉任一语言仍完整 |
| S 库 | 取（file/http/repo）、跑（run/bench/test）、算（features/diff/ast/log_stage/union_find）、抽（sample/neighbors/split/枚举器）、渲染（a11y/ocr/table/去主张渲染） | 每函数一行参数说明；返回值已渲染 |
| 召回层 | 检索器 / 嵌入聚类 | 配对前压 N_s（E8 追加的规划器职责） |
| fit 注册表 | 每个 `FitRef` 的训练集、特征键、错误率、版本 | 只能训练产生 |
| select 策略 | 先验绑测试证据（E9d）：默认候选全过则保留；默认候选挂测试且存在全过者才替换；全同分才用读数；一致性投票（CodeT）作确定性基线 | 策略参数，不是语义 |
| 校准库 | 记录、保形分位数、模式级先验、延迟真值通道、漂移监控（无标签：读数分布偏移）、模型版本迁移报告 | 共享资产 |

**为什么。** 判据只有一条：去掉它语言是否仍完整（H §5.4）。上面每一项去掉后六形式 IR 仍能写出同样的程序，只是更长。先验规则、去向表放进库是因为每次实验都会改它们（H §12.3、§12.6），语义不该随实验换。

## 6. Python 构建器 API 草案

构建器只是构造 IR 图（像 JAX 建图）：`@jv.program` 内的调用不立即执行，先建图，IR 检查器跑 J-01…J-15，规划器跑 §4 的 pass，再解释执行。宿主的一切（函数、lambda、列表、字典、二分、优先队列）原样可用。

```python
import jv
jv.state(on=..., ctx=[...], ref=[...], over=[...])      # 2.1
q = jv.test("题面", calib="键")                            # Q，op=test；select/measure 同理
jv.select("题面", calib=..., prior=jv.prior.test_evidence)  # 策略是参数
jv.measure("题面", scale=["低","中","高"], anchors=jv.anchors("名"), calib=...)
r = jv.judge(state, q1, q2, ...)                         # → 读数元组（不透明）
e = jv.cut(r[i], calib=jv.calib("键"), cost=(fp, fn))     # → Exit；calib 必须是 CalibRef
jv.fit(jv.fitref("名"), r[a], r[b])                      # 第二座桥
jv.gen(prompt, ctx=[...], n=8) ; jv.do(action, *args) ; jv.ask(state, q)
with jv.loop(bound=8, variant=jv.decreasing(lambda: len(xs))): ...
match e: case jv.Act(): ... ; case jv.Ignore(): ... ; case jv.Unsure(c): jv.handle(c, ...)
@jv.program(budget=jv.Budget(calls=..., cost=..., layers=..., escalate=..., unsure=...))
```
出口用 `match` 消费，检查器以穷尽性判 J-05；`jv.handle(cause, ...)` 调 handler 库。读数没有 `__float__`、`__lt__`，J-01 在 Python 类型层直接拦。

```python
@jv.program(budget=jv.Budget(calls=40, cost=0.02, layers=8, escalate=1))
def 定位回归(repo, good, bad):                                   # 9.5 二分（v1.1 12 行）
    慢了 = jv.test("这份基准输出相对基线明显变慢了吗？", calib="perf.慢了")
    cands = commits(repo, good, bad); base = bench_of(good)     # 有序列表：宿主自带
    with jv.loop(bound=8, variant=jv.decreasing(lambda: len(cands))):
        if len(cands) == 1: break
        mid = cands[len(cands) // 2]
        e = jv.cut(jv.judge(jv.state(on=jv.do(bench, repo, mid), ctx=[base]), 慢了)[0], calib=jv.calib("perf.慢了"))
        match e:
            case jv.Act(): cands = cands[: cands.index(mid) + 1]
            case jv.Ignore(): cands = cands[cands.index(mid) + 1 :]
            case jv.Unsure(c): jv.handle(c, then=jv.escalate)
    return cands[0]
```

```python
@jv.program(budget=jv.Budget(calls=60, cost=0.02, layers=6))
def 生成并执行(目标, cwd):                                        # 9.7（v1.1 12 行）
    成功 = jv.test("退出码为 0 且输出符合目标描述吗？", calib="cmd.成功")
    史 = []
    for k in range(6):                                          # 有界：range 即 bound
        cmds = jv.gen("生成一条完成目标的 shell 命令", ctx=[目标, *史], n=4, retry_seq=k)
        outs = [jv.do(run, c, cwd) for c in cmds]                # 并发由调度 pass 决定
        exits = [jv.cut(jv.judge(jv.state(on=o, ctx=[目标]), 成功)[0], calib=jv.calib("cmd.成功")) for o in outs]
        if (对 := [c for c, e in zip(cmds, exits) if isinstance(e, jv.Act)]): return 对[0]
        史 += [c for c, e in zip(cmds, exits) if not isinstance(e, jv.Act)]
    return jv.escalate(史)
```

```python
def 生成到全绿(spec, repo):                                       # 9.11（v1.1 12 行）

            case jv.Unsure(c): jv.handle(c, regen=True, then=jv.escalate)
    match jv.cut(jv.judge(jv.state(on=报告), 全过)[0], calib=jv.calib("test.全过")):

        case _: return jv.escalate(报告)
```

```python
@jv.program(budget=jv.Budget(calls=40, cost=0.02, layers=20, escalate=1))
def 取物(目标, 场景):                                            # 9.13（v1.1 11 行）
```

```python
@jv.program(budget=jv.Budget(calls=500, cost=0.05, layers=1, escalate=20))
def 工单转部门(工单流, 部门表):                                    # G3-b（读者版 8 行）

    out = {}
    for t in 工单流:                                              # 纯映射：调度 pass 融合并发
        match jv.cut(jv.judge(jv.state(on=t, over=部门表), 去哪)[0], calib=jv.calib("ticket.去哪")):
            case jv.Pick(k): out[t] = 部门表[k]
            case jv.Unsure(c): out[t] = jv.ask(jv.state(on=t, over=部门表), 去哪)   # 转错能升级：ask 是效应
    jv.on_truth("ticket.去哪", lambda t, dept: dept)                # 事后发现转错 → 真值回填校准集（选型骨架）
    return out
```

## 7. 能做域表（更新 09 §8）

| 边界 | 加入物 | 它是哪种效应 | 量法 |
|---|---|---|---|
| 构造类、支持集外 | 生成器 | `gen` | 原来写不出的任务多少条能跑 |
| 抽取类 | **确定性枚举器**（正则、解析器、语法、k-子集、全配对） | `gen` 的零成本实现 | 宿主穷举 + Jev 选 vs LLM 抽取：召回与成本 |
| 字面化不足（运行时可见的错误） | 执行器；**求解器/检查器**（SAT/SMT、类型检查、linter、schema） | `do` | 字面化后 AUC；证明/反例覆盖的锁回归数 |
| 模态 | 渲染器（OCR、a11y、ASR、结构化抽取）；去主张渲染 | `do` | 模态锁回归数；带偏读数消除量 |
| 大规模关系（配对平方） | **检索器 / 嵌入聚类**召回层 | 宿主 + `do` | 同召回下配对数缩减倍数 |
| 推理深度（一跳） | **写推导的生成器**：多跳写成一串字面主张，逐跳判 | `gen` + `judge` | 逐跳 AUC 与整体一致率 |
| 稳定性 | 置换、重跑；**独立第二传感器**（另一判官或精确规则，分歧即 unsure） | `judge` | 翻转率随深度曲线 |
| 无校准就无出口 | 校准库；**延迟真值通道**（期限过了没、部署挂了没：免费标签）；人 | `ask` + 校准库 | 线的置信区间收窄速度；能做域 = 有校准记录的 (题, 域) 对 |
| 目的无关中间状态 | **跨程序读数缓存**（缓存键 §2.2） | 运行时 | 命中率随任务数上升 |
| 想象不出的东西 | **自举**：生成器写本语言程序（IR/构建器）→ 执行器跑探针 → Jev 判输出 → select | 全部四种 | 自动写出的程序通过探针的比例 |
| 时延、无增益 | 无 | | 域外 |

**为什么。** H §7 按 Jev 的八个限制逐条配加入物，比原表（只有生成器、执行器、人）完整；每一行都是 §2 里某种效应的实例，所以扩域不需要加 IR 形式，只需要加库与外部部件。增益用成本比公式量（H §13.1），不用 pass@k。

## 9. 建造顺序（取代 v3 §10 与 11 §12 的顺序）

1. IR 数据结构 + 检查器（J-01…J-15）+ Python 构建器，$0。
2. 解释器：沿用 `item/log/table/canon/ledger/eye/registry`，改造 `outlet`（三桥 + cause + 保形）、`calib`（五元键 + 字面化模式 + 四状态 + 漂移）、`view`（JSON 槽 + taint + derived_from）、`checker`（J 规则）；废弃 `beat/pack/arbiter`。
3. 编译 pass 六个，各带开关。
4. 用构建器重写 21 条程序（18 + G3），跑 E-ENOUGH、E14c。
5. 可运行级：`设计/E` §26.5 十条探针 + 压力应用「交付前文档自检」，每条记（调用、钱、秒、省掉的核对次数）对照裸调手写版。
6. 实跑消融：逐个关 pass 与运行时部件。
7. 校准库与飞轮：保形线、延迟真值、漂移监控、迁移报告。
8. 表面语法：无限期推迟。
