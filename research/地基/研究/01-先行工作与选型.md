## 1. 语义算子 / LLM 作谓词的数据系统

### 1.1 LOTUS（Stanford，TAG-Research → lotus-data）

论文原名《LOTUS: Enabling Semantic Queries with LLMs Over Tables》，后扩展改题为
《Semantic Operators: A Declarative Model for Rich, AI-based Data Processing》，
arXiv:2407.11418（v3，2025-03），已发表于 VLDB 2025（DOI 10.14778/3749646.3749685）。
官方仓库 github.com/lotus-data/lotus（原 TAG-Research/LOTUS），文档站
lotus-ai.readthedocs.io。(来源: https://arxiv.org/abs/2407.11418, https://github.com/lotus-data/lotus)

**算子集合**：sem_filter、sem_join、sem_topk、sem_agg、sem_group_by、sem_sim_join、
sem_search、sem_map、sem_extract。仓库比论文多出 sem_dedup、sem_partition_by、
sem_cluster_by 三个，论文和当前实现已经分叉。

**成本优化**：核心是代理模型加级联——小模型先给全体条目打分，基于采样学出的阈值
（论文 Algorithm 1）决定哪些条目要送大模型复判。某 join 场景实测减少 1000 倍 LLM
调用；不同任务组合下报告 3.6x/1.7x/17.4x 加速比。

**校准概率**：代理分数是模型输出 logprob 的原始重缩放值，**不是校准过的概率**。
论文给出的统计保证（γ_R/γ_P，置信度 1-δ）是相对"跑遍全部数据用大模型会得到的输出"
这个参照系的召回率/精确率下界，不是相对客观真值的校准声明；sem_agg 没有带保证的
近似版本。

**确定性重放**：未发现可重放/可审计机制。缓存（enable_cache，SQLite）是为省钱设计，
不是确定性保证——论文自己的实验方法论用 temperature 0.7、n=20 次试验衡量结果方差，
即作者也承认同一输入多次调用结果不同。

**已知失效点**：代理模型质量假设不总成立；sim-filter 依赖"相似度与判断结果相关"
的假设在部分谓词上不成立；长上下文靠分层 reduce 处理（是应对而非纰漏）；GitHub 有
两个实测 bug——推理模型 token 预算耗尽时 filter 结果被**静默默认为 True**（issue
#255、PR #260），以及级联要求模型输出单 token，在某些多 token 答案（如 col_A/col_B）
上失效。

### 1.2 Palimpzest（MIT）

原型论文 arXiv:2405.14696，官方仓库 github.com/mitdbg/palimpzest，文档站
palimpzest.org。(来源: https://arxiv.org/html/2405.14696v2, https://github.com/mitdbg/palimpzest)

**算子集合**：核心是关系代数加新算子 **convert**（Schema A → Schema B，缺失字段由
LLM 按自然语言 `desc` 生成），配传统 filter/groupby/aggregation/limit。当前发布版
重命名为 sem_map/sem_flat_map、sem_filter、sem_join、sem_agg、sem_topk。

**成本优化**：模型选择、代码合成替代 LLM 调用、多字段打包进单次 prompt、输入裁剪、
算子重排。论文明确说**级联未实现**（"This approach is not implemented in Palimpzest
yet"）。优化器用 3 个 sentinel plan 采样统计后，在 234–10140 个候选物理计划里估算
Pareto 前沿。实测：Legal Discovery 场景 90.3x 加速、9.1x 降本；Real Estate 场景
3.3x 快、2.9x 省且质量更好。

**校准概率**：原型用"champion model"（GPT-4 输出当伪真值）打分，属无监督非校准
方法。当前系统的 Validator 默认走 LLM judge 打 [0,1] 分（文档自陈"not always
accurate or faithful"），或用户自定义 score_fn。论文全文未出现 "calibration" 字样。

**确定性重放**：按 Dataset 名做跨程序缓存复用，但论文明确写"different physical
plans can yield results of different quality, so two runs of the same program
may yield different results"——**不保证跨计划确定性**。

**已知失效点**：论文自称采样算法"admittedly naive"，无严格终止判据；后续论文
Abacus 指出其代价模型无法建模算子间交互（如下游 filter 依赖上游 map 输出）；
GitHub 现存开放 issue：本地 vLLM 配图像语义过滤会挂起（#297）、sem_agg 生成失败
抛 TypeError（#300）。

### 1.3 ZenDB（UC Berkeley + Columbia）

需要先澄清一个容易搞混的点：ZenDB 不是 sem_filter/sem_map 那种算子代数系统，而是
**面向模板化文档集合的 SQL 分析系统**。论文《Querying Templatized Document
Collections with Large Language Models》，arXiv:2405.04674，ICDE 2025。未找到公开
代码仓库。(来源: https://arxiv.org/abs/2405.04674)

**核心设计**：用户声明"表名+描述"的 document table，属性可懒声明；DML 支持有限
的聚合和 LIKE（默认 Jaccard 阈值 0.9）。核心结构是 Semantic Hierarchical Tree
（SHT），配合谓词下推/重排、投影上拉，自顶向下定位相关节点再调 LLM。SHT 构建阶段
每种模板只调一次 LLM 做表头判别（GPT-4，200 篇文档实测 97% 准确），文档匹配到已知
模板后完全不再调用 LLM。实测成本约为逐文档调 LLM 基线的 3%–10%（10–32 倍降本）。

**校准概率**：未找到，全文检索 calibrat/confidence/probabilit 均无命中。它有的是
一个结构正确性的形式化定理（Theorem 1）：若文档满足其定义的"良构性"且 LLM 正确
判别表头，SHT 抽取保证恢复真实结构——这是结构层面的确定性证明，不是语义判断的
统计保证。

**确定性重放**：未找到缓存/可复现执行机制，相关但不同的机制是每条查询结果保留
来源文档片段供用户核实。

**已知失效点**：论文自陈需要处理"无模板或模板噪声很大"的文档，当前 SQL 查询空间
受限；v1 预印本承认属性抽取结果可能与谓词判断相互矛盾，并明确把这个不一致问题
列为超出本文范围。

### 1.4 DocETL（UC Berkeley + Columbia）

论文《DocETL: Agentic Query Rewriting and Evaluation for Complex Document
Processing》，arXiv:2410.12189，VLDB 2025。文档站 ucbepic.github.io/docetl。
(来源: https://arxiv.org/html/2410.12189v3, https://ucbepic.github.io/docetl/)

**算子集合**：核心 LLM 算子 Map、Reduce、Resolve（实体消歧）、Filter、Equijoin；
辅助非 LLM 算子 Split、Gather、Unnest。"Agentic rewriting" 用 13 条重写指令自动
分解算子：Split 指令把单个 Map 重写成 Split→Gather→Map→Reduce 处理长文档；
Gleaning 指令把 Map 变成"验证→改进"迭代循环。论文举例：法律合同 41 条款抽取
从单一 Map 被分解成 21 个独立 Map + Reduce。

**成本优化**：优化器用 gpt-4o-mini 生成/评估候选计划；按文档大小加权采样，Reduce
批大小在上下文窗口 20%-90% 间网格搜索。实测：法律合同任务优化阶段成本 $1.58，
F1 相比 LOTUS 基线提升 21.4%；总体计划比精调基线准确率高 25%-80%，但因分解出
更多 LLM 调用，执行成本会上升。未描述小模型到大模型的级联回退机制。

**校准概率**：不输出校准概率，是裸的正确性判断。用"验证代理"针对具体任务合成
评价标准，对样本打 1-4 分，再对 top-6 候选计划两两比较选优；正确性判定多用任务
特定的相似度阈值，未给出置信区间或校准概率。

**确定性重放**：官方文档明确默认缓存所有 LLM 调用结果，重跑未变更算子直接读缓存，
保证相同输入/配置下结果一致；可用 `docetl clear-cache` 清缓存或 `bypass_cache`
局部绕过。这是六个项目里**唯一明确宣称确定性重放（经由完整缓存）的系统**。

**已知失效点**：论文承认 LLM 非确定性加文本模糊性使最优解不可达，搜索空间无限
只能靠启发式；长文档场景即便优化过提示词，准确率仍随长度显著下降；Reduce 批大小
无原则性方法只能网格搜索；分解类重写会把 1 个 Map 拆成 21 个，显著推高调用数和
成本。

### 1.5 Evaporate（Stanford Hazy Research）

论文《Language Models Enable Simple Systems for Generating Structured Views of
Heterogeneous Data Lakes》，arXiv:2304.09433（2023），VLDB 2023。官方仓库
github.com/HazyResearch/evaporate。(来源: https://arxiv.org/abs/2304.09433)

**核心方法**：对比 EVAPORATE-DIRECT（逐文档调 LLM 抽取）与 EVAPORATE-CODE（LLM
只在约 10 篇样本上生成 Python 抽取函数，之后普通代码批量执行）。依据是半结构化
文档存在格式冗余，成本结构从"随文档数线性增长"变为"只在小样本阶段调 LLM"。

**成本优化**：EVAPORATE-CODE+ 在小样本上生成多个候选函数，用弱监督方法（依赖
Hazy Research 自家的 metal-evap / Snorkel MeTaL）聚合它们的输出而非只选一个。
16 个真实场景（每个约 1 万篇文档）上平均实现 **110 倍**的 LLM token 处理量下降，
单函数单文档运行时间约 0.00025 秒。

**校准概率**：对每个候选函数按覆盖率/一致性算分数，过滤低于 0.5 阈值的函数，
再用弱监督学出的 label model（参数化各函数准确率加函数间相关性）聚合剩余函数
输出，显式处理"弃权"情形——比纯投票更接近概率建模，但论文未用 "calibrated
probability" 这个表述。

**确定性重放**：函数生成完毕后对同一文档反复执行天然确定（普通代码执行）。论文
用这一点反衬 EVAPORATE-DIRECT 每次调 LLM 会遗漏/多出属性（实测平均遗漏 4.4 个
属性、多出 9.7 个虚构属性/值），但更多是论证性对比，未专门讨论"重放"这个工程
概念。

**已知失效点**：约 40% 生成函数准确率低于 25%，不同数据集"高质量函数占比"差异
很大（31%–91%）；方法假设文档间有格式冗余，对完全异构文档、属性命名不一致、
属性出现在非常规位置的场景效果明显下降。

### 1.6 2025–2026 后续工作

以下三篇已核实一手内容：

- **Abacus**（MIT CSAIL，Palimpzest 原班人马，PVLDB 2026，arXiv:2505.14661）——
  建在 Palimpzest 代码库上的新优化器，用置信区间（UCB/LCB）加多臂老虎机搜索物理
  算子实现，追踪质量-成本-延迟 Pareto 前沿。实测比第二名系统平均省 10.8x 成本、
  快 3.4x、质量提升 6.7%-39.4%。代价模型假设算子独立，论文承认无法建模算子间
  交互；序列化采样比 LOTUS 慢；依然不做校准概率，也不提供确定性重放机制。
  (来源: https://arxiv.org/abs/2505.14661)

- **PLOP**（UC Berkeley + Wisconsin-Madison，arXiv:2604.09944，2026-04）——用动态
  规划代价模型决定语义谓词在混合查询计划（关系算子加语义算子）里的放置位置：
  早放减少下游数据量但增加 LLM 调用，晚放反之。直接引用并复用了 Hellerstein &
  Stonebraker 的函数缓存概念（见第 3 节）。报告最高 1.5x 加速、4.29x 降本，F1
  保持 0.85。有函数级缓存但目标是省调用次数，不保证 LLM 跨调用结果一致；论文把
  剩余质量缺口归因于 LLM 本身的非确定性。(来源: https://arxiv.org/html/2604.09944v2)

- **SemStats**（清华大学，SIGMOD 2026）——专门解决"语义谓词没有直方图"的基数
  估计问题，见第 3.3 节详述。(来源: https://dbgroup.cs.tsinghua.edu.cn/ligl/papers/SIGMOD26-SemanticCE.pdf)

- **Query-Centric Optimization of AI Workflows via AQP and Proxy Models**
  （Georgia Tech + Adobe，arXiv:2607.00254，2026-06）——本次调研在"统计保证"上
  最直接的一篇：AQP 策略把 AI 流水线当在线聚合处理，渐进采样、维护带置信区间的
  running estimate、区间稳定后提前终止，实测省 20%-50% 的 oracle 调用量、准确率
  损失小于 5%；PM 策略用一个在少量标注上训练的**校准决策树代理**预过滤，只把
  不确定样本送大模型，reward-model 打分提速最高 19 倍、准确率损失小于 10%，且
  用固定随机种子保证结果可复现。这是这条研究线里唯一明确提到"校准"和"固定种子
  可复现"两个词的工作。(来源: https://arxiv.org/abs/2607.00254)

另有一批同期工作只核实了 arXiv 存在性、未逐篇核实一手内容，仅作存在性线索列出，
不建议直接引用其结论：Larch（arXiv:2606.07923）、SemJoin（arXiv:2606.29532）、
Sema（arXiv:2603.11622）、SEMA-SQL（arXiv:2604.23477）、Trummer 团队的语义 join
论文（arXiv:2510.08489）、OLLA（arXiv:2603.08443）、SemCEB（arXiv:2606.23081）。

### 1.7 与 Jev 设计的关键对比点

**校准概率是这条研究线的系统性空白。** 六个主要项目里没有一个做"校准过的
概率"——LOTUS 的代理分数是裸 logprob 重缩放；Palimpzest 用 LLM judge 或用户
自定义打分，文档自认"not always accurate"；DocETL 用 1-4 分的验证代理；ZenDB
只有结构正确性的形式化证明，没有语义层面的概率概念；Evaporate 用弱监督聚合，
是最接近"概率建模"的但不自称校准。唯一真正逼近校准的是最新的 GT/Adobe 论文，
但它是二值决策边界的校准（决策树代理），不是给每个判断都产出经过验证的置信度
数值。如果 Jev 的校准概率是真实做到的，这是整条产品线里目前没人做到的差异化点。

**"状态收费、问题免费"的成本结构在这条线里没有直接对应物。** 这些系统的成本
优化几乎全聚焦"减少调用次数、减少送进 LLM 的数据量"（代理模型、级联、缓存、
代码合成替代调用），核心假设仍是"每次判断本身有边际成本"。DocETL、Abacus、
PLOP 的代价模型都按 LLM 调用次数/token 数定价，没有一个系统把"同一状态内追加
问题几乎零边际成本"当作一等的成本假设去设计规划器。这个假设一旦成立，规划器
的目标函数和这条研究线的所有优化器都不同，需要在设计文档里主动澄清区别，否则
容易被按"减少调用次数"的框架误读。

**确定性重放上，DocETL 是唯一的正面案例。** LOTUS 论文自己用 temperature 0.7、
n=20 次重复测方差，等于承认结果不确定；Palimpzest 论文原话"two runs of the
same program may yield different results"；只有 DocETL 把"缓存全部 LLM 调用、
重跑读缓存"做成显式产品特性。如果 Jev 想主张"确定性重放"是设计原则而非事后
缓存，需要讲清楚这是"缓存同一状态加问题组合的结果"（工程层面的可重放），还是
"模型本身在给定输入下总给出相同校准概率"（更强的主张，目前没有任何被调研系统
敢做这个声明）。

**"一跳、看字面"与"级联/agentic 分解"是两种应对同一问题的不同思路。** DocETL
用 agentic rewriting 把复杂判断拆成多步 LLM 调用链（Map→Reduce、验证→改进
循环），本质是用更多次调用逼近多跳推理；LOTUS/Abacus/PLOP 用级联逼近"用大模型
才能做对的判断"。Jev 把自己限定在一跳字面判断，把多跳推理下放给语言层的递归
函数（切片 → 筛证据/语境 → 拼小状态 → 再问），相当于把 DocETL 式的 agentic
分解从系统内部黑箱优化器的决策，变成语言层面的显式递归结构。这个位置的差异
值得在设计文档里明确对照 DocETL 的 agentic rewriting 一节。

## 2. Datalog / 逻辑引擎

### 2.1 工程 Datalog：半朴素求值与分层否定

**Soufflé** 面向静态分析场景优化，把 Datalog 规则翻译成 C++ 而不是解释执行。
半朴素求值用标准三关系模式：每个关系维护 `full`（到当前迭代为止的全部事实）、
`delta`（上一轮新增的事实）、`new`（本轮新增的事实）三个版本，规则体只用
`delta` 版本去匹配依赖前一轮新知识的位置，避免重复推导。分层做法是先建关系间
的依赖图，取每个强连通分量（SCC）作为一层，按拓扑序逐层跑不动点。分层否定的
规则：被否定的关系不能出现在包含当前规则头的 SCC 里，不允许递归否定。没有任何
三值逻辑或概率扩展的迹象，唯一相关的扩展是 subsumption（某些事实可以被更强的
事实覆盖）和 Choice construct，都是确定性机制。
(来源: https://souffle-lang.github.io/rules, https://souffle-lang.github.io/pdf/toplas20.pdf, https://souffle-lang.github.io/pdf/ppdp21incremental.pdf)

**DDlog / Differential Datalog**（已归档）把 Datalog 规则编译成 Frank McSherry
的 Differential Dataflow 程序，面向持续变化的输入流做增量执行，而非批量半朴素。
分层否定通过 antijoin 算子实现：否定项被编译成对被否定关系的反连接。类型系统
丰富但没有概率或三值逻辑扩展，纯粹的确定性增量计算语言。
(来源: http://budiu.info/work/ddlog.pdf, https://github.com/vmware/differential-datalog)

**Datafrog** 是刻意做得没有运行时的最小 Datalog 引擎，半朴素求值靠 `Relation`
（静态排序元组集合）和 `Variable`（单调递增元组集合）两个类型抽象，由程序员
手写迭代循环驱动，不做自动分层调度——分层否定的正确性完全靠程序员手写的迭代
顺序保证。最著名的应用是 rustc 的 Polonius 借用检查器。
(来源: https://github.com/rust-lang/datafrog, https://docs.rs/datafrog/latest/datafrog/)

**Ascent** 用 Rust 过程宏把 Datalog 嵌入 Rust，编译期生成半朴素求值代码，分层
机制与 Soufflé/DDlog 一致（依赖图 → SCC → 拓扑序）。最值得注意的机制是
**lattice**：除了普通 `relation`，`lattice` 声明允许同一 key 上的新事实与旧值
用用户定义的 `join` 操作合并（而非简单去重存入集合），把 Datalog 从"集合上的
最小不动点"推广到"任意有界格上的最小不动点"（如最短路径取 min）。这是四个
系统里离"非布尔事实值"最近的机制，但格上的 join 是用户手写的确定性代数运算，
不是概率合并。
(来源: https://github.com/s-arash/ascent, https://thomas.gilray.org/pdf/seamless-deductive.pdf)

四个工程系统的共同结论：半朴素求值的三分结构（full/delta/new）和分层否定的
依赖图分析，与"标签是布尔值还是概率"完全正交，是可以直接借用的通用机制。

### 2.2 ProbLog

把 Prolog/Datalog 扩展为一部分事实标注概率（`p::fact`），规则本身保持普通语法。
语义基础是 Sato 的 distribution semantics：每个 ground 概率事实对应一次独立的
原子选择，一次对所有概率事实的选择按乘积得到该组合的概率，规则从选中的事实
推导出一个可能世界，全体可能世界的概率之和为 1。查询的多条证明往往不互斥，
直接对证明的析取式求概率是 #P-hard 的"disjoint-sum-problem"。ProbLog1 用二叉
判定图（BDD）解决：把全部证明表示成 DNF 布尔公式，编译成 BDD 后按变量真假概率
自底向上加权求和。ProbLog2 把程序转换为带权 CNF，编译到 d-DNNF 或 SDD，用知识
编译把边际概率、最大后验解释、参数学习统一到带权模型计数这一个问题上。
annotated disjunction 允许一条规则体成立时，从多个互斥候选头里按各自概率选一个
成立。已知限制：全量 grounding 通常不可行，必须按查询/证据做相关性裁剪；
disjoint-sum-problem 本身是 #P-hard，知识编译只是让其在实践中可扩展。
(来源: https://dtai.cs.kuleuven.be/problog/, https://ar5iv.labs.arxiv.org/html/1006.4442, https://lirias.kuleuven.be/retrieve/b0fd5460-1d90-45e8-bc6c-864836156116)

### 2.3 Scallop

**概率标签的表示**：用 `[PROB]::[TUPLE]` 语法直接给事实打概率标签，分号分隔的
多个带概率候选事实互斥（对应"神经网络输出一个 one-hot/softmax 分布"的场景）。
规则与普通 Datalog 一致（支持递归、否定、聚合），概率标签沿关系代数运算自动
传播。

**核心机制——provenance semiring 框架**：把"标签怎么传播"抽象成 7 元组
`(T, 0, 1, ⊕, ⊗, ⊖, ≐)`——标签空间、加法/乘法单位元、二元析取（对应逻辑或/
关系并）、二元合取（对应逻辑与/关系连接）、一元取反（对应否定）、以及不动点
饱和检查。要求 `(T,0,1,⊕,⊗)` 构成吸收半环（`t1 ⊕ (t1⊗t2) = t1`，保证递归
不动点存在）。不同 provenance 实例对应不同推理模式：`max-min-prob` 用
`[0,1]` 配 `max`/`min` 做概率近似（论文明确说"标签不是真实概率，只是近似"）；
`diff-top-k-proofs`（默认推荐配置）用"最多保留 k 条合取子句"的 DNF 布尔公式做
带权模型计数，k 取到 2 的输入事实数次方以上时退化为精确概率推理，但 WMC 是
#P-complete，k 越大运行时指数级增长，实践中 k=3 是折中点。

**聚合算子在概率语义下的定义（multi-world semantics）**：n 个带标签元组构成
2ⁿ 个可能世界，每个世界内先用普通离散聚合算出结果，再按各世界的标签权重合并。
朴素实现指数级，但针对特定"聚合算子 × provenance"组合可以给出多项式算法（如
count 在 max-min-prob 下有 O(n log n) 算法）。聚合语法统一支持
count/sum/prod/min/max/argmin/argmax/exists/forall，聚合和否定一样必须分层。

**可微分机制**：把每个概率标签替换成对偶数，⊕/⊗/⊖ 在对偶数上的定义使整个
Datalog 程序执行天然构成前向自动微分的计算图，训练时把最终结果的梯度反传到
每个输入事实的概率。这部分服务于训练上游神经网络参数，与 Jev 无关。

**已知局限**：dtkp 的运行时随 k 指数增长；mmp/dmmp 给出的"概率"是近似值，
不满足真实概率公理；论文摘要明确承认这套系统"asymptotically reduces
computational cost, and provides *relative* accuracy guarantees"——放弃精确
概率语义换取可扩展性，只保证相对意义上的精度保证而非绝对误差界；全量 grounding
在大规模场景下不可行。
(来源: https://doi.org/10.1145/3591280, https://www.cis.upenn.edu/~mhnaik/papers/pldi23.pdf, https://scallop-lang.github.io/, https://www.scallop-lang.org/doc/probabilistic/aggregation.html)

### 2.4 对 Jev 判断语义设计的启发

半朴素求值的三分结构与分层否定的依赖图分析可以原样搬用，与标签语义无关——
Jev 规划器"分层执行，能挤进同一层的判断挤进同一层"，本质就是先建判断间依赖
图、取 SCC、按拓扑序分层，这套算法四个系统做法完全一致。

Scallop 的 provenance semiring 接口把"标签怎么代数化传播"和"关系代数怎么跑"
彻底解耦，这个解耦模式本身值得借用：只要标签满足半环加吸收律，过滤、配对、
聚合、递归这套算子就能统一实现一遍，标签语义可以换（布尔、区间数或别的）。
它的 multi-world 聚合语义——枚举开关子集、每个子集算一次离散聚合、按子集权重
合并，以及"朴素指数但对特定算子可做多项式特化"这个降复杂度模式，对"一批带
概率标签的判断经过聚合"这一步有直接参考价值。

明显不适用之处：Scallop/ProbLog 的概率来自一次性给定、可反复查询的事实表或
训练好的、部署后权重固定的神经网络输出，推理时可以对同一批概率反复做代数
运算、做不动点迭代。Jev 的判断概率来自每次现场调用 LLM，调用有成本、有延迟、
不可重复查询、且明确不做算术——Scallop 那种"标签在 ⊕/⊗ 下反复代数组合"的
假设不成立，每个概率标签更接近一次性观测值，而非可以无限次参与代数运算的
稳定权重。半环框架要求的结合律、交换律、分配律、吸收律在"概率来自现场 LLM
调用"的场景下未必成立，生搬这套代数接口有过度形式化的风险。可微分机制完全
不适用，Jev 没有需要梯度反传的可训练参数。分层否定的"不能递归穿过否定"这条
规则也需要重新定义：Soufflé/DDlog/Ascent 的否定是"关系里没有这个元组"的布尔
判断；如果 Jev 里"某判断为假"本身是一个带概率的一跳字面判断，否定算子在半环
意义下该如何定义（⊖ 的语义）就不能直接照搬 Scallop 的 `1-p`，这需要 Jev 自己
定义，不是已解决问题。

## 3. 查询优化

### 3.1 连接顺序优化

核心论文是 Selinger 等人 1979 年的 System R 优化器论文《Access Path Selection
in a Relational Database Management System》。(来源: https://courses.cs.duke.edu/compsci516/cps216/spring03/papers/selinger-etal-1979.pdf,
DOI: 10.1145/582095.582099) n 个表朴素枚举有 n! 种连接顺序，但优化器不需要
穷举：n 个表连接的结果基数与连接顺序无关，但代价可以天差地别；利用最优子结构
剪枝——一旦前 k 个表已连接，把复合结果连到第 k+1 个表的最优方法与前 k 个表
连接的顺序无关。这句话是动态规划能生效的根本原因：按子集大小逐层构建"最优子
解"表，把搜索空间从阶乘降到 2ⁿ 量级。选择率估算有一套默认公式表（等值谓词、
范围谓词、AND/OR/NOT 组合各有公式），连接代价的关键输入是已连接子集的基数
乘积乘以已施加谓词的选择率乘积——这套"选择率连乘决定中间结果基数、中间结果
基数决定后续代价"的链条，是连接顺序影响巨大的机制解释。Chaudhuri & Shim《Optimization
of Queries with User-Defined Predicates》（VLDB 1996）把这套思想扩展到用户
自定义函数谓词，直接接到第 3.3 节的昂贵谓词优化。
(来源: https://www.vldb.org/conf/1996/P087.PDF)

### 3.2 自适应查询处理

Avnur & Hellerstein《Eddies: Continuously Adaptive Query Processing》
（SIGMOD 2000）是这条线的原点。(来源: https://dsf.berkeley.edu/cs286/papers/eddies-sigmod2000.pdf,
DOI: 10.1145/335191.335420) 核心设计是把路由决策做成一个独立的运行时算子——
eddy，插在数据源和一组算子之间，逐元组决定它接下来该被送去哪个算子处理，而
不是在编译期把算子顺序定死进静态计划树，"merging the optimization and
execution phases of query processing"。支撑这个设计能安全重排的关键概念是
"对称时刻"（moment of symmetry）与同步屏障：像 pipelined hash join 这类算法
内部状态达到某个特定点之前，重排输入顺序不破坏正确性也不需要重算状态，这类
算法才适合被 eddy 自由路由。动机是选择率会随运行时数据分布漂移而变化，传统
"先估计、定计划、再执行"的架构对这种漂移毫无适应能力。

现代系统最直接的后继是 Spark SQL 的 Adaptive Query Execution（AQE，自 Spark
3.2.0 起默认开启），官方定义为"利用运行时统计信息选择最高效的查询执行计划，
在查询执行过程中重新优化计划"。(来源: https://spark.apache.org/docs/latest/sql-performance-tuning.html)
但 AQE 和 Eddies 哲学不同：AQE 在 shuffle 边界这种粗粒度的"阶段边界"上重新
规划（根据实测表大小切换 join 策略、合并过多分区、拆分倾斜分区），而不是像
Eddies 那样逐元组细粒度路由——这个"在物化边界重新决策，而非逐条数据决策"的
折中，对 Jev 规划器设计很关键（见 3.4）。

### 3.3 昂贵谓词的基数/代价估计

奠基论文是 Hellerstein & Stonebraker《Predicate Migration: Optimizing Queries
with Expensive Predicates》（SIGMOD 1993）。(来源: https://dsf.berkeley.edu/papers/sigmod93-predmig.pdf,
DOI: 10.1145/170035.170078) 传统谓词下推假设限制操作零成本，但限制条件是用户
定义函数（可能耗费大量 CPU/IO）时，盲目下推可能是错的，应考虑谓词上拉。论文
证明最优排序由一个源自 W. E. Smith 1956 年作业调度结果的简单排序引理给出：
`rank = (选择率 − 1) / 单次代价`，单表内部的限制谓词按 rank 升序排列即最优，
直觉是优先执行选择率低、单次代价低的谓词，尽早减少后续更贵谓词要处理的元组数。
另一个关键机制是函数缓存：按参数值缓存谓词结果，使谓词上拉到连接之上后不因
连接放大元组数而重复付费。

2025–2026 出现了两条直接针对 LLM 语义算子的延伸：

**PLOP**（第 1.6 节已提及）直接引用并复用了函数缓存概念，证明"把所有语义
过滤器上拉到连接之上加函数缓存"能最小化 LLM 调用总次数，但可能让关系代数
处理的中间结果爆炸，因此用动态规划代价模型在 LLM 调用成本与关系处理成本间
找加权和最优的放置点。(来源: https://arxiv.org/html/2604.09944v2)

**SemStats**（清华大学，《Bridging the Gap: Cardinality Estimation for
Semantic Queries on Unstructured Data》，SIGMOD 2026）专门解决"语义谓词没有
直方图"的问题：离线阶段用轻量模型（非 LLM）构建"语义目录"（核心语义维度）和
"语义索引"（数据点到目录的关联），把最贵的 LLM 标注成本移到构建期且用便宜模型
完成；在线估计时用语义索引引导的分层重要性采样加轻量判别模型精修，而非对全体
数据均匀采样（均匀采样在低选择率查询上会因命中样本太少产生灾难性误差）。相比
基线报告误差最多降低 25 倍、延迟最多降低 31 倍。
(来源: https://dbgroup.cs.tsinghua.edu.cn/ligl/papers/SIGMOD26-SemanticCE.pdf)

另外 **Abacus**（第 1.6 节已提及）用少量验证样本加先验信念估计每个语义算子的
质量/代价/延迟表现，在给定预算约束下搜索最优物理实现，这条线更偏"给定谓词
选实现方式"而非"估计谓词选择率"，但与成本模型高度相关。
(来源: https://arxiv.org/abs/2505.14661)

### 3.4 对 Jev 规划器设计的启发

Eddies 的运行时自适应路由思想和"层是编译期静态展开、执行期动态收缩"的设计
不是同一个粒度，但方向一致，可以理解为 Eddies 的一个受限版本。Eddies 逐元组
路由的前提是算子间存在对称时刻——重排不破坏正确性且不需要重算状态。Jev 的
判断调用天然满足这个条件更强：大多数判断是无状态的一元函数调用，不像 join
算子那样有内部缓冲和游标状态，重排的安全性证明比 Eddies 处理的那些有状态
连接算法更容易成立。这意味着理论上可以比传统 AQE 做得更细粒度，不必等到
"shuffle 边界"才重新决策。但这也正是 AQE 的教训：Spark 选择在物化点而非逐
元组重新规划，是因为运行时统计的收集和决策本身有开销，细粒度到每条数据反而
不划算。Jev 的"层"天然是一个物化点（一次网络往返产出的结果集合），这与 AQE
的粒度选择吻合度更高——建议把层边界当作重新优化的天然锚点，而非追求 Eddies
式的逐元组路由。

Predicate Migration 的 `rank = (选择率 − 1) / 代价` 排序原则可以直接套用到
"先问一元判断、再问二元关系判断"这个直觉上，且能给出比直觉更精确的判据：不是
简单地"先便宜后贵"，而是同时权衡选择率——一个略贵但选择率极低的一元判断，
可能比一个便宜但选择率接近 1（几乎不过滤任何数据）的判断更值得先问，因为它
能更快压缩后续需要处理的数据量。二元关系判断的代价通常与两个实体的笛卡尔积
规模成正比，这和经典 join 代价的结构完全同构，意味着"先问一元过滤、再做实体
配对、最后问二元判断"这个顺序在多数情况下确实是 rank 排序的自然推论，但如果
某个一元判断选择率其实很低（接近 1，几乎不过滤），而某个二元判断虽然要问的
次数多、选择率却极低，rank 公式会建议反过来——PLOP 论文已经证明纯粹"先过滤
后连接"的启发式并不总是全局最优。

Jev 的成本模型"材料收费、问题几乎免费"与经典优化器的成本模型有一个本质
错位：经典模型里代价和选择率是两个独立但都难估的量，Jev 的代价几乎只取决于
"要不要读材料"这一个二元开关，选择率才是真正的未知数。这让 SemStats 的思路
特别值得借鉴：与其对每个新谓词都做代价高昂的在线采样，不如维护一个离线构建的
"语义目录/索引"（用免费的问题标注一批代表性数据，构建可复用的判断-数据关联
结构），在线阶段用这个索引做分层重要性采样估计选择率，把最贵的一次性构建成本
摊到多次查询规划上——这与 Predicate Migration 的函数缓存在效果上同构，都是
把重复付费改造成一次性付费、多次复用。

## 4. 信息论选题与不确定性采样

### 4.1 mRMR（最大相关最小冗余）

Peng, Long, Ding，《Feature Selection Based on Mutual Information Criteria
of Max-Dependency, Max-Relevance, and Min-Redundancy》，IEEE TPAMI 2005。
(来源: http://home.penglab.com/papersall/docpdf/2005_TPAMI_FeaSel.pdf, DOI: 10.1109/tpami.2005.159)

目标函数三层递进：Max-Dependency（式，特征全集与类别的联合互信息，需要估计
高维联合密度，作者承认样本不够时协方差矩阵求逆病态、实际不可行）→
Max-Relevance（式4，单变量互信息的均值近似，回避联合密度估计，但容易选出
彼此高度冗余的特征）→ Min-Redundancy（式5，已选特征两两互信息均值）→
mRMR 组合准则（式6，Φ(D,R) = D − R，最大化 Φ）→ 贪心增量选择（式7，每步从
剩余候选里选一个使 `I(x_j;c) − 已选特征互信息均值` 最大的特征加入，复杂度
O(|S|·M)）。核心定理证明：一阶增量选择下 mRMR 等价于 Max-Dependency，但这个
等价性**只对"序贯地、每步固定已选特征去加一个新特征"这个过程成立**，不是
证明选出的子集在所有可能子集里目标函数值最优——论文原文明确用"first-order"
限定词。论文自己承认局限：mRMR 是 filter 方法不直接优化分类误差，实用流程是
两阶段算法（先 mRMR 粗选候选集，再用 wrapper 对分类器实测误差精筛）；连续
变量的互信息估计要么离散化预处理，要么用 Parzen 窗核密度估计，可靠性依赖足够
大的样本量。

### 4.2 主动学习的不确定性采样

Burr Settles，《Active Learning Literature Survey》，UW-Madison TR1648
（第 3.1 节）；Lewis & Gale，《A Sequential Algorithm for Training Text
Classifiers》，SIGIR 1994。
(来源: https://burrsettles.com/pub/settles.activelearning.pdf, https://arxiv.org/abs/cmp-lg/9407020)

三种量化方式：Least Confident（`1 − 模型给出的最高后验概率`，只看最可能标签，
"throws away" 剩余标签分布的信息）；Margin Sampling（第一高与第二高后验概率
之差，纠正 LC 的缺陷，但类别很多时仍忽略大部分输出分布）；Entropy Sampling
（对全部标签的后验分布求熵）。三者在二分类下等价，都等价于查询后验最接近 0.5
的实例。Lewis & Gale 原论文实测：这个方法把训练一个统计分类器所需的人工标注
量减少了最多 500 倍。

**与 mRMR 的本质区别**：不确定性采样解决"该挑哪一个未标注实例送去人工打
标签"，判据来自"一个已用部分数据训练出的模型对这个具体实例的预测有多不
确定"——序贯的、依赖当前模型状态。mRMR 解决"该保留哪些维度/特征"，判据是
特征与目标的统计关联和特征间冗余，是静态的一次性打分，不依赖模型预测置信度。
一个选样本，一个选特征，优化对象空间完全不同。

### 4.3 信息增益 / 决策树 / 二十问

Quinlan，《Induction of Decision Trees》，Machine Learning 1986（ID3 原始
论文）；Hyafil & Rivest，《Constructing Optimal Binary Decision Trees is
NP-Complete》，Information Processing Letters 1976。
(来源: https://trhvidsten.com/docs/classics/Quinlan-1986.pdf, https://people.csail.mit.edu/rivest/pubs/HR76.pdf)

ID3 用集合的期望信息量 I(p,n)（即熵）定义属性 A 的信息增益
`gain(A) = I(p,n) − E(A)`，E(A) 是按属性 A 划分后各分支期望信息的加权平均。
每一步选 gain 最大的属性，递归地对划分出的子集重复这个过程。论文脚注 3 明确
承认：由于 I(p,n) 对所有属性都是常数，最大化 gain 等价于最小化 E(A)，即
**gain(A) 本质上就是属性 A 与类别标签的互信息 I(A;class)**——与 mRMR 用的
是同一个数学对象，但用法不同：mRMR 是对一批候选变量一次性或增量式计算相关性
和冗余度后挑子集；ID3 是逐层、条件化于已选属性的递归过程，每一层的 gain 是
在当前节点的局部子样本上重新计算的条件统计量，不是全局统计量。论文自己称之为
"a good rule of thumb"，没有给出全局最优性证明——是贪心、局部、逐层递归的
启发式。

Hyafil & Rivest 证明构造期望提问次数最少的最优决策树是 NP-完全问题。这意味着
贪心逐步选当前信息增益最大的问题不保证全局期望提问次数最少；当候选问题之间
存在强相关/交互效应时（典型是 XOR 式组合：单独看每个属性边际信息增益接近零，
但两个属性联合起来能完美区分类别），贪心的单变量 gain 计算会对这类属性一视
同仁地打低分，从而选不到真正有效的组合。这与"二十问"/Huffman 编码的区别在于：
后者假设问题本身可以任意设计，针对已知分布量身定制最优二分；决策树面对的是
候选问题（属性）是给定的、有限的集合，只能从这个集合里挑，还要面对属性间
统计关联导致的组合效应——这正是它比纯粹信源编码问题更难、被证明 NP-完全的
原因。

### 4.4 能否直接用于筛选 Jev 候选谓词

**mRMR 不能直接套公式，样本量前提不成立，但目标函数的形状可以借鉴。** mRMR
的互信息估计默认前提是每个变量在足够多样本上都有观测。论文实验里样本量最
紧张的数据集（NCI，60 个样本、9703 个特征）用 Leave-One-Out 交叉验证，已经
是作者处理"样本远少于特征数"场景的极限退化方案，仍有 60 个样本可用。Jev 的
场景更极端：每个候选谓词可能只在几份材料上问过几次，样本量比 mRMR 论文最
紧张的场景还小一个量级以上，用最大似然频率估计互信息在小样本下有已知的正向
偏差。能借鉴的是目标函数结构（单变量统计量度量相关性、两两统计量度量冗余、
两者相减或加权组合来权衡），不能照搬互信息的具体估计公式——工程上大概率需要
退化为方差更小的代理统计量（比如用少量样本上答案分布的极端程度代替熵、用
简单一致率代替两两互信息），或规定候选谓词必须先在数量足够的共享样本上统一
测过一遍，把"样本不够"这个问题挪到流程更早的阶段解决。这里有一个需要与红队
意见对照的张力：mRMR 的 relevance 项 I(x;c) 本身就要求条件于目标标签 c 计算，
这与"熵筛不该无监督地做、否则会在稀有目标上砍掉唯一有用的谓词"这类顾虑方向
一致——mRMR 的公式本身已经蕴含了"必须相对目标算相关性，不能只看候选问题自身
的边际熵"这条原则。

**决策树的条件化增量顺序对"分层"设计有实质启发，且是静态版 mRMR 没有的。**
ID3 的信息增益是在当前节点的局部子样本上重新计算的条件统计量，样本本身被
已选属性切分；mRMR 的增量搜索虽然也是序贯选择，但每步用的互信息是在全体
样本上算出的边际量，并未随"已选特征"重新分组。这提示如果 Jev 的谓词筛选要
设计"层"，第二层及以后该看的是"在第一层谓词已经问出答案、样本被它的答案分流
之后，条件熵/条件相关性还剩多少"，而不是拿分流之前算好的边际统计量去挑后续
层的谓词——只用边际统计量选多层，会重复 mRMR 定理"仅一阶等价"的局限，并且
会漏掉类似 XOR 的组合信息。但也要留意代价：子集越分越小，层数一深，条件统计量
需要的样本量问题会比第一层更严重，与上一段的样本量紧张问题叠加。

**不确定性采样更适合用在"该把哪份材料送去问 Jev"，不是"该问哪个候选谓词"。**
它的输入是模型对某个具体实例预测置信度，天然对应"这份材料现在测起来含糊，
值得多花一次 Jev 调用去问细、或优先纳入下一轮取样"，而不是"这个问题本身有没
有区分度"（后者是 mRMR/信息增益管的范畴）。这两者应该在流程里互补而非互相
替代，分别对应"选材料"和"选谓词"两个独立子问题——用同一套统计量处理两者，
会混淆"样本不确定性"和"特征信息量"这两个不同维度的概念。

## 5. 三值逻辑

### 5.1 Kleene 三值逻辑

Stanford Encyclopedia of Philosophy，"Many-Valued Logic" 词条，2.2 节。
(来源: https://plato.stanford.edu/entries/logic-manyvalued/)

Kleene（1938, 1952）用三元集合 {0, ½, 1}（false / unknown / true）替换经典
二值集合，构成三元 Kleene 代数 K₃。真值表：∧ = min，∨ = max，¬ = 1−x。由此
得到"吸收规律"——unknown AND false = false（0∧½=0，一旦有一个分支确定为假，
整体就是假）、unknown OR true = true（½∨1=1）；以及"传播规律"——unknown AND
true = unknown、unknown OR false = unknown。**强 Kleene（K₃）与弱 Kleene
（Bochvar/B₃）的区别**：弱 Kleene 把第三值解释为"无意义/junk"值，只要任一
分支取该值，∧ 和 ∨ 结果都强制为该值，不允许确定值盖过未知值；强 Kleene 允许
确定值盖过未知值（吸收），弱 Kleene 里未知会无条件污染整个表达式。**量词**：
Mostowski（1961）的格论语义把全称量词解释为下确界（min）、存在量词解释为
上确界（max）——与命题层面的强 Kleene AND/OR 完全一致，是二元 ∧/∨ 向任意
多个分支的自然推广。

### 5.2 SQL NULL 的教训

PostgreSQL 官方文档明确写道 SQL 用三值逻辑系统，NULL 代表 unknown，真值表与
强 Kleene 完全同构。(来源: https://www.postgresql.org/docs/current/functions-logical.html)

**教训一：同一套三值逻辑在 WHERE 和 CHECK 里被打成方向相反的两值。** 官方
文档在 WHERE 子句一节明确规定"if the result of the condition is true, the
row is kept...otherwise (i.e., if the result is false or null) it is
discarded"——unknown 在 WHERE 里被当假处理，行被过滤掉。(来源: https://www.postgresql.org/docs/current/queries-table-expressions.html)
而 CHECK 约束一节明确规定"a check constraint is satisfied if the check
expression evaluates to true **or the null value**"——unknown 在 CHECK 里
被当真/通过处理，脏数据反而放行。(来源: https://www.postgresql.org/docs/current/ddl-constraints.html)
同一个三值结果，在两个不同算子上下文里被静默映射成方向相反的布尔语义，且没有
任何语法标志提醒使用者切换了哪种映射。

**教训二：NOT IN 遇到 NULL 会让整个查询消失。** 官方文档："if the left-hand
expression yields null, or if there are no equal right-hand values and at
least one right-hand expression yields null, the result of the NOT IN
construct will be null, not true as one might naively expect."(来源: https://www.postgresql.org/docs/current/functions-comparisons.html)
这是三值语义与 De Morgan 变换在 NULL 面前不再等价的经典陷阱。

**教训三：聚合函数对 NULL 的处理彼此不一致。** 官方文档："sum of no rows
returns null, not zero as one might expect."(来源: https://www.postgresql.org/docs/current/functions-aggregate.html)
COUNT 对空集返回 0，SUM/AVG/MAX/MIN 对空集返回 NULL——同一"没有数据"的情形，
不同聚合函数给出互不一致、需要用户逐个记忆的默认值。C.J. Date 在多部著作及
ACM SIGMOD Record 上主张 NULL 破坏了关系模型基础，因为域按定义是纯值集合，
NULL 混入后关系代数的等价变换不再普遍成立；Claude Rubinson 2007 年反驳 Date
举的具体例子，但仍认同"NULL 与三值逻辑给看似直白的查询引入了惊人复杂度"这一
结论。(来源: Rubinson, ACM SIGMOD Record 36(4), 2007, DOI: 10.1145/1361348.1361350；
Date 的回应, ACM SIGMOD Record 37(3), 2008, DOI: 10.1145/1462571.1462574)

### 5.3 对 Jev 算子库设计的警示

强 Kleene 语义可以直接套用到 filter 和 aggregate 算子上，因为语义结构完全
同构。filter 逐条判断应保持三值输出，不做二值化；filter 条件是多个子判断的
合取时，严格用强 Kleene 的 ∧ 真值表——一个子判断确定为假，整体就是假（吸收），
不因另一个子判断 unsure 而升级，但没有子判断为假且至少一个 unsure 时，整体
必须是 unsure（传播），不能因其余子判断都真就悄悄放行。对 aggregate 的存在
量词（"是否存在一个片段满足 P"）应取所有片段判断结果的上确界（max）：有一个
片段确定为真，整体就是真，哪怕其余都 unsure；只有没有片段为真且至少一个
unsure 时才是 unsure；全部确定为假才是假。全称量词（"是否所有片段都满足 P"）
取下确界（min），对称地定义。这是强 Kleene（而非弱 Kleene）的正确用法：Jev
需要"确定值能盖过未知值"的吸收行为，弱 Kleene 那种"沾了不确定就整体作废"的
污染式传播会导致大量本可以给出确定答案的聚合被不必要地升级为 unsure，浪费
人工审核成本。

SQL 三十年的坑给出的具体警示：Jev 的算子库必须在以下几处把"遇到 unsure 时
怎么办"写进算子签名或返回类型，而不是靠文档一句话带过——(1) 每一个把三值
判断结果落地成程序控制流分支的算子（相当于 WHERE），必须显式声明对 unsure
的处理策略（过滤、升级给人、报错），不能有默认的隐式降级；(2) filter 与
aggregate 必须分别锁定语义，aggregate 的全称/存在语义要在类型签名或文档里
显式写清 unsure 的含义，不能像 SQL 的 COUNT 和 SUM 对空集分别返回 0 和
NULL 那样让不同聚合算子给出互不一致的默认值；(3) NOT/取反算子对 unsure 的
行为要单独声明——强 Kleene 里 ¬unsure = unsure，不能被想当然地推导为"不是
真就是假"；(4) 任何把三值结果压缩为二值供下游系统消费的出口，必须是显式、
命名清楚、且强制要求处理 unsure 分支的转换算子，不能允许隐式截断的路径存在。
SQL 的坑几乎都源于三值到二值的转换点太多、太隐蔽、太不一致。

## 6. 黑板系统与 Subsumption

Hearsay-II（Erman, Hayes-Roth, Lesser, Reddy，《The Hearsay-II
Speech-Understanding System》，ACM Computing Surveys 1980）的核心机制是多个
独立的知识源模块不互相直接通信，而是共享一块分层的公开黑板数据结构，每个
模块读取当前已有的部分假设、做出自己的贡献，由 focus-of-control 机制调度
下一个该被激活的知识源，机会主义地逐步累积构造出完整解释。
(来源: DOI: 10.1145/356810.356816) Brooks 的 subsumption architecture
（《A Robust Layered Control System for a Mobile Robot》，1986）是另一种
协作结构：多层异步控制模块各自独立运作，高层可以抑制低层的输出信号接管
控制权，低层即使被盖过依然继续独立运行。(来源: https://people.csail.mit.edu/brooks/papers/AIM-864.pdf)
两者与本设计"判断结果本身也是数据、可以被再判断"共享同一个核心机制：把中间
结果提升为一等公民，放进所有模块都能读写的公共空间，而不是隐藏在某个模块
内部的私有状态里——判断产出数据、数据被再判断的迭代式累积，是同一个设计
模式在不同领域的重现。

## 8. 本设计与所有先行工作的真正差异

以下每条都要求在上文六节里能找到对应的一手证据支撑，不写没有证据的差异。

**校准概率是六个语义算子系统的共同空白。** 第 1.7 节列出的六个主要项目（LOTUS、
Palimpzest、ZenDB、DocETL、Evaporate 加 Abacus/PLOP）没有一个做逐判断的校准
概率——最接近的 GT/Adobe 2026 论文也只做了二值决策边界的校准（决策树代理），
不是给每个判断产出经过验证的置信度数值。如果 Jev 的校准确实做到，这是有一手
证据支撑、目前无人做到的差异点，而不是主观感觉上的差异。

**"状态收费、问题免费"的成本假设不见于任何被调研的规划器/优化器。** DocETL、
Abacus、PLOP 的代价模型均按 LLM 调用次数或 token 数定价（第 1.7、3.3 节），
没有一个系统把"同一状态内追加问题几乎零边际成本"当作一等的成本假设。这个
差异有直接证据：这些系统的成本优化手段（代理模型、级联、批量采样）全部服务
于"减少调用次数"这个目标，而"一状态多题几乎免费"这个前提如果成立，会让
"减少调用次数"本身变成一个错误的优化目标——真正该优化的是"减少切换状态的
次数"，这与所有被调研系统的目标函数方向不同。

**确定性重放上，六个系统里只有 DocETL 明确宣称，且是工程缓存层面而非模型
层面的确定性。** LOTUS 论文自己用多次采样测方差、Palimpzest 论文明确写"两次
运行可能得到不同结果"（第 1.7 节），说明这条研究线普遍接受"LLM 判断不确定"
这个前提，靠缓存掩盖而非靠校准/账本机制正面解决。如果 Jev 的确定性重放是靠
账本记录每次调用的输入输出、而非单纯靠缓存命中来实现，这个机制本身（账本
重放 vs. 缓存命中）在被调研系统里没有先例。

**一跳字面判断加递归函数的分工，与 DocETL 的 agentic 分解是同一个问题的两种
解法，边界画在不同位置。** DocETL 把"复杂判断怎么拆"放在系统内部的黑箱优化器
决策里（第 1.4、1.7 节的 13 条重写指令），Jev 把这个分工显式地写成语言层面的
递归函数（05 号文档第 8 节）。这个差异是结构性的、有据可查的（DocETL 论文
明确描述其重写指令是运行时自动选择、不对用户暴露具体分解逻辑），但需要谨慎
表述：这不是"我们比它们更好"，而是"分解逻辑放在优化器黑箱里，还是放在语言的
显式语法里"这两个不同的工程选择，各自的可调试性、可预测性、学习成本不同，
本文没有一手证据证明哪个更优，只能确认这是一个真实存在、可以指认的差异位置。

**三值逻辑的显式化程度，SQL 三十年的坑提供了直接可对照的反面案例（第 5.2、5.3
节），但目前没有证据表明被调研的语义算子系统在这一点上比 SQL 更糟或更好**——
它们大多数根本没有三值逻辑，直接用连续分数或裸判断，回避了 SQL 遇到的"三值
在不同上下文被悄悄打成两值"这个具体问题，代价是把"这个判断到底可信到什么
程度"这个信息直接丢弃。如果 Jev 坚持三值出口且在每个算子上显式声明 unsure
语义，这个差异的价值来自 SQL 反面案例的一手教训，而不是来自与语义算子系统的
直接对比。
