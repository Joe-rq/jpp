# 怎样在这门语言上写一个新系统

五步：定义单元、定义包、`probe`、`run`、答上交。本文附的示例
（`foundation/testbeds/mini_todo/`，跟 `a_notes` 平级放着，随时可以直接跑）今晚
真实跑过一遍——`probe` 真实花了 $0.0001（6 次调用），`run` 真实判对了两条测试待办
（一条判 `act` 打上 `urgent` 标记，一条判 `ignore` 不动），过程和数字都在下面，不是
纸面推演。命令一律从项目根目录 `/Users/nature/个人项目/jev/地基` 执行。

## 1. 定义单元：一句话 + 手 + 验题

一个单元就是一句能让人一次判断清楚的话，外加"判完了做什么"。新建
`<testbed>/defs/<name>.yaml`：

- **一句话**（`eye.instructions`）：写成"是/否"（`noul`）、"选哪个"（`choice`）或
  "几档"（`score`）三选一，配 `criteria` 给判断标准的正反例（不是复述问题）。
- **手**（`hand`）：判"是"之后做什么——`mark` 打标记、`put` 换成新 Item、`code` 跑
  登记过的函数、`write` 调写手改写正文、`ask` 额外问人一句。
- **验题**（`<testbed>/probes/<name>.yaml`）：至少 3 条 `expect: act` + 3 条
  `expect: ignore`（`choice`/`score` 每个选项/档位至少 2 条）。这是上岗的硬闸门，
  不是参考——缝不够（noul 默认门槛 0.20，`layer: safety` 是 0.30）单元会停在
  `draft`，一只手都不许动（施工单 §3.3）。

## 2. 定义包

`<testbed>/pack.yaml`（注意文件名精确是 `pack.yaml`，放在试验台**根目录**，不在
`defs/` 里——混进 `defs/` 会被当成一个内容全空的假单元解析）：

```yaml
pack: <包名>
inlets: [<外面喂进来的 kind>]
outlets: [<算完成、可以交出去的 kind>]
units: [<单元名, ...>]
packs: []
budget: {beats: 30}
```

## 3. `probe`：看缝够不够（真花一点钱）

```
.venv/bin/python -m foundation probe <testbed路径> --run <run-id>
```
每个 jev 单元真的问一遍验题，打出缝（`gap`）和状态（`on_duty`/`draft`）。缝不够就
回第 1 步改句子，不要去改验题凑数——`gap` 是真实读数算出来的，改验题等于把闸门
拆了。顺手在这一步之前先跑一次 `.venv/bin/python -m foundation check <testbed路径>`
（施工单 §8 S6，零花费）：抓悬空产出（手产出的种类没人盯）、无源之水（单元盯的
种类没人产、也不是 inlet）、越权手（不限种类却会取代原物）、同层同优先级冲突
（两个单元同层同优先级、都会取代同一种东西）——这几个错误留到 `probe`/`run` 才
发现要贵得多。

## 4. `run`：真实喂数据

```
.venv/bin/python -m foundation run <testbed路径> --input <文件或目录> --kind <起点kind> --run <run-id>
```
系统自己看、自己判、自己动手，跑到没有新东西出现（`quiet`）或人队列非空
（`waiting_on_human`）为止。想看安全阀怎么工作，可以 `--disable-guard <name>` 关掉
某道保险单独测（`once`/`return_to_same`/`runaway`/`beat_budget`/`cost_budget`，
施工单 §3.7）。

## 5. 答上交

`unsure`（拿不准）和 `ask`（单元主动想问一句）都会进这个 run 的人队列：
```
.venv/bin/python -m foundation answer <run-id> <unsure_id> act|ignore
```
写进这个单元的校准集（不是验题集），当场打印当前校准集条数与两条线；动作在下一拍
生效——续跑一次：
```
.venv/bin/python -m foundation run <testbed路径> --run <run-id> --resume
```

## 最小示例：`mini_todo/`（今晚真跑过，见上）

一个单元的最小系统：待办事项进来，Jev 判断"今天必须处理"就打 `urgent` 标记。

**`pack.yaml`**
```yaml
pack: todo_triage
inlets: [task.raw]
outlets: [task.raw]
units: [mark_urgent]
packs: []
budget: {beats: 10}
```

**`defs/mark_urgent.yaml`**
```yaml
unit: mark_urgent
version: 1
watches:
  kinds: [task.raw]
eye:
  type: jev
  primitive: noul
  instructions: "这条待办是否要求今天之内处理完？"
  criteria:
    "true": "字面写了今天/马上/尽快之类的时限词，或语境明显不能拖到明天"
    "false": "没有时间压力的字面或语境证据"
view: self
hand:
  type: mark
  label: urgent
layer: correctness
priority: 10
probes: probes/mark_urgent.yaml
```

**`probes/mark_urgent.yaml`**（真实跑出缝 `+0.880`，`on_duty`，$0.0001／6 次调用）
```yaml
- {view: "老板说这个方案必须今天下班前发出去。", expect: act, source: builder}
- {view: "十分钟内把签好的合同扫描件发到我邮箱，现在就要。", expect: act, source: builder}
- {view: "麻烦马上确认一下会议室有没有空。", expect: act, source: builder}
- {view: "有空的时候看一下这个链接就行，不着急。", expect: ignore, source: builder}
- {view: "下个月的年会场地可以再慢慢比较。", expect: ignore, source: builder}
- {view: "这份资料存档，以后要用再翻。", expect: ignore, source: builder}
```

`check` 对这份 defs 只报 1 条预期中的 warn（`mark_urgent` 产出 `mark`，没有任何
单元盯着它——今晚没有 `with_marks` 视野，这是所有走 `mark` 手的单元共有的性质，
a_notes 自己 `defs/` 下的单元里也有五个同样被这样警告，见 `foundation/reports/
stage-6.md`），0 error。真跑两条测试待办："客户催得很紧，这份报价单必须今天下班
前发过去"读数 `p=0.99` → `act`，打上 `urgent`；"仓库的旧设备清单整理一下就行，
不着急，下个月弄完都行"读数 `p=0.02` → `ignore`，不动——`run` 状态 `quiet`，人队列
0 条，额外花费 $0.0000（两次调用金额太小，四位小数四舍五入为零）。
