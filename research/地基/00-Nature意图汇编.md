# Nature 意图汇编（必读）

主会话维护。收录 Nature 反复强调过、却在施工中被误解过的意图，每条注明日期与原话。与 `00-定位与方法论-v1.md`、`00-目标与动机-v1.md` 一起在开工前读。本文件只汇编 Nature 说过的话，不新增设计；依据文本（`00-*`、`12`、`13`、宪法、施工单）仍只有 Nature 或经他授权的 Fable 裁定能改。发现与本文件冲突的做法，先停下对照，再报主会话。

## 一、J++ 是什么

1. **J++ 是一门语言，两件事都要做到：写起来好，能做到别人做不到的。**（2026-09-25）「当然这个 J++ 本身还是要一个语言的……写起来好，能做到别人做不到的。」写起来好的检验是「一句顶一百句」：同样的效果，代码量远少于手写，对照业界参考带（`研究/07`、`研究/08`）。做到别人做不到的检验是搭配（下一节）。两件事缺一件都不算做成。
2. **基本单元是一次判断，JEV 是今天的判断器。**（`00-目标与动机`）判断器可替换，今天的大模型将来也会进入这一类。

## 二、搭配是底层，组合可以无限再组合

3. **JEV 与生成器（大模型）、执行器、图算法等精确算法的搭配，是 J++ 的底层。**（2026-09-25，依据 `08-最基本的定义-v0.md` §4「搭配：1000 与 10000」、`06-三种判断的本质-v0.md` §3、`附注/2026-09-23-核心设计讨论-Fable入口.md`）「JEV 和大模型，或者 JEV 和图算法，或者 JEV 和生成器，或者是它们两者或者三者的组合，是作为 J++ 的底层的。」
4. **搭配不是「能调用」，是能放进复杂函数里组合的积木。**（2026-09-25）「不只是简单调用，而是它能放到复杂函数里面去做组合的。」每种搭配本身是一个值或函数，能当参数传、嵌进筛选、配对、循环，也能嵌进另一种搭配。
5. **最小的搭配只是一个元素，元素之间继续组合，组合的组合再组合。**（2026-09-25）「暴力求解本身只是最小的一个元素，比如叫做枚举加判断。那枚举加判断本身作为一个组合，再跟其他组合进行组合的组合的组合。」例：枚举加判断（大模型列出可能解，JEV 逐个判）是一个元素；提出、判断、再提出是搜索；执行后判断是接地；JEV 判出的图上跑图算法；这些元素彼此嵌套成更大的程序。跨层时未决的去向、误差界、预算、账本与重放、放行把关都由语言自动带着走。
6. **大模型在程序里按结构需要时调用。**（2026-09-25）「不是每次都要调用，也不是说不调用的。」生成的产物按键缓存、跨运行复用；日常运行主要由 JEV 跑。
7. **生成期间别的工作照常调度。**（2026-09-25）「在它生成的时候，其他的东西也可以进行调度和等待的呀。」生成走非阻塞端口，与同层的判断、执行并行。
7a. **代码能定的用代码，JEV 只判代码判不了的。**（2026-09-26）「这玩意儿为什么要让 JEV 来判断输出是不是 385 的？……写一个 Python 就能达到的事，为什么要单独用 JEV 来去判断呢？」起因是搭配示例（`examples/search-ground.jpp`、GUIDE「搭配」一章、群通知草稿）让 JEV 判「输出是否等于 385」。能否运行、数值相等、格式、字段齐不齐，这些用普通代码判，不花调用；JEV 只判没有标准答案、要理解语义的问题（查询答没答对问题、方案合不合要求）。示例、文档和对外文字不得让 JEV 判字面可算的东西。改写实测里原项目自己这么问的，照原样对照（第 9 条要求效果一模一样），但在报告里标出来。
7b. **JEV 的价值在复杂判断；复杂靠结构拆开，不靠把题问成显而易见。**（2026-09-26）「JEV 的价值就在于它能判断那些非常复杂的问题……十几二十个判断如果拿代码做，我要写很多很多的程序，但是拿 JEV 做我就能很快地出智能的判断，那它的问题我们完全可以是用结构消解，而不是判断一个显而易见的东西。」他举的例子：两个人相不相似、适不适合合作；透露一条信息会不会推进合作；已知两人情况，第三个人加入会不会让合作更紧密。如果会，就接着问：是让合作金额变大还是变小，在什么地方，概率多高；金额变大是因为谁的加入，再加一个元素会不会更多。「这些问题本身其实是由在这个循环开始之前的生成器就已经全部生成完了，它只不过是快速地验证而已。」也就是说，大模型事先生成整棵追问的题树，JEV 按每一步的出口沿着题树快速往下判。他要求回查设计环节里所有有这个问题的地方，全部修掉。
7c. **要效果，不省调用；不把今天模型的弱点写进语言；拿不准就问缺什么信息、补上再判。**（2026-09-26，看到真机语义深度实验后）「你不需要太考虑调用次数，而是说考虑效果。因为它其实非常便宜，所以如果调用次数越多，带来的效果越好，这是完全没有问题的。」「你不能去锚定说『让第三个人加入会不会让合作更紧密』这类深度的问题……它干的就是这个事……可能今天它做得不是很好，但过一段时间能做得特别好了……你不需要过度地说『我要追求一定的确定性』。它不用十分完美，因为你要想，这个模型一旦升级了，一切都变了。」「他答案不明显，你就要去想：到底是增加什么样的信息，才能让它更加给出更明确的答案……不是去诱导它，而是说……如果你这个东西判断不准，你认为我还需要给你更多什么信息……这不也是一个快速问题吗？」落到语言上：深问题直接问，不因今天的读数表现改写成别的结构；调用次数不作为设计约束；拿不准时的默认去处是「问缺哪类信息（候选由生成器事先列好，JEV 快速选）→ 取来补进材料 → 再判」。

## 三、做法

8. **按真实的倍率与水平比较，反复测、反复修。**（2026-09-24）「按真实的倍率或者真实的水平比较……不断反馈、修正。」仪表可反复跑。
9. **拿真实项目检验：丢任何一个 JEV 项目过来，用更少的代码做出一模一样的效果。**（2026-09-25）生态归档 `实测/jev-ecosystem-2026-09-23`（3361 个仓库）全部过一遍：先聚类去重，每类取最完整、最能用的代表，逐个改写并在同读数下逐字段验收。只测几个任务不够。
10. **不为演示施工，把语言本身做好。**（2026-09-25）「这些东西暂时都不需要奔着去做什么演示去做的，而是……做 J++ 本身。」比赛（2026-09-27 中午，评委是投资人）的目标是现场能直接用 J++ 写很多能用的软件。
11. **作者的策略不能被剥夺。**（2026-09-25）「你不就是应该让我自己去判断多少分算是要退款吗？为什么你要剥夺我的策略呢？」作者可以自己写判断线（B128，选甲）；标注只在要语言担保错误率时才需要。
11a. **语言不内置防御，不把我们的价值观按进去；默认相信 JEV 的判断。**（2026-09-26，批 8 讨论「题树认证」「代码判断能否放行撤不回的动作」时）「为什么要做题注和认证呢？我真的觉得这是一个极度防御的一件事情。你这本质上是你不相信 JEV 的判断能力……你不能绑定在这个上面。」「我现在都不明白为什么你要给那么多东西做什么标注……那些标注是极其不重要的东西。」「为什么你要提前放一个内置的防御呢……这相当于是把你的价值观全部按进去了，但是问题是，可能使用者他不需要。」落到语言上：标注、认证、放行把关、不可信标记都只是可选工具，由作者或宿主自己开，不是默认；没写线、没标注时，程序照 JEV 的回答走，不落成「拿不准」；账本照记（记录是信息，不是防御）。与 11 条同向，更进一步。同日追定：「直接改掉，以后永远不允许出现这种『信任问题』。我们要的是创造价值，我们专注的部分是怎么做出更精美、更复杂、更加强大功能的案例，而不是在这里防这个防那个。」——语言默认值今晚直接翻过来，不走开关过渡；今后任何设计、裁定、示例不得再以「不信任判断器」为前提加默认限制。落点：B187–B190（`地基/附注/2026-09-26-批9裁定-默认相信判断器.md`）。
12. **写程序的主要是代理。** skill 讲「为什么这样设计」；签名、示例、报错修法由代码生成，不能成为第二个维护点。（2026-09-24）
13. **先设计，再把设计全部落实成代码，再做其他。** 仪表只监测、不打乱施工顺序；仪表暴露的问题回到设计层裁定。（2026-09-24）
14. **极简。** 最后做消融，没有可测贡献的部件删掉。（2026-09-23）

## 四、协作

15. 能从已表达的意图推出答案的，直接决定再告知；只有 Nature 能答的才问。（2026-09-24）
16. 讲人话，没听懂就换说法重讲；对外文字不能有知识诅咒。（2026-09-25）
17. 控制成本：派出的任务默认 Sonnet、medium 强度；Opus 用于核心实现；Fable 只用于最难的裁定；能用脚本做的用脚本。（2026-09-25）
18. 全量测试尽量少跑：每步完成时一次，合入时只跑相关测试。（2026-09-25）
19. 报告、页面一律用本地文件，不发 artifact。（2026-09-26）「这些 artifact 你不要老是给我做 artifact。你用本地的文件就好了。」
20. 做出来的演示都发到公开链接，并更新到 GitHub 主页 README。（2026-09-26）「以后做的这些演示都能够发到公开的链接，然后更新到我们 GitHub 的主页上面。这是 README 上面，然后我们可以去看这些。」渠道：Towow-ai/jpp 的 GitHub Pages（towow-ai.github.io/jpp/demos/），README 靠前一节「演示 / Demos」列链接与一句照实的结论。只发真机数据的页面；模拟数据页面等真机结果出来再发。
