## 零、先说这轮盘点自己的两个局限

1. **`13` 整份缺席于审计的材料清单**。我在 01:10 派出审计，`13` 写于 01:14。所以审计报出的 21 条「与新设计冲突」**不可信**——它们大多是拿 `12` 去对 Rust，而 `13` 恰恰已经把其中几条定死了（例如 drop 是否合法去向，`13` §3 已明文保留）。**本计划不采用审计的 C 类结论**，冲突一律回到 `12`+`13` 原文重判。
2. **复核也不是终审**。它推翻的 30 条里有若干是「分类错、现象对」。凡进本计划的条目都标了证据位置，实施者动手前**必须自己再核一次代码**——今夜已有五次「凭记忆或凭过期文本」的教训，其中一次的来源就是依据文本自己。

## 一、这门语言现在能做什么（已验证，不是声称）

`.jpp` 源码 → 解析 → 检查 → 原生 Rust 执行，不依赖 Python。提交树 `2acf692` 干净 checkout 全绿。六种效应形式都有内置且能跑；方法是一等值，可传、可返回、可再组合；未决是一等出口且**必须被消费**（四条合法去向）；效应跟着类型走并在调用点实例化（rank-1 多态）；账本记账、重放零调用；`allocate` / `unsure_bound` 对照 Python oracle 逐条一致。

## 二、根缺口：执行模型没迁

**这是本轮盘点最重的一条，而且它此前不在任何待定清单里**——只活在 `crates/jpp-core/src/interp.rs:1` 的一句模块注释：「效应即时发出（惰性融合是后续优化，未迁移）」。

`12` §2.2 与 §4 要求的是**惰性登记 + 刷新点 + 分层**：登记后不发，到 `cut`/`fit`/`match`/`if`/读内容/程序结束时，把所有已登记且输入就绪的 `judge` 按状态分组、按依赖分层，一层一次发出。Rust 是逐语句即时执行。

**它是下面五条的共同根，一个决定动五行**：
- `judge(ss: [State], qs)` 向量化签名在 Rust 里写不出来（`12`:126）
- `12` §4 的编译 pass 只落地 1 个（ledger），提升 / 融合 / 裂变 / 下沉 / 调度 / 预算六个没有，**也没有任何开关机制**——而开关是消融的唯一载体
- `ast::Budget` 连 `layers` 字段都没有，J-07 的「层边界核」没有落点
- 同状态多题融合：代码路径成立（`effects.rs:26` 的 `judge(state, &[&Question])`、一次 `charge`、一次 `calls += 1`），**但仓库里没有一个测试钉住它**，全部 `judge(` 调用点都传单题。`12` §10 G2 判「满足」是对 Python 说的，在新内核上 P5 未验证
- 结构摘要 Φ 不存在，而 Codex 的回答指出：`ε={judge}` 不等于可融合，融合要的是站点/依赖/需求点/分支/顺序/循环/屏障

**排期：第一包。** 但先做最便宜的一格——补一条「两题一次调用」的断言（照 `tests/strength.rs:199` 的 `assert_eq!(outcome.cost.calls, …)` 写法），成本极低，不补则 G2 在新内核上没有依据。

## 三、第七种形式缺席：`fit` 桥

`FitRef` 全仓零命中。连带缺失：`Readings.agg()/.order()`、`on_truth`/`on_fail`、`Q` 的 `evidence`/`prior`/`anchors` 五个参数。后果是三处没有入口：J-09 的 `insufficient`（`cut` 的判序第一步）、`12` §2.3 的代价矩阵线 `cost={fp,fn}`、`12` §G4「发挥不确定性长处」的一半。

Python 侧都有且有测试，是可直接照搬的 oracle。**排期：第二包。**

## 四、`cut` 的判序缺两步（`12` §2.3:147）

规定顺序是 `insufficient` → `taint` → 过线 → `band`。Rust 是 fail → 冷 → 停岗 → 过线/band/tie，**缺前两步**：
- `insufficient` 不存在，且 `Question`（`value.rs:103-111`）没有 `evidence` 字段可供检查
- taint 步骤不存在：`interp.rs:425` 原文 `let taint = Taint::Trusted; // 首包按 trusted`
- `cost={fp,fn}` 传不进去（第二参是校准键）
- 复核另补：`select` 的 `Pick` 要求置换众数一致且先验策略核验，也没做

**排期：第三包**（taint 那半与第六节合并）。

# 附：Codex 设计文档与 taste 的挖掘结果（2026-09-21 02:10）

第二轮 workflow（8 组精读 + 8 组定位复核，16 代理，$0）。原始结果 `foundation/experiments/审计/设计挖掘-2026-09-21.json`。125 条：**已落实 45、本版待做 39、后续增强 19、尚未机制化 16、与现行依据冲突 2、已被新决定取代 4**；性质分布：机制 85、施工安排 20、taste 13、外部借用 7。

## 十一、这一轮最有价值的产出：22 处「被包装成机制的 taste」

我给复核员的头号任务是揪出「写得像规则、实际无法写进检查器、无法被测试钉住」的条目。它揪出 22 处，**其中几处是我们自己写的**。记几条典型，作为以后的识别样本：

- **「在结果协议里预留字段」**——复核员判它「正好是任务点名的那种失败：造一个听起来像机制的壳来装 taste」。`Outcome` 上加一个 `goal` 字段，没有生产者、没有消费者、没有任何测试能因为它红。
- **「新增内置必须说明它是哪一种语言级操作」+ 遍历 BUILTINS 对照白名单的测试**——「这个测试只能验证有人给这个名字贴了一个分类标签，验证不了标签诚实。一个领域专用的 `search_bounded` 贴上『通用容器操作』就能过」。
- **「本版排除清单的棘轮」**——「加一节文档不构成棘轮。没有任何东西能检测『悄悄删了一项能力』——恰恰因为它是悄悄的」。
- **「优化器必须声明依赖了哪些效应画像」**——「没有任何检查器能验证这份声明是真的或完整的；声明写得漂亮而 pass 照样偷跑，测试一样绿」。
- **`unsure_bound` 的「独立估计只作参考不作判据」**——最隐蔽的一例，因为它被一条真机制掩护着：这条纪律**只写在注释里**（`strength.rs:70-78`），没有任何东西阻止调用者拿 `independent_any` 当判据。
- **「三种量词语义」「统一后差异由显式参数承载」「抽象用了几次逃生口」**——都自承「一般不可机械判定」，随后声称「有一半可判」，而那半也不成立。

**由此立一条识别法则**：一条规则若**说不出「什么情况下它会让什么东西变红」**，它就是 taste，不管措辞多像规则。写进文档可以，**不许记成「已落实的机制」**。

## 十二、本版待做里最便宜且后果最重的（按可做性排序）

以下每条都经定位复核确认并给了代码位置，**实施者动手前仍须自核**：

1. **J-01 逃逸**：读数禁止比较，但**包进列表或记录字段就逃过检查**（`value.rs:391/:393` 的容器分支不逐元素传播、`interp.rs:380-381`）。复核员原话：「目前唯一确认还活着的『会算错』」。
2. **`Ledger::put` 的只增语义没有任何测试**（`ledger.rs:77-85` 遇同键直接 return）。「账本是审计物不是缓存」全靠这个不变量，却没有一条断言对着它。
3. **`collect_exit_ids` 缺 `Value::Fn` 臂**（`interp.rs:1419`，注释在 1417-1418 自认）。这不是缺口，是**内核内部两半打架导致的假拒绝**：类型侧已用 `captures_responsibility` 认了「方法可以捕获责任」，扫描侧却不进函数环境。
4. **`--resume` 静默执行未记账的 `do`**（`jpp-cli/src/options.rs:3` 帮助文本原话即如此）。与 `13` §5「恢复时复用已完成记录」同源。CLI 归 Codex，core 侧先把动作记账做严。
5. **未决责任跨恢复没有测试**——这同时关掉 `13` §3 唯一没验过的那句验收「暂停恢复仍能找到它」，并订正 `COORDINATION.md` 上一条错误绿灯。复核员原话：「**一个假绿比一条已知的红更坏**」。
6. **`filter` 的谓词返回非 `Bool(true)` 时无契约**（`interp.rs` 的 `else if matches!(r, Value::Bool(true))`）——`Exit`、`Duty` 传进去会被静默当假。
7. **`W-legacy-fn-type`**：凡 `Type::Function`（旧式无效应）出现在被调用的方法参数位即告警，并清掉 `INTERFACE.md:66-68` 那段过期文字。
8. **账本头加校准依据的指纹**——与第五节 `profile_hash` 那条合并做，同时拍板两个岔口（覆盖全部 `CalibStore` 还是本次实际用到的记录；头在 `run()` 入口定稿还是结束时补齐）。
9. **资源估计里未知必须显示为未知，不许写成零**（Python `plan.py` 的 `Sym` 是 oracle）。**它的失效方式是静默的**——含 opaque 叶的计划会报出一个看起来精确的数字。这条排在惰性那一包的前面还是里面，由实施者定。
