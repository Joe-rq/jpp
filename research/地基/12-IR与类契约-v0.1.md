## 0. 一句话

程序是普通的宿主程序（数据结构、纯函数、有界循环），里面在任意位置出现四种带类型的效应：`judge`（问模型）、`gen`（生成候选）、`do`（触世界）、`ask`（问人）。
效应是**惰性**的：调用只登记，不发；到程序真的需要一个出口（`cut`、`match`、`if`、读 `.content`）时，把此前登记的效应按依赖组成层，一层一次发出。这样 Python 原生控制流照常用，同一直线段内的判断仍然融合成一次调用（v0.1.1：由推测提升与循环向量化两个 pass 保证，见修订记录 1）。
`judge` 的输出是读数，读数只能经 `cut`（内核桥）或 `fit`（库桥）变成程序能用的出口。规划器在每个层边界按效应画像做融合、裂变、下沉、调度、核预算。
语言的原创部分全在效应与类型纪律；其余是无聊但好的宿主。
边界声明：这不是概率编程语言，没有联合分布可推断，读数不是后验，只是一次校准传感器读数（研究 04 §7-6）。

**为什么。** v0 同时承诺「先建图」与「原生 match」，红队 06 A1 指出这正是 JAX 必须提供 `lax.cond` 的矛盾。选惰性 + 需求驱动刷新，是因为通用性（清单 A0、G2）要求宿主控制流不打折，而融合（P5）只需要「直线段内的判断同层」，不需要整程序静态图；跨分支推测求值放弃，它在含 `do` 的分支里本就不安全。

## 1. 类契约

契约分两栏。**类不变量**对「校准判断传感器」这一类模型必然成立，语言的纪律建在它们上。**类假设**是这一类模型目前普遍具备、但某个版本可能不具备的性质，每条绑档案（`foundation/profile/profiles/<model>.json`）里一个字段；编译 pass 与检查器规则声明自己依赖哪条假设，档案字段为反值时按 §1.3 降级，程序不改。凡是数字，都是档案字段，契约不写。

```
Model : State × [Q] → [Reading]                  一次调用：一个状态，一批题，每题一个读数
```

### 1.1 类不变量（I）

| # | 不变量 | 依据 |
|---|---|---|
| I1 | 模型是 `State × [Q] → [Reading]`：给状态与题，返回每题一个分布；它只在**给定集合**上分配概率，不产生集合。候选、刻度、动作都来自别处（宿主、`gen`、`do`） | H §1.4；D2 |
| I2 | 读数是随机变量不是值：重跑可变；确定性只由账本定义（同键取同读数） | P2、P3 |
| I3 | 跨题读数不成恒等式：P(x)+P(¬x) ≠ 1，跨题算术无定义；读数只能经桥离开 | 官方文档；v0 §1.3 |
| I4 | 线只从校准记录来（标注集、保形、代价），程序里不可写线 | E4 纪律 |
| I5 | 每个读数记模型的不可变 id；换模型 = 重跑档案测试组 + 迁移报告 | 审核 A |
| I6 | 材料带来源链与 taint；由题 q 派生的材料回到问 q 的状态会自我锚定 | P4；H §2 |

## 2. 六形式 IR

宿主之外只有六种形式：`state`、`judge`、`cut`、`gen`、`do`、`ask`。桥两座：`cut` 是内核形式，`fit` 是注册表驱动的桥库（§2.9）。`Mat` 是唯一材料类型：

```
Mat = {content, addr, modality, origin: [Mat | Q | do | gen | ask | transform], taint ∈ {trusted, untrusted}, derived_from: Set[Q_hash], render_version}
```

### 2.1 `state`（槽构造子，纯）

```
state(on: Mat | (Mat, Mat), ctx: [Mat] = [], ref: [Mat] = [], over: [Mat] = []) → State
State = {slots: JSON, size_tokens, taint = ∨ slots.taint, derived_from = ∪ slots.derived_from, repr ∈ {json, text}}
```
- JSON 具名槽渲染；题面按 `on` / `ctx[i]` / `over[k]` / `ref[ℓ]` 路径引用 [H1、P24]。
> **判据（v0.2，2026-09-21 转正文）：凡结果依赖于答案的操作，皆是刷新点。** 上面的清单是例子不是穷举——实测教训：`allocate` 读的是「读数离决定带多远」，那是**答案上的量**，它不在原清单里，于是拿到未答读数、选出 `[0,1,2,3]` 而非 `[2,4,6,8]`，**不报错、不告警**。清单形式的失效方式是**静默给出错误结果**，所以改判据优先。新增的读答案操作**默认**即刷新点，要例外才需论证。落地形状：把判据摆到唯一入口上（Rust 侧 `Reading::answer_after_flush()`），不指望作者去查本条。

- 窗口检查（H6）：对象槽内单段材料按 `profile.window.text_slots.usable_lower`（一段带主张文字的自身长度，E5 测的量）；槽间干扰按 `profile.window.json_slots`（E-JSON-hi 测的量）。静态已知时编译期查，否则调用前查，超窗交裂变 pass（红队 06 B5）。
- `on` 恰一个判断对象（H8）；关系是 `on=(a, b)` 的复合对象，配对是状态构造不是题型 [P8]。
- `ctx` 可含 untrusted 材料，但状态 taint 随之为 untrusted，进 J-08 路径（红队 06 A6，替代 v0 J-14「ctx 只收 trusted」）。
- 进入任何槽的材料只能来自：字面量、IR 形式的输出、`transform` 的输出（§2.8）。宿主任意函数的返回值不能直接进槽（红队 06 A5）。

### 2.2 `judge`（效应，惰性）

```
Q = {op ∈ {test, select, measure}, slot_shape, text, calib: CalibRef, phys?: {noul, choice, score, k_noul}}
judge(s: State, qs: [Q]) → Readings                     # 单状态
judge(ss: [State], qs: [Q]) → [Readings]                # 向量化：状态列表，同层并发
Readings = 不透明向量 {per q: {q_hash, state_hash, run_seq, model_id, phys, perm_seed}}
```
- **惰性**：登记后不发；被 `cut`、`fit`、`match`/`if`、或宿主读内容时刷新。刷新时把所有已登记且输入就绪的 `judge` 按状态分组、按依赖分层，一层一次发出（§4.2 融合、§4.5 调度）。
- 对 `over` 槽的 `select`，出口是 `Pick(k)`；对 `over` 的 `subset`（K 道 test）向量化返回 `Map[候选, Exit]`（红队 06 B9）。
- **判断向量**的合法操作只有两种，以方法挂在 `Readings` 上（红队 06 C2）：`.agg()` 同题跨运行的均值/众数；`.order()` 同题同锚单独渲染的跨对象偏序（相邻档并列）。其余运算不存在（J-01）。
- 画像：成本 `profile.cost.regression`；时延 `profile.concurrency.latency_s.p95`；几乎不失败；噪声 `profile.delta`。
- `calib_key` = `(q_text_hash, slot_kinds, phys, render_version, literal_mode)`；`literal_mode` ∈ {判执行输出, 判代码字面, 判文档段落, …}，题级样本不够时用模式级校准做先验收缩（jev-f6）。
- 题式（属性/关系/子集/充分性/比较/归类/提及/程度/决定）不是 IR 形式：由 `op × slot_shape` 推断，只作校准键分类与下沉提示（H §12.2）。

### 2.3 `cut`（内核桥，纯）

```
cut(r: Reading, c: CalibRef = r.q.calib, cost?: {fp, fn}) → Exit
Exit = Act | Ignore | Unsure(cause)               # test
     | Pick(k) | Unsure(cause)                    # select
     | At(ℓ)   | Unsure(cause)                    # measure
cause ∈ {band, tie, cold, insufficient, fail, budget, noprogress, drift}      # v0.2：`taint` 已删，见下
Exit.consumed : Bool                              # J-05 用；被 match/handler/返回类型消费时置真
```

### 2.4 `gen`（效应，惰性）

```
gen(prompt: Str, ctx: [Mat], n: Int, retry_seq: Int) → [Mat]      # 可能为空
```
- 画像：成本 `profile_gen.cost_per_candidate`，时延分布（LLM 秒到分钟；枚举器 0），失败 = 超时/空（E9b 30%），首候选常是强基线 [P20]。
- 键：`(site, prompt_hash, ctx_hash, n, retry_seq)`；`regen` 必须递增 `retry_seq`（J-13）。
- 输出 taint = ∨ ctx.taint（§2.11）；输出默认入料库（§5）。
- 确定性枚举器（正则、解析器、语法、k-子集、全配对）是 `gen` 的零成本实现，同签名，输出 taint = ∨ 输入。

### 2.5 `do`（效应，惰性）

```
do(action: Action, args: [Mat], iter_seq: Int) → Mat ⊎ Fail
Action = {name, cost, latency, reversible: Bool, fail_types, taint_out ∈ {trusted, untrusted, inherit}}
```
- `Fail` 是值，进账本，走 `Unsure(fail)` 流（J-12）。
- 键：`(site, action, args_hash, iter_seq)`；重放取账本，不重触世界。
- 输出 taint 由动作声明（§2.11）：沙箱执行不可信代码 → untrusted；仓库测试框架、可信工具 → trusted；`inherit` → ∨ args.taint。
- 执行器、渲染器（OCR、a11y、结构化抽取）、求解器/检查器都是 `do` 的实例；返回的 `Mat` 已渲染，不需再渲染。不可逆动作（`reversible=false`）的放行守卫走 J-08。

### 2.6 `ask`（效应，异步）

> **（v0.2，2026-09-21 转正文）恢复只以账本为准，运行时续延不得成为恢复的依据。** 挂起与恢复在语义上是分隔延续，而宿主提供的续延（Rust 的 `async`、OCaml 5 的 effect handler、协程）**都不可序列化**，因此都不能承担跨进程恢复。它们只许作为同一次进程内的实现细节，**不得成为恢复的依据，也不得让恢复路径绕过账本记账**。防的是这件事：若有人为省掉重放的墙钟时间做一个进程内 resume，「恢复后那一半」的控制流就来自内存里的续延而不是账本，**J-18 会在没人注意时失效，账本从审计物退化成缓存**。


```
ask(s: State, q: Q) → Exit ⊎ Pending
```
- 画像：贵、小时到天、可能不答；答案是真值，进校准集；输出 taint = trusted。
- 有预算（`budget.escalate`）与去重（同键只问一次）；键 `(state_hash, q_hash)`。
- **`Pending` 是程序级出口**（红队 06 B2）：`ask` 返回 `Pending` 时程序整体挂起并结束本次运行；`match` 不需要 `Pending` 分支。恢复 = 从头重跑，账本重放使此前所有 `judge`/`do`/`gen` 不付费、不重触世界，`ask` 的答案到达后作为账本条目参与重放。这要求 §2.8 成立（宿主不产生不可重放的材料）。

### 2.7 宿主与有界循环

纯函数、数据结构（列表、映射、集合、记录、优先队列）、`loop(bound, variant)`。变式：宿主计量严格单调；或打分出口带耐心（连续 p 轮无提升即停）；或账本键在本循环内重复即停 [P6]。`loop` 提供 `it.n` 作为本轮序号，供 `do.iter_seq`、`gen.retry_seq` 使用。

### 2.8 `transform`（宿主材料变换，记账）

```
transform(f: HostFn, args: [Mat]) → Mat            # 键 (site, f_hash, args_hash)；输入输出哈希入账本
```
宿主函数不能直接产出进槽的材料（红队 06 A5）。要用宿主代码变换材料（切分、抽字段、拼摘要、`commits()` 这类），必须经 `transform`：运行时记输入输出哈希，重放取账本；同输入异输出时判该函数不纯，禁用其所在直线段的融合并报 W-impure。纯性不再是假设，是账本核出来的事实。

### 2.9 `fit`（桥库，注册表驱动）

```
fit(m: FitRef, rs: [Reading]) → Score ;  然后 cut(Score, c)
FitRef = {trained_from: set_id, features: [(calib_key, fingerprint_kind)], min_n, error_rate, version}
```
注册约束（注册表拒绝不满足的记录，检查器只认注册表签名，J-16）：
1. 输入读数的 `(calib_key, fingerprint_kind)` 必须与训练时逐项相同：同题、同候选集指纹种类、同刻度指纹种类（红队 06 A3 反例一）。
2. `n ≥ 20 × 特征数` 且 `≥ 50`；样本不足退化为投票，不注册为 fit（反例二）。
3. `trained_from ≠ 后续 cut 的 CalibRef.set_id`（训练集与保形集不相交，反例三）。
4. 输出是分数不是概率，必须 `cut(…, CalibRef)` 才能出口。
这是跨题读数唯一合法的算术（I3）；程序里不可手写。

### 2.10 账本键、缓存键、账本头

| | 组成 | 用途 |
|---|---|---|
| 账本键（程序局部） | `(model_id, canon_json(state) 含槽结构, q_text_hash, phys, render_version, perm_seed, run_seq, site)` | 同程序重放逐字节相同 |
| 缓存键（跨程序） | `(canon_json(state) 含槽结构, q_text_hash, phys, render_version, model_id)`；choice 的缓存值是按 `perm_seed` 索引的读数集合，命中只复用同 seed，众数在集合上算 | 目的无关的中间状态；账本 #24 的替代 |
| 账本头 | `budget`、`profile_hash`、`model_id`（解析后的不可变 id，不是别名）、`render_version`、handler 库版本、`retry` 策略 | 两次运行头不同即不承诺重放一致（红队 06 B8） |

**〔09-21 08:35 订正，并且这条订正的是我自己用了三次的一个论据〕出口不进账本，所以「两者在账本里不能是同一个值」对出口不成立。**

实测：`Entry` 只有 `Judge` / `Effect` / `Ask` 三种，**没有 `Exit`**。出口唯一的持久痕迹是程序自己把 `exit_kind(e)` 带进返回值，加上 `W-` 告警。**本夜我至少三次拿「两者在账本里不能是同一个值——账本是审计物」当决定性论据**（兜底档案的 `hash` 该是 `None`、`tie` 不许兼职、`mode_share` 不许裸记）。**那三条结论仍然对，但对出口那两条的理由是错的**——理由应当是「**handler 路由不同**」与「**告警要说真话**」，不是账本。来源：`rust-core-4` 在做 J-15 那一位时撞上，非推断。

**而顺着它往下看，是一个真的 J-18 洞：**

> **出口 = f(读数, 线)。读数进了账本，线没有。**

账本头记了 `profile_hash`（**档案里的缺省线**）与行为承载子集摘要，**但没有 `CalibStore` 的哈希**——而 `cut` 实际用的是**按键的线**，它住在 `CalibStore` 的记录里，可独立变更、不进头、不进任何键。**所以「同程序重放逐字节相同」（§2.10 账本键那一行）对出口不成立**：同一份账本，换一批校准记录重放，读数一样、出口可以不一样，**而账本上看不出发生过这件事**。

**这正是 J-12 那条附注（「线重算之后，已经发出的出口不改；账本是审计物不是缓存」）的前提**——而前提今天是空的。**结论仍成立**（一次运行内已发出的出口不该被回头改写），**但它现在只是运行期的纪律，不是审计上的事实**。

**要补的是两件之一，不是随便哪件都行**：(a) **账本头记 `CalibStore` 的哈希**——最便宜，且与 `profile_hash` 同形，**让「换线重放」像「换档案重放」一样报 `W-header`**；(b) **出口进账本**——更彻底，但要动序列化格式与重放，代价大得多。**先做 (a)。** 在 (a) 落地之前，任何引用「出口在账本上如何如何」的论证都要先停下来问一句：**出口根本不在账本里。**

`materials_hash` 一词废弃：键里用的是含槽结构的规范化 JSON，`state(on=A, ctx=[B])` 与 `state(on=B, ctx=[A])` 不同键（红队 06 A4）。

**`profile_hash` 覆盖整份档案，包括自由文本（v0.2，2026-09-21 转正文）。** 定义不变：`sha256(canon([整份档案 JSON]))` 取前 16 位，**两个内核必须算出同一个数**，否则跨内核重放判定对不上。覆盖全文件是**对的方向**——头不同只是「不承诺重放一致」，是拒绝那一侧；漏掉一个会影响行为的字段才是替不确定说了确定。

**但它只给出一个比特，而现场有两个比特可给。** 实测：同一晚上改了两次档案里的说明文字（都是更正一个写错的数字），行为一个字节没变，`profile_hash` 两次都变，对照基准两次都红。**这会造出一个反向激励——改对文档要付代价，于是不如不改。** 三次把同一个数写错，第三次才改对，正是在这个激励下发生的。

**所以档案另记一个「行为承载子集摘要」，而且它必须按「排除法」定义，不能按「列举法」**：**覆盖整份档案，只减去一张封闭的说明字段清单（`note`、`source`、`value`）**；不写成「只覆盖 `lines`/`delta`/`window`/`k_limit` 这些」。**两种写法的差别全在新字段上**：按列举法，以后有人加一个会进执行的新字段而忘了改清单，这个摘要会说「行为没变」——**那是一个假的「相同」，正是 §2.11 那条通则禁的方向**；按排除法，新字段默认落进行为集，摘要说「不同」，**倒向拒绝那一侧**。〔这条本身犯过一次：初稿就是按列举法写的，**在一份专门讲这条 taste 的裁定里**。〕账本头两个都记。**它不放行任何东西**——`profile_hash` 不同时该怎么判还怎么判；它只让看账本的人知道这次不同属于哪一种：**线和 δ 也变了，还是只改了说明。** 现在两种情况长得一模一样，而人要据此决定要不要重跑。

**这是同一条 taste 的第三种形态**（另两种：`order` 让「δ 之内不可分」活成结构而不是两个一样的「通过」；`knoul` 这个区别只活在旁路标记上而 `phys` 两条路都写 `"noul"`）：**不要把区别压平；让它出现在做决定的那个位置上。**

### 2.11 taint 代数

| 效应 | 输出 taint |
|---|---|
| 字面量、`ask` | trusted |
| `gen` | ∨ ctx.taint |
| `do` | 动作声明：`trusted` / `untrusted` / `inherit`(= ∨ args.taint)（v0.1.1：显式标记，语言不设审核方，见修订记录 3） |
| `transform` | ∨ args.taint |
| `state` | ∨ slots.taint |
| `cut` | 继承状态 taint |
多个 untrusted 合取仍 untrusted；trusted 由来源给出，不由数量给出。不做逐字标签传播（研究 04：会拖垮融合），只在效应边界赋值。

**实现层通则（v0.2，2026-09-21 转正文；来源：Rust 内核实测连抓五条同形状的缝，Python 参照实现一条都没有）**

**兜底值要往「拒绝」那边倒，不往「放行」那边倒。** 在任何「说不准」的分支上先问一句：**这个默认值是在替谁说话？** 替不确定说「确定」、替不可信说「可信」，就是把三值静默压成两值——这正是本表存在的理由（宪法登记表第 30 行「SQL 三值 WHERE 的三十年的坑」）。**只 grep `unwrap_or` 不算查干净**：五条里有两条不是 `unwrap_or`（一条是 `_ =>` 兜底臂、一条是把算好的值不往下传）。

**必须同时守的两条边界，缺一条这条通则就会造出新的错：**

1. **单位元 ≠ 兜底值。** `fold(trusted, ∨, 入料.taint)` 里的 `trusted` 是**单位元**（有一个入料脏，结果就脏）——**正确**；`taint := trusted` 是**兜底值**（替不可信说了「可信」）——**才是 bug**。同一个字面量，两种角色。判别法：问它是「折叠的起点」还是「说不准时的替代」。不做这个区分，按本通则扫一遍会把 `gen`、`transform` 两处**正确的折叠**当成缺口改掉，那就是**假拒绝**——而假拒绝没人会抱怨，所以更难发现。
2. **「没实现」与「算好了又丢掉」是两种病。** 后者更隐蔽：代码里到处都能看到那个值被正确计算，只是在某一段没被带下去（实例：`cut` 的状态 taint，`state` 早已折算好，只是读数没带过来）。

3. **每一个把值搬过去的边界，默认都会把「这个值怎么来的」留在原地。** 帧、容器、回调、聚合都是边界。**值本身有类型护着，过不去编译器会接住；来源信息没有类型，是附在旁边的**——所以边界只搬值不搬它，而且不报错。判别法：问「这个边界两侧，来源信息是不是同一份」，**不要问「这里会不会丢 taint」**——后者只覆盖你已经想到的那一种来源信息（taint、`derived_from`、「经 `ask`」这个事实、状态 taint，都是同一类东西）。
   〔**凭证**：三个实例，未做穷尽扫描。(a) `cut` 不继承状态 taint（`state` 算好了，读数没带过来）；(b) helper 自成一帧、帧弹掉后「经 `ask`」这个事实丢失，J-08 因此误伤了一个守卫实际经过 `ask` 的程序；(c) 已知的假拒绝方向：来源穿过 `map`/`fold` 回调或存进容器再取出时追不到。**〔穷尽扫描已做，2026-09-21 04:30，`审计/边界来源扫描-2026-09-21.md`：通则成立，但谓词要收窄。〕**
   **真正会丢来源的，不是「把值搬过去」的边界，是「用旧值的一部分现造一个新值」的边界。** `Mat`/`State`/`Exit` 都是 `Rc` 包着的不可变值——**纯搬运丢不掉字段**（函数返回、容器存取、`map`/`filter` 单次调用、推测执行，实测全过）；**丢发生在显式 `X::new(...)` 或反序列化重建的地方**。**给下一个人的判据：先问这个边界的代码里有没有 `X::new(...)` 或等价的重建；有，才去查它把哪些输入折算进去了、哪些漏了。纯引用转发的边界可以跳过。**
   扫描新确认四处**丢**，全是重造边界：`do`/`gen`/`transform` 三处输出 `Mat::new(…, BTreeSet::new())` **恒清空 `derived_from`**（同一行模式的三份拷贝），账本序列化往返**又独立丢一次**（写的时候没这个字段，读回来硬编码空集）。**后果已实测：`transform(fn(x){content(x)}, 洗过的)` 一次恒等变换就能洗掉 `derived_from`，J-02 禁自指随即失守**——而 `transform` 是切分、抽字段、拼摘要这类常规操作，不是冷门用法。**另：账本这一丢意味着「重放出来的程序」和「原程序」在 J-02 上不是同一个程序，而 J-18 的整套重放判定建立在它们是同一个上。**

5. **给没有类型的东西补来源，人会另搭一张旁路表；旁路表没有作用域，于是它同时会漏、也会串。** 这不是「边界搬运时漏了一个字段」，是**补丁本身没有作用域**——性质上是独立的架构缺陷，只是长在「来源信息」这个话题下面。**判别法：这条来源通道，它的作用域是谁给的？** 如果答案是「没有，它是一张全局表」，那么它既会在该带的时候没带到，也会在不该带的时候带过去，**而后者是假放行**。
   〔**凭证**：实测。`Value::Bool` 没有地方挂 taint，于是解释器另开了 `bool_provenance`（**按变量名字符串索引**）与 `last_eval_provenance`（**一条跨帧的传送带**）来喂 J-08 的守卫分析。传送带在帧弹出时把那一帧的出口折进去**不管有没有被消费**，而只有绑定 `Bool`/`Record` 的 `let` 才会把它取走。**后果：程序里任何一次「返回值不是 `Bool`/`Record`、内部走过 `ask`」的调用，会把「经过 ask」这个事实留在传送带上，被之后任意一条不相关的 `let` 继承——`let ok = true;` 这种纯字面量赋值也会被污染，J-08 随即放行不可信状态上的判断去驱动不可逆 `do`**（三条命令行可复现，经 `map` 回调触发同一路径同样绕过）。

**J-02 的范围：保一跳，不做传递闭包（裁定，2026-09-21 04:35）。** 扫描问到 `as_mat` 只放本次的 `q_hash`、不并入状态原有的 `derived_from`，算不算缺口。**裁定：不算，那是对的。** 理由与宪法登记表第 44 行同源——**逐字传播会让几乎所有输出不可用**，`derived_from` 做成传递闭包会重演同一个失败：材料越传越「派生自所有题」，J-02 最后拦住一切，等于没有。

**但「不做闭包」与「可以清零」是两回事，现在的实现是后者。** 两条分开守：
- **保一跳（必须修）**：`do` / `gen` / `transform` 的输出材料**要并入各输入材料的 `derived_from`**。`transform(f, m)` 的产物当然仍然派生自 m 派生的那道题——**这是保持同一跳，不是增加一跳**。账本序列化往返同理，写得出也要读得回。
- **不加跳（保持现状）**：`as_mat(exit)` 只放这次 `cut` 的 `q_hash`，**不去并状态本身的 `derived_from`**。这一步才是「增加一跳」，不做。

这样闭包在 `as_mat` 那里自然截断：材料经多少次 `transform` 都还是那一跳，一旦经过一次判断再材料化就重新起算。

**传播机制的失效方式是「丢」，归属机制的失效方式是「滥」（v0.2，2026-09-21 05:00 转正文）。** 上面第三、五条讲的是两种不同的东西，**不要用同一套词去描述**：
- **传播机制**把来源跟着值带走（`Mat.taint`、`derived_from`）。它坏掉的样子是**传不动**——五条 taint 洗白缝全是这一族。
- **归属机制**把来源记在别处、按某个键认领（`bool_provenance` 按**变量名字符串**、`taint_source` 的 `Field` 臂**继承整条记录**）。它坏掉的样子是**认领得太宽**。

**拿从「传播会丢」里长出来的词去描述一个「归属会滥」的机制，措辞一落笔方向就定了**——「把来源留在原地」这句话里，「留在原地」就是「丢」，于是整条规则被标成防假拒绝，而它实际是假放行。

**J-08 现行实现就在这个坑里，而且是「为了让检查通过把区别抹平」的教科书形态。** `12`:265 要的是「**至少一个合取项**来自 trusted 状态」——**合取项是值级的概念**。实现把它做成了名字级：`let` 绑定 `Bool | Record` 时把这次求值新增的**所有出口按析取**折成一个 `(trusted, asked)`；`taint_source` 的 `Field` 臂让**取字段等于继承整条记录的来源**。于是**「这条记录里由可信判断决定的那个字段」和「由不可信判断决定的那个字段」变成同一个来源**。

**最尖锐的一处是它自相矛盾**：`walk_conjuncts` 在**守卫那一层**专门拒绝追析取（「里面的东西不再是这个条件成立所保证的，不追」），**而同一次修法在绑定那一层做了析取折叠**。守卫里不许写 `脏 || 净`，但 `let 包 = 混合(脏, 净)` 再 `if 包.脏字段` 就过。**同一份谨慎，隔一层被自己拆掉。**

**由此给修法定向**：`content()` 的反洗白修到完美也拦不住 `if 包.脏字段 { do(不可逆) }`——**器官是 `bool_provenance` 的粒度与作用域，不是 `content()`**。来源：独立校准顾问，`审计/校准-2026-09-21-04.md`。

**J-15 加宽，并落成「测没测过」那一位（裁定，2026-09-21 05:15；来源：独立校准顾问）。**

**判据先于结论**：一个新冒出来的区别，该加一个 `cause`，还是加一个维度？
> **看这个区别是「这一格特有的」，还是「会在很多格上重复出现的」。特有的加 `cause`；重复出现的加维度。**
> **判别法：数一数今天已经有几个量正处在「没测过」的状态，问每一个是不是都要一条自己的 `cause`。**

数下来是五个载体、同一个性质：**线未测**（已有 `cause: cold`）、**置换未测**（`mode_share == None`）、**档案字段未测**（`choice_same_call_perm_crosstalk`）、**`k_limit` 120–250 档未测**、**ECE 未过检**（H3 明写概率含义要 n≥100 过检才成立）。按 `cause` 的路子走会得到 `cold`/`no_perm`/`no_ece`/`no_klimit`……**而 `cold` 的存在正是证据：这条路已经走过一次，然后停了。** 每多一个 `cause`，handler 库就多一条要记得加的路由，**而漏加路由的失效方式是静默的**——`otherwise` 兜住，没人知道。

**所以正解不是发明第二维，是把 J-15 落地成那个第二维。** J-15 规定的本就是这件事：引用「未测」→ 取该假设为真（保守）、报 `W-untested`、不阻塞。它今天**零实现**。

**措辞要加宽**：从「引用档案『未测』字段」改成「**引用任何被声明为判据、但在本次路径上没有被测量的量**」。加宽之后五个载体一条规则管完。**`mode_share == None` 本来就是 J-15 的一个实例，只是没人认出来**——因为 J-15 的措辞绑在「档案字段」上，而这个未测的量在客户端返回值里。

**两条硬要求：**
1. **那一位必须对 handler 可见，不能只进 trace。** 理由是路由真的不同：`tie` 的既定去向是「逐候选 noul」，而 K-noul 路径**本来就是逐候选 noul**，路过去是空转。handler 看不见那一位，就只能把两种情形当同一件事处理——**而那正是要消除的东西**。
2. **`tie` 不能留着兼职。** `12`:151 只把 `tie` 指派给**不一致**；`mode_share == None` 是「这条路上根本没有置换这回事」。两者现在在**账本**里是同一个值，**而账本是审计物**——这与「兜底档案的 `hash` 必须是 `None` 而不是兜底值的哈希，否则两种情形在账本上分不开」是同一条判据，**区别只在一个落在档案身份上、一个落在出口原因上**。

`cause` 保持它的本分——**路由键**；「测没测过」是**正交的一位**，跟着出口走，产出 `W-untested`。**§5 那张表的原则是「能骑既有行就骑」，但不是绝对**〔09-21 08:35 裁，来源：实现时撞上，非推断〕：**当骑过去会让审计物说一句假话时，新增一行。** 实例：置换未测**找不到可骑的行**——骑 `tie` 就是让 `tie` 兼职（正是这次要消除的）；骑 `band` 会在 **p 远高于 `hi`** 时写假话（实测夹具 p=0.9 / hi=0.65，同一夹具只把 `mode_share` 换成 1.0 就拿到 `pick`）。**两者都比新增一行更糟，故新增 `untested → 补测该量 / escalate` 一行。** **能骑的仍然骑**：`cold` 已骑既有行（`cold → 保守线 + 标记`），照做。**我原来那句「不新增行」写绝对了**——它想防的是「每个载体一条自己的 `cause`」那种发散，不是禁止任何新增行；**防发散靠的是「重复出现的加维度」那条判据，不靠禁令。**

**置换的 K、记法与默认（裁定，2026-09-21 05:40）。** `12`:151 只写「置换众数一致」，没写几个置换。三条一起定：

1. **K=2 维持，理由是「门本身是二值的」，不是「够便宜」。** `Pick` 是一道**门**不是一次测量，门要的是布尔。**而且 K=2 取的是正序与逆序——那是对首位偏置的极大对抗对**，如果存在位置偏置，正逆两序最容易让它现形；两个随机置换反而可能都没碰到那个位置。**这一点必须写在能看见的地方，否则下一个人会以为 K=2 只是图便宜。** Python `position_bias` 用 `runs_per_set: 15` 不构成反例——**它测的是偏置本身有多大（需要分辨率），我们测的是这一次 select 稳不稳（只需要判定）。K 由这个数拿来干什么定，不由「越多越准」定。**

2. **`mode_share` 不许裸记，必须与 `perms` 一起进账本与校准记录。** **证据是本项目自身的事故**：同一个数被写错三次，第四次能定下来**靠的正是原始数据里的 `perms: 2`**——有它才分得出「测出来的 1.0」与「写死的 1.0」。**K 是这个测量的身份的一部分，不是做法的参数**：K=2 的 1.0 与 K=15 的 1.0 是两个不同的测量。裸记则改 K 时**不同 K 下的值合进同一格、第二个覆盖第一个，而它长得像一次观察**——与 `literal_mode` 缺维、`judge_key` 缺 `site` 同族。改 K 应产生**新键**，两边并存（同「线重算之后已发出的出口不改」）。

3. **置换默认不开。** **它是两次不同的调用，不是同一状态多问一题**——P5 的「题免费」不覆盖它，它实打实让 select 调用数 ×2。默认不开之后：`mode_share == None` → J-15 那一位亮 → 取保守项（给不出 `Pick`）+ `W-untested`，**这是有痕迹的失败关闭**；默认开的代价是**每道 select 悄悄花双倍而作者不知道自己买了什么**。按「兜底往拒绝倒」：不给强出口是拒绝，替作者花钱买强出口是放行。
   **三件连起来是一个完整形状**：**不付钱 → 没测 → J-15 亮 → 保守出口 + 告警；付钱 → 测了 → `mode_share` 连同 `perms` 进账本 → `Pick` 可给。** 这让「线只能来自校准记录」在 select 这一格也成立：**不付证据的钱，就拿不到强出口。**

**成本账要公开**：开置换 = select 调用数 ×2（E-CAL 那批 97 条全走原生路径即 194 次 vs 97 次）；**判据在 K=2 上是二值的（1.0 或 0.5），测得出「不一致」，测不出「多不一致」——这是那个数的限制，不是那道门的限制。**

**积累证据不该改变判定（v0.2，2026-09-21 08:50 转正文；来源：实现时自造自堵）。** 校准记录的运行期写入口落地后，`absorb` 把冷记录推到 `待真值`，**而 `待真值` 当时会落进过线比较、用上合成的 `0.65/0.35` 缺省值**——于是「程序积累了几条**无标注**观察」会**静默地**把一个 `Unsure(cold)` 的键变成 0.65 就放行。**证据的数量不是证据的质量：没有标注的观察一条也不构成线。**

**这条附带的方法教训比它本身更重**：**两包分开看都看不见它，合起来才看得见**——A 包（能积累了）对、B 包（能回退了）对，合起来才出事。**而我们的验收全是逐包的。**

**`n` 只随带标注的样本长。** `samples` 是 `[[p, label]]`，一次读数只有 `p`、没有 `label`；把无标注的观察计进 `n`，那条线就「**看起来有 200 条标注撑着而其实一条也没有**」。无标注的进 `samples` 并把记录推到 `待真值`，`n` 不动。

**来源要算出来，不要做成可写字段。** `CalibRecord.provenance()` 由 `(n, 观察数, 有标注数)` 算出「空 / 宿主手填 / 程序积累 / 混合」。**反证在 Python 侧**：那边的 `source: str = ""` **全仓零引用**，没人写也没人读——**一个自由字符串正是「给没有类型的东西补来源」那个形状，而替身会把它填成让检查恰好通过的值。算出来的答案填不错。**

**J-03 的边界（补依据，非新裁）**：`12`:64 I4 的原文是「线只从校准记录来……**程序里**不可写线」——**拦的是程序，不是校准过程**。宿主能在 `put` 里写线是设计意图；**正因如此，来源必须能分辨，否则「线来自校准」在审计上是空的。**

**注解 vs 承重件：一个限定挡不挡得住下一个人，看「把它删掉会不会有东西坏掉」（v0.2，2026-09-21 09:45 转正文；来源：实测，非推理）。**

**不看它长在数据、代码还是流程上。** 反证是实测：「E-CAL 的校准集是『两模型都同意』的子集」这件事**今天已经横跨三者写在六处**（每行的 `label_source`、`set_id` 串里那四个字、`source` 字段的散文、档案的 `label_source`、表格上面一行、专节），**而那个数照样丢掉一半**——ECE 0.057 被写出 15 次带限定 7 次（**47%**）、AUC 0.748 **46%**、置换那条 **64%**。**没有一条守住 100%；加第七处会得到第七个 ~50%。**

| | 判别 | 实测留存率 |
|---|---|---|
| **注解** | 删掉还照常跑 | **46%–64%** |
| **承重件** | 删掉就撞键、就路由不同、就不承诺重放 | **至今一次没丢过** |

承重件的例子：`profile_hash`（头不同就报 `W-header`）、`judge_key` 里的 `site`（缺了就撞键，第二个站点命中第一个的答案）、`perms` 与 `mode_share` 成对（改 K 产生新键而不是覆盖）、`untested` 那一位（handler 路由真的不同）。

**要害不在人的认真程度**：**承重件守得住，是因为它根本不靠散文传输。注解要靠人抄；承重件跟着产出物走，抄不动一半——因为少一半东西就不成立，而不是读起来不完整。**

**由此定方向（落地形态未定，按纪律不进「已落地机制」栏）**：**限定要进那个数的地址，不是它的注释。谁抄走那个数的名字，就抄走了限定，因为名字就是它的地址。** 具体到这件事：**让「模型双标子集上的 ECE」与「全体上的 ECE」不是同一个值**，两者合并、互相引用、互相比较时**应当失败**，而不是读起来有点怪。**这与 `calib_key` 缺 `literal_mode` 同形**——今天这两个 ECE 合进了同一格，只不过第二个还没被算出来。

〔**2026-09-21 11:10 升格：方向已定、落地形态也有了一个实例，可进「已落地机制」栏。**〕

**实例是这条判据自己走完的一遍**：`conformal-proto` 与 `jpp-core::conformal` 并存**八个**同名项（含 `binomial_upper`/`certify`/`drift`/`Certificate`/`DriftReport`/`cluster_subsample` 等），而它们**已经分叉过一次**——内核把 `delta` 改成 `conf_delta`，**而那次改名是一条判断**（保形的 δ 是置信水平，档案的 δ 是迟滞带宽，**两个不同的保证不许共用一个名字**）。**那条判断没有跟过去，而且永远不会断编译**：那条依赖当时只活在 `Cargo.toml` 一行 `path` 里，**改字段会响亮地坏（两小时内坏了两次），改名不会**。

**修法不是再写一条「记得同步」的注解，是把拷贝换成引用**（`pub use jpp_core::conformal::*`，八份拷贝全删）。**改完之后内核改名也会断编译了——两种漂移都变响亮。**

**它满足这条判据自己的定义**：**删掉它（再复制一份回来），就不再有东西坏掉——而那恰恰是要避免的事。** 这就是「把它删掉会不会有东西坏掉」这句话在正面方向上的兑现。

**逐项对照的做法也一并记**（`conformal-proto/交付-与内核的对照.md`）：**把内核那份的 `conf_delta` 归一化回 `delta` 再逐字节比，不默认内核对**——八处逐字节相同；内核多的 serde 派生是**内核对**（它们要进校准记录，必须可序列化）；`cost_line` 内核独有；**没有出现「原型才对」的格子**。**「这处两边一样」也要写进对照表**，否则下一个人还得再对一遍。

**每加一道门，要问「被这道门拦住的东西，还回得来吗」（v0.2，2026-09-21 10:40 转正文；来源：实现者在修一个夹死的同一次编辑里又造了一个）。**

实例：`put` 被证书门拦住时**失败开放**（旧线继续放行而你已不能收紧它），第一版修法改成「**拦住就停岗**」——**更糟**：`commission` 明写「停岗的键不经由 commission 复岗」，那个键于是**永久死掉**。**修锁的那次编辑造出了新锁。** 它自己的复盘：**「我当时脑子里只有『不能失败开放』，没有『拦住之后这个键还回得来吗』。」**

**正确的判据是方向，不是「拦或不拦」**：

> **收紧永远放行，放宽才要凭据。**

`hi` 更高、`lo` 更低 = 带更宽 = `Unsure` 更多 = **往拒绝那边倒，这个方向不需要任何凭据，因为它不会让任何东西多放行。**

**两件正交的事不许挤进一个字段。** 同一包里的第二次自纠：`line_source` 第一版把「凭什么」（手填 / 证书）盖掉了「哪一层」（题级 / 模式级），层级信息当场丢失、既有测试红。现在是 `题级·手填` / `题级·证书:α=0.45` / `模式级·手填`。**这条判据它自己反复在用，写的时候没用上——判据要在下笔时想起来才算有。**

**用选择规则消灭一个坑，比再加一道门去拦它好。** 证书按限定寻址（`(α, conf_delta, 簇单位)` → `Cert`），**选择规则取 α 最小的那张**——α 越小 = 风险目标越严 = 线越高 = 越保守，**于是后认一个更松的 α 永远不会把线放宽，「覆盖」那个坑从规则上就不存在了**，不需要额外拦。`hi`/`lo` 是那条规则算出来的**视图**，`line_source` 报的那张出自**同一个函数**，不是第二处真相。

**「不许有任何告警」的断言是有害的。** 两处示例原本断 `warnings.is_empty()`，而它们真正要断的是「不该有 `W-bound` / `W-header`」。**一个「不许有任何告警」的断言，会逼着后来的人去掐掉正确的告警**——`W-uncertified` 在那两处响得完全正确（`n=120`/`150`/`90` 的手填线拿到强出口），**差点被当成回归修掉**。

**空放行区上的「零错」不是证据，而一个缩小的放行集合把率压低了不是变好（v0.2，2026-09-21 11:00 转正文；来源：代价线三组实测）。**

| 代价矩阵 | 线 | 放行 | 误放行 | 经验假放行率 |
|---|---|---|---|---|
| `fp=1, fn=1` | 0.590 | 50/73 | 15 | **0.300** |
| `fp=10, fn=1` | 0.780 | **6**/73 | 0 | 0.000 |
| `fp=1, fn=10` | 0.385 | 63/73 | 22 | 0.349 |

**那个 0.000 要防误用**：率降到 0 的同时**放行集合从 50 缩到 6**。所以 `CostLine` **必须同时带 `n_accepted`**，且**放行集合为空时 `false_accept_rate` 是 `None` 不是 0**——与保形那边 `binomial_upper` 在 `n==0` 返回 `1.0` 而非 `0.0` 是同一条。**一个比率单独看永远不够，它和它的分母是一件事。**

**同一个 α 上可以有两张线差很远的证书**（`fn` 重的线 0.385 放行 63 / `fp` 重的线 0.780 放行 6），故选择规则加一格：**同 α 取线更高的那张**（线更高 = 放行更少 = 往拒绝那边倒）。

**判定不做：保形版的代价线。** `12`:159 写「给 `cost` 时线由保形风险控制按代价求出」——**那要保形与代价同时成立，而保形今天在这批数据上拿不到有意义的证书**（noul α=0.10 被拒，`best_ucb 0.319`）。**先把经验版做出来，保形版等有证书的键出现再说。**

**一条把不变量和快照混在一起的断言，修对的那一刻它必然变红（同批第三个实例）。** `strength.rs` 原断「上界里每个字段都是数」——**那是当时的形状，不是不变量**；真正的不变量是「**判据必须是数、参考值不许是数**」，而它把两者一起断成了「都是数」。修掉那个漏洞（`仅供参考` 不再以裸浮点交给 J++ 程序，改交一段**看得见、打得出、比不了大小、做不了算术**的文字）时，这条断言当场红。**判别法：问这条断言保护的是一个不变量，还是一个当时的快照。**

**论据引了一件产物的性质，先问这件产物在不在那条路上（v0.2，2026-09-21 10:35 转正文；来源：独立校准顾问把四个实例收成一句）。**

**这是 §2.11 第四条的加宽**：第四条指着**字段**说「问这个字段的生产者是谁」，**这一条指着论据说**——

> **问这个论据引的东西，在不在它所论证的那条路径上。**

**五个实例，全部是本项目自己的**：
1. 「**账本是审计物**，所以两者不能是同一个值」——**出口根本不进账本**（`Entry` 只有 `Judge`/`Effect`/`Ask`），结论对，论据不在那条路上。
2. 「Fable 顾问停住是**额度耗尽**」——那个先验不在这次失败的产出路径上，实际是 502。
3. 「推测**搬的是站点不是值**，所以没有新边界」——证的是「值的来源」，**守卫链不在那条论证路径上**。
4. 「**责任归属可查**，就不必再加一道门」——引 `provenance()` 的一个性质，而 **`provenance()` 在 `src/` 下零调用点、出口无标记、trace 无告警**；结论可以讨论，**论据是空的**。
5. 「出口 taint 继承状态 taint，**一路带到 `do` 那里由 J-08 查**」——**J-08 根本不读 `Exit.taint`**，它读的是 `guards` 里的 `GuardInfo`。

**可执行检查（这条比记五个实例有用）**：**引一件产物的性质当论据时，落笔前 grep 一次它的调用点。**

**「论据错了但结论对」不是运气，是这个模式的常见形态**：结论往往由别的理由独立支撑着，所以它看起来没问题——**而下一次同样的论据被用在一个没有那个别的理由的地方时，就会错。** 实例 4 与 5 正是这样：4 支撑了一条后来被撤销的豁免，5 掩盖了 J-08 在 handler 臂上完全不生效这件事。

**一组测试可能只覆盖当时的写法，而覆盖率数字照样好看（v0.2，2026-09-21 11:00 转正文；来源：J-08 在 handler 臂上完全不生效而十一条守卫测试全绿）。**

**这是「快照型断言」那一族的另一面**：
> **一个断言可能只保护当时的形状；一组测试可能只覆盖当时的写法。**

实例：`tests/guard.rs` **十一条全对、全绿，而 J-08 在 `handle` 臂上完全不生效**——**因为十一条全走 `if`**，而 `self.guards` 只在 `ExprKind::If` 一处 push。**那一臂正是 §5 与 J-05 推荐的写法。**

**判别法：问这组测试覆盖的是「这条规则要管的所有到达方式」，还是「我写测试时想到的那种写法」。**

**同族的第三句（同一批落地里提炼）**：**一条曾经故意红、现在故意绿的测试，在一份「全绿」的报告里，和一条从没展示过任何东西的测试长得一模一样。** 故「展示缺口」的测试转成「保护缺口不再出现」时，**必须在文件头写明记录的是什么缺口、何时被什么机制堵上**——**不是为了礼貌，是因为两者在唯一被读的那个输出上不可分辨。**（来源：公开同步稿 §5）

**修这类洞时，真正的风险不在那几条正面测试上。** 实例：改完之后**每个 `handle` 都压一层守卫**，`guards.is_empty()` 在一大批以前为真的地方变成了假。**所以必须同时加一条「正常程序照常通过」的回归闸**——**没有它，就会发出一个把正常程序也拦住的规则，而且要等别人的测试才发现。**

**移植纪律。** 把原实现的「响亮失败」改成「防御性兜底」，往往是在悄悄削弱一条纪律。原实现敢直接索引、敢显式继承，本身就是一个判断：**该字段缺失不可能，若真缺失就该炸**。移植者看到会本能地「加固」，**而加固的方向若默认是放行，就是在逐个拆掉原作者设的闸**。问自己：原来那个会炸的地方，是作者疏忽，还是作者故意让它炸？

**为什么。** 六形式是 H §9(3) 独立推出的最小集，红队 06 B1 指出 v0 把 `fit` 混进了形式，改为桥库后形式回到六个。惰性是 A1 的直接后果。`transform` 是 A5 三个选项里成本最低的：它与「材料不可变、来源链」是同一条纪律的两面。taint 代数是 A6 三个反例的共同修法：taint 是效应的输出属性，不是材料上的可选标签。缓存键与账本键分成两张表，是 A4 四个反例逐条要求的。

## 4. 编译 pass（每个一个开关，给消融留门）

执行模型：解释器逐语句跑；效应登记不发；到一次**刷新点**（`cut`/`fit`/`match`/`if`/读内容/程序结束）时，取所有已登记且输入就绪的效应，按依赖排成层，跑下面的 pass，一层一次发出。

| 序 | pass | 做什么 | 依据 | 依赖假设 | 不做会坏什么 |
|---|---|---|---|---|---|
| 1 | 提升 `--lift` | 直线段内不依赖前面效应结果的 `judge` 提到同一层；**不跨分支**（分支还没走到，且含 `do` 的分支推测不安全） | P3 批无偏；A1 | — | 同段判断逐个发，层数 = 判断数 |
| 2 | 融合 `--fuse` | 同 `canon_json(state)`、同层的题合成一次调用；键按题不变 | P5 | H7 | E8：成本 +45% |
| 8 | 推测提升 `--speculate` | 刷新点向前推测同帧可求值的 `judge` 站点（含分支体）并入本层；真站点按（状态哈希, 题）命中；推错记 `W-spec-unused`；超预算先丢推测。**只推测 `judge`**：含 `gen`/`transform` 的站点仅在无条件直线可达时提前执行，分支/match 体内不推测 | P5、P3、I1 | — | 同状态的题分散在多层，层数 = 刷新点数 |
| 9 | 循环向量化 `--vectorize` | 宿主 `for` 体内无 `do`/`ask`/`return`/`break`、无 loop-carried 名字时，其余轮次在沙盒里重放前置语句、各自的 `judge` 登记进本层 | P5、E7 | — | 每轮各成一层 |
| 3 | 裂变 `--fission` | 对象槽单段超 `text_slots.usable_lower`、或槽间超 `json_slots` 时按窗切开，对象单独占位；合回按 op：test → exists/all，select → 分块 K-noul 再决（锦标赛只在 cmp 判据相对时），measure → 按出口计数 | P4、P24 | H6 | 带偏读数 |
| 4 | 下沉 `--lower` | `select` → choice（候选 token 在档案 `k_limit` 已测档内且 K 在档内，置换 ≥ 2 取众数）或 K-noul argmax（长候选或未测档）；`measure` → score（锚 ≥ `anchors.default_per_level`，对象单独渲染）；`test` → noul | E9b、E10、J-15 | H2 | 首位偏置直接进结果 |
| 5 | 调度 `--schedule` | 层内效应 DAG：`gen`/`ask` 一登记就先发（它们慢，不等刷新点）；`judge` 按层批发、并发按状态大小自适应（`profile.concurrency`）；`do` 按依赖并发；宽优先于深 | H §6.8；E10 SSL EOF | — | 时延与限流 |
| 6 | 预算 `--plan` | 计划期：按 J-07 的符号签名估调用数、钱、层数、gen 时延、unsure 上界，报 W-cost（笛卡尔积）、W-taint、W-window、W-untested，只告警不拒；层边界：按已知规模核 `budget`，超即停记 `Unsure(budget)` | P5；A1、B3 | H7 | 平方项在运行时炸 |
| 7 | 键与重放 `--ledger` | 生成账本键与缓存键；写账本头；重放不付费；`ask` 挂起后恢复即重放；`transform` 纯性核对 | P3；B2、B8 | — | 不确定 |

下沉阈值不是常量：`jv lower` 打印每题命中的档案字段与依据。

**为什么。** 跨分支提升被删，因为它需要静态图而我们选了惰性执行（A1），且 B3 指出它的目标函数会为少一层花任意多的钱。`gen`/`ask` 一登记就发，是 H §4 效应画像的直接用法：它们的时延比 `judge` 大一到三个数量级，等刷新点再发就把它们放回了关键路径。

## 6. Python 构建器

### 6.0 执行模型

`@jv.program` 内的代码**逐语句即时执行**。效应调用返回惰性句柄（`Readings`、`Mat` 期物、`[Mat]` 期物）；宿主可以随意把它们放进列表、传给函数。需要真值的那一刻（`jv.cut`、`match`、`if`、`.content`、`len()` 对期物列表）触发**刷新**：解释器取所有已登记、输入就绪的效应，按 §4 分层发出，然后继续。`gen`/`ask` 例外，一登记就发（§4.5）。
后果：Python 原生控制流全部可用；同一直线段内的多个 `judge` 自动同层融合；跨分支不提升；预算在层边界核；J-05 由出口的 `consumed` 标记在程序返回前核。整程序的静态估计只对可追踪的直线段做，其余在计划期给区间。

```python
import jv
jv.state(on=..., ctx=[...], ref=[...], over=[...])                 # §2.1
q = jv.test("题面", calib=jv.calib("键"))                            # Q；select / measure 同理，calib 挂在题上
jv.select("题面", calib=jv.calib("键"), prior=jv.prior.pass_count)   # 策略是参数

r = jv.judge(state, q1, q2, ...)          # Readings（惰性）；jv.judge([s1, s2, ...], q) 向量化
e = jv.cut(r[i], cost=(fp, fn))           # Exit；校准取自题，cost 可选；刷新点
jv.fit(jv.fitref("名"), r[a], r[b])       # 桥库；输出仍要 cut
jv.gen(prompt, ctx=[...], n=8, retry_seq=k) ; jv.do(action, *args, iter_seq=k) ; jv.ask(state, q)
jv.transform(f, *mats)                    # 宿主材料变换，记账
for it in jv.loop(bound=8, variant=jv.decreasing(lambda: len(xs))): ... it.n ...
match e: case jv.Act(): ... ; case jv.Ignore(): ... ; case jv.Unsure(u): ...      # u 是未决责任本身，不是原因字符串
handle(e, {act: …, ignore: …, unsure: fn(u) { … }})                  # unsure 臂必须显式，通配兜不住（13 §3）
# 未决责任 u 的四条合法去向（13 §3；本行替代旧的 jv.consume(exits, unsure=jv.drop|jv.escalate)）：
escalate(u, state, 题)        # 交给人，效应 ask，计入 budget.escalate
literalize(u, state, 更字面的题)  # 重问，效应 judge；只表示走了这条受检路径，不保证新题更字面
consume(u, "drop")            # 显式丢弃并记账，trace 留 W-drop-vs-escalate
# 或：包进本臂的返回值交给调用者——返回类型须含 Exit，否则 W-untyped-transfer（补齐标注后升 error）
unsure_cause(u)               # 只读原因文本，不构成处理
jv.on_truth("键", fn) ; jv.on_fail(expr, alt)
@jv.program(budget=jv.Budget(calls=..., cost=..., layers=..., escalate=..., unsure=...))
```

### 6.1 六条程序（即时执行语义下重写）

> **〔标注，2026-09-21 08:20〕本节六条程序是 Python 构建器的写法，不是 `.jpp` 的写法。**
> 两者在**未决责任**这一点上不同，而且这份文件里两种都在：
> - **本节（Python 构建器，冻结作行为对照）**：`Unsure(cause: str)` 的 `cause` 是**原因字符串**，`jv.handle(c, then=jv.escalate)` 收的是那个字符串。**这仍是 Python 侧的真实 API**（`foundation/jv/ir.py:722`、`__init__.py` 的 `handle`），照抄能跑。
> - **上面 §6 速查（`.jpp`，当前正式实现）**：走 `13` §3 的责任协议，`unsure: fn(u)` 收到的是**未决责任本身**，不是原因字符串；`unsure_cause(u)` 才是只读原因文本，而且读原因**不构成处理**。
>
> **两边都对，但对的是不同的目标。** 不标出来，照 §6.1 去写 `.jpp` 的人会写出跑不通的程序——**而这正是「一份文件里两个说法，实际生效的永远是读者先翻到的那一个」。**

```python
@jv.program(budget=jv.Budget(calls=40, cost=0.02, layers=8, escalate=1))
def 定位回归(repo, good, bad):                                        # 二分：有序列表是宿主的

        mid = cands[len(cands) // 2]

            case jv.Act(): cands = cands[: cands.index(mid) + 1]
            case jv.Ignore(): cands = cands[cands.index(mid) + 1 :]
            case jv.Unsure(c): jv.handle(c, then=jv.escalate)
    return cands[0]
```

```python
    忠实 = jv.select("哪个 docstring 最忠实地描述了这段代码？", calib=jv.calib("doc.忠实"), prior=jv.prior.none)
    通过 = jv.test("测试报告显示全部通过吗？", calib=jv.calib("test.全过"))
    fs = jv.transform(ast_functions, repo)
    过 = jv.cut(jv.judge([jv.state(on=jv.do(run, "pytest -q", repo, f, iter_seq=0)) for f in fs], 通过))   # 一层
    jv.consume(过, unsure=jv.drop)                                                       # 跑不过或拿不准的不改
    out = {}
    for f, e in zip(fs, 过):
        if not isinstance(e, jv.Act): continue
        vers = jv.gen("为这个函数写一句 docstring", ctx=[f], n=3, retry_seq=0)
        match jv.cut(jv.judge(jv.state(on=f, over=vers), 忠实)):
            case jv.Pick(k): out[f] = vers[k]
            case jv.Unsure(c): jv.handle(c, keep=None)
    return out
```

### 6.3 自举易错模式（J-17，检查器报文直接回喂生成器）

| 模式 | 拦截 | 报文修法 |
|---|---|---|
| `e = jv.judge(s, q)` 后直接 `match e` | 类型：`Readings` 不是 `Exit` → J-01 错 | 「judge 返回读数向量，取 `[0]` 再 `jv.cut`」 |
| `if e == jv.Act:` | 类型比较非实例 → warn W-cmp-type | 「用 `match` 或 `isinstance(e, jv.Act)`」 |
| `r1 > r2` | J-01 错 | 「读数不可比；同题跨对象用 `.order()`，出口用 `jv.cut`」 |
| 循环里 `jv.do(run, c)` 不带 `iter_seq` / `jv.gen(..., retry_seq=0)` 常量 | J-13 错 | 「用 `it.n` / `range` 变量作序号」 |
| `jv.cut(r, calib="perf.慢了")` 传字符串 | J-03 错 | 「用 `jv.calib("perf.慢了")`，或把 calib 挂在题上」 |
| 期望 `for c in cands: jv.do(...)` 并发，但后一次依赖前一次结果 | 调度 pass 发现串行依赖 → warn W-serial | 「依赖链使 do 串行；无依赖请先收集句柄再刷新」 |

**为什么。** 六条程序在即时执行下几乎不用改写，证明 A1 的选择对：宿主控制流本来就是这样用的。多出的 4 行全是把「愿望」（重放、unsure 不丢）变成「可核」的代价。§6.3 是自举（H §7）的第一道门：生成器写错的六种模式要能被检查器指着说怎么改。

> **附注（总控提议，2026-09-21 02:45，待 Nature 认）：补一条实现层的通则「兜底值要往拒绝那边倒」。** 来源：Rust 内核实测连抓两条同形状的缝，**两条都是把三值静默压成两值**——
> 1. `("==", _, _) => Bool(l.equals(&r).unwrap_or(false))`：`equals` 返回 `None` 是「**不可比**」的信号，`unwrap_or(false)` 把它吃成「**不相等**」。顶上那道 J-01 只拦裸读数，读数一装进容器就从这条缝漏过去。
> 2. `json_to_effect_value` 反序列化材料时 `taint` 解析失败一律 `.unwrap_or(Taint::Trusted)`：**一份 untrusted 材料经账本往返回来会变成 trusted**。
>
> **第二条比第一条重，理由不是更容易触发，是丢的东西不同**：第一条丢的是一个比较结果；第二条丢的是**来源可信度**，而 §2.11 的整个 taint 代数、以及宪法登记表 IFC 那行唯一那条纪律「不可信材料上的判断不得单独放行不可逆 `do`」，全都建在这个字段上。**一个被洗白的材料之后走到哪里都是干净的，没有任何地方会再发现。**
>
> **补充（总控自查）**：Python 侧**没有**这个洞——`foundation/jv/store.py:97` 反序列化材料用的是直接索引 `taint=ev["taint"]`，字段缺失当场 KeyError，响亮地失败。**这个洞是移植时新引入的。** 故一并提议第二句：**移植时把原实现的「响亮失败」改成「防御性兜底」，往往是在悄悄削弱一条纪律**——原实现敢直接索引本身就是一个判断（该字段缺失不可能，若真缺失就该炸）；移植者的本能是「加固」，而加固方向若是放行，纪律就没了。**问自己：原来那个会炸的地方，是作者疏忽，还是作者故意让它炸？**
>
> 这两条正是宪法登记表第 30 行「SQL 三值 WHERE（反面）：三值在 WHERE/CHECK 被隐式打成两值，三十年的坑」的同一个错——**我们在自己的解释器里犯了这门语言存在的理由所要防的那件事**。清单式的防法（记得哪些地方要小心）挡不住它，因为失效方式是静默的。
>
> **第三条（2026-09-21 03:00 补）：`mat(content(脏))` —— 不需要账本往返，三行源码就能洗白。** `content` 把材料拆成裸值（taint 与 origin 留在壳上），`mat` 包回去走字面量路径给 `Trusted`。前一条要材料经账本序列化往返才触发，**这条是语言里现成的一条路径，写两行就走到了**；宪法 IFC 那行唯一那条纪律在这条路上不会报错，只是失效。已修：`content` 拆 untrusted 材料时记下内容，`as_mat` 的字面量兜底臂遇到它包成 `Untrusted`（`origin = ["unwrapped"]`），并配**反面测试**保证源码里的 `mat("字面量")`、`mat({记录})` 仍是 trusted——**判断标准是「这份内容是不是从 untrusted 材料里拆出来的」，不是「有没有经过 `mat()`」**。
>
> **三条合起来，共同点不是「用了 `unwrap_or`」**——第三条根本没用 `unwrap_or`，它是一个 `_ =>` 兜底臂。共同点是：**在一个说不准的地方，替不确定/不可信做了乐观的默认**。所以下面这条通则的适用面比 `unwrap_or` 宽，**只 grep `unwrap_or` 不算查干净**。
>
> **第五条（03:00 补，最重的一条）：`cut` 把状态的 taint 扔了。** `12`:150 原文「**出口 taint 继承状态 taint**」，§2.11 的代数同样写「cut 继承」；而实现里是 `let taint = Taint::Trusted;`——**一份不可信材料上的判断，切出来的出口是可信的**。后果最重：宪法登记表 IFC 那行唯一那条纪律「不可信材料上的判断不得单独放行不可逆 `do`」，**因为判断的结论根本不带这个标记而连抓手都没有**；前四条至少还能在别处看见 taint。**它也不是「没实现」，是算好了又丢掉**——`State::new` 早把四个槽的 taint 折算好存在 `State.taint`，只是 `Reading` 没带过来。**前四个是「传不动的地方默认成可信」；这个是「传得动，但中途断了」。**
>
> **必须同时写进通则的一条区分，否则这条规则会制造假拒绝**（实现者走完全部路径后给出，总控认为它是这条规则可用与否的关键）：
> - `fold(Trusted, join, mats.taint)` 里的 `Trusted` 是**单位元**——只要有一个入料脏，结果就脏。**正确。**
> - `let taint = Trusted;` 是**兜底值**——它替不可信说了「可信」。**这才是 bug。**
>
> **同一个字面量，两种角色，只有后者是错的。** 不做这个区分，按本通则扫一遍会把 `transform` 输出、`gen` 输出两处**正确的折叠**也当成缺口改掉——那就是假拒绝。判别法：**问这个值是「折叠的起点」还是「说不准时的替代」。**
>
> **提议写进 §2.11 或 §3 作实现层通则**：**兜底值要往「拒绝」那边倒，不往「放行」那边倒；在任何「说不准」的分支上先问一句「这个默认值是在替谁说话」——替不确定说「确定」、替不可信说「可信」，就是把三值打成两值。** 同时配反面测试防假拒绝：**判断标准是「这个值的来源是什么」，不是「它经过了哪个函数」。** 落地形状照 `Reading::answer_after_flush()` 的先例：把判据摆到调用点上，不指望作者记得去查条文。
