角色说明：本文作者只读了 `11-语言规范-v1-草案.md` 这一份文件，没有背景知识、没有看仓库里任何其它文档、没有联网、没有改任何文件。以下是纯粹按这一份文件推出的理解与产物。

## 一、我读完之后的理解

这是一门给"要不要相信一个模糊判断"这件事写死流程的编程语言：程序不直接写业务逻辑的分支条件，而是把每一个需要"读材料、下判断"的地方声明成一道有类型的问题（判断是非用 attr/rel、挑选项用 cmp/decide/mention/class、挑子集用 subset、打分档位用 degree、判断材料够不够用 enough），问题作用在一份叫 Mat 的材料上，答案只有三种出口——act（是）、ignore（否）、unsure（不确定）——绝不允许把"不确定"偷偷二值化成是或否；每个用到判断的地方都必须显式写清楚 unsure 时去哪儿（重新拆材料、换语境、升级给人、放弃这轮循环等）。除了这些"问题守卫"之外，剩下的代码全是确定性的：普通函数（s pure/do）、赋值、循环、集合映射，这些和判断本身不产生新的不确定性，所以整个程序理论上能逐字节重放。写一个程序的过程，就是先声明预算（花多少次调用、多少钱、多少层、多少次升级），再声明会用到的几道问题和几个函数，然后用 if/select/switch/while/choose 这几种控制结构把问题当"守卫"接进去，每次接入时说清楚三个出口分别走哪条分支、以及 unsure 走哪条兜底路径；至于问题的原始文字提示怎么拼、材料怎么渲染成看得懂的格式，都交给编译器按固定的四个槽位（对象/语境/候选/参照）自动拼，程序员不手写提示词字符串。

## 二、三个程序（§2 文法）

### a. 合同里找出对甲方不利的条款并按严重程度排序

```
program 甲方风险条款(合同: Mat) -> Set {
  budget calls <= 200, cost <= $0.02, layers <= 1
  q 不利 : attr = "这条条款对甲方不利吗？"
  q 严重 : degree[低 < 中 < 高] anchors 风险锚 = "这条条款对甲方不利的严重程度"
  let (不利条款, 有利条款, 疑) = partition 不利(on: 条款) over split(合同, 200)
  return rank(严重, 不利条款) with 疑
}
```

### b. 客服对话判断流失边缘并选挽留话术

```
program 客服挽留(对话: Mat, 话术库: Set) -> Mat {
  budget calls <= 10, cost <= $0.01, layers <= 2, escalate <= 1
  q 流失 : attr = "这段对话显示客户有明显的流失倾向吗？"
  q 最合适 : decide = "针对这位客户当前的状态，哪条话术最合适？"
  if 流失(on: 对话) { return take(最合适, 话术库, 对话) } else { return "无需挽留" }
  unsure -> drop then escalate
}
```

### c. 从简历里为岗位挑最匹配的三份并说明理由

```
program 挑简历(岗位: Mat, 简历库: Set) -> Set {
  budget calls <= 60, cost <= $0.02, layers <= 2
  q 匹配度 : degree[低 < 中 < 高] anchors 匹配锚 = "这份简历与岗位描述的匹配程度"
  s do 写理由(简历: Mat, 岗位: Mat) -> Mat = "s/写理由.py"
  let 前三 = top(3, 匹配度, 简历库)
  return for r in 前三 yield r with 写理由(r, 岗位)
}
```

## 三、我写的时候卡住的地方（逐条标行号/章节）

1. **§2 第 55 行 `stmt ::= "let" ID "=" expr` 与 §9 的示例互相矛盾**：形式文法里 `let` 只能绑定单个标识符，但 9.2（约第 304 行）、9.3（约第 315 行）、9.10（约第 392 行）全部写的是 `let (a, b, c) = partition ... over ...` 这种三元解构。到底该照哪一个来写，规范正文没交代；我最后选择照示例（元组解构）来写，因为 partition 本身语义上就是三流输出（§4.5，第 139 行），不解构几乎没法用，但严格来说这不合 §2 的 EBNF。

2. **§4.6（第 143–153 行）的去向表用的是自然语言，`dest` 枚举（§2 第 65 行：escalate/refine/drop/continue/regen/anchor/skip）没有明确哪个词对应哪一行**。比如"动作"这一行写的是"不执行，记账"，我猜是 `drop`，但也可能是 `skip`——两个词在枚举里都存在，规范没给对照表，纯靠字面猜的。

3. **组合子的调用写法只给了 9 个具名的（§6.4，第 231–241 行），"top k" 只在 §4.7（第 159 行）的聚合子清单里提过一句话，没有函数签名、没有任何示例**。我在程序 c 里自己发明了 `top(3, 匹配度, 简历库)` 这种调用形式，规范里完全没有依据；如果这不是合法调用，我不知道正确写法是什么。

4. **`partition` 里 `on:` 槧位怎么"逐元素自动绑定"没有明文规则**。9.2/9.3/9.10 都是 `partition q(on: x, ...) over S`，x 看起来会自动对应 S 里的每个元素，但规范没有一句话说明这个绑定机制（是按名字匹配？按位置？），我是靠三个示例反推的，不确定是不是巧合。

5. **字符串字面量能不能直接当 `Mat` 返回，没有强制转换规则**。9.9（第 382 行）写 `return "破坏" with diff(前, 后)`，把裸字符串和 Mat 用 `with` 拼在一起；§3.1（第 84 行）说 Mat 是"唯一材料类型，带地址、来源链、渲染函数"，裸字符串显然没有这些东西。我在程序 b 里也直接 `return "无需挽留"`，但不确定这样类型对不对，规范没有讲字符串到 Mat 的隐式转换。

6. **§6.1（第 219 行）S 库里 `split`/`sample`/`neighbors` 等函数完全没有参数含义说明**。9.2 用 `split(msg, 80)`，我在程序 a 里用 `split(合同, 200)`，第二个参数到底是"按多少字切"还是"切成多少块"还是别的单位，规范一个字都没提，纯靠猜。

7. **`degree` 的锚（anchors）在程序里怎么"声明内容"完全没写**。§6.3（第 227 行）只说锚来自"参照库"，但一个新手要怎么往参照库里放"风险锚""匹配锚"的具体锚点样例，规范里没有任何语法或流程——好像这一步整个在语言之外，靠某个我没看到的外部系统完成，我只能在程序里写一个标识符占位。

8. **`Map` 类型的定义和示例自相矛盾**。§3.1（第 85 行）明确写 `Map = Map[Mat, 出口]`，也就是值只能是 act/ignore/unsure 这三种出口；但 9.4（第 322–326 行）的 `分类日志` 程序返回类型是 `Map`，`yield` 出来的却是 `类别(on: r)` 这个 class 题的标签结果，注释里还写"class 出口即标签"——这跟 §3.1 的定义不是一回事。我因为吃不准这条矛盾，程序 c 干脆没敢用 `Map`，改成了 `Set` + `with` 拼接，绕开了这个类型到底能不能装"任意标签/文本"的问题。

9. **在 `for … yield` 这种"纯映射"里能不能调用 `s do`（会触碰真实世界、会失败的函数）没写清楚**。§4.5（第 138 行）只禁止"体内对外层变量赋值"（E8），没提是否允许调用有副作用的 do 函数；但 §4.5 又说这一层的意义是"同层判断由调度器融合并发"，如果体内混了 do 调用，融合优化还成不成立，规范没说。我在程序 c 里还是在 `for … yield` 里调了 `写理由`（一个 s do），不确定这算不算滥用这个结构。

10. **一道 `degree` 题能不能直接套在一整个候选集合上取排名，规范没有直接示例**。9.10 是先 `partition` 出一个子集再对子集 `rank`，我在程序 c 里是想对整个 `简历库` 直接跑 `匹配度` 再取 top 3，规范里没有"degree 题直接作用于一个 Set、然后聚合"这种模式的示例，我不确定这是不是合法/惯用的写法，还是必须先经过某种切分。

## 四、一句话评价

不能——这份规范里真正立住脚的是形式文法（§2）和错误规则表（§3.3、§4.6），但一半以上"怎么把语义操作接成一个能跑的程序"的知识（元组解构、组合子调用形式、锚怎么落库、标准库函数签名）只存在于 §9 的十五个示例里、而且这些示例本身还跟正文条款互相矛盾，新手不靠人解释、只靠通读这份文件，写不出一个自己确信没有猜错的程序。
