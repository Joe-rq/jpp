## 零、先说结论

**保形风险控制在我们今天这批数据上给不出任何可用的线。** 三种题型上能认证到的最紧风险上界分别是 **0.319 / 0.269 / 0.251**（noul / choice / score，δ=0.10），也就是说任何「假放行率 ≤ 20%」的目标都无解。**〔适用范围，2026-09-21 09:20 与全文其余「0.319/0.269/0.251」同一处补：这三个上界算在 E-CAL 那 202 条真值上，而那 202 条在定义上是「两个模型都同意」的子集（202/202=100%，未标注 95 条里只有 77/95=81.1%）——若同意与否与对错相关，这三个上界同向乐观有偏，即真实上界可能更差。见 `foundation/experiments/前提结论.md`「选择偏倚」节。〕** 这不是实现没写好，是数据不够——而**不够在两个不同的地方，修法完全相反**：

- **noul 是样本量不够。** 它的最紧上界那一格（线 0.775）放行 6 条、**一条都没错**。零错时认证 α=0.10 需要放行区有 **22** 条、α=0.05 需要 **45** 条（`ln δ / ln(1−α)`，与数据好坏无关）。
  **〔2026-09-21 08:50 订正〕** 我原先在这里写「所以 noul 有一条终点明确的路：再标到高读数区有 22 条且仍零错」。**写预注册时去数那 22 条在哪，结果是它们不存在**：noul 一共只有 100 条，`p ≥ 0.775` 的**总共 7 条**（6 条已标 + 1 条未标），**把 100 条全标完仍然是 7 条**。按 7/100 的出现率凑 22 条要约 **315 条新读数**，且必须落在新片段上——**那是一次新实验，不是一次标注**。而且放行区只有 **6 个不同对象段**，簇级最小可认证的 α 是 `1/7 = 0.143`，**α=0.10 在 6 个簇上无论如何认证不到**。终点仍然明确，**但不在标注那条路上**。详见预注册 `foundation/experiments/EXPERIMENTS.md` 的 E-NOUL-HI。
- **choice 是读数本身不够准。** 它最紧那一格放行 18 条、错 2 条，经验假放行率 **0.111**。这是渐近值：**再多的标注也认证不到 α=0.10**。要动的是读数，不是标注集——这与 E-CAL-0 的「校准是字面化程度的函数」（P1/P10）是同一件事。
- score 居中：经验率 0.071，α=0.10 渐近可达、α=0.05 不可达。

所以这份设计交的不是「一条保形线」，是**一道证书门**：认证得到就给线，认证不到就**拒绝，并把差多少一起说出来**。拒绝是一等出口，不是错误。

**而这份东西里最该先读的不是上面那三个上界，是 score 那一行**（详见第一节）：

> **条级 α=0.30 有解；簇级 200 次重采样，0 次有解。**

同一批数据、同一个方法、**只换计数单位，结论从「有」翻到「没有」**。这是「把同一段落的多条读数当成多次独立观察会**凭空造出一个保证**」的当场证据。本项目在别处反复撞的「恒真项不是测量」「构造测试不是功能测试」，**这是它在统计上的那张脸**。

## 一、可交换性是被材料复用打破的，不是被时间

论文里可交换性通常是被时间打破的（分布漂移）。**我们这里先被打破的是另一件事：标注集里的条目不是独立单位。**

E-CAL 那 297 条读数只由 **61 个不同片段**重组而成，片段出现总次数 533，其中 6 个片段各出现 13 次、6 个各出现 15 次、最多的一个出现 23 次。只有 18 个片段是只用过一次的。

把「判断的对象」作为独立单位（`segments[0]`，题问的就是这一段），有真值的 202 条落在 **53 个不同对象段**上：

| 题型 | 有真值条数 | 不同对象段 | Kish 有效 n |
|---|---|---|---|
| noul | 73 | 36 | **24.3** |
| choice | 74 | 37 | **28.8** |
| score | 55 | 28 | **18.8** |

Kish 有效 n 用的是 `(Σmᵢ)² / Σmᵢ²`（mᵢ = 第 i 个对象段被用了几次），它回答的是「在簇内完全相关的最坏情形下，这批样本相当于几个独立观察」。**18.8–28.8，正好落在 17–26 附近**——这是我自己量出来的，不是接受一个前提。

**怎么知道我对了。** 换一种计数方式看结论会不会翻：把「一条读数」换成「一个对象段」（每簇随机取一条），重做认证 200 次：

| 题型 | 条级（n=73/74/55）α=0.30 有解？ | 簇级 200 次重采样里有解的次数 |
|---|---|---|
| noul | 否 | **0 / 200** |
| choice | 是 | 55 / 200（28%） |
| score | **是** | **0 / 200** |

**score 那一行是最干净的实例**：按条数算，α=0.30 有解；按独立单位算，200 次重采样一次都没解。**把同一段落的多条读数当成多次独立观察，会凭空造出一个保证。** 这与「兜底档案的 `hash` 必须是 `None`」是同一条纪律的另一面——那一条说的是不能让两种情形在账本上分不开，这一条说的是不能让一次观察在账本上记成多次。

**由此定的机制**：校准记录的 `set_id` 必须同时记**分簇单位**（这里是对象段），保形分位数按簇取。不记分簇单位的标注集，其 n 不得用于任何有限样本计算。

## 二、δ 非单调：档案里有痕迹，但那个痕迹说的是另一件事

`jev-1.13.0.json` 的 `delta` 有四栏，每栏两种时序（`immediate` / `after_gap`）、三个摘要（p95 / p99 / max）。**四栏里有两栏的 p95 与 p99 方向相反**：

| 栏 | n | p95 | p99 | max |
|---|---|---|---|---|
| noul | 420 → 140 | 0.0300 → 0.0305 ↑ | 0.0400 → 0.0461 ↑ | 0.050 → 0.070 ↑ |
| choice_prob_chosen | 120 → 40 | 0.0600 → 0.0500 **↓** | 0.0781 → 0.0866 **↑** | 0.110 → 0.110 |
| choice_confidence | 120 → 40 | 0.0805 → 0.0705 **↓** | 0.1162 → 0.1288 **↑** | 0.180 → 0.160 ↓ |
| score | 60 → 20 | 0.0800 → 0.0710 ↓ | 0.1141 → 0.0862 ↓ | 0.120 → 0.090 ↓ |

**但在断言「δ 非单调」之前要先问这个 p99 是什么。** `after_gap` 的 n 是 140 / 40 / 40 / 20，而第 ⌈0.99n⌉ 个顺序统计量在 n=40 与 n=20 上**就是最大值本身**：

| 栏 | 时序 | n | p99 落在第几个 | 离最大值差几个样本 |
|---|---|---|---|---|
| choice_prob_chosen | after_gap | 40 | 第 40 | **0** |
| choice_confidence | after_gap | 40 | 第 40 | **0** |
| score | after_gap | 20 | 第 20 | **0** |
| noul | after_gap | 140 | 第 139 | 1 |

所以那两处「p95 降、p99 升」的翻转，**在算术上就是「大多数样本靠拢了、而单个最大值更极端了」**。这两种解释——「δ 随时间非单调」与「n=40 的最大值是噪声」——**这份档案分不开**。

**诚实的答案是：档案既不证实也不证伪 δ 非单调。** 但它证实了另一件更该管的事：**「δ 单调」这句话在不指定分位数时根本不成立**，同一栏里 bulk 和 tail 可以反向。而 Rust 侧 `Profile::from_json` 今天只读 `immediate.p99` 一个数——**一个 n=120 上的次大值**，并且从不读 `after_gap`。今天不咬人是因为迟滞那条路还没实现；**谁实现它，读到的就是 n=20 的最大值**。

**由此定的机制**：档案里的 δ 不许以单个标量的形式被读走。`Profile` 读 δ 时必须同时读 `n`，并且 `n < 50` 的格子要带上「这个分位数就是最大值」的标记——**这一位与 J-15 同族**（见第四节）。

## 三、阈值 = 代价 + 风险控制：代价决定**定在哪**，保形决定**给不给**

现有的是 `foundation/jv/calib.py::cost_line`：在标注集上找使经验代价 `fp·#误放行 + fn·#漏放行` 最小的阈值。它的 docstring 自己写明「保形风险控制的有限样本修正是第 7 步校准库的事」——**这份设计就是那第 7 步**。

两者在什么输入上给出不同的东西，实测：

| 题型 | `cost_line(fp,fn)` | 线 | 放行 | 经验假放行率 | 保形能给什么 |
|---|---|---|---|---|---|
| noul | (1,1) | 0.590 | 50/73 | 0.300 | α=0.30 **无解** |
| noul | (5,1) | 0.780 | 6/73 | 0.000 | 上界只能压到 **0.319** |
| choice | (1,5) | 0.000 | 74/74 | 0.243 | α=0.40 有解（线 0.000，与代价线重合） |
| score | (5,1) | 0.700 | 14/55 | 0.071 | 上界只能压到 **0.251** |

**分叉点很清楚：代价线永远给得出一条线；保形在样本撑不住目标时给不出。** 当风险目标松到样本撑得住（choice α=0.40），两者重合；当目标比样本能认证的紧（其余全部），代价线照样交出一个看起来能用的数，而**那个数背后没有任何有限样本保证**。noul 的 (1,1) 那一行最刺眼：线 0.590、放行 50 条、**经验假放行率就有 0.300**，程序拿到的是一条「过线即放行」的线，没有任何东西告诉它这条线放行的东西三成是错的。

**由此定的机制**，两件事分开，都不重复造：

1. **代价矩阵继续决定线定在哪。** `cut(r, calib, cost=(fp,fn))` 与 `cost_line` 原样保留，它们回答的是「fp 和 fn 哪个更贵」——那是作者的偏好，保形没有资格替它回答。
2. **保形证书决定这个键能不能上岗。** `CalibRecord.status` 从 `冷` 变 `上岗` 需要一张证书；没有证书就留在 `冷`。这正好接上已经定下的形状：**不付证据的钱，就拿不到强出口**——`冷` → `cut` 给 `unsure(cold)` → J-15 那一位亮 → 告警。

这条分工的好处是它**不新增任何出口种类**：证书是 `put` 的前置条件，不是 `cut` 的新分支。

**一处容易混的地方，实测钉住。** 认证成功时给出的线是「**最宽的、仍被认证住的那条**」（RCPS 的做法：放行越多越好，只要风险还压得住），而它与「**上界最紧的那一格**」不是同一格——上界在阈值上不单调：

| 题型 | 松到有解时的**认证线** | 上界最紧的那一格 |
|---|---|---|
| choice（α=0.40） | hi=0.000，放行 74/74，上界 0.319 | hi=0.615，上界 **0.269** |
| score（α=0.40） | hi=0.655，放行 18/55，上界 0.396 | hi=0.700，上界 **0.251** |
| noul（α=0.45） | hi=0.295，放行 64/73，上界 0.447 | hi=0.775，上界 **0.319** |

所以拒绝时报的 `best_hi` **不是**「把 α 放松一点就会拿到的那条线」，它是「这批数据能给出的最好证据在哪」。两者混为一谈会让人以为只要把 α 调到 0.32 就能拿到 noul 的 0.775 线——实际拿到的是 0.295 那条，放行 64 条里错 23 条。

## 四、漂移监控：与 J-15 那一位**不是**同一族，但有两格是

先把三个状态摆开，它们今天在 Rust 侧已经是三个不同的出口，不该合并：

| 状态 | 含义 | 今天的出口 |
|---|---|---|
| **未测**（J-15） | 这个量在本次路径上**从来没被测量** | `cause` 不变 + `Exit.untested = Some(载体)` + `W-untested` |
| 测了、过检 | 线可用 | 正常出口 |
| 测了、**而且测出漂了** | `status == 停岗` | `unsure(drift)` |

**`drift` 和 `untested` 取值相反**：一个是「测过并且结果是坏的」，一个是「根本没测」。合并它们会让「这个键从没被监控过」和「这个键被监控出问题了」在账本上分不开——正是 `tie` 兼职那条已经裁过的毛病。

**但监控本身今天不存在，而且缺得比想象中更彻底。** 实测三条：

1. `foundation/jv/calib.py` 的 `CalibRecord.drift_stat` 是**声明了从不算的字段**。全仓唯一写它的地方是 `e_cal_写校准记录.py:210` 的字面量 `"drift_stat": 0.0`，三条已落地的校准记录里它全是 `0.0`。
2. `foundation/core/calib.py::should_suspend` 确实有停岗逻辑，**但它在另一个系统里**（`core` 从不 import `jv`；`jv` 只从 `core` 取 `canon`/`ledger`/`log`，不取 `calib`/`escalation`），而且它**要标签**——判据是 act 区错误率与 ignore 区漏放率。
3. `12`:410 要的是**无标签**监控：「读数分布偏移 + 保形覆盖跌落告警」。**两个系统都没有。**

**所以「必备」二字指的是一个真空。** 原型里给了最小实现：两样本 KS 统计量 + PSI，都只用读数、不用真值，所以**每次运行都能算**，不必等真值回填。

**而 J-15 那一位在这里有两格用武之地，都不必新造机制**——它们是「被声明为判据、但在本次路径上没有被测量的量」的两个新载体：

| 新载体 | 什么时候亮 | 为什么不是 `drift` |
|---|---|---|
| `drift_monitor` | 这个键有线，但漂移监控**从来没跑过** | 没跑过 ≠ 跑了没报警 |
| `conformal_line` | 线是代价线定的，**没有保形证书** | 没证书 ≠ 证书说它坏了 |

两者都**不新增 `cause`、不新增 §5 路由行**：`cause` 仍是 `cold`（线不可信 → 保守线 + 标记），那一位挂在旁边。这是 J-15 加宽措辞的直接用法——五个载体一条规则管完，现在是七个。

**监控自己也要有那一位。** 原型的 `DriftReport` 带 `underpowered`：KS 统计量小于 α=0.05 临界值 `1.36·√(1/n₁+1/n₂)` 时，这个数算得出来但不该拿去停岗。**没有这一位，一次 20 条的抽样就能把一个键停岗**——而停岗按设计是人下的判断、不自动复岗，代价是不对称的。

## 五、有限样本：在 n≈20 上还剩多少保证

三个数，从弱到强：

**第一，最小可认证的 α 是 `1/(n+1)`。** 这是顺序统计量的硬下限，与数据好坏无关。n=20 时是 **0.048**：**在 20 个独立单位上，你连「风险 ≤ 4%」这句话都说不出口，更不用说验证它。**

**第二，Hoeffding 在这个尺度上是空的。** 松弛 `√(ln(1/δ)/2n)` 在 n=20、δ=0.10 上是 **0.240**。任何低于 24% 的风险目标，用 Hoeffding 界得到的结论是「不知道」。所以原型用的是**精确二项上界（Clopper–Pearson）**——损失本来就是 0/1，没有理由做次高斯放缩。

**第三，保证是「对标注集抽取平均」的，不是「对这一个标注集」的。** 条件覆盖服从 `Beta(n+1−l, l)`，`l = ⌊(n+1)α⌋`。要 90% 覆盖时：

| n | α=0.10 下条件覆盖的 10% 分位 |
|---|---|
| 20 | **0.819** |
| 26 | 0.858 |
| 73 | 0.860 |
| 297 | 0.880 |

**在 n=20 上，十次里有一次你的实际覆盖低于 82%，而你要的是 90%。** 报「平均覆盖 90%」而不报这一列，就是结论把注意力从依据上引开。

**这三个数都是上限，真正咬人的是别的。** 前面第零节那张分解：noul 卡在样本量（零错区只有 6 条），choice 卡在读数准确度（渐近 0.111）。所以：

| 题型 | 当前最紧上界（**实测**） | 该格放行/错 | 经验假放行率 | 外推：经验率不变时的极限（**不是界**） | 结论 |
|---|---|---|---|---|---|
| noul | **0.319** | 6 / 0 | 0.000 | **未知**——6 条零错撑不出一个极限 | 见下 |
| choice | **0.269** | 18 / 2 | 0.111 | ≈0.111 | **买标注解决不了**，要动读数 |
| score | **0.251** | 14 / 1 | 0.071 | ≈0.071 | α=0.10 外推可达、α=0.05 不可达 |

**这三个上界的适用范围同第零节**：算在「两模型都同意」的 202 条真值子集上，同向乐观有偏，见 `前提结论.md`「选择偏倚」节。

**「外推」那一列不是测量，是在「放行区的经验错误率不随 n 变」这个假设下的推算，而那个假设在 n=6/18/14 上根本没被检验过。** 尤其 noul 那一格：6 条零错**与「真实错误率高达 32%」完全相容**——那正是同一行左边 0.319 说的话。在「极限」一栏里写 0.000，等于用一个 6 样本的经验值去否掉自己算出来的界。**所以那一格写「未知」。**

**noul 的结论不靠外推也成立**，靠的是两个硬数：它最紧那一格**零错**，而零错认证到 α=0.10 需要放行区有 **22** 条、到 α=0.05 需要 **45** 条（`ln δ / ln(1−α)`，与数据好坏无关）。当前是 6 条。

**〔订正〕** 我原先由此推出「对 noul，『再标注』是一条有明确终点的路」。**这一步推错了**：`p ≥ 0.775` 的条目在整个 noul 里**总共只有 7 条**，全标完也到不了 22。noul 卡的确实是样本量，**但缺的是高读数区的材料，不是那批材料上的标注**——两者的价钱差三个数量级（约 315 条新读数 + 315 条人标，对 1 条人标）。而对 choice，经验率 0.111 已经压在 α=0.10 之上，**连新材料也不改变这一点**。这个分别仍是本设计最该被记住的一条，只是「noul 那条路」比我原先写的长得多。

## 三·二、证书门站在哪一步：`待真值 → 上岗`（实测，2026-09-21 补）

`rust-core-3` 的 `324786d` 把**生产端**补上了：`CalibStore::absorb` 收样本，无标注的观察只把 `冷` 推到 `待真值`、`n` 不动——它自己堵掉了「无标注也算进 n」那个洗白口。**而它不让记录上岗，这是设计不是缺陷。**

于是 `待真值 → 上岗` 这一步**今天没有任何代码在做**，全库唯一能上岗的入口是 `put`，而 `put` 只核一件事：`n > 0`。**「这条线凭什么能上岗」由调用方手写，没有任何东西核过它。** 实测（`tests/gate.rs`）：

```
absorb 之后：status=待真值 n=73 samples=73
证书：Refused { best_ucb: 0.319, best_hi: 0.775, best_n_accepted: 6, n_needed: 22 }
**缺口**：put(0.78, 0.22, 73, "上岗") 直接 ok，而同一批数据的证书是拒绝
```

**73 条标注、一条手写的 0.78，就上岗了。** 证书门要站的就是这一格：`put(..., "上岗")` 需要一张 `Certificate::Line`；没有证书的记录最多停在 `待真值`。这不新增状态——**`待真值` 本来就是四个状态里为这件事留的那一格。**

### 顺带：总控刚定的「账本头记 `CalibStore` 哈希」要连证书一起记

那条 J-18 补法（头里加校准库的哈希，让「换线重放」像「换档案重放」一样报 `W-header`）是对的，但**只哈希 `hi/lo/n/status` 不够**。两条记录可以有**一模一样的 `hi/lo`，而背后的证书是两张不同的**——一张 α=0.10、一张 α=0.40，一张按簇取、一张按条取。

**所以证书必须存进记录、跟着进哈希，不能算完就丢。** 否则哈希覆盖了线、没覆盖线的**凭据**，于是「这次重放用的是一条松得多的 α」在账本上看不出来——**与兜底档案的 `hash` 必须是 `None` 是同一个形状，只是深了一层**：那一条说的是「用了兜底」要留痕，这一条说的是「凭什么」要留痕。

记进记录的最小字段：`alpha` / `delta` / `n_accepted` / `n_errors` / `ucb` / **`cluster_unit`**（按什么分的簇——第一节证明了不记这个，n 本身就没有意义）。

## 六、判定不做的

**一、不做条件覆盖（conditional coverage）。** 保形只给边际保证；要按题型/材料种类分组保证，n 还要再除以组数，而我们现在连边际的都认证不到。写下来是因为「保形能给保证」这句话最容易被读成条件保证。

**二、不做加权保形 / 协变量漂移修正（weighted conformal）。** 它需要密度比估计，而密度比本身要标注。在 n≈20 上引入一个要估计的比值，只会把不确定性藏进另一个没人检查的数。

**三、不改 `cost_line`。** 它做的事（代价决定线定在哪）是对的，证书门加在 `put` 上，不动它。

**四、不把 ECE 当门。** 宪法第四列写的是「ECE 降诊断」。E-CAL-0 已经把「代码正确性 noul 读数 ECE ≤ 0.10」证伪（E9c 0.228、E9d 0.180），而 H3 要 n≥100 过检才成立——我们的独立单位只有 19–29。**ECE 记进记录、进报告，不参与放行判定。**

**五、不在 `jpp-core` 里落地任何东西。** 原型是独立 crate，`path` 只读引用。理由与我无关：`jpp-core` 现在有别人在写。

## 七、由此该发展的新机制（宪法第四列的落法）

1. **证书门。** `CalibStore::put(..., "上岗")` 需要一张 `Certificate::Line`。`Certificate::Refused` 是一等出口，必须带 `best_ucb`（这批数据能拿到的最紧上界）与 `n_needed`（零错时要多少条），**「不行」和「差多少」一起报**。
2. **标注集的单位是簇不是条。** `set_id` 记分簇单位；保形分位数按簇取；不记分簇单位的 n 不得进任何有限样本计算。
3. **无标签漂移监控。** 读数分布的 KS/PSI + 保形覆盖跌落，每次运行都算；自带 `underpowered` 位，小样本不许停岗。
4. **J-15 加两个载体**（`conformal_line`、`drift_monitor`），不新增 `cause`、不新增 §5 路由行。
5. **δ 不许以单标量被读走**，必须连 `n` 一起读；`n < 50` 的分位数带「这就是最大值」的标记。
6. **ECE 降为诊断**，进记录不进门。

## 八、`conformal_line` 这一位：**不阻塞，但也不放行**（总控 2026-09-21 已裁，方向已定）

**「阻塞」和「不放行」不是一件事，我先前把它们当成了一件事。**

- **阻塞** = 程序跑不下去、报错退出。**J-15 原文说的「不阻塞」是这个意思。**
- **不放行** = 程序照常跑，但这个键切不出 `Act`，出口是 `Unsure`，带告警。

J-15 的原话是「取该假设为真（**保守**）、报 `W-untested`、**不阻塞**」——**「不阻塞」与「取保守项」是同一句话里的两半，只取后半句就读错了。** 没有证书时取的保守项，就是「不放行」。

**订正一句我自己写错的话。** 我原先写「若阻塞，E-CAL 这批读数一条出口都给不出来，**语言在这批数据上等于停摆**」。**那是误述**：全是 `unsure` 的程序不是停摆，是这批数据上**诚实的结果**——`unsure` 是一等出口，有 handler 路由、能 `escalate` 给人、能 `literalize` 重问。**这门语言存在的理由就是让这种情形有地方可去，而不是被压成一个假的「通过」。** 已钉成可跑的反例（`tests/boundary.rs::拿不到证书不等于程序跑不下去`）：冷键的线是档案保守线 `hi=1 / lo=0`（一切都在带内），`cut` 照常切，出口是 `unsure(cold)`。

**而我给的另一半正是这条裁定的依据**：noul 的 `cost_line(1,1)` 放行 50/73、经验假放行率 **0.300**，程序拿到的是一条「过线即放行」的线，没有任何东西告诉它这条线放行的三成是错的。加上这道门，这批数据上的语言会**变得更不好用——而那是对的方向**。

### 门管谁、不管谁：边界用 `provenance()` 划，不新造

| 证据来源（`CalibRecord::provenance()`，**算出来的**） | 要不要证书 | 理由 |
|---|---|---|
| `程序积累` / `混合` | **要** | 程序自己攒的证据要让一个键上岗，必须有人核过它凭什么 |
| `宿主手填` | **不要** | I4：线来自程序之外，**宿主为它负责**；责任归属可查，就不必再加一道门 |
| `空` | 不适用 | 没有线也没有证据，本来就是 `冷` |

**这条边界之所以划得住，是因为 `provenance()` 是算出来的**（比对 `n` 与实际带标注的样本条数），不是调用方自己声明的——**声明的边界拦不住任何人**。实测（`tests/boundary.rs`）：73 条真实标注 `absorb` 进去 → `provenance=程序积累`、`status=待真值`、证书拒绝 → 上不了岗；`put(0.78, 0.22, 200, "上岗")` → `provenance=宿主手填`（宣称 200 条、证据 0 条）→ 不过门、照旧上岗。

**不新增出口种类、不新增 `cause`、不新增 §5 行**：代价矩阵决定线定在哪，证书决定这个键能不能上岗。

```rust
//! 保形弃权域的原型：**先回答「这条线能不能被认证」，再谈线定在哪**。
//!
//! 宪法借用登记表那一行（`00-宪法.md`:41）把条件写得很清楚：
//! 「可交换标注集 + 损失函数 → 阈值带风险保证」是**当年的条件**；在 Jev 下
//! 「可交换性会被打破、δ 非单调」。所以本 crate 的主出口不是一条线，是一张
//! **证书或一次拒绝**——拒绝时把「差多少才能认证」一起给出来。
//!
//! 三个部件：
//! 1. [`certify`]：给定标注集与 (α, δ)，返回带有限样本保证的线，**或拒绝**。
//! 2. [`drift`]：**无标签**漂移统计（`12`:410 那一行里唯一带「必备」的东西）。
//! 3. [`Certificate::untested_carrier`]：拒绝时该点亮 J-15 哪个载体。

use std::collections::BTreeMap;

/// 二项比例的**精确**上置信界（Clopper–Pearson）。
///
/// 为什么不用 Hoeffding：在我们的 n 上 Hoeffding 的松弛是
/// `sqrt(ln(1/δ)/2n)`——n=20 时 **0.24**，对任何低于 24% 的风险目标都是空的。
/// 精确二项界在小 n 上紧得多，而且这里的损失本来就是 0/1，用不着次高斯放缩。
pub fn binomial_upper(k: usize, n: usize, delta: f64) -> f64 {
    // **`n == 0` 返回 1.0 是承重的，不是防御性写法。** 空放行区的风险**没有定义**，
    // 返回 0.0（「零错所以零风险」）会让「全弃权」在算术上满足任何 α，于是全弃权被
    // 报成「认证通过的线」。返回 1.0 是「说不准时往拒绝那边倒」的直接实例。
    if n == 0 || k >= n {
        return 1.0;
    }
    let (mut lo, mut hi) = (k as f64 / n as f64, 1.0);
    for _ in 0..200 {
        let mid = (lo + hi) / 2.0;
        // P(Bin(n, mid) ≤ k)
        let mut cdf = 0.0;
        let mut term = (1.0 - mid).powi(n as i32);
        for i in 0..=k {
            if i > 0 {
                term *= (n - i + 1) as f64 / i as f64 * mid / (1.0 - mid);
            }
            cdf += term;
        }
        if cdf > delta { lo = mid } else { hi = mid }
    }
    (lo + hi) / 2.0
}

/// 零错时要认证到 α 所需的**放行条数**：`ln δ / ln(1−α)`。
/// 这是「就算一条都不错，样本也得有这么多」的下限，与读数准不准无关。
pub fn n_needed_zero_error(alpha: f64, delta: f64) -> usize {
    (delta.ln() / (1.0 - alpha).ln()).ceil() as usize
}

/// 一次认证的结果。**拒绝是一等出口**，不是错误。
#[derive(Clone, Debug, PartialEq)]
pub enum Certificate {
    /// 认证成功：`hi` 之上放行，风险上界 `ucb ≤ α`。
    Line { hi: f64, n_accepted: usize, n_errors: usize, ucb: f64 },
    /// **认证失败**：任何非平凡的线都给不出 ≤ α 的上界。
    /// `best_ucb` 是这批数据上能拿到的**最紧**上界（对应最保守的非空放行区）。
    Refused { best_ucb: f64, best_hi: f64, best_n_accepted: usize, n_needed: usize },
}

impl Certificate {
    /// 拒绝时该点亮的 J-15 载体名。**不新造机制**：
    /// 「这条线没被认证」与「置换没测过」「线是冷的」是同一个性质——
    /// **一个被声明为判据、但在本次路径上没有被测量的量**。
    pub fn untested_carrier(&self) -> Option<&'static str> {
        match self {
            Certificate::Line { .. } => None,
            Certificate::Refused { .. } => Some("conformal_line"),
        }
    }
    pub fn is_refused(&self) -> bool {
        matches!(self, Certificate::Refused { .. })
    }
}

/// 保形风险控制（RCPS 形状）：**从最宽的线往紧里走，取第一个上界 ≤ α 的线**。
///
/// `samples`：`(读数 p, 这条读数蕴含的判断对不对)`。损失 = 放行区里的假放行。
///
/// **空放行区不算解。** 这一条是纪律不是实现细节：`t = 1.0` 上「放行 0 条、
/// 假放行 0 条」在算术上满足任何 α，但它说的是「全弃权」——把全弃权报成
/// 「认证通过的线」，正是**结论把注意力从依据上引开**的那个形状。
pub fn certify(samples: &[(f64, bool)], alpha: f64, delta: f64) -> Certificate {
    let mut pts: Vec<(f64, bool)> = samples.to_vec();
    pts.sort_by(|a, b| a.0.partial_cmp(&b.0).unwrap());
    let mut ps: Vec<f64> = pts.iter().map(|x| x.0).collect();
    ps.dedup();
    let mut cands = vec![0.0];
    for w in ps.windows(2) {
        cands.push((w[0] + w[1]) / 2.0);
    }
    // **不放 1.0**：那是全弃权，不是线。（这是三道保护的第二道，见 `binomial_upper` 的 `n == 0`。）
    let mut best: Option<(f64, f64, usize)> = None; // (ucb, hi, n_accepted)
    for t in cands {
        let acc: Vec<&(f64, bool)> = pts.iter().filter(|x| x.0 >= t).collect();
        // 第三道。**实测：单独去掉这一道不会变红**——候选表里本来就没有让放行区为空的阈值。
        // 三道一起去掉才红（tests/ecal.rs 的「空放行区不算解」，6 条里红 4 条）。
        if acc.is_empty() {
            continue;
        }
        let k = acc.iter().filter(|x| !x.1).count();
        let ucb = binomial_upper(k, acc.len(), delta);
        if best.as_ref().map(|b| ucb < b.0).unwrap_or(true) {
            best = Some((ucb, t, acc.len()));
        }
        if ucb <= alpha {
            return Certificate::Line { hi: t, n_accepted: acc.len(), n_errors: k, ucb };
        }
    }
    let (best_ucb, best_hi, best_n) = best.unwrap_or((1.0, 1.0, 0));
    Certificate::Refused {
        best_ucb,
        best_hi,
        best_n_accepted: best_n,
        n_needed: n_needed_zero_error(alpha, delta),
    }
}

/// **无标签**漂移统计。`12`:410 那一行里唯一带「必备」二字的东西，而它今天两边都没有：
/// `jv/calib.py` 的 `drift_stat` 是声明了从不算的字段（全仓只有写死的 `0.0`），
/// `core/calib.py::should_suspend` 是另一个系统的、**要标签**的错误率监控。
///
/// 这里给的是只用读数分布的两个量——**不需要真值，所以每次运行都能算**：
/// - `ks`：两样本 Kolmogorov–Smirnov 统计量（读数分布位移）
/// - `psi`：population stability index（分桶质量迁移，工业上常用 0.1 / 0.25 两档）
#[derive(Clone, Debug, PartialEq)]
pub struct DriftReport {
    pub ks: f64,
    pub psi: f64,
    pub n_ref: usize,
    pub n_recent: usize,
    /// **样本够不够算这个数**。不够时上面两个数照样算得出来，但不该拿去停岗
    /// ——这一位与 J-15 同族：量本身没被**可信地**测量。
    pub underpowered: bool,
}

pub fn drift(reference: &[f64], recent: &[f64], bins: usize) -> DriftReport {
    let ks = {
        let mut a = reference.to_vec();
        let mut b = recent.to_vec();
        a.sort_by(|x, y| x.partial_cmp(y).unwrap());
        b.sort_by(|x, y| x.partial_cmp(y).unwrap());
        let mut all: Vec<f64> = a.iter().chain(b.iter()).copied().collect();
        all.sort_by(|x, y| x.partial_cmp(y).unwrap());
        all.iter()
            .map(|t| {
                let fa = a.iter().filter(|x| *x <= t).count() as f64 / a.len().max(1) as f64;
                let fb = b.iter().filter(|x| *x <= t).count() as f64 / b.len().max(1) as f64;
                (fa - fb).abs()
            })
            .fold(0.0, f64::max)
    };
    let hist = |v: &[f64]| -> Vec<f64> {
        let mut h = vec![0.0; bins];
        for x in v {
            let i = ((x * bins as f64).floor() as usize).min(bins - 1);
            h[i] += 1.0;
        }
        let n = v.len().max(1) as f64;
        h.into_iter().map(|c| c / n).collect()
    };
    let (ha, hb) = (hist(reference), hist(recent));
    let eps = 1e-4;
    let psi = ha
        .iter()
        .zip(hb.iter())
        .map(|(a, b)| {
            let (a, b) = (a.max(eps), b.max(eps));
            (b - a) * (b / a).ln()
        })
        .sum::<f64>();
    // KS 的 α=0.05 临界值 ≈ 1.36·sqrt(1/n1 + 1/n2)；小于它就分不出移没移。
    let crit = 1.36 * (1.0 / reference.len().max(1) as f64 + 1.0 / recent.len().max(1) as f64).sqrt();
    DriftReport { ks, psi, n_ref: reference.len(), n_recent: recent.len(), underpowered: ks < crit }
}

/// 把标注集按**对象段**分簇，每簇取一条——簇级保形。
///
/// 为什么需要它：可交换性在我们这里**不是被时间打破的，是被材料复用打破的**。
/// E-CAL 那 297 条读数只由 61 个不同片段重组而成；按对象段分簇后
/// noul 36 簇 / choice 37 簇 / score 28 簇。**同一段落的多条读数不是多次独立观察。**
pub fn cluster_subsample(samples: &[(f64, bool, String)], seed: u64) -> Vec<(f64, bool)> {
    let mut by: BTreeMap<&str, Vec<(f64, bool)>> = BTreeMap::new();
    for (p, l, seg) in samples {
        by.entry(seg.as_str()).or_default().push((*p, *l));
    }
    let mut s = seed.wrapping_mul(6364136223846793005).wrapping_add(1);
    by.values()
        .map(|v| {
            s = s.wrapping_mul(6364136223846793005).wrapping_add(1442695040888963407);
            v[(s >> 33) as usize % v.len()]
        })
        .collect()
}
```
