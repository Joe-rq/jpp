## (1) 我理解这是一门什么语言

这是一门"判断语言"：一个程序由若干条**带守卫的命令**组成，守卫是一道对当前"渲染出的文字状态"提出的问题，回答由 Jev（一段文字状态 + 一道带类型的问题 → 校准过的概率，规范里只叫它"读数"，程序本身看不到概率，只看到出口）给出；问题只有三种问法——**判**（是/否/不确定）、**选**（从候选集里选一个）、**量**（在一条锚定过的档位刻度上打档），对应三种"出口"类型。基本单元不是数值也不是字符串，而是 `Mat`（材料，唯一的数据类型，带地址和来源链）和 `Q`（题，一等值，声明一次、可反复调用、可传参）。写程序的方式是：先声明预算（跑多少次、花多少钱、多少层、多少次升级），再声明若干道题（每道题选一种题式——属性/关系/比较/归类/提及/程度/决定——并写死中文题面），需要打档的话再声明一条锚（每档一个样例），需要确定性计算的话再声明一个 S 函数（外部任意语言的可执行文件）；然后用固定的控制结构（if / select / switch / while / choose / loop / partition / for…yield）把这些题当"守卫"或"值"接起来，凡是可能出现"不确定"出口的地方都必须显式写清楚不确定时去哪儿（升级给人、换一条材料再问、放弃、回退到默认……），最后用 return / escalate 交出结果，全程只有题的调用是"非确定"的一跳，其余都是普通确定性代码，因此整个程序可以逐字节重放。

## (2) 三个程序（严格用 §2 文法，各 ≤ 20 行）

### a. 从用户反馈里找出提到同一个 bug 的反馈并归组

```
program 同bug分组(反馈: Set) -> Map {
  budget calls <= 300, cost <= $0.03, layers <= 1
  q 同bug : rel = "这两条反馈说的是同一个bug吗？"
  s pure 聚类(关系: Map) -> Map = "s/聚类.py"
  let 关系 = for p in pairs(反馈, 反馈) yield (p, 同bug(on: left(p), ctx: right(p)))
  return 聚类(关系)
}
```
（7 行）语义操作用 `rel` 逐对判断"是否同一 bug"，得到 `Map[pair, Outlet3]`；分组本身（把两两关系并成连通的组）不是语言原语，我自己声明了一个 `s pure` 函数把这份两两关系表交给外部代码去做连通分量。

### b. 会议纪要里找出承诺了但没负责人或没期限的事项，按紧急度排序

```
program 找失责事项(纪要: Mat) -> Map {
  budget calls <= 200, cost <= $0.02, layers <= 2
  q 承诺 : attr = "这句话是一项承诺要做的事情吗？"
  q 缺负责人 : attr = "这项承诺没有指定负责人吗？"
  q 缺期限 : attr = "这项承诺没有约定完成期限吗？"
  anchors 紧急锚 = {低: "不影响当前工作", 中: "本周内需要跟进", 高: "阻塞其他人或已逾期"}
  q 紧急度 : degree[低 < 中 < 高] anchors 紧急锚 = "这项事情的紧急程度"
  let (承诺项, 其它, 疑1) = partition 句 in split(纪要, 100) where 承诺(on: 句)
  let (缺失, 完备, 疑2) = partition 句 in 承诺项 where 缺负责人(on: 句) ∨ 缺期限(on: 句)
  return rank(for s in 缺失 yield (s, 紧急度(on: s))) ∪ for s in 疑1 yield (s, unsure) ∪ for s in 疑2 yield (s, unsure)
}
```
（10 行）两层 `partition`：先筛出"是承诺"的句子，再从中筛出"缺负责人或缺期限"的句子，最后用 `degree` 打紧急度并 `rank` 排序；两层 partition 各自的 unsure 流都并进返回的 Map（跟 §9.10 配置漂移的写法同一个模子）。

### c. 在网页（给定可访问性树）上找到"取消订阅"并点击，最多 10 步

```
program 取消订阅(页面: Mat) -> Mat ⊎ unsure {
  budget calls <= 20, cost <= $0.01, layers <= 10, escalate <= 1
  q 已完成 : attr = "取消订阅的操作已经完成了吗？"
  q 下一步 : decide = "下一步点击哪个元素最可能找到并触发取消订阅？"
  let 观 = 页面
  loop bound 10 {
    if 已完成(on: 观, ctx: 页面) { return 观 } unsure -> escalate
    select 下一步(over: actions(观), ctx: 页面) as a { 观 = a11y(do act(a)) } unsure -> escalate
  }
  escalate 观
}
```
（11 行）照搬 §9.13「取物」的骨架：`loop bound 10` 里先判是否已完成，未完成就用 `decide` 选下一个动作、执行、把执行后的屏幕重新跑一次 `a11y` 当新的观察，直到完成或到界。

## (3) 我写的时候"猜"的地方

1. **partition 的 unsure 流绑定后不用，算不算"未处理"（E3）**——§2 partition 约定（行 96）、E3（§3.3 行 124）、去向表（§4.6 行 179-194）都没说清楚：把 `(act, ignore, unsure)` 三流解构进变量后，如果那个 unsure 变量根本没被用到（既没进返回值也没 escalate/drop），算不算"可达的 unsure 未被接住"从而报错。规范给的十几个示例里，每次 partition 出的 unsure 流都被显式用掉了（`mark_unsure` 或并进 Map），没有一个"故意不用"的反例来确认这条线在哪。我在程序 b 里选择保守做法——两层 partition 的 unsure 流都并进最终 Map——但这是我自己补的规矩，规范没有直接写。

2. **语言里没有"分组/聚类"原语**——三种数字化（判位、选索引、量档）和 §4.7 的全部聚合子，都是对单个材料或候选集合做操作，没有"把一批材料按某种等价关系划分成多个组"的算子（§4.7 表、§6.4 组合子表、§6.5 骨架列表都没有）。我在程序 a 里的解法——用 `rel` 题两两判断，再自己声明一个 `s pure` 函数做连通分量——规范没有例子或文字确认这是不是设计者设想的写法；也可能是设想里根本不该由 Jv 做分组，而应该整个交给 S，但规范没说清边界在哪。

3. **`a11y(screen)` 的参数与"已经拿到的可访问性树"是不是同一回事**——`Mat` 是唯一材料类型（§3.1，行 106），规范没有在类型层面区分"原始屏幕/scene"和"渲染后的可访问性文字"。题目给的输入本身就是"可访问性树"，我因此猜测程序的入参 `页面` 已经是 `a11y()` 的输出，不需要在最开始再包一层；但循环里 `do act(a)` 之后要不要再套一层 `a11y()` 才能拿到能用的下一步观察，规范同样没有正面回答，我是照搬 §9.13 的写法（`a11y(do act(a))`）类比过来的，不是从正文直接推出来的。

4. **"缺负责人或缺期限"该拆成两道原子题用 `∨` 组合，还是允许写成一道复合题面**——§0.1"字面化定律"（行 15）要求"每道判断必须对面前的材料一跳可判"，我据此推断复合条件应该拆成两道原子 `attr` 题再用 `∨` 组合（就是我程序 b 的写法），但规范没有给出两种写法的对比或明确禁止后者，这是我自己的推断，不是规范直接写明的规则。

5. **`pairs(A, B)` 在 A、B 是同一个集合时要不要去重/去自反**——§6.1 的 S 库表（行 286）只给了签名 `pairs(A, B) / left(p) / right(p)`，没有说明 `pairs(反馈, 反馈)` 会不会包含 `(x, x)` 这种自反对，以及 `(x, y)` 和 `(y, x)` 是否都出现。我按最字面的"笛卡尔积"理解写了 `pairs(反馈, 反馈)`，可能会让下游的两两判断产生冗余调用。

除以上五处，其余语法结构（`let`、赋值只在 loop/while 体内合法、`if…unsure`、`select…as…unsure`、`partition…where`、`for…yield`、`for…yield(k,v)`、`∪`、`rank`、`mark_unsure` 的用法、题的 `on/ctx/over` 具名槽规则、`degree` 必须带 `anchors`、`escalate` 预算与 `budget` 必填等）都能在规范正文或 §9 的示例里找到直接依据，没有再猜。

## (4) 一句话评价

这份规范能让新手照猫画虎写出**语法正确**的程序（§9 的现成范式几乎能覆盖所有常见写法），但一碰到规范没给过现成范式的任务（比如"分组/聚类"这类没有对应原语的需求，或者"partition 的 unsure 流不用算不算错"这类边界情况），新手就得自己猜、自己编规矩，说明规范目前是"照着例子抄能过关，跳出例子就得靠猜"的状态，还没到"不问人就能独立推导出唯一正确写法"的程度。
