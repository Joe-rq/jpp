# G3·零上下文读者第三次读后作业

> 读者设定：只读了 `11-语言规范-v1.md`（v1.1），没有读仓库里任何其它文件，没有联网，没有问过任何人。以下内容是这次阅读期间边读边写的记录。

## （1）我理解这是一门什么语言

这门语言（规范里暂叫 Jv，正文说以后会改名）是一门**把"问 AI 一个校准过的判断题"当成语言里唯一不确定运算的编程语言**。它的底层原语是 Jev：给一段渲染成文字的"状态"（材料 + 语境 + 参照）配一道带类型的问题，回来的不是随口一个答案，而是经过统计校准的三类读数之一——判"是不是"（act/ignore/unsure 三出口）、选"哪一个"（从候选集里选中一项，或 unsure）、量"到什么程度"（在一条带锚点的刻度上给档位，或 unsure）。程序员在语法里完全看不到概率数字本身，只能看到这三种"出口"的值，概率只活在编译器背后的校准表里。

除了这一个不确定原语，其它所有运算——取材料、算差异、跑命令、拼字符串、做有界循环——都是确定性的普通函数，规范里管它们叫 `S`（`s pure` 无副作用、`s do` 会碰真实世界比如跑测试或调用人），本质是登记一行签名再让任意语言实现的外部可执行文件。所以一个 Jv 程序读起来像："声明我要用哪些判断题（`q`）和哪些外部函数（`s`），声明预算（`budget`，必填），然后用 `let`/`if`/`select`/`switch`/`while`/`choose`/`loop`/`partition`/`for…yield` 这套控制流把材料喂给题、把出口收集成 `Set`/`Map`，每一处可能出现 `unsure`（不确定）或 `fail`（世界没给材料）的地方都必须显式写清楚要往哪个方向处理——继续问细一点（`refine`）、升级给人（`escalate`）、换一条参照（`anchor`）、丢弃记账（`drop`），不允许"没写"就等于默默吞掉。整个程序可以逐字节重放，因为唯一的随机性（判断的读数）连同它走的去向都进了账本。

一句话概括我的理解：**这是一门"确定性代码 + 有类型的、会说'不确定'的判断句"拼起来的语言，判断句只有三种形状（是否/选谁/几档），程序员的活是把材料摆对位置、把每一条不确定的出路显式接住。**

## （2）三个程序（每个 ≤ 20 行，严格 §2 文法）

### a. 找互相引用同一数据集但结论相反的论文对

```
program 找矛盾论文对(论文集: Set) -> Set ⊎ unsure {
  budget calls <= 200, cost <= $0.02, layers <= 1
  q 同数据集 : rel = "这两篇论文引用的是同一个数据集吗？"
  q 结论相反 : rel = "这两篇论文的结论相反吗？"
  let (矛盾, 不矛盾, 疑) = partition p in pairs(论文集) where 同数据集(on: left(p), ctx: right(p)) ∧ 结论相反(on: left(p), ctx: right(p))
  return 矛盾 ∪ mark_unsure(疑)
}
```
6 行。用 `pairs(论文集)` 拿到无序不自反的论文两两配对（§6.1），`left/right` 拆出两篇；按 v1.1 第五规则「一题一命题」把"同数据集"和"结论相反"拆成两道 `rel` 题，再用 `∧` 合成一道复合守卫（§4.4），这样每道题各自能被单独校准。`partition` 给三流，`矛盾` 是两条都成立的对，`疑` 走 `mark_unsure` 进返回值的 unsure 分量（§9.2/9.8/9.14 都是这个写法）。

### b. 客服工单路由，转错升级给人

```
program 工单路由(工单流: Set, 部门集: Set) -> Map {
  budget calls <= 300, cost <= $0.03, layers <= 1, escalate <= 50
  q 该部门 : decide = "这张工单最应该转给哪个部门处理？"
  return for w in 工单流 yield (w, take(该部门(over: 部门集, ctx: w)))
}
```
5 行。`该部门` 是一道 `decide` 题，按 G-b 示例（§9.16）的写法用 `over` 给候选部门集、`ctx` 给这张工单。`take(call)` 组合子固定语义是"索引→材料"，unsure 时按 §6.4 固定去向 `regen→escalate→返回 unsure`——这里没有 `over` 来自 `do gen`，所以直接进 `escalate`（已在 `budget` 里留了 `escalate <= 50`），escalate 用尽后退回 `unsure`，落进 `Map` 的出口位，等于"转错/转不准就升级给人"。返回 `Map` 不需要写 `⊎ unsure`，因为 §3.1 明说 `Map` 的值位天然带 unsure，是"unsure 透明"的。

### c. Python 仓库函数写 docstring，生成三版选最忠实，测试不过不改

```
program 写docstring(repo: Mat) -> Map {
  budget calls <= 400, cost <= $0.04, layers <= 2, escalate <= 20
  q 最忠实 : cmp = "这份候选 docstring 对函数签名与实现的描述最准确吗？"
  s pure 测试通过的函数(repo: Mat) -> Set = "s/测试通过的函数.py"
  let 可改 = 测试通过的函数(repo)
  return for f in 可改 yield (f, take(最忠实(over: do gen(3, "为这个函数写一句忠实于代码的docstring", {signature(f)}), ctx: signature(f))))
}
```
7 行。「测试跑不过的函数不改」在语法里没有对应的确定性过滤器（见第（3）节 G2），所以我把它做成一个自己声明的 `s pure` 函数，内部（Python 实现文件里）先跑测试再返回通过测试的函数集合，`可改` 之外的函数干脆不进返回值，等于不碰。`do gen(3, …)` 生成三版候选（数量、提示、语境材料三个位置参数，语境用 `{signature(f)}` 包成集合，跟 9.7/9.11 的写法一致），交给 `cmp` 题 `最忠实` 在 `over` 里比较、`ctx` 里给函数签名做参照，`take(...)` 拿到选中项或把 unsure 升级。

## （3）我猜的地方

**G1｜`Map` 的值类型没写全，但示例已经在用没写的那部分。**
§3.1（第 112 行）把 `Outlet` 定义死为 `Outlet3 ⊎ 标签 ⊎ 档 ⊎ unsure` 四种。可是 `cmp`/`decide` 题的出口是"选中的候选项本身"（`Chosen[q, C] = C ⊎ unsure`，§3.2 第 120 行），它既不是 `Outlet3`、也不是分类用的"标签"、也不是档位。§9.1（第 396 行）`return for e in 错 yield (e, 哪块(on: e, over: 块))`（`哪块 : cmp`）却直接把这种 `Chosen` 值塞进了 `Map`；G-b（第 573 行）也直接用 `take(最合适(...))` 产出 `Mat ⊎ unsure` 当"决定"用。我的程序 b、c 都跟着这个先例把 `decide`/`cmp` 的结果放进 `Map`，但这到底算不算合法的 `Outlet` 成员，正文的类型定义没圆上，我是照着示例的行为猜的，不是照着正文的定义猜的。

**G2｜`partition` 的守卫只能是判断题，没有"确定性过滤"的位置。**
§2 第 80 行 `guard ::= call | guard∧guard | guard∨guard | ¬guard | (guard)`，`call` 只能是题的调用；`if host hexpr` 是唯一能写确定性条件的地方，但它是语句不是可嵌进 `for…yield`/`partition` 的表达式。也就是说"测试跑不过的函数不改"这种纯确定性筛选，语法里没有直接的写法——§6.5（第 328 行）说 `filter` 是拿 `partition` 搭出来的骨架，暗示"筛选=判断"，但我要筛的这一步恰恰不是判断（跑没跑过测试是确定事实，不该消耗一次 Jev 判断，也不该占校准表）。我在程序 c 里的解法是把这一步整个挪进自己声明的 `s pure` 函数（§6.1 允许任意语言实现），规范里没有一个正面例子演示"仓库里先用确定性条件筛一批，再把剩下的喂给判断"该怎么写，是我猜的搭法。

**G3｜"转错要能升级"被我等价成了"选择时不确定就升级"，规范里没有"事后发现选错"这条路。**
§4.6 的去向表（第 184–194 行）和 §6.4 的 `take` 固定去向（第 321 行）只处理"当场判断/当场选择就是 unsure"这一种不确定；没有任何机制表示"当时选得挺有把握，后来发现选错了，要把这个已经执行完的决定回炉升级给人"。我写程序 b 时，把题面里的"转错"直接读成"路由题给出 unsure"，用 `take` 的内建 `escalate` 去向去接。这是我把任务的自然语言目标套进语言仅有的机制上做的一次翻译，规范原文并没有告诉我这个翻译是不是它想要的意思。

**G4｜`do gen(...)` 里的 `fail` 穿过 `cmp` 题、穿过 `take`，最后要不要让外层 `Map` 也带 `⊎ fail`，正文前后没对齐。**
§4.11 第 1 条（第 237 行）："任何子表达式为 fail，整体为 fail"；§4.1 最后一句（第 153 行）说题的槽位里出现 `fail` → 该次判断直接出 `failed`，"按 unsure 去向处理"。但 §4.6 的去向表本身只列到 `unsure` 这一层，没有单独一行叫"failed 时怎么走"，也没写"组合子内置的去向是否同时覆盖 failed"。我程序 c 里 `do gen(...)`（返回 `Set ⊎ fail`）直接塞进 `最忠实(over: ..., ctx: ...)` 再套 `take(...)`，程序的返回类型只写了 `Map` 没写 `⊎ fail`。我是假设 `take` 的固定去向能把 `failed` 一并折进它对外承诺的 `Mat ⊎ unsure`，但正文没有一处直接确认这个折叠，是我猜的。

**G5｜§1 与 §2 对"档位序列"是不是一种字面量互相矛盾（没用在我的三个程序里，但读的时候看到了）。**
§1 第 39 行词法一节把"档位序列 `低 < 中 < 高`"列为一种字面量，跟字符串、整数、金额、时长并列；但 §2 第 95 行 `literal` 产生式只有 `STRING | INT | MONEY | DUR | "unsure"`，压根没有档位序列这一项。`低<中<高` 这种写法只在专门的 `degree[...]`（第 60 行）和 `anchors {...}`（第 61 行）两个非表达式位置出现，不能像别的字面量一样出现在 `expr` 里。§1 说它是字面量，§2 的文法不承认它是字面量，两处没对上。

## （4）一句话评价

能让新手照着 §2 的文法和现成示例把程序的骨架敲对、大部分场景不用问人，但一旦任务需要"确定性过滤"或"选择/决定类判断的结果要不要能进 Map"这种不在示例覆盖范围内的组合，新手只能像我一样悄悄猜一个解法，规范本身发现不了这个猜测对不对。
