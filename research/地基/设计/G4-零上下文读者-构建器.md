## 程序 1：客户名单合并去重

```python
@jv.program(budget=jv.Budget(calls=50, cost=0.02, layers=2))
def 名单合并(名单甲, 名单乙):
    同人 = jv.test("这两条客户记录指的是同一个人吗？", calib=jv.calib("crm.同人"))
    对子 = [(i, j) for i in range(len(名单甲)) for j in range(len(名单乙))]
    exits = jv.cut(jv.judge([jv.state(on=名单甲[i], ctx=[名单乙[j]]) for i, j in 对子], 同人))   # 一层全并发
    并掉 = set()
    for (i, j), e in zip(对子, exits):
        match e:
            case jv.Act(): 并掉.add(j)
            case jv.Ignore(): pass
            case jv.Unsure(c):
                答 = jv.ask(jv.state(on=名单甲[i], ctx=[名单乙[j]]), 同人)          # 交给人：Pending 挂起
                if isinstance(答, jv.Act): 并掉.add(j)
    return [m.content for m in 名单甲] + [m.content for j, m in enumerate(名单乙) if j not in 并掉]
```

演示数据：甲 2 条、乙 3 条，6 对一层 6 题。张三对（邮箱相同）→ Act；李四对（同名不同邮箱）→ 假读数 0.5 落在 hi=0.6/lo=0.3 之间 → Unsure → `jv.ask` 抛 Pending；`run_all` 捕到后 `rt.answer(key, "act")` 假装人答"是同一人"，重跑一遍返回合并后 3 条。

## 程序 2：日志异常分级

```python
@jv.program(budget=jv.Budget(calls=50, cost=0.02, layers=2))
def 日志分级(日志段):
    严重 = jv.measure("这段日志的严重程度是？", scale=("低", "中", "高"), calib=jv.calib("log.严重"))
    exits = jv.cut(jv.judge([jv.state(on=s) for s in 日志段], 严重))
    汇总, 已发 = [], []
    for i, (s, e) in enumerate(zip(日志段, exits)):
        match e:
            case jv.At(2): 已发.append(jv.do(告警, s, iter_seq=i, guard=e))    # 不可逆：带守卫
            case jv.At(1): 汇总.append(s.content)
            case jv.At(0): pass
            case jv.Unsure(c): 汇总.append(s.content); jv.handle(c, keep=None)    # 拿不准的不发，进汇总
    return {"告警": [f.content for f in 已发], "汇总": 汇总}
```

四段日志一层 4 题；FATAL 一条走 `jv.do(告警, guard=e)`，WARN 一条进汇总，INFO/DEBUG 丢弃。

## 程序 3：网页表单自动填写

```python
@jv.program(budget=jv.Budget(calls=60, cost=0.03, layers=12, escalate=1))
def 填表(目标, 页面):
    下一步 = jv.select("为完成目标，下一步该做哪个动作？", calib=jv.calib("form.下一步"))
    全填 = jv.test("页面显示目标要求的所有字段都已填好了吗？", calib=jv.calib("form.全填"))
    观 = jv.do(读页, 页面, iter_seq=0)
    for it in jv.loop(bound=8, variant=jv.decreasing(lambda: 观.content.count("(空)"))):
        动作 = jv.transform(候选动作, 观, 目标)
        match jv.cut(jv.judge(jv.state(on=观, ctx=[目标], over=动作), 下一步)):
            case jv.Pick(k) if "提交" in 动作[k].content:
                好 = jv.cut(jv.judge(jv.state(on=观, ctx=[目标]), 全填)[0])
                if isinstance(好, jv.Act): return jv.do(提交, 页面, iter_seq=it.n, guard=好).content   # 只有可信 Act 才放行
                jv.consume([好], unsure=jv.drop)                                             # 没填全/拿不准：不提交，继续
            case jv.Pick(k): 观 = jv.do(读页, jv.do(操作, 动作[k], 页面, iter_seq=it.n), iter_seq=it.n)
            case jv.Unsure(c): jv.handle(c, then=jv.escalate)
    return jv.escalate(观)
```

三轮：填姓名 → 填邮箱 → 候选只剩「提交」→ 追加一道 `全填` 是非题 → Act → 提交。4 层、每层题数 [2, 2, 1, 1]（select 的两个置换算两题）。`读页` Action 设成 `taint_out="trusted"`，否则 J-08 的守卫过不了（这是猜的，见猜 16）。

## 猜点清单（共 24 处）

按写代码时遇到的顺序编号。每条：猜的是什么 / 为什么文档没告诉我 / 最后怎么写。

**猜 1** · `jv.state(on=…, ctx=[…])` 里 on 和 ctx 的分工。文档只列了参数名，没说 on 是"被判的对象"、ctx 是"背景"还是两者可互换；一对记录该放 on=甲 ctx=[乙] 还是 on=[甲,乙]。按 six.py 的 `state(on=o, ctx=[目标])` 类推，写 on=甲、ctx=[乙]。

**猜 2** · `jv.judge([state, …], q)` 传列表时 `jv.cut` 返回出口列表且顺序与输入一致。six.py 里 `zip(cmds, exits)` 隐含了这一点，README 没写。照 zip 写。

**猜 3** · `jv.ask(state, q)` 恢复重放后返回什么：Act/Ignore 出口对象、bool、还是 Readings？README §2.6 只说 Pending 抛出、恢复即重放。写 `isinstance(答, jv.Act)`，实测人答 `"act"` 后确实是 Act。

**猜 4** · `Mat` 能否放进 set、能否 `==`。README 说 Readings 没有 `__bool__/__lt__`，没说 Mat；不敢用，改成下标集合 `并掉`。

**猜 5** · Pending 之后怎么"人答"。README 偏差表 9 提了 `rt.answer(key, kind)`，`kind` 取值没写。传 `"act"` 不报错；但无 `root` 的 Runtime 重跑仍是同一个 Pending，带 `root` 才生效——这个也是试出来的，不是读出来的。最后 `run_all` 默认建一个临时 root。

**猜 6** · `rt.answer` 的完整签名。只好在 REPL 里 `inspect.signature`：`(key, kind, k=None, level=None)`。`k`/`level` 大概是 select/measure 的人答，`kind` 大概是 "act"/"ignore"，未验证 ignore。

**猜 7** · 三档严重程度用 `measure` 还是 `select(over=[低,中,高])`。任务说"打分"是第三种题，三档有序，选 measure；但 six.py 六条里没有一条用 measure，无样例可抄。

**猜 8** · `measure` 的 `scale` 参数是什么：标签元组？`(min, max)` 数值区间？`anchors` 又是什么。签名只说 `scale` 必填（tuple），写 `scale=("低","中","高")`。

**猜 9** · FakeClient 的 rule 对 measure 题要返回什么结构。six.py 只演示了 noul/choice。实测 `q["type"]=="score"`，`q["criteria"]` 是 scale 原样；返回体要有 `probabilities`（否则 KeyError）和 float 的 `score`（否则 ValueError）。

**猜 10** · score 的数值域和 probabilities 的键。做了三轮实验才定：档位 = `int(score)` 截到 `len(scale)-1`，p = `probabilities[档位下标]`（int 键），scale 元素的值本身不参与取档。第一次按标签作键得到全 `Unsure('band')[p=0.00]`，没有任何报错提示键不对。

**猜 11** · measure 的出口类型。`__init__` 导出了 `At`，README 只在 `Exit` 族里列了它。实测 `jv.At(k)`，`k` 是 0 起的档位下标，不是标签，所以 `case jv.At(2)` 才是"高"。可读性差，但没找到按标签匹配的写法。

**猜 12** · 校准记录 `hi=0.6, lo=0.3` 对 measure 的意义。对 test 是上下线，对 score 呢？实测 p≥hi → At，p 在 band 里 → `Unsure('band')`；`lo` 对 measure 有没有用不知道。

**猜 13** · `jv.loop(bound=8)` 静态检查 J-06 要 `variant` 必填。README 只提了"loop 变式"三个字。补 `jv.decreasing(lambda: 观.content.count("(空)"))`；但 lambda 里读 `观.content` 是 README 说的"刷新点"，会不会拆层、变式在提交那一轮不递减会不会报错——都没报，也不知道是不是该报。

**猜 14** · `jv.transform(f, …)` 返回列表的元素类型。six.py `seen.add(acts[k])`、`a not in seen` 让我以为是 str，实际是 Mat（`'Mat' is not iterable` 之后才知道），要 `.content`。

**猜 15** · `guard=` 怎么用：传出口对象本身？传 bool？J-08 说"守卫要求 trusted 的 Act 或 ask 答案"，没有一条示例程序用过 guard。写 `guard=e` / `guard=好`，没报错；传 Ignore 或 Unsure 会怎样没试。

**猜 16** · 页面可访问性树的 taint 该设 trusted 还是 untrusted。six.py 里 `a11y` 是 `inherit`、`run` 是 `untrusted`。要让 `全填` 的 Act 能当守卫，只能把 `读页` 设成 trusted，等于自己宣布"页面文本可信"——这正是任务要求库替我把关的地方，我却靠一个字符串绕过去了。

**猜 17** · `jv.handle(c, keep=None)` 的语义。six.py 写 docstring 用它表示"拿不准的不改"；`handle` 的 `**kw` 还能接什么不知道。第一次跑（四条全 Unsure）时 handle 之后多出了 4 层和 W-budget 警告，像是 handle 在重判，README 没写 handle 会发题。

**猜 18** · `iter_seq` 在普通 `for i, … in enumerate` 里怎么给。六条只在 `jv.loop` 里用 `it.n`；J-13 说循环里常量序号是错，写 `iter_seq=i` 没被静态检查拦。

**猜 19** · `Budget` 各字段怎么估：`layers` 到底数什么（一次 cut 一层？向量化算一层？），`escalate=1` 是升级次数上限还是别的。抄 six.py 的量级，名单合并/日志分级给 2，填表给 12。

**猜 20** · `jv.escalate` 在 `handle(then=jv.escalate)` 里是抛 `Escalated` 异常还是返回值；`return jv.escalate(观)` 抄 six.py。填表没走到这条路。

**猜 21** · `jv.do` 的 `MatFuture` 能否直接 `return` 出程序。第一次结果显示 `MatFuture(submit@…, done)`，改成 `.content`。README 说"程序返回"是刷新点，但返回的是期物本身还是刷新后的值没说。

**猜 22** · `case jv.Pick(k) if 条件:` 守卫失败后落到下一个 `case jv.Pick(k)`，J-05 的"match 命中即消费"以哪次为准；同一个 `Pick` 被两个 case 检查会不会算重复消费。没报错。

**猜 23** · `全填` 的出口若是 Ignore（没填全），是否也需要显式消费。README 只说未消费的 Unsure 报错；我用 `jv.consume([好], unsure=jv.drop)` 一并处理，不知道 Ignore 进 consume 有没有副作用。

**猜 24** · FakeClient 送给 rule 的 `text` 是 JSON 串，键为 on/ctx/over，ctx 是列表、over 是 {标签: 候选文本}。从 six.py 的 `json.loads(text)` 和 `state.get("over")` 反推，README 没写渲染格式；写 `名单合并` 的 rule 时第一次把 ctx 当字符串切，邮箱比对全失败、六对全 Ignore，没有任何报错。

## 如果我来改 README，我会加哪三句话

1. **每种题的读数怎么变成出口**：`test → Act/Ignore/Unsure`，`select → Pick(k)/Unsure`（k 是 over 的下标），`measure → At(k)/Unsure`（k 是 scale 的 0 起下标，不是标签；p 取该档位概率，与校准线 hi 比）。现在 README 只在 `ir.py` 一行里列了 `Act/Ignore/Pick/At/Unsure` 五个名字。

2. **FakeClient 三种题的返回体各长什么样**：noul 要 `{"type":"noul","noul":p}`；choice 要 `choice` + `probabilities`（按标签键）；score 要 `score`（float 档位下标）+ `probabilities`（按 int 下标键）——键错了不报错，只会全 Unsure。加一句"rule 收到的 text 是 `{"on":…, "ctx":[…], "over":{标签:候选}}` 的 JSON"。

3. **人答与守卫的最小用法**：`jv.ask` 抛 `Pending` 后，用带 `root` 的 Runtime 调 `rt.answer(e.key, "act"|"ignore", k=…, level=…)`，重跑程序即从账本取答案；`jv.do(action, …, guard=出口)` 只在出口是 trusted 的 Act 时放行，Action 的 `taint_out` 决定它产出的材料是否可信。另外把 `jv.loop` 必带 `variant=jv.decreasing(…)` 写进 §2，别让读者从 J-06 报错里学。
