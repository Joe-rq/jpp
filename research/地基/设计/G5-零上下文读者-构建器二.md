## 0. 三条程序

### 程序一：会议纪要派待办

```python
@jv.program(budget=jv.Budget(calls=40, cost=0.02, layers=3, escalate=10))
def 纪要派待办(纪要, 人员表):
    可执行 = jv.test("这是不是一条可执行的待办？", calib=jv.calib("todo.可执行"))
    派给谁 = jv.select("这条待办该派给谁？", calib=jv.calib("todo.派给谁"))
    条目 = jv.gen("从会议纪要里提取待办条目，一条一句", ctx=[纪要], n=6, retry_seq=0)      # 猜 1、2
    出口 = jv.cut(jv.judge([jv.state(on=t, ctx=[纪要]) for t in 条目], 可执行))         # 一层：全部条目并发
    待派, 待问 = [], []
    for t, e in zip(条目, 出口):
        match e:
            case jv.Act(): 待派.append(t)
            case jv.Ignore(): pass
            case jv.Unsure(): 待问.append(t)                                              # 猜 3：命中即消费，先攒着
    选 = jv.cut(jv.judge([jv.state(on=t, over=人员表) for t in 待派], 派给谁))            # 第二层：猜 4
    派单 = {}
    for t, e in zip(待派, 选):
        match e:
            case jv.Pick(k): 派单[t.content] = 人员表[k].content
            case jv.Unsure(): 待问.append(t)
    return {"派单": 派单, "问人": jv.escalate([t.content for t in 待问])}                  # 猜 5：攒起来一次交人
```

结果：5 条候选里 3 条派出（张三 / 王五 / 赵六），「大家这周辛苦了」是 Ignore，「李四评估…待定」读数落线附近成 Unsure，进「问人」。2 层，题数 [5, 6]（第二层 3 个状态 × 2 置换），8 次调用。

### 程序二：合同条款风险标红

```python
def 拆条款(合同):
    return [ln.strip() for ln in str(合同.content).splitlines() if ln.strip()]

@jv.program(budget=jv.Budget(calls=40, cost=0.02, layers=3))
def 条款标红(合同, 模板):
    风险 = jv.measure("这条条款对我方的风险档位？", scale=("低", "中", "高"), calib=jv.calib("contract.风险"))
    冲突 = jv.test("这条条款与我方模板条款冲突吗？", calib=jv.calib("contract.冲突"))
    条款 = jv.transform(拆条款, 合同)                                                    # 猜 6：拆分是宿主函数 → transform
    rs = jv.judge([jv.state(on=c, ref=[模板]) for c in 条款], 风险)                      # 猜 7：模板进 ref
    档 = jv.cut(rs)
    高, 中 = [], []
    for i, (c, e) in enumerate(zip(条款, 档)):
        match e:
            case jv.At(2): 高.append((i, c))
            case jv.At(1): 中.append(i)
            case jv.At(0): pass
            case jv.Unsure(): 中.append(i)                                              # 猜 9：拿不准按中风险人看
    门 = jv.cut(jv.judge([jv.state(on=c, ref=[模板]) for _, c in 高], 冲突))            # 第二层：高风险才问冲突
    标红 = []
    for (i, c), g in zip(高, 门):
        match g:
            case jv.Act(): 标红.append({"条款": i + 1, "理由": jv.gen("摘录这条条款与模板冲突之处", ctx=[c, 模板], n=1, retry_seq=i)[0].content})   # 猜 10
            case jv.Unsure(): 标红.append({"条款": i + 1, "理由": "拿不准，需人看"})
    序 = [i for 组 in rs.order() for i in 组]                                            # 猜 11、12：.order() 实测返回「下标分组列表」，先展平
    中序 = [i + 1 for i in 序 if i in 中]
    return {"标红": 标红, "中风险从高到低": 中序}
```

结果：条款 1（无限责任）判高且与模板冲突，输出编号与 gen 出的理由摘录；中风险三条按 `.order()` 排成 [3, 4, 2]（假规则给的档位概率 0.9 / 0.85 / 0.8）。2 层，题数 [5, 1]，6 次调用。

### 程序三：命令行工具报错改写并写回

```python
_FILE: dict[str, str] = {}

def _write_back(新, 原, *rest):
    _FILE[原.content] = 新.content
    return {"written": 原.content}

写回 = jv.register_action("write_back", fn=_write_back, taint_out="inherit", reversible=False,
                          reason="写回本地文件，只写入已守卫放行的改写", cost=0.0)

def 保留错误码(报错, 候选):                                                              # 猜 13：transform 的参数可以是材料列表
    code = str(报错.content).split(":")[0].strip()
    return [c.content for c in 候选 if code in str(c.content)]

@jv.program(budget=jv.Budget(calls=40, cost=0.02, layers=4))
def 改写报错(报错们):
    最清楚 = jv.select("哪个改写最清楚？", calib=jv.calib("err.最清楚"))
    没走样 = jv.test("这条改写保留了原报错的意思与错误码吗？", calib=jv.calib("err.没走样"))
    候选表 = []
    for i, e in enumerate(报错们):
        cands = jv.gen("把这条命令行报错改写得更清楚，保留错误码", ctx=[e], n=3, retry_seq=i)   # 猜 14：retry_seq 用循环变量
        有码 = jv.transform(保留错误码, e, cands)                                          # 猜 15：返回 [Mat]，可能为空
        候选表.append((e, 有码))
    可选 = [(e, cs) for e, cs in 候选表 if cs]                                             # 猜 16：over 为空不敢交给 select
    选 = jv.cut(jv.judge([jv.state(on=e, over=cs) for e, cs in 可选], 最清楚))            # 一层
    中选 = [(e, cs[k]) for (e, cs), x in zip(可选, 选) if isinstance(x, jv.Pick) and (k := x.k) is not None]   # 猜 17
    jv.consume(选, unsure=jv.drop)
    门 = jv.cut(jv.judge([jv.state(on=新, ctx=[原]) for 原, 新 in 中选], 没走样))          # 第二层：守卫题
    写了, 没写 = [], []
    for i, ((原, 新), g) in enumerate(zip(中选, 门)):
        if isinstance(g, jv.Act): 写了.append(jv.do(写回, 新, 原, iter_seq=i, guard=g))   # 猜 18：guard 传 Act
        else: 没写.append(原.content)
    jv.consume(门, unsure=jv.drop)
    return {"写了": 写了, "没写": 没写}
```

结果：三条报错各生成 3 个改写，其中「连接被拒绝」没有错误码，被宿主函数筛掉不参加选择；E1042、E2001 选出改写并经守卫放行写回（`_FILE` 里两条）；W300 的守卫题读数 0.5 落 Unsure，不写。2 层，题数 [6, 3]，6 次调用。

## 2. 猜点清单（24 处）

每条：猜的是什么 / 文档为什么没告诉我 / 最后怎么写。

- **猜 1**：`gen(n=6)` 是「恰好 6 条」还是「最多 6 条」。README 只说返回 `[Mat]`、可能为空。待办条数本来不定，我把 n 当上限，不对返回长度做假设。实测生成器给 5 条就是 5 条。
- **猜 2**：`jv.lit` 出来的材料 taint 是什么。README 说 gen 的 taint = ∨ctx、守卫要「trusted 状态的 Act」，但通篇没写 `lit` 是 trusted 还是 untrusted——这决定程序三的写回能不能放行。我赌 trusted，实测 `do` 输出 `taint=trusted`，放行了。
- **猜 3**：`case jv.Unsure():` 不绑 cause、不调 `handle`，算不算「已消费」。§2.5 说 match 命中即消费，但所有示例都写 `jv.Unsure(c)` 再 `handle(c, …)`，我不确定光命中就够。写法：不绑、不 handle、先攒着。跑通没报 J-05。
- **猜 4**：向量化 judge 的输入列表为空（没有可派的待办）时会怎样。README 没说。我没设防；事后单独探了一下，`jv.cut(jv.judge([], q))` 返回 `[]`，不报错。
- **猜 5**：「攒起来问人」怎么写。`jv.ask` 一次只问一题且抛 `Pending` 挂起整个程序，攒不成一批；`jv.escalate(x)` 返回 `Escalated(x)`，README 说它「作 handle 标记时含义是对该题问人」，单独用是什么含义没说。写法：把待问条目列表 `jv.escalate(...)` 放进返回 dict。它的内容怎么取出来 README 也没写，事后 `dir` 看到属性叫 `.payload` / `.note`。
- **猜 6**：宿主函数返回 `list[str]`，`jv.transform` 会不会逐个包成 `Mat`。README 说「返回 Mat 或 [Mat]」，但没说输入是 str 列表时的规则。赌会包。跑通。
- **猜 7**：模板放 `ref` 还是 `ctx`。§2.1 说 ref 是「参照（锚点样例、标准）」，模板像标准 → ref。但 ref 里的东西会不会渲染进假客户端的 `text`、measure 题是否看 ref，都没写。两题都放 `ref=[模板]`。
- **猜 8**：条款编号从哪来。出口和材料都不带位置，README 没提 `Mat` 有下标元数据。用 `enumerate` 宿主列表下标 +1。
- **猜 9**：measure 的 `Unsure("band")` 归哪一档。§2.4 给 cold 带 provisional，band 没有；δ 多大没写。写法：拿不准的一律当中风险交人看。实测假规则给 0.7、hi=0.6 就落 band——δ 至少 0.1。
- **猜 10**：理由摘录用 `gen n=1` 还是直接引条款原文；在 for 里 `retry_seq` 该填什么。README §2.7 说「retry_seq 与 iter_seq 同规则」。第一版填 0，库报 `W-seq-const` 提醒用循环变量，改为 `i`。
- **猜 11**：中风险排序。README 关于 `.order()` 只有一句「同题跨对象偏序，向量化才有」——没有签名、返回形态、方向。写 `rs.order()` 试，实测返回 `[[0], [2, 3, 1], [4]]`（下标分组列表），先展平再过滤中风险。
- **猜 12**：`.order()` 的分组依据和组内顺序。看结果像是「按档位分组、组内按该档概率降序」，但 README 没写，也没写它算不算刷新点、会不会消费读数。实测层数没变（仍 2 层）。「从高到低」对 measure 到底按档位下标还是按概率，也是猜。
- **猜 13**：`jv.transform` 参数里放材料列表（`cands`）行不行、宿主函数收到的是 `Mat` 列表还是原值。偏差表 14 说可以、键按元素哈希，但正文 §2.7 没说。宿主函数按 `Mat` 写（`.content`）。跑通。
- **猜 14**：普通 `for` 里 `gen` 的 `retry_seq` 用循环变量。§2.6 的规则是对 `iter_seq` 写的，`retry_seq` 只有一句「同规则」。照做。
- **猜 15**：transform 的过滤结果为空时返回的是 `[]` 还是别的（`Mat([])`？）。README 没说。用 `if cs` 判真，实测过。
- **猜 16**：`select` 的 `over=[]` 会怎样（报错 / Unsure / 静默）。没写。提前剔除，不交给 select。
- **猜 17**：`Pick(k)` 的 k 在 match 之外怎么取（属性名）。README 只演示 `case jv.Pick(k)`。列表推导里我写 `x.k`，跑通说明属性就叫 `k`。
- **猜 18**：`guard=` 能不能直接传 `Pick`。§2.6 说至少一个是「trusted 状态的 `jv.Act`」，那 Pick 不算，所以专门加一道「没走样」test 当守卫题，多一层。守卫状态 `on=改写, ctx=[原报错]` 的 taint 又取决于猜 2。
- **猜 19**：`jv.Runtime(generator=…)` 参数与生成器签名 `(prompt, ctx, n, retry_seq)`。README 完全没提，只在 six.py 里看到；`ctx` 元素是 `Mat` 还是原值也没说，我两种都处理。实测是 `Mat`。
- **猜 20**：`Budget.escalate` 默认值。程序一调了 `jv.escalate` 一次，六条示例有的不写 escalate；保险写 `escalate=10`。程序二、三没写，也没报错。
- **猜 21**：`Budget.layers` 该给多少：程序返回时刷新 `do` 算不算一层。§2.10 说「一次 cut 通常一层」，返回时的刷新没说。程序三实测仍 2 层，所以 do 的刷新不计层（猜）。
- **猜 22**：假客户端 `text` 里 `ref` / `ctx` 会不会和 `on` 一起渲染，我的假规则只看 `on` 会不会被模板里的「无限」干扰。§4 只写了 JSON 键名。只看 `on`，跑通。
- **猜 23**（观察）：假规则自己抛异常时库怎么办。README 说 `do` 失败是值、切成 `Unsure("fail")`，没说模型调用失败。实测：先 `W-call-fail`，随后 `cut` 抛 `TypeError: float() argument must be … not 'NoneType'`，程序整个崩，而不是 Unsure。
- **猜 24**：`Escalated` 值放进返回 dict，程序返回时的期物解析和 J-05 核会不会碰它。没写。跑通了。

## 3. 如果我来改 README，我会加哪三句话
