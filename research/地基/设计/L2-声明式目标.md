## 1. 这是一门什么语言

一门三值的逻辑规则语言。事实是料库里的材料（Item，带种类）；谓词有三种类型，分别由 Jev 的三种题求值：
关系谓词（是非）、函数谓词返回一个候选（选择）、函数谓词返回一个档位（打分）。规则是 Horn 子句，
体是字面的合取，头是派生的材料或值。程序员写规则和一个目标；编译器把规则图分层、把同一材料上的题合成一次调用、
选 K、排序副作用、算预期费用；运行时逐层求值，每次调用入账本，目标的每个答案都带推导树。
它和 Datalog 的区别在三处，全部来自 Jev 的公理：谓词的真值是校准的三值出口而不是布尔（P2）；
递归不是不动点而是有界且带变式（P2、P4 非单调）；规则体可以调用有副作用的「变字面」函数（P1、P10、P16 字面化定律）。

## 2. 组成部分，以及每部分怎么利用 Jev

| 部分 | 设计 | 利用的公理 |
|---|---|---|
| 料库声明 `source` | 任何来源装成带种类的材料集；渲染函数按格式注册 | 材料一个类型 [选择#1]；渲染文本是账本键 [P3] |
| 谓词声明 `judge` | 程序员写的是**三种语义操作**：`test`（判，出位）、`select`（选，出索引）、`measure`（量，出数），不写物理题型。槽位显式：`on` 对象、`ctx` 语境、`over` 候选集、`anchors` 锚。程序员永远不拼字符串，状态由编译器按四槽构造 | 三种题是判断的三种数字化，对驱动程序完备且最少（06 §6）；对象绑定与窗口 [P4]；参照进类型 [E10] |
| 下沉（语义 → 物理） | 编译器决定每个语义操作用哪种题：`select` 在短候选且 K ≤ 16 时下沉为一道选择题，长候选或 K 超限时下沉为 K 道是非取最高；`measure` 下沉为打分题，同伴入状态时改为「每候选一道打分，只按出口计数」；`test` 下沉为是非题 | 短候选 choice 足够且省调用 [E10]；长候选 noul-argmax 更准（首位偏置 33% 对 0）[E9b]；批不变性 0.90 [E10] |
| 融合与裂变 | **融合**：同一渲染状态上的所有语义操作合成一次调用（约束、目标、决定三样一次往返）；**裂变**：材料超窗时按窗口切开成多个状态，出口按聚合规则合回（exists=max、count=区间） | 调用次数是成本轴 [P5]；窗口 [P4、E10] |
| 规则 `rule` | 三值 Horn 子句；`not` 是出口对调不是 1−p；比较只在同一打分谓词内合法 | P(x)+P(¬x)≠1 [推导#3]；偏序 [推导#15] |
| 变字面函数 `fn` / `fn!` | S 库；`!` 标副作用（做）。纯 S 按参数键缓存；`!` 按账本键至多执行一次 | 字面化定律 [推导#20]；账本只增 [推导#11] |
| 有界迭代 `iterate` | 规则集在 `bound` 内重复求值，`variant` 是一个聚合（计数或打分），不再进步即停并出 unsure | 非单调无不动点 [推导#11]；打分做变式 [选择#6] |
| 目标 `goal` | 每个目标必须写 unsure 策略；可带排序（只对打分谓词） | unsure 必填 [推导#4] |
| 规划器 | 谓词依赖图 → 分层；同层同对象的题合成一次调用；choice 的 K 按候选长度定；副作用按数据依赖排序；干跑 | 调用次数是成本轴 [P5]；K 上限 [E10、E9b] |
| 账本与推导树 | 每个答案可展开到每一层的读数、分布、置换 | 重放逐字节 [P3] |

三种语义操作各自怎么用足 Jev：`test` 是过滤和守卫；`select` 是关系判断，不止选候选——选材料（16 段里哪段与 a 矛盾，
一次调用代替 16 道是非）、消歧、分类（固定标签集）、决定（动作索引）、解非确定；下沉为选择题时规划器自动置换取众数
（≥2 次，众数不一致即 unsure，[P9、E9b]），下沉为是非组时自动取最高并把并列判 unsure。`measure` 是语言的模数转换器：
档位进宿主后可合法地算（同题同刻度同锚、单独渲染 [E10]），凡「多少」都由它给：优先级、带程度的阈值、变式、把判断力花在哪。
排序只在「状态不含同伴」时合法（编译器检查 `ctx` 不含同类候选，[E10 批不变性 0.90 证伪 → 怎么才能对]）。
一次调用可以同时要三样：对一组候选，每个一道 `test`（可行吗）、每个一道 `measure`（多好）、一道 `select`（哪个最好），
融合后一次往返给出约束、目标、决定，题免费 [P5]。

## 3. Jev 要加什么（从能做域表推）

| 加入物 | 语言里的形式 | 扩哪一格 | 怎么量 |
|---|---|---|---|
| 生成器 | `fn write!(n, spec, ctx) -> set M`，S 库标准函数 | 构造类任务（修到零、生成到全绿） | 原锁/部分的构造任务里多少条写得出且跑通；E9c 题级通过率（假设#22 部分） |
| 执行器 | `fn run!(…) -> M` 等 S 库函数 | 字面化不足 | 字面化前后 AUC（P15 0.79 → P16 0.95） |
| 人 | `fn ask!(q, m) -> M`；答案自动进校准集 | 真值不可观测、边界案例 | 停岗率下降、线的置信区间收窄 |
| 渲染函数 | `source … render a11y / ocr / ast` | 模态 | 模态锁回到文字的条数与错误率 |
| 分治骨架 | 标准库规则模板 `divide` | 不可分解 | 近似与整体一致率 |
| 时延、无增益 | 不加；`⊤ → S` 纯段交给求解器 | 域外 | — |

## 4. 语言长什么样

### 4.1 词法
标识符可用中文；关键字：`source kind fn judge rule goal iterate bound variant decreasing increasing on ctx over anchors
not in count exists max top order by unsure escalate keep drop refine module import`。字符串是题面；`!` 后缀标副作用。

### 4.2 文法（BNF）
```
program   ::= decl*
decl      ::= source | kind | fn | judge | rule | goal | iterate | module | import
source    ::= 'source' ID '=' LOADER '(' args ')' ['render' ID] ['as' KIND]
kind      ::= 'kind' KIND ['=' '{' ID (',' ID)* '}']          # 枚举种类可作 choice 的静态候选集
fn        ::= 'fn' ID ['!'] '(' params ')' '->' type           # 声明 S；实现由 S 库按名注册
judge     ::= 'judge' ID '(' params ')' ':' jtype '=' STRING slots
jtype     ::= 'test' | 'select' 'over' expr | 'measure' '{' ID (',' ID)* '}' 'anchors' ID
              # 语义操作。物理题型（noul/choice/score）由编译器下沉决定，程序员不写；`pin noul|choice|score` 可强制，只供实验
slots     ::= 'on' expr ['ctx' expr (',' expr)*]
rule      ::= 'rule' head ':-' body '.'
head      ::= ID '(' vars ')' ['->' var]
body      ::= lit (',' lit)*
lit       ::= atom | 'not' atom | var '=' expr | var 'in' expr | expr CMP expr
atom      ::= ID '(' args ')'
expr      ::= var | ID '(' args ')' | ID '!' '(' args ')' | agg | STRING | INT | expr '+' expr
agg       ::= ('count' | 'exists' | 'max' | 'top' INT) '(' atom [ 'by' ID ] ')'
goal      ::= 'goal' atom ['order' 'by' ID ('asc'|'desc')] 'unsure' policy '.'
policy    ::= 'escalate' | 'keep' | 'drop' | 'refine' expr
iterate   ::= 'iterate' 'bound' INT 'variant' agg ('decreasing'|'increasing') '{' (rule)+ '}'
module    ::= 'module' ID '{' decl* '}'        import ::= 'import' ID ['as' ID]
type      ::= KIND | 'set' KIND | 'text' | 'int'
```

### 4.3 类型规则
- 材料：每个变量绑定一个 Item，种类是标签；`set KIND` 是材料集。
- 读数：`test` 谓词的元组带出口 {act, ignore, unsure}；`select` 谓词是函数 `→ 候选 ⊎ unsure`，类型参数是候选集表达式；
  `measure` 谓词是函数 `→ 档位 ⊎ unsure`，类型参数是档位集与锚。读数类型跟随语义操作，与下沉成的物理题型无关。
- **读数不可写进 `on`/`ctx`**（语法上没有取概率的表达式，只有出口和值），概率永远不进状态 [推导#2]。
- `CMP` 只对同一 `measure` 谓词的两个值合法，且该谓词的 `ctx` 不含同种类候选（编译器检查）；跨谓词比较、跨候选集比较是类型错误。
- `measure` 无 `anchors` 是类型错误；`select over` 的候选集为空是运行期 unsure。
- `goal` 无 `unsure` 策略是类型错误；递归的 `rule` 不在 `iterate` 内是类型错误。
- 线不在语言里：没有任何语法能写阈值。线只在校准存储 [选择#8]。

### 4.4 语义规则
- 求值是分层的：谓词依赖图取 SCC、拓扑排序成层；`not` 与聚合要求分层（不得递归穿过），同 Datalog 分层否定（登记表 R1）。
- 三值合取：体内字面按强 Kleene：有 ignore 即 ignore；无 ignore 有 unsure 即 unsure；否则 act。头元组继承体的出口。
- `not A`：act↔ignore 对调，unsure 不变。它不是反问；反问是另一条 `judge`。
- 函数谓词（`select`/`measure`）：`x = 选(…)` 中若结果 unsure，则该字面 unsure，整条体 unsure，元组进 unsure 流。
- 聚合：`exists` = max，`count` = 区间 [act 数, act 数 + unsure 数]，`max/top k by 打分` 含 unsure 则结果 unsure。
- `iterate`：每轮全量重求值体内规则，派生材料用 `supersedes` 取代上一轮同源材料；`variant` 每轮计算，
  不严格单调则本轮停止、目标出 unsure；到 `bound` 亦停。同一轮内（渲染状态，题）键重复 ⟹ 该题直接取账本，不重问；
  跨轮键完全相同 ⟹ 判无进展停止（运行期规则，登记表 R2 修正）。
- `fn!`：按数据依赖定序，同键至多执行一次并记账；重放时取记录的观察不重做。`fn`（无 `!`）纯，按键缓存。
- `goal` 的 unsure 策略：`escalate` 交人并进校准集；`keep` 作为 unsure 答案输出；`drop` 丢弃并记账；
  `refine e` 用表达式 e 替换对象槽后重问一次（把它变更字面）。
- **下沉**：`test` → 是非题。`select over C` → 若 C 的元素渲染后平均 ≤ 300 token 且 |C| ≤ 16（段落级 [E10]），一道选择题，
  ≥ 2 次记账置换取众数；否则（长候选或 |C| > 16）→ 对每个 c∈C 一道是非「c 是否…」，取最高读数，并列（差 < δ_noul 0.05）判 unsure，
  这一路在 8 个代码候选上 14/14 优于选择题 12/14 [E9b]；|C| > 255 一律裂变成组再锦标赛 [D1]。
  `measure` → 打分题；若状态含同种类同伴 → 改为每候选单独状态各一道打分，结果只许出口计数聚合，不许排序 [E10]。
- **融合**：同一层内、渲染状态相同的所有语义操作（不论 test/select/measure）合成一次调用；账本键是（渲染状态，题集）。
  三种语义操作对同一候选集可以在一次调用里同时要（约束、目标、决定），程序员写三条 `judge`，编译器发一次请求。
- **裂变**：`on` 或 `ctx` 渲染后超窗口（noul 500 带主张 [P4]；choice 段落级 1.8k、代码级 1.5k [E10]）时，
  编译器按窗口把对象切成块，各块独立求值，出口按聚合规则合回：`test` 用 exists=max（任一块 act 即 act，无 act 有 unsure 即 unsure），
  `select` 每块先选再锦标赛，`measure` 各块打分后只按出口计数。裂变的每一块都进推导树。
- 状态构造：编译器对每条 `judge` 的调用按四槽渲染：`on` 是对象槽单独占位；`ctx` 是语境槽；`over` 是候选槽（随机置换，种子入账）；
  `anchors` 是参照槽。渲染后超窗口（noul 500 带主张 [P4]；choice 段落级 1.8k、代码级 1.5k [E10]）在编译期（材料已知）或调用前拒绝。

### 4.5 模块与组合
`module` 导出谓词与 `fn`；`import` 后按 `模块.谓词` 引用。程序的接口就是它导出的谓词（材料集 → 材料集 ⊎ unsure），
所以模块可以放在任何谓词能放的位置：组合的组合是同一接口。不同模块的规则合并求值时仍按全局依赖图分层。

## 5. 标准库

- **骨架（规则模板，参数是谓词名）**：
  `pair_select(S, J)`：对每个 a∈S，一个状态放 a + K 个邻居，`J : choice` 选出与 a 相关者，K 按长度自动。
  `tournament(C, J)`：K 选一逐轮，unsure 组晋级前二，到一个或全 unsure。
  `divide(M, J)`：拆 ≤ 窗口的块，各块判，出口渲染成摘要再判。
  `bisect(L, J, x)`：有序列表上按 `J : noul` 二分，做的次数 log|L|。
  `select_type(...)`：预测 + 「待真值」校准回填。
  搜索类（做→观察→选→做）不是模板，用 `iterate` + `fn!` 直接写（见 §7 探针 41）。
- **S 库（变字面函数）注册接口**：`register("run", fn, effect=True, render=...)`；声明处 `fn run!(…) -> …` 只写签名。
  首批：`run!`、`diff`、`ast`、`log_stage`、`render_features`、`neighbors`、`a11y_tree`、`ocr`、`write!`、`ask!`。
- **题库**：按谓词类型存题面模板与验题集；一条题入库须带验题闸门结果与试验台幸存率。
- **参照库**：`anchors` 命名集合（每档一条 [E10]）与 choice 的「都不是」常驻选项。

## 6. 工具链

- `jl check P`：类型与七类诊断（§6.1），种类流 lint（悬空谓词、无源之水、每个中间谓词必须被某目标或聚合消费）。
- `jl plan P --dry`：打印层、每层的调用数、每次调用的题数、状态 token、K、置换次数、预期费用与秒（按 P5 公式）。
- `jl run P`：分层执行，并发 ≤ 32 [P5]，四道终止（层深、无进展、步数、费用上限），每次调用入账本。
- `jl replay P --layer n`：关网络按账本重放到第 n 层，打印该层每条题的读数、分布、置换前后 argmax。
- `jl trace 答案`：从一个目标元组展开推导树到叶子读数与材料地址。
- `jl calib`：验题闸门、错误率扫描、上岗/停岗，按三种题型分别报告，附置信区间。

### 6.1 七类编译期诊断
| 码 | 触发 | 报什么 |
|---|---|---|
| E1 读数入状态 | 语法上不可能（无取概率表达式）；若 `on` 引用 `score` 值以外的读数 | 「概率不进 Jev；只能放出口或值」 |
| E2 跨谓词比较 | `CMP` 两侧来自不同 `judge` | 两侧谓词名、各自刻度 |
| E3 跨候选集比较 | 两个 `choice` 值比较 | 两个候选集表达式 |
| E4 跨刻度/异锚比较 | `score` 谓词不同或锚不同 | 锚名与档位集 |
| E5 缺 unsure 策略 | `goal` 无 `unsure` | 「unsure 必须有去向」 |
| E6 无界递归 | 递归规则在 `iterate` 外 | 递归环上的谓词 |
| E7 无锚打分 / 同伴入序 | `score` 缺 `anchors`；或对 `ctx` 含同种类候选的 `score` 做 `order by` | 「打分要锚」/「含同伴时只能计数聚合」 |

## 9. 弱点与所赌的假设

弱点：
1. **成本被声明式藏起来**：`rule 退化(c) :- commit(c), …` 一写就是对全部提交跑基准；程序员看不到平方项，只能靠 `jl plan --dry`。规划器要好到能拒绝坏计划，否则声明式比命令式更容易烧钱。
2. **副作用与迭代的语义是新的**：`fn!` 在规则体里、`iterate` 全量重求值 + `supersedes`、`prev_scene` 这种运行时绑定，没有先行语义可靠；D41 这种做→观察→选→做的搜索写起来别扭，本设计在交互类任务上最弱。
3. **三值函数谓词的 Datalog 没有现成理论**：分层否定、聚合、`choice`/`score` 函数谓词与 unsure 流的组合需要自己证明求值终止与确定性，红队会打这里。
4. 下沉规则目前只有两个实测点（E10 段落级、E9b 代码级 8 候选），中间长度与 K 的边界是插值，编译器可能选错题型；要在 `jl plan --dry` 里显示下沉决定并允许 `pin` 复核。
5. 谓词推导、S 库、题库全是标准库，语言核心很小但可用性全靠库；库没建好之前语言几乎写不了东西。

所赌的假设（账本编号）：#13 选择吸收配对（成立·条件 K），#14 锦标赛（成立·条件），#19 谓词推导可写成规则（形式成立、未实现），
#22 生成 + 判断（部分），#26 组合稳定性（未测），#9 内核四样独立（未做消融）。
