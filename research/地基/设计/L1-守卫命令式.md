# L1 · 守卫命令式（竞争设计一）

日期 2026-09-21。输入只用 `设计/设计环节-输入与要求.md` 允许的材料；引用标签照 `09` 账本；借用照 `00-宪法.md` 登记表（本设计新增两行，见 §9.3）。
设计哲学：程序是 `g → S` 的集合，命令式书写；三种题分别是 `if` / `select` / `while` 的守卫；S 是普通函数；字面化由程序员显式写、编译器检查。目标：语法最直接、诊断最清楚、最容易上手。

---

## 1. 这是一门什么语言

一门命令式的判断语言。程序由语句顺序组成，语句只有四种：把材料变字面的确定调用（S）、由一道 Jev 判断守卫的分支或循环（g）、纯宿主计算、对外部世界的动作。每道判断的读数在程序里不可见，程序只看见出口：是非题的 act / ignore / unsure，选择题的某个候选或 unsure，打分题的某档或 unsure。每个分支和循环必须写出 unsure 去哪，否则不编译。每次判断连同渲染后的状态进只增账本，程序可逐字节重放。编译器把同一状态上的所有判断合成一次请求、把彼此独立的判断并发、把依赖链排成层，程序员写顺序逻辑，不写批处理。[推导 ← P5 成本形状；#4 三值必填；#12 一状态全题；#20 字面化定律]

## 2. 组成部分，与每部分怎么用足 Jev

| 部分 | 设计 | 用足的公理 / 账本 |
|---|---|---|
| 题（question） | 具名、带语义操作类型、带验题文件的声明：`test`、`select[固定标签集 \| 动态候选]`、`measure[刻度] anchors`。题是值，可传给库函数。物理题型由编译器下沉。 | D2 三题型；#5 三种运算；06 §6 语义/物理分离；#8 线只来自校准 |
| 材料（Mat） | 唯一的数据类型。带地址、来源链、渲染函数。出口也是 Mat。读数不是 Mat。 | #1 一个材料类型；#2 读数无渲染 |
| 状态构造 | `state(obj, evidence, ctx, ref)` 内建；渲染带四槽标记；窗口检查在此。简写 `m with ctx c`。 | #10 state 一等；P4 对象带偏 |
| 守卫语句 | `if`（是非）、`select`（动态选择）、`switch`（静态标签选择）、`while`（打分变式）。unsure 分支必填。 | #6 守卫/非确定/变式；#4 |
| S 函数 | 宿主函数，签名 `Mat… -> Mat`，分 `pure`（无副作用）与 `do`（触世界）。调 `do` 必须写 `do` 关键字。 | #20 字面化；#21 判断即执行；#9 内核含做 |
| 循环 | `while` 必带 `bound`；运行期键重复即 unsure 退出。 | #11 有界迭代 |
| 集合语句 | `for m in S { … }` 无顺序语义；体内独立判断由调度器合批并发。 | #12；P5 并发 ≥32 |
| 账本与重放 | 每次判断键 = (渲染状态, 题, 置换种子)；每次 `do` 键 = (动作, 序号)。 | P3 键排除批次 |
| 校准存储 | 程序外的数据目录：验题、人标、线、上岗状态、置换一致率。程序只引用题名。 | #8；E4 纪律 |
| 规划器 | 编译期从语句依赖建层；同状态合并；`select` 的 K 按候选长度分档；干跑输出费用。 | #12；#13 成立条件（段落 K≤16，代码 K≤4 或逐候选 noul）；L4 |

**语义操作与物理题型分离（06 §6）。** 程序员只写三种语义操作：`test`（判）、`select`（选）、`measure`（量），对应 `if` / `select`·`switch` / `while` 三种守卫语句。物理题型（noul / choice / score）由编译器按 K、候选长度、已测偏置下沉：
- `test` 在单个材料上 → noul；在一组候选上要「哪个成立」→ 可下沉为一道 choice 或 K 道 noul 取最高。
- `select` 短候选（段落级，K ≤ 16）→ 一道 choice，≥2 次记账置换取众数 [E10 P12]；长候选（代码级）→ K 道 noul 取 argmax [E9b P17：首位偏置 33% 对 0]；K = 2 且只问「哪个」→ 一道 noul。
- `measure` 档位数 = 2 → noul；≥ 3 → score，锚每档 1 条 [E10 P13]。
下沉规则在 `jv plan` 干跑里逐题打印，源码不写题型。改路径不改程序。

**融合。** 同一渲染状态上、同一层内的所有语义操作合成一次请求（P5：时间与题数无关，题 token 便宜）。典型形：对一组候选一次调用同时要「可行吗」（test）、「多好」（measure）、「哪个最好」（select）——约束、目标、决定一次往返。`for` 体内对同一元素的多个守卫也被融合。

**裂变。** `state` 渲染超窗口（带主张材料约 500 token，P4）时，编译器按窗口切开：对象段保持单独占位，证据与语境分块，各块出口摘要再进一次判（等价于 `divide` 骨架）；程序员写 `refine` 时是显式裂变，超窗时是隐式裂变并在干跑里报告。裂变不改语义，只改层数与费用。

融合与裂变是本编译器区别于现有编译器的核心工作，直接来自 P5 与 P4（借用登记见 §9.3）。

## 3. Jev 要加什么（从能做域表推）

| 加入物 | 语言里的形式 | 扩哪一格 | 怎么量 |
|---|---|---|---|
| 生成器 | `do gen(n, "指令", ctx)` 是 S 库里的一个 `do` 函数，返回 n 个 Mat | 构造类任务、支持集外 | 200 任务里「支持集外 / 构造」条目可运行数；E9c 题级 |
| 执行器 | 一切 `do` 函数（run、bench、upgrade、click…） | 字面化不足 | 执行后 AUC（E9b：0.79 → 0.95） |
| 人 | `escalate` 语句：把状态送人，答案回账本与校准集 | 真值不可观测、边界案例 | 停岗率、线的 CI 收窄 |
| 渲染函数 | S 库 `pure`：a11y_tree、ocr、ast、log_stage… | 模态 | 模态锁回到文字的条数与其错误率 |
| 分治 | 库骨架 `divide(mat, q)`：拆块→各块出口摘要→再判 | 不可分解 | 与整体判断一致率（待测） |

不加的：时延、无增益，标域外。

## 4. 语言长什么样

### 4.1 词法
- 标识符：Unicode 字母开头（中文可作标识符）。关键字：`q` `s` `fn` `pure` `do` `test` `select` `measure` `if` `else` `unsure` `switch` `case` `while` `bound` `for` `in` `let` `return` `escalate` `refine` `state` `with` `anchors` `import` `program`。`select` 在 `q … =` 之后是语义操作，在语句首是守卫语句，按位置区分。
- 字面量：字符串 `"…"`、整数、集合 `{a, b}`、档位名、标签名。
- 注释 `# …`。

### 4.2 语法（EBNF）
```
program    ::= "program" IDENT "(" params ")" "->" type block
params     ::= (IDENT ":" type ("," IDENT ":" type)*)?
type       ::= "Mat" | "Set" | "Set[" type "]" | IDENT
block      ::= "{" stmt* "}"
stmt       ::= qdecl | sdecl | let | ifstmt | selstmt | switchstmt | whilestmt | forstmt
             | "do" call | "return" expr | "escalate" expr? | "refine" expr | call
qdecl      ::= "q" IDENT "=" qtype STRING ("probes" STRING)?
qtype      ::= "test" | "select" ("[" labels "]")? | "measure" "[" levels "]" "anchors" expr
             # 语义操作；物理题型（noul/choice/score）由编译器下沉，源码不写
labels     ::= IDENT ("," IDENT)*            # 静态标签集；省略则为动态候选
levels     ::= IDENT ("<" IDENT)+            # 有序档位，低到高
sdecl      ::= "s" ("pure" | "do") IDENT "(" params ")" "->" type "=" STRING   # 绑定宿主实现
let        ::= "let" IDENT "=" expr
ifstmt     ::= "if" IDENT "on" expr block ("else" block)? "unsure" block
selstmt    ::= "select" IDENT "over" expr ("with" expr)? "as" IDENT block "unsure" block
switchstmt ::= "switch" IDENT "on" expr "{" ("case" IDENT block)+ "unsure" block "}"
whilestmt  ::= "while" IDENT "on" expr "<" IDENT "bound" INT block "unsure" block
forstmt    ::= "for" IDENT "in" expr block
expr       ::= IDENT | STRING | INT | set | call | expr "with" expr | "state" "(" args ")" | expr "." IDENT
set        ::= "{" (expr ("," expr)*)? "}"
call       ::= IDENT "(" args ")"
args       ::= (expr ("," expr)*)?
```
`while … < 档` 的意思：打分出口低于该档时执行体；达到即退出。`refine e` 把材料 e 细拆后重入当前守卫（unsure 的合法去向之一）。

### 4.3 类型规则
- `Mat` 唯一材料类型；`Set` = `Set[Mat]`。出口是 `Mat` 的子类型：`Outlet3`、`Chosen[q]`、`Level[q]`。
- 题的类型：`Q_test`、`Q_select[labels|dyn]`、`Q_measure[levels, anchors]`。`measure` 缺 `anchors` 是类型错。[#18；E10 P13] 物理题型不在类型里：同一个 `Q_select` 可下沉为 choice 或 K 道 noul，类型不变。
- 读数类型 `Read[q]` **不出现在语法里**：程序无法写出一个读数，因此「跨题算读数」「读数当材料」在语法层就不可表达。唯一看见读数的地方是调试器。[#2、#3]
- `select` 的 `as x`：`x : Chosen[q, C]`，绑定候选集 C；把 `x` 与另一 `select` 的结果比较是类型错。
- `rank(set, q)` 返回 `Set[Mat]` 的偏序视图，`q` 必须是 `Q_measure`，同一 `rank` 内同锚。[#15]
- `if/select/switch/while` 的守卫必须是题名，不接受任何数值表达式（没有阈值的写法）。[#8]
- `do` 函数只能在 `do` 语句或 `let x = do f()` 调用；`pure` 不能有副作用（宿主端声明）。
- `state(obj, evidence, ctx, ref)`：obj 必填；渲染后超窗口是错误（材料编译期已知）或运行期拒绝。[P4]
- 每个 `if`、`select`、`switch`、`while` 必须有 `unsure` 块；`switch` 的 `case` 必须恰好覆盖静态标签集。

### 4.4 语义规则
```
[下沉] 语义操作 → 物理题：test→noul；select→choice(K≤16 段落级) | K×noul(长候选) | noul(K=2)；measure→score(档≥3) | noul(档=2)
[融合] 同 render(state)、同层的全部物理题 → 一次 jev 调用（P5）
[裂变] render(state) 超窗 → 按窗口切块，对象单独占位，块出口摘要再判（P4）；干跑报告层数增量
[判]   o = outlet_q( jev(render(state), q), calib(q) )        每题一次；融合后同状态一次请求
[if]   o=act → B₁ ; o=ignore → B₂ ; o=unsure → B_u
[select] 对 C 做记账置换 r 次（默认 2，长候选自动改逐候选 noul）；众数 c 且线过 → x=c, B ; 否则 B_u
[switch] 同 select，候选集 = 静态标签
[while] 每轮 o=outlet(score)；o<档 → B，再判；o≥档 → 退出；o=unsure → B_u
       键重复规则：本循环内 (render(state), q) 已见 → 本轮出口 unsure 并退出，记账
       bound n：第 n 轮后退出，出口标 bound
[for]  体内语句对每个元素独立求值；无顺序；同层独立判断并发
[do]   执行宿主函数；观察结果入账本 (动作, 序号)；重放时取账本不重触世界
[refine e] e 由 split 细拆，重入当前守卫；细拆到单段仍 unsure → escalate
[escalate e] 送人；程序在此挂起或返回 unsure（由调用者决定）；人答入校准集
[复合守卫] 不提供 ∧/∨ 语法；要合取就嵌套 if，编译器把嵌套的同状态 if 合成一次请求，语义按强 Kleene 展开
```
确定性：判断与动作都按键入账本；桥之后全是纯函数；`for` 无顺序，`do` 按数据依赖定序，定不了序报错。[P3；#11]

### 4.5 模块与组合
- `program` 是唯一组合单位，签名 `(…Mat/Set…) -> Mat|Set`，调用像函数。程序调程序，账本共用。
- `import "路径"` 引入题库、S 库、骨架库。
- 程序的 unsure 出口：`return` 之外所有路径必须终于 `escalate` 或 `return`；编译器检查。

## 5. 标准库

### 5.1 S 库（先建，宪法：S 比 g 值钱）
注册接口：一行声明 + 宿主实现文件。
```
s pure split(m: Mat, limit: Int) -> Set        = "s/split.py"      # 切片到窗口内
s pure diff(a: Mat, b: Mat) -> Set              = "s/diff.py"       # 切 hunk
s pure ast(m: Mat, kind: String) -> Set         = "s/ast.py"        # 抽签名/调用/类型
s pure log_stage(m: Mat) -> Set                 = "s/log_stage.py"  # 日志切阶段/切行
s pure sample(m: Mat, n: Int) -> Mat            = "s/sample.py"     # 抽样例值
s pure features(m: Mat, spec: String) -> Mat    = "s/features.py"   # 宿主算特征再渲染
s pure neighbors(m: Mat, S: Set, k: Int) -> Set = "s/neighbors.py"  # K 邻居渲染
s pure a11y(m: Mat) -> Mat                      = "s/a11y.py"       # 可访问性树
s pure ocr(m: Mat) -> Mat                       = "s/ocr.py"
s pure table(S: Set) -> Mat                     = "s/table.py"      # 集合渲染成一段文字表
s do   run(cmd: Mat, cwd: Mat) -> Mat           = "s/run.py"        # 沙箱执行，返回 退出码+stdout+stderr
s do   bench(repo: Mat, rev: Mat) -> Mat        = "s/bench.py"
s do   gen(n: Int, instr: String, ctx: Mat) -> Set = "s/gen.py"     # 写手
s do   ask(m: Mat, question: String) -> Mat     = "s/ask.py"        # 人
```
宿主实现是任意语言的可执行文件，输入输出是 Mat 的序列化；`pure` 由宿主端承诺无副作用，账本按输入哈希缓存。

### 5.2 骨架（用本语言写，随库发布）
```
program filter(S: Set, g: Q_noul) -> Set             # 三条流：act 集、unsure 集另返回
program pick(C: Set, g: Q_choice, ctx: Mat) -> Mat   # select 的函数形式，含置换
program rank(S: Set, g: Q_score) -> Set              # 偏序；状态只放锚与对象
program tournament(C: Set, g: Q_choice, k: Int, bound: Int) -> Mat   # unsure 组晋级前二
program divide(m: Mat, g: Q_noul, limit: Int) -> Mat # 拆块→各块出口摘要→再判
program search(goal: Q_noul, step: Q_choice, act: Fn, bound: Int) -> Mat  # 做→观察→判→定→做
program choose_then_verify(C: Set, g: Q_choice, v: Q_noul) -> Mat   # 选型：预测 + 事后回填
```
### 5.3 题库与参照库
题库按领域文件存放，每题带验题文件（`probes/题名.yaml`：noul 3+3；choice 每选项 3 + 都不是 3；score 每档 3）。参照库存 score 的锚样例（每档 1 条即收敛，E10）与 choice 的「都不是」模板。题的上岗状态、线、置换一致率在校准存储里，程序不写。

## 6. 工具链

- `jv check prog.jv`：编译。输出七类错误（§6.1）、警告（种类流、无进展静态子集）。
- `jv plan prog.jv --scope dir`：干跑。输出每层的题、状态数、预期 token、预期钱、预期秒（P5 公式）。
- `jv run prog.jv --scope dir --budget $`：运行。分层、并发（默认 32）、四道终止（深度、键重复、bound、钱）。
- `jv replay run-id [--layer n]`：重放到第 n 层，打印该层每题的读数、选择题分布、打分档位分布、置换前后的 argmax。
- `jv probe 题名`：跑验题闸门；`jv calib`：错误率扫描与停岗。

### 6.1 七类编译错误各报什么
| 代码 | 触发 | 报文（示例） |
|---|---|---|
| E1 读数外泄 | 试图把守卫结果当值使用（语法上只有一种可能：把 `if` 写成表达式） | `E1 第12行：判断没有值，只有出口。用 if/select/switch/while。` |
| E2 跨题比较 | 两个 `select` 的 `as` 变量互比；两个 `rank` 的结果互比 | `E2 第20行：x 来自候选集 C₁，y 来自 C₂，不同候选集的选择不可比。` |
| E3 缺 unsure | 守卫语句无 `unsure` 块 | `E3 第8行：if 有观点 缺 unsure 块。写 escalate、refine 或 continue。` |
| E4 线字面量 | 守卫位置出现数值或比较 | `E4 第15行：守卫只能是题名。线来自校准，不写在程序里。` |
| E5 无锚打分 | `score` 声明缺 `anchors` | `E5 第3行：score 紧急度 没有锚样例，刻度不成立。` |
| E6 无界循环 | `while` 缺 `bound`；或体内既无 do 也无状态写（静态子集，warn） | `E6 第22行：while 缺 bound。` / `W6：循环体不改状态也不做动作，将在第 2 轮键重复退出。` |
| E7 状态越窗 / 覆盖 | `state` 渲染超窗口（材料已知时）；`switch` 未覆盖标签 | `E7 第30行：状态 1,930 token > 窗口 500（带主张）。用 split 或 divide。` |

## 7. 通用性检测：15 条探针程序

这些任务只是检验语言能否任务无关地表达的探针，不是目标任务；语法没有为它们做任何调整。前 10 条来自 `设计/E` §26.5，后 5 条从 `设计/D` 通用组取编号 7、23、41、66、88（含一条锁、一条无增益，照实写）。共用题库 `import "q/std.jv"`、S 库 `import "s/std.jv"`；每条程序自带题声明以便独立阅读。

### 7.1 #13 编译错误归因到修改行
```
program 归因编译错误(repo: Mat, diff: Mat) -> Set {
  q 哪块 = select "这条编译错误由 diff 里哪一块引起？"
  q 剩余 = measure[无 < 少 < 多] anchors 参照.错误数 "剩余未归因的错误有多少？"
  let 块 = diff(repo, repo with diff)
  let 错 = log_stage(do run("make", repo with diff))
  let 归因 = {}
  while 剩余 on table(错) < 无 bound 5 {
    for e in 错 {
      select 哪块 over 块 with e as b { 归因 = 归因 + {e with b}; 错 = 错 - {e} }
      unsure { refine e }
    }
  } unsure { escalate table(错) }
  return 归因
}
```
### 7.2 #17 提交信息与 diff 一致
```
program 提交信息一致(msg: Mat, diff: Mat) -> Set {
  q 出现 = test "这句描述的改动在 diff 里出现了吗？"
  let 句 = split(msg, 80)
  let 块 = diff(msg.parent, msg.parent with diff)
  let 未见 = {}
  for s in 句 {
    if 出现 on state(s, 块) { } else { 未见 = 未见 + {s} }
    unsure { 未见 = 未见 + {s with "unsure"} }
```

## 9. 弱点与赌的假设

### 9.1 弱点（自评）
1. **unsure 块处处必填让短程序变长**：7.4 和 7.6 的 switch 有一半行是 case 与 unsure。可读性换来的是没有静默二值化，但上手者会烦。可能的缓解（未采用）：`unsure escalate` 单行简写。
2. **复合守卫不提供 ∧/∨**：合取要嵌套 if，编译器合批后语义等价，但程序面上比声明式啰嗦；7.5 的三层嵌套就是例子。
3. **下沉与裂变在源码上不可见**：select 下沉为 choice 还是 K 道 noul、状态超窗后裂成几层，只在 `jv plan` 干跑里可见，源码看不出费用与层数；「逻辑可见」只满足了一半。
4. **变式必须是打分题**：7.10「未审差异数」本可由宿主计数，为了让 while 有校准的停机依据硬配了一道打分题，是无增益的判断（设计/E「无增益」类）。应允许宿主计数作变式的纯段形式，但那样 while 就不再是守卫命令的重复形式。
5. 参照库（anchors）的作者负担：每个 score 题都要先准备锚样例，没有锚的题写不了。

### 9.2 赌的假设（引账本）
- #13、#14 选择吸收配对与锦标赛：成立条件段落级 K≤16、代码级 K≤4 或逐候选 noul（E10、E9b）——本设计的 select 自动切路径全靠它。
- #16 打分批不变性证伪后的条件（状态不放同伴）：rank 骨架与 while 的变式依赖它。
- #22 Jev + 生成（部分）：7.7 的价值取决于 E9c。
- #26 串联翻转率未测：program 嵌套的稳定性未知。
- #9 内核四样独立性未做实跑消融：本设计的四种语句是否最小，纸面上的消融只在 §8 B2 一行。
