## 程序 1：邮件分流

```python
FOLDERS: dict[str, list] = {}                                   # 宿主的文件夹映射
def _file(email, folder):
    FOLDERS.setdefault(folder.content, []).append(email.content["id"]); return {"filed": email.content["id"], "to": folder.content}
分流 = jv.register_action("file_email", fn=_file, taint_out="inherit", reversible=False, reason="", cost=0.0)   # 猜 4

@jv.program(budget=jv.Budget(calls=50, cost=0.02, layers=2))
def 邮件分流(邮件, 文件夹):
    正常 = jv.test("这封邮件是正常的业务邮件（不是钓鱼或诈骗）吗？", calib=jv.calib("mail.正常"))   # 猜 2
    去哪 = jv.select("这封邮件应归入哪个文件夹？", calib=jv.calib("mail.去哪"))
    rs = jv.judge([jv.state(on=m, over=文件夹) for m in 邮件], 正常, 去哪)     # 猜 1；一层，每封一次调用两题
    安, 夹 = jv.cut([r[0] for r in rs]), jv.cut([r[1] for r in rs])            # 猜 5
    写, 交人 = [], []
    for i, (m, a, f) in enumerate(zip(邮件, 安, 夹)):
        match (a, f):
            case (jv.Act(), jv.Pick(k)): 写.append(jv.do(分流, m, 文件夹[k], iter_seq=i, guard=a))   # 猜 3、猜 21
            case _: 交人.append(m.content["id"])                                  # 可疑 / 拿不准：都不分流
    jv.consume(安, unsure=jv.drop); jv.consume(夹, unsure=jv.drop)                # 猜 6
    return {"已分流": 写, "交人": jv.escalate(交人, note="可疑或拿不准，攒起来交人")}   # 猜 7、猜 18
```

## 程序 2：代码评审排队

```python
def split_hunks(diff): return [h.strip() for h in diff.content.split("\n@@") if h.strip()]
def 合格(hunk_text, 意见): return any(n in 意见 for n in re.findall(r"def (\w+)", hunk_text))

@jv.program(budget=jv.Budget(calls=50, cost=0.02, layers=2))                    # 猜 19
def 评审排队(diff):
    要看 = jv.test("这个 hunk 需要人工评审吗？", calib=jv.calib("review.要看"))
    风险 = jv.measure("这个 hunk 的风险等级是？", scale=("低", "中", "高"), calib=jv.calib("review.风险"))
    hunks = jv.transform(split_hunks, diff)
    states = [jv.state(on=h) for h in hunks]
    看, 险 = jv.judge(states, 要看), jv.judge(states, 风险)      # 猜 8、猜 9
    看出 = jv.cut(看)
    拿不准 = [i for i, x in enumerate(jv.consume(看出, unsure=jv.drop)) if x is None]
    顺序 = [i for tier in 险.order() for i in tier if isinstance(看出[i], jv.Act)]   # 猜 10、猜 11
    意见 = {}
    for j, i in enumerate(顺序[:2]):
        for 试 in range(2):                                        # 不合格重新生成一次
            句 = jv.gen("为这个 hunk 写一句评审意见，点名其中的函数", ctx=[hunks[i]], n=1, retry_seq=试)   # 猜 12
            if 句 and 合格(hunks[i].content, 句[0].content): 意见[i] = 句[0].content; break          # 猜 13
    return {"顺序": 顺序, "拿不准": 拿不准, "意见": 意见}
```

## 程序 3：地址标准化

```python
def 校验(addr): return addr.endswith("号") and "区" in addr and (addr.startswith("北京市") or addr.startswith("上海市"))
def 过校验(cands): return [c.content for c in cands if 校验(c.content)]          # 猜 14

@jv.program(budget=jv.Budget(calls=50, cost=0.02, layers=2))
def 地址标准化(地址们):
    忠实 = jv.select("哪个标准化结果最忠实于原文地址？", calib=jv.calib("addr.忠实"))
    待判, 结果, 失败 = [], {}, []
    for i, a in enumerate(地址们):
        通过 = jv.transform(过校验, jv.gen("把这条地址改写成「省市+区+路+号」的标准格式", ctx=[a], n=3, retry_seq=i))
        if not 通过: 失败.append(i); continue                       # 猜 15
        待判.append((i, a, 通过))
    exits = jv.cut(jv.judge([jv.state(on=a, over=c) for _, a, c in 待判], 忠实))   # 一层；猜 16
    for (i, a, c), e in zip(待判, exits):
        match e:
            case jv.Pick(k): 结果[i] = c[k].content
            case jv.Unsure(): 失败.append(i)                        # 猜 17
    return {"结果": 结果, "失败": 失败, "成功率": round(len(结果) / len(地址们), 3)}
```

## 猜点清单（21 处）

每条三段：猜的是什么 / 文档为什么没告诉我 / 最后怎么写。标「表里有，我漏看」的是契约表或正文其实写了、我没找到或没把握的。

**猜 1** test 题的状态能不能带 `over=`。§2.1 说 `over` 只有 select 用，契约表 `jv.state` 行只写 select 的 `over=[]` 报错，没说 test 看到 `over` 会不会报错或把它渲染进题面。我要 test 与 select 同状态融合，只能共用带 `over` 的状态。结果：跑通，12 题 4 调用。

**猜 2** 「是否可疑」这道题得反着问成「是否正常」。§2.6 说守卫只认 trusted 的 `Act`，`Ignore` 不行。可疑 = Act 的话，安全邮件得到 Ignore，无法放行分流动作。文档没有一句「不可逆动作的守卫题要把『放行』写成肯定命题」。结果：题面改成「是正常的业务邮件吗」，Act 放行，Ignore 与 Unsure 都交人。

**猜 3** 真实邮件是外部文本，应该是 untrusted，那时守卫永远不过。§2.6 说 untrusted 出口再多也不够、要 `jv.ask` 的答案；契约表 `do` 行只列了失败条件。文档没给「材料本来就 untrusted 时不可逆动作的完整路径」（每封都 ask？还是登记一个 trusted 的钓鱼检测动作？）。结果：靠 `jv.lit` 是 trusted 才跑通，真机形态没解决。

**猜 4** `register_action` 在 `taint_out="inherit"` 时 `reason` 能不能传空串。契约表只说 trusted 无 reason 报错；我照 seven.py 传 `reason=""`。**表里有一半**（trusted 那半）。结果：跑通。

**猜 5** 同一批读数拆两个列表 `cut` 两次算一层还是两层。§2.10 说「一次 cut 通常一层」，契约表 `cut` 行「刷新点：是」，没写第二次 `cut` 遇到已就绪读数不加层；我照 seven.py 的写法并把 `layers` 设成 2 兜底。结果：实测 1 层。

**猜 6** `match (a, f)` 元组模式加 `case _` 不消费 `Unsure`，我事后用 `jv.consume(..., unsure=jv.drop)` 补，但这些 Unsure 实际是交人而不是丢弃；而且 consume 对已经被 match 消费过的出口是否幂等——§2.5 只说 match 守卫失败的幂等。结果：跑通，没报重复消费；语义上「drop 记账」和「交人」不一致，文档没说该用哪个。

**猜 7** `jv.do` 的期物放在返回 dict 里的一个 list 里，返回时会不会被解析。契约表 `do` 行写「作返回值解析成 Mat」，没说嵌套在容器里也行。结果：解析了（输出里是 `Mat(..., origin=('do',))`）。

**猜 8** 两次独立的 `jv.judge(states, q)` 调用（同状态、同直线段）会不会融合。§2.3 有「同一直线段登记的、同一个状态上的题融合成一次调用」，§5 lift 行也提到「同段两次 judge」。**正文有，我没把握**——不确定「两个 judge 调用」算不算一个直线段。结果：10 题 5 调用，融合了。

**猜 9** `rs = judge(states, q1, q2)` 的多题向量能不能直接 `.order()`、按哪道题排。§2.3 与契约表 `order` 行只写单题向量。结果：把两题拆成两次 judge，对 `险` 单独 `.order()`。

**猜 10** `.order()` 的 δ 是多少、组内并列谁先。文档说「组内并列（读数差 ≤ δ）」，δ 在哪定义、多大没说。结果：p=0.9 与 0.8 落同一组 `[1, 4]`，组内按宿主下标顺序展平。

**猜 11** 只 `.order()` 不 `cut` 的读数向量，返回时会不会被查「读数未出口」。契约表 `order` 行「消费：否（不产生出口）」，J-05 只管 Unsure。**表里有，我没把握**。结果：没报。

**猜 12** 嵌套循环里 `gen` 的 `retry_seq` 用哪个循环变量。§2.6 / §2.7 只说「普通 for 用循环变量」，没说嵌套时外层不同 hunk 靠 ctx 区分是否够。结果：用内层 `试`（0 / 1），ctx 带 hunk，没警告，重生成一次生效。

**猜 13** 「意见里提到函数名」这个宿主检查要不要经 `jv.transform`。J-11 与 §2.7 都讲「进槽」；这个 bool 不进槽。文档没有明确一句「不进槽的宿主计算直接读 `.content` 就行」。结果：普通 Python 函数读 `.content`，静态检查 0 警。

**猜 14** `transform` 收 `list[Mat]` 时能不能把原 Mat 原样返回（保留来源链）。§2.7 只说返回 `list[str]` 逐个包成 Mat。结果：返回 `list[str]`，来源链断在这里。

**猜 15** `transform` 返回的列表能不能直接 `if not 通过`。正常路径是 Python list 没问题；但 §2.7 说宿主函数抛异常时返回一个 fail 材料（不是列表），契约表 `Mat` 行说 `bool(m)` 抛 `JvTypeError`，两格合起来推出失败路径会崩。文档没有一句直说「列表型 transform 失败时返回什么形状」。结果：只处理了正常路径。

**猜 16** select 的 `over` 只剩 1 个候选合不合法、会不会因为「两个置换」而 tie。§2.1 只说非空。结果：地址 0 就是这种情况，得 `Pick(0)` p=0.9。

**猜 17** 选题的 Unsure 直接 `case jv.Unsure(): 失败.append(i)` 不 handle 算不算合规消费。§2.5 说 match 命中即消费。**表里有**。结果：跑通。

**猜 18** `Escalated` 载荷的属性名。§2.8 / 契约表写 `Escalated(payload, note)`，没说是 `.payload`。**表里有一半**。结果：实测 `.payload` / `.note`。

**猜 19** `Budget.layers` 该填几：`gen` 立即发不算层、`.order()` 触发发层算——§2.10 有这两句。**正文有，我漏看后又找到**，最终保守填 2。实测三条各 1 层。

**猜 20** 假客户端 `rule` 收到的 `text` 里，`on` 是 dict 时是 dict 原样还是字符串。§4 写 `{"on": …}` 没说形状；契约表 `FakeClient` 行没写。结果：`json.loads` 后是 dict 原样。

**猜 21** 动作函数收到的参数是 `Mat` 还是原值。契约表 `do` 行「输入：登记动作 + 材料」；six.py 的 `_bench` 用 `commit.content`，从示例学到。**表里有一半**。结果：用 `.content`。
