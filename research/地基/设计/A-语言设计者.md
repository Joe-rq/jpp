# 专家团 A · 语言设计者：从三种判断推导语言的形态

日期 2026-09-20。输入：`需求与启发清单.md`、`06-三种判断的本质-v0.md`、`05-语言本质-v2.md` §1/§9、`研究/01-先行工作与选型.md` §7–8。
不花 Jev 钱，不改代码。全文用形式定义和代码，不用比喻。「待测」处如实标出。

## 1. 最基本的单元

### 1.1 定义

```
Call   = M × Q⁺                     一次 Jev 请求：一个渲染后 ≤ 界限的状态，一批题（三种类型可混排）
R      = ⟨R_q⟩_{q∈Q⁺}                每题一个读数，类型随题
β      = ⟨outlet_q⟩_{q∈Q⁺}           每题一座桥：读数 → 出口，线来自校准存储，不来自程序
Unit   = Call ▷ β  :  M → ⟨O_q⟩      一次请求加它的出口
```

三种出口类型（桥的值域）：

```
O_noul          = {act, ignore, unsure}
O_choice[C]     = C ⊎ {unsure}            C : Set[M]，候选集，是题的类型参数
O_score[L]      = L ⊎ {unsure}            L : 有序档位，是题的类型参数
```

出口是材料（`O ⊂ M`，可渲染、可入料库）；读数不是材料（`R` 无 `render`）。

### 1.2 为什么不能更小（消融）

| 去掉 | 坏在哪 | 对应清单 |
|---|---|---|
| 状态 `M` | 题没有对象；或把全部材料塞进去，超界限带偏（E5/E6 实测） | C2、D1 |
| 题 `Q⁺` | 没有判断 | A1 |
| 桥 `β` | 读数是死数：确定性代码拿不到可分支的值，账本记不下「决定」，下一轮无从选材 | C1、C3 |
| 把 `β` 并进 `Q` | 桥是确定性代码，题是给 Jev 的文本，两者在不同世界；合并后线无法从校准来 | E4 |
| 把状态并进上游单元的桥 | 单元失去独立接口，不能与不同上游组合 | B3 |
| 只留一种出口类型 | 昨晚的锁死：选择与打分被压成三值，分支与程度消失 | A4 |

### 1.3 为什么不能更大

选材、迭代、生成、升级给人，全部由单元加确定性代码组合出来（§4 消融）。
单元是**成本单位**（一次请求）、**账本键**（渲染后的状态 + 题）、**确定性边界**（桥之后全是纯代码）三者的重合点，
再大就把三条边界拆开了。

## 2. 类型系统

```
M                              材料：addr, origin(about, made_by), render : M → Text
Kind ⊂ Tag(M)                  种类是标签，不是类型

Q_noul        (text)
Q_choice[C]   (text, C : Set[M])                         候选集进类型
Q_score[L]    (text, L : Ord, anchors : L → M)            刻度进类型；锚样例是必填材料

R_noul[q]         : [0,1]
R_choice[q, C]    : Dist(C)
R_score[q, L]     : Dist(L)

Line[q]           两条线，只能从 Calib 取得：calib(q) : Line[q]；程序字面量不能构造
outlet_q          : R_q × Line[q] → O_q
```

**类型错误（编译期拒绝）：**

1. `R_q₁ ⊕ R_q₂`、`R_q₁ < R_q₂`，`q₁ ≠ q₂`：不同题的读数不可算不可比。
2. `R_choice[q, C]` 与 `R_choice[q, C']`，`C ≠ C'`：候选集是参照，换候选集读数不可比。
3. `R_score[q, L]` 与 `R_score[q, L']` 或锚样例不同：刻度不同不可比。
   **合法的例外**：同 `q`、同 `L`、同锚样例时，跨材料的 `R_score` 可以排序、可以聚合期望。
   这是全语言唯一允许跨材料算读数的地方，打分题的价值全在这里。
4. 把 `R` 放到要 `M` 的位置：读数无渲染，概率不进 Jev。
5. `Q_score` 缺 `anchors`：无锚的刻度不是类型。
6. `outlet_q(r, 0.65)`：线是字面量。线只有 `calib(q)` 一个来源，禁止手调在类型里。
7. `render(state)` 超界限：材料已知时编译期查，否则调用前运行期拒绝。
8. 程序出口缺 `unsure` 策略：见 §3。

## 3. 控制流

三种题对应三种控制结构。`unsure` 分支一律**必填**，缺失是编译错误；没有默认降级。

```
if q_noul on m [ctx E]:
    act:    B₁
    ignore: B₂
    unsure: B₃            必填；可写 escalate / 进下一层 / 细拆
```
语义：`o = outlet_q(jev(m ⊕ E, q), calib(q))`；按 `o` 选一支。复合条件按强 Kleene：
`∧` 有 ignore 即 ignore，无 ignore 有 unsure 则 unsure；`∨` 对偶；`¬` 不是反问，反问是另一道题。

```
switch q_choice over C [ctx E]:
    c₁: B₁  …  c_K: B_K
    unsure: B_u           必填
```
语义：运行时对 `C` 做一次记入账本的随机置换后渲染成一个状态（位置偏差对策，研究/02），
`o = outlet_q(jev(state, q), calib(q))`；分支表必须恰好覆盖 `C`，多一支少一支都是编译错误。
`outlet_choice` 的两条线：最大概率下限、前二差距下限；任一不过即 `unsure`。

```
while q_score on m [ctx E] < ℓ  bound n:
    B
    unsure: break | continue | escalate     必填
```
语义：每轮 `o = outlet_q(jev(m, q), calib(q))`，`o ∈ L` 且 `o < ℓ` 则执行 `B`，否则退出；`bound n` 必填。
**无进展检查**：账本键是（渲染后的状态，题）。若 `B` 既不含 `act` 也不改变 `m`，
下一轮的键与上一轮相同，重放必得相同读数，循环必不终止。编译器静态拒绝这种循环。
这条检查只有在「同键同读数」的账本语义下才成立，是本语言独有的。

集合上的 `for` 没有顺序语义：同一层内彼此独立的单元由调度器合并（同状态合一请求，异状态并发）。
`act` 有顺序，按数据依赖排定，依赖不足以定序时编译错误，不默认。

## 4. 算子集合的最小完备集

候选：判、做、有界循环、过滤、选、序、配对、聚合、生成、升级、拆、拼、排序、去重、纯函数。

| 候选 | 能否由别的组合 | 结论 |
|---|---|---|
| 判（三种出口） | 不能 | **内核** |
| 做 `act : Action → M` | 不能：唯一触碰世界的地方，纯代码做不到 | **内核** |
| 有界循环 | 不能：无它则无深度（C6）；无界循环在非单调判断下不终止（红队 A6） | **内核（控制结构）** |
| 纯函数 `Set[M] → Set[M]` | 不能：拆、拼、排序、配对、聚合的确定性部分都是它 | **内核（宿主）** |
| 调度（合并与并发） | 不是算子，是运行时性质 | 内核运行时 |
| 账本 | 不是算子 | 内核运行时 |
| 过滤 | = `for m in S: if q on m` 按出口分三流 | 库 |
| 选 | = `switch q_choice over C` 的表达式形式 | 库（一等，因为它是唯一的相对判断） |
| 序 | = `for m in S: score` + 纯排序 | 库 |
| 配对 | = 纯笛卡尔积 + 渲染 | 库（纯函数） |
| 聚合 | = 纯折叠 + Kleene 规则（存在 max、全称 min、计数区间、前 k 含 unsure 则 unsure） | 库（纯函数，规则由内核出口语义定） |
| 生成 | = `act writer(...)` | 库（做的实例） |
| 升级给人 | = `act ask(...)`，回来的答案是材料，也进校准集 | 库（做的实例） |
| 锦标赛 | = 有界循环 + 选 | 库骨架 |

内核由此定为：**判（三出口）、做、有界循环、纯宿主**，加运行时的调度与账本。
06 号文档写的「七算子」是库的第一层，不是内核；内核比它小。消融的结论就是这一句。

## 5. 组合规则

- **程序** `P : Set[M] → Set[M]`，接口 = 入口种类 × 出口种类 ⊎ {unsure}。单元的接口形状相同，
  所以程序可以放在任何单元能放的位置（组合的组合，B3）。
- **连接**：上游出口（`O ⊂ M`）进入下游状态构造。状态构造本身可由单元组成（选材是判断，C9）。
- **unsure 边界**：每个程序出口必须声明 `unsure` 策略（传出 / 升级 / 丢弃并记账），缺失是类型错误。
- **确定性**（三条，缺一不可）：
  1. 判以（渲染后的状态，题，置换种子）为键入账本；重放取账本，逐字节相同。
  2. 做以（动作，序号）为键记观察；重放用记录的观察，不重新触碰世界。
  3. 桥之后全是纯函数；调度顺序不影响结果（批不变性已测无偏；`act` 的顺序由依赖显式定）。
- **新鲜运行的稳定性**：同程序同输入不经账本重跑，读数差在 δ 内（noul 0.05，choice/score 0.15，已测），
  出口靠迟滞抑制翻转，翻转率按题型有实测上界（choice argmax 约 3%）。这是「稳定」的可验定义。
- **可重放的随机**：候选置换、抽样都从账本里的种子来。

## 6. 表面语法草案：三个程序共用一套语法

语法骨架：

```
program 名(参数: 类型) -> 类型
  x = 表达式
  if 是非题 on m [ctx E]: act: … ignore: … unsure: …
  switch 选择题 over C [ctx E]: c: … unsure: …
  while 打分题 on m < 档 bound n: …  unsure: …
  loop bound n: …
  return 表达式 | escalate
表达式 = filter(S, noul "…" [ctx E]) | select(C, choice "…" [ctx E])
       | rank(S, score "…" on L anchors A [ctx E]) | generate(n, "…" [ctx E])
       | act 动作(参数) | 纯函数(…)
```
`ctx E` 是拼进状态的语境与参照；被判的对象段由运行时结构化标出（红队 A7）。

### 6.1 文档找矛盾并生成修改到零矛盾（14 行）

```
program 修到零矛盾(docs: Dir) -> Set[M]
  段   = split(docs, bound)
  观点 = filter(段, noul "这段陈述了一个可核查的主张吗?")
  loop bound 5:
    对 = for a in 观点: select(others(观点, a), choice "哪一段的主张与 a 直接相反?" ctx a)
    if empty(对): return 观点
    for (a, b) in 对:
      候选 = generate(8, "改写 a 或 b 使两者不再相反，其余含义不变" ctx {a, b})
      修   = select(候选, choice "哪个改写消除了矛盾且改动最少?" ctx {a, b})
      观点 = replace(观点, 修)
    unsure: escalate
  escalate
```
（选择题的 `unsure` 由 `select` 的类型强制：`对` 的元素类型是 `观点 ⊎ {unsure}`，`for` 只遍历非 unsure 项，unsure 项由 `unsure:` 一句接住。）

### 6.2 给代码库和 5 个候选补丁选一个（12 行）

```
program 选补丁(repo: Dir, patches: Set[M]) -> M
  相关 = filter(files(repo), noul "这个文件会被任一候选补丁改到或调用吗?" ctx patches)
  语境 = filter(files(repo), noul "这个文件定义了相关文件用到的类型或约定吗?" ctx 相关)
  结果 = for p in patches: act run_tests(repo ⊕ p)
  可行 = filter(patches, noul "测试输出显示全部通过吗?" ctx 结果[p])
  if empty(可行): escalate
  分   = rank(可行, score "这个补丁的改动风险" on {低, 中, 高} anchors 风险样例 ctx 相关 ⊕ 语境)
  return select(top(分, 3), choice "哪个补丁最完整地解决了问题且改动最小?" ctx 相关 ⊕ 语境)
  unsure: escalate
```

### 6.3 computer use 找一个设置项（13 行）

```
program 找设置项(目标: M) -> M
  seen = {}
  loop bound 20:
    屏 = act screenshot()
    if noul "目标设置项在当前屏幕上可见吗?" on 屏 ctx 目标:
      act:    return 屏
      unsure: escalate
      ignore:
        入口 = elements(屏) \ seen
        switch choice "哪个入口最可能通向目标设置项?" over 入口 ctx 目标 ⊕ summary(seen):
          e:      act click(e); seen = seen ∪ {e}
          unsure: escalate
  escalate
```

三个程序不同的只有：题的文本、料库来源（目录 / 仓库 / 屏幕）、`act` 的具体动作。
控制结构、算子、unsure 处理、账本，一行不变。

## 7. 逐条对照清单

| 条目 | 判定 | 理由 |
|---|---|---|
| A1 语言、原语是 Jev | 满足 | 内核 = 判 + 做 + 有界循环 + 纯宿主；判是唯一非确定运算 |
| A2 像 C++ 那样说清 | 满足 | §1 单元、§2 类型、§3 控制流、§6 语法，无比喻 |
| A3 判断组成一切 | 部分 | 一阶逻辑 + 有界递归 + 做 + 生成，能写任何一阶可述的判断与搜索；不做算术，不做无界不动点 |
| A4 三种题都用上并深挖 | 满足 | 三种出口类型进内核；if/switch/while 各对应一种 |
| A5 加生成成千分 | 部分 | 生成 = `act writer`，锦标赛 = 循环 + 选；「更极致」待 E9 数字 |
| A6 原理推导的原创 | 部分 | 原创：候选集与刻度进类型、线只能来自校准、读数无渲染、无进展循环静态检查、unsure 必填。借用：Kleene、Datalog 分层、rank 排序、AQE 粒度 |
| B1 清晰优雅 | 满足（自评） | 内核四样、三出口、一本账 |
| B2 消融极简 | 部分 | §1.2、§4 是纸面消融；运行消融（去掉一样跑坏）未做 |
| B3 确定性可组合 | 满足 | §5 三条确定性 + 单元与程序同接口 + δ 有实测上界 |
| B4 任务无关 | 满足 | §6 三个程序共用语法，只换题文本、料库、动作；复杂计算未写例 |
| C1 几秒几千次 | 满足 | 调度合并 + 并发；E8 实测并发 32 每秒 35 次调用、p95 1 s |
| C2 三个基本操作 | 满足 | 状态构造 / 题 / 桥，正是单元的三个分量 |
| C3 数字决定下一轮且可见 | 满足 | 桥是确定性代码；账本记（状态，题，读数，出口） |
| C4 任意材料 1–2 s 成原料 | 部分 | 料库是纯宿主，文本实测秒级；OCR 类格式时限未测（红队 B7） |
| C5 并行免费、维度成程序 | 部分 | 合并与并发是运行时自动的；「问哪些题」由谓词推导给出，本文未含 |
| C6 深度 | 满足 | 有界循环 + 分层；深度成本 = 层数 × p95 |
| C7 目的无关中间状态 | 部分 | 只用于选择率估计的离线目录（研究 §3.4），不用于判断本身 |
| C8 二阶谓词表 | 部分 | 谓词推导是库程序，条件于目标带标签；本文只给它挂的位置（题文本） |
| C9 选材是判断、可递归 | 满足 | 状态构造由单元组成；§6.2 的「相关」「语境」就是两次判 |
| C10 一切是数据一个类型 | 部分 | 材料一个类型；读数必须是第二个类型，否则概率进 Jev（红队 A5） |
| C11 生成互斥穷尽解、Jev 只选 | 满足 | `select` 一次 K 选一，锦标赛递归；§6.2 |
| D1 有用不等于相关 | 满足 | 证据的类型规则：能区分候选 / 能让 Q 动；「相关」不在语言里 |
| D2 证据、语境、参照 | 满足 | 参照进类型（候选集、锚样例）；语境是 `ctx`；证据是被判对象 |
