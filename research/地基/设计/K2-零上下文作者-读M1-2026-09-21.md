## 二、三个程序

三个题目我自己定的。挑的时候刻意让它们落在三条不同的轴上：一条走效应与不可逆动作，
一条完全不判断只当普通语言用，一条走生成与排序并把判不准的交给人。

### 程序 A：代码评审分诊器（效应 + `allocate` + J-08）

从磁盘读一批 PR，逐个判风险档，挑两条送人工复核，没有高风险就把结论写回文件。

```jpp
// 程序 A：代码评审分诊器
budget {calls: 8, cost: 0, depth: 256, escalate: 2};

fn risk_of(m: Mat) -> Reading !{judge} {
    judge(state(m), measure("这个改动的风险有多高？", ["low", "mid", "high"], "risk"))
}

fn label(r) -> Text {
    handle(cut(r), {
        at:     fn(l) { "档" + text(l) },
        unsure: fn(u) { consume(u, "drop"); "未定" }
    })
}

let loaded = do("read_json", ["prs.json"], 0);
let prs = if is_fail(loaded) { [] } else { content(loaded).prs };
let mats = map(prs, fn(p) { mat(p) });
let readings = map(mats, risk_of);
let review_picks = allocate(readings, 2);
let labels = map(readings, label);
let report = {n: len(prs), labels: labels, human_review: review_picks};
let safe = len(filter(labels, fn(x) { x == "档2" })) == 0;
// 照 J-08 的修法一：在条件里再合取一个来自 trusted 状态的判断
let policy = mat({rule: "auto-write", max_high: 0});
let policy_ok = handle(cut(judge(state(policy), test("这条写回策略现在可以生效吗？", "policy"))), {
    act:    fn() { true },
    ignore: fn() { false },
    unsure: fn(u) { consume(u, "drop"); false }
});
let saved = if safe && policy_ok { do("write_json", ["triage-out.json", report], 1) } else { fail("不写") };
{report: report, saved_ok: !is_fail(saved)}
```

**第一版没有 `policy` 那一段**，`if safe { do("write_json", …) }` 直接被拦：

```
A-triage.jpp:24:23: J-08: 不可逆动作 write_json 的守卫里没有一个来自可信状态的合取项：
不可信材料上的判断不得**单独**放行不可逆动作（宪法 IFC / 12 §5 J-08）。
修法：在条件里再合取一个来自 trusted 状态的判断，或改走 ask 让人拍板，或把这个动作登记成可逆
```

M1 §4.7 那张 D1/D4/D6/D7 对照表预言得准：材料来自 `read_json` → `write_json` 被 J-08 拦。
我照第一条修法加了一个来自字面量材料的判断做合取项，**一次就过**。

最终输出（`stderr` 空，`status: returned`）：

```json
{"report": {"human_review": {"picked": [1, 2], "算不出": []},
            "labels": ["档0", "未定", "未定", "未定"], "n": 4},
 "saved_ok": true}
cost = {"asks": 0, "calls": 5, "replayed": 0, "usd": 0.0}
warnings = [ "W-uncertified: @390 键 risk 的线是手填的…修法【需接线人】…",
             "W-drop-vs-escalate: …" ×3,
             "W-uncertified: @1065 键 policy …修法【需接线人】…" ]
```

反向核对：把 PR#102 的 `Score` 从 `[0.05,0.25,0.70]` 翻成 `[0.93,0.05,0.02]`，
`labels` 从 `["档0","未定","未定","未定"]` 变成 `["档0","档0","未定","未定"]`，
`picked` 从 `[1,2]` 变成 `[2,3]`。夹具确实在驱动分支，不是我碰巧看到想看的结果。

### 程序 B：构建依赖的拓扑排序（纯计算）

我想知道这门语言当普通语言用是什么手感，所以写了一个完全不判断的 Kahn 算法。

```jpp
budget {calls: 0, cost: 0, depth: 256};

let deps = {
    setup:   [],
    build:   ["setup"],
    lint:    ["setup"],
    test:    ["build"],
    package: ["test", "lint"],
    publish: ["package"]
};

fn needs(n: Text) -> List { deps[n] }

fn all_done(ds: List, done: List) -> Bool {
    len(filter(ds, fn(d) { !contains(done, d) })) == 0
}

let result = loop(16, {done: [], waves: []}, fn(acc, i) {
    let remaining = filter(keys(deps), fn(n) { !contains(acc.done, n) });
    if len(remaining) == 0 {
        stop(acc)
    } else {
        let now = filter(remaining, fn(n) { all_done(needs(n), acc.done) });
        if len(now) == 0 {
            stop({done: acc.done, waves: append(acc.waves, ["<有环，停在这里>"])})
        } else {
            {done: concat(acc.done, now), waves: append(acc.waves, now)}
        }
    }
});

{waves: result.waves, depth: len(result.waves), scheduled: len(result.done),
 total: len(keys(deps)), ok: len(result.done) == len(keys(deps))}
```

一次写对，零告警：

```json
{"depth": 5, "ok": true, "scheduled": 6, "total": 6,
 "waves": [["setup"], ["build", "lint"], ["test"], ["package"], ["publish"]]}
cost = {"calls": 0, "replayed": 0, "usd": 0.0}
```

把 `setup: []` 改成 `setup: ["publish"]` 造一个环，走另一条分支：

```json
{"depth": 1, "ok": false, "scheduled": 0, "total": 6, "waves": [["<有环，停在这里>"]]}
```

这个程序里有一处 M1 没写、我只能猜的东西：`deps[n]`，**用一个 `Text` 变量给记录取字段**。
M1 §一「取值」只写了 `r.field` 和「`xs[0]`，下标可以是变量」，讲的是列表。我赌记录也能这么索引，赌中了。
没有这一条，记录就当不成映射表，B 得整个换数据结构。

### 程序 C：方案分组排序器（`gen` + `order` + `escalate` + `--resume`）

让模型生成三个方案，同一道题判一遍，用 `order` 分组，取最强那组的头一个；判不准就升给人。

```jpp
budget {calls: 6, cost: 0, depth: 256, escalate: 2};

let brief = mat({feature: "离线草稿同步", constraint: "不改数据库 schema"});
let plans = gen("给这个需求写三个实现方案", [brief], 3, 0);
let q = test("这个方案两周内做得完吗？", "feasible");

let readings = map(plans, fn(p) { judge(state(p), q) });
let groups = order(readings);
let best_idx = groups[0][0];
let winner = plans[best_idx];

let verdict = handle(cut(readings[best_idx]), {
    act:    fn() { {pick: content(winner), by: "auto", why: "最强组里的头一个"} },
    ignore: fn() { {pick: unit, by: "auto", why: "连最强的一组都不过线"} },
    unsure: fn(u) {
        let why = unsure_cause(u);
        let e2 = escalate(u, state(winner), test("人来定：这个方案两周内做得完吗？", "human"));
        handle(e2, {
            act:    fn() { {pick: content(winner), by: "human", why: why} },
            ignore: fn() { {pick: unit, by: "human", why: why} },
            unsure: fn(u2) { consume(u2, "drop"); {pick: unit, by: "human", why: "人也定不了"} }
        })
    }
});

{groups: groups, n_plans: len(plans), verdict: verdict}
```

分数拉开时（0.62 / 0.91 / 0.08）一次跑通：

```json
{"groups": [[1], [0], [2]], "n_plans": 3,
 "verdict": {"by": "auto", "pick": {"name": "整段 JSON 存 localStorage", "risk": "低"}, "why": "最强组里的头一个"}}
cost = {"asks": 0, "calls": 4}
```

把冠军挪进带内（0.62 / 0.58 / 0.08），第一趟 `pending`，`--resume` 第二趟返回：

```json
{"groups": [[0, 1], [2]], "n_plans": 3,
 "verdict": {"by": "human", "pick": {"name": "本地队列 + 后台重放", "risk": "中"}, "why": "band"}}
cost = {"asks": 1, "calls": 0, "replayed": 4}
```

`order` 把 0.62 和 0.58 归进同一组，这正是它该干的事。**三个程序都真跑起来了，没有写不出来的。**

## 三、`M1` 说错了或说漏了什么

逐条给原话、我的代码、实际报错。**这一节是我最有把握的产出**，因为每一条都是我先照着 M1 做、做不到、才查出来的。

### 1. `allocate` 的返回类型写错了 —— 照 M1 写是硬错

M1 §二 原话：

> ```jpp
> allocate(读数们, k) -> [Int]        // 把 k 份复核分给最不确定的，返回下标
> ```

照这句写：

```jpp
let picks = allocate(rs, 1);
{first: picks[0], all: picks}
```

```
t09.jpp:6:9: Record[Int] 不可索引
{first: picks[0], all: picks}
        ^^^^^^^^
```

**实际返回的是记录**：`{"picked": [1, 2], "算不出": []}`。
这条影响不小——M1 §4.3 整节都在教人怎么自检 `allocate` 有没有退化，而**退化的证据今天就摆在返回值的
`算不出` 那一栏里**，M1 的类型签名恰恰把这一栏藏掉了。往好处说，它至少是个硬错而不是静默给错；
往坏处说，`Record[Int] 不可索引` 这条报错**没有 J 号、没有「修法：」**，是整个会话里质量最差的一条报文。

### 2. `allocate` 在冷键上现在会响了，M1 那段「一句告警都没有」已经过期

M1 §4.3 原话：

> 冷键那条 `W-untested` 是在 **`cut`** 时发的，**不在 `allocate` 时发**——
> 而 `allocate` 的典型用法恰恰是「挑 k 条送人工、其余不过线」，**那条路上一句告警都没有**。

我把程序 A 的 `risk` 校准记录清空重跑：

```
W-untested: @714 uncertainty 对 4 条读数算不出（它们的校准键没有上岗记录，没有属于自己的线），
这些读数不进 allocate 的榜。按 J-15 不阻塞。
修法【作者可改】：按 `算不出` 那一栏另行处置（那一栏就在 allocate 的返回值里）；
【需接线人】给那些键写上岗记录、或给 CLI 接上 --calib/--profile
```
```json
"human_review": {"picked": [], "算不出": [0, 1, 2, 3]}
```

**不再是「文件顺序前 k 条」，是空榜 + 点名 + 告警。** M1 在那节末尾承认「已于 2026-09-21 修」，
但正文还留着「一句告警都没有」和退化成 `[0, 1]` 的那张表，读的人会以为自己仍要靠自检去防。
这一条建议 M1 改写，而不只是加脚注。

### 3. `responses` 未命中是**静默**的 —— M1 把观察的那条好报错讲成了通例

M1 §三 原话：

> **未命中的报错现在会把答案直接给你**（2026-09-21 改…）… **调法就是照抄这两份 JSON。** 不用再猜。

对 `observations` 完全属实，我故意把题面的「？」改成半角「?」验过：

```
probe03.jpp:3:13: 客户端错误：固定观察未命中：题「行吗？」× 状态 95677678（键 a4a1188bab4f8b960a60d796）；
固定观察不是模型，缺记录即错。内核这次算出来的状态 = {"on":{"a":1}}；
题 = {"calib":"k","evidence":[],"op":"noul","scale":[],"text":"行吗？"}。…
```

**但 `responses` 未命中什么都不说。** 我用同一种破坏做了一次一对一的对照：拿同一个探针
`probe03.jpp` 和同一份夹具，**只把题面里的全角「？」改成半角「?」**，一次改观察、一次改回答。

| 改哪一条 | 结果 |
|---|---|
| `observations[0].text` | `客户端错误：固定观察未命中：题「行吗？」× 状态 95677678（键 a4a1188bab4f8b960a60d796）…内核这次算出来的状态 = {"on":{"a":1}}；题 = {"calib":"k","evidence":[],"op":"noul","scale":[],"text":"行吗？"}…` + 源码行高亮，程序中止 |
| `responses[0].text` | `stderr` 空；`warnings: []`；`status: "pending"`；`pending: [{"cause":"ask","detail":"等人回答「人来定：行吗？」",…}]` |

**同样的一个字符，观察大声报、回答一声不吭**，而且它吐出来的 `pending` 跟「人确实还没答」
逐字段一模一样——作者没有任何办法从输出上把「我写错了」和「等人呢」分开。

程序 C 的 `--resume` 第二趟就是这个坑：

```
$ jpp run C-plans.jpp --fixtures fx-c-resp.json --resume l-c.json
stderr: (空)
{"status": "pending", "value": null, "cost": {"asks": 1, "calls": 0, "replayed": 4}, "trace": {"warnings": []}}
```
我因此写了 P02–P05 四个探针，才把范围缩到「不是 `ask` 的问题、不是 `escalate` 的问题、
不是 `gen` 的问题、不是 `--resume` 的问题」，最后发现是我自己把 `on` 写成了错的那个方案
（翻分之后 `order` 的冠军换了人）。**这四个探针本来一条报错就能省掉。**
M1 这一节该加一句：那条好报错只覆盖 `observations`，`responses` 走的是另一条路，不报。

### 4. 报错里「照抄这两份 JSON」——**照抄跑不起来**

接上条。我把那条报错里的两份 JSON 一个字不改地贴进夹具：

```json
"observations": [{"on": {"a": 1}, "calib": "k", "evidence": [], "op": "noul",
                  "scale": [], "text": "行吗？", "answer": {"Noul": 0.5}}]
```
```
fx-t03.json: invalid type: map, expected a sequence at line 3 column 25
```

把 `on` 改回列表、只留 `op` 照抄：

```
fx-t03b.json: unknown fixture question kind 'noul'
```

两处不一致：报错打印的状态里 `on` 是**对象**，夹具要**列表**；报错打印的题里 `op` 是内核名
**`noul`**，夹具只认 `test` / `select` / `measure`。M1 §三 一边正确地写着「`op` **只认
`test`/`select`/`measure`**」，一边又把那条报错原样引用并背书「**调法就是照抄**」，
两句话在同一节里互相打架。真实的调法是「照抄 `on`/`ctx`/`ref`/`over`/`text`/`calib`/`scale`
的**内容**，但 `on` 要包成列表、`op` 要换回 `test`/`select`/`measure`」。

### 5. `iter_seq` 这一格：**字面量常量是错（挡 check），换成一个常量绑定就一句话都没有**

M1 §二 原话：

> 循环里 `iter_seq` 要随轮次变，常量会发 `W-seq-const`…**真撞键是 `J-13`**。

我试了四种形状：

| 写法 | 结果 |
|---|---|
| `loop(3, 0, fn(acc,i) { do("record_check", ["x"], 0) … })` | **J-13，`check failed`** |
| `map([1,2,3], fn(x) { do("record_check", ["x"], 0) })` | **J-13，`check failed`** |
| `fold([1,2,3], 0, fn(acc,x) { do("record_check", ["x"], 0) … })` | **J-13，`check failed`** |
| `let s = 0;` 放在循环外，循环里 `do("record_check", ["x"], s)` | **零错误、零告警**，`value: 3`，只发了一条 `W-bound: loop 到 bound=3 仍未 stop` |

报文：

```
t08.jpp:2:33: J-13: 循环里的 do 用常量 iter_seq：每轮的键都一样，第二轮起会被当成重放，
效应不再发生。修法：把 loop 的轮次 i 传给 iter_seq
t08.jpp: check failed (1 errors)
```

两点要更正 M1，方向和我第一版写的不一样：

- **J-13 认的是字面量，不是「常量」。** 把同一个 `0` 换成一个循环外的绑定，检查就完全放行。
  M1 那句「常量会发 `W-seq-const`」描述的正是这种情形，而实测**这种情形什么都不发**——
  按报文自己的说法，此时「第二轮起会被当成重放，效应不再发生」，作者却看不到任何提示。
  **`W-seq-const` 我用四种写法都没撞出来。**
- **报文写死了「循环里的 do」和「把 loop 的轮次 i 传给 iter_seq」**，但它在 `map` / `fold` 里也会报，
  而那两个函数的方法**没有轮次参数 `i`**（`map` 的方法收元素，`fold` 的收 `acc, x`）。
  照字面做不到；自己想到改传元素（`map([1,2,3], fn(x) { do("record_check", ["x"], x) })`）确实能过，
  三次 `record_check` 都发出去了。M1 §二 说 `map` / `fold` 体内可以做 `do`，
  那就该在这里补一句：那条路上 `iter_seq` 拿什么当种子。

### 6. 【作者可改】/【需接线人】标签只贴在 `W-*` 上，J-08 上没有

M1 §4.5 原话：

> **报文现在会自己说清这一点**（2026-09-21 改）：修法带 `【作者可改】` / `【需接线人】` 标签。
> 看到 `【需接线人】` 就别再试了

`W-uncertified` 和 `W-untested` 确实贴了，很好用。但程序 A 撞到的 J-08，三条修法里
第三条（「把这个动作登记成可逆」）**明明是 `.jpp` 作者做不到的**，报文一个标签都没有：

```
修法：在条件里再合取一个来自 trusted 状态的判断，或改走 ask 让人拍板，或把这个动作登记成可逆
```

M1 写成「报文带标签」会让人以为没标签就等于可执行。准确的说法是「`W-*` 带标签，`J-*` 还没带」。

### 7. `state` 的 `on` 槽放多个对象，M1 没写怎么写

M1 §二 写了限制却没写用法：

> **`state` 的 `on` 槽最多两个对象**（一题一对象，关系用一对），多了 `J-14`

于是我知道「两个是合法的」，却不知道**怎么把两个传进去**。§二 的签名只有
`state(任意值)` 和 `state(m, {ctx, ref, over})`。我试了三轮：

| 轮 | 写法 | 结果 |
|---|---|---|
| 1 | `state(mat(1), {on: [mat(1), mat(2), mat(3)]})` | **照常跑通，零告警** —— `on` 不是选项槽的字段，被静默吃掉（M1 §三「认不得的字段既不报错也不告警」在这里同样成立） |
| 2 | `state(mat(1), mat(2), mat(3))` | `check` **通过、0 warnings**；`run` 才报 `state(on) 或 state(on, {ctx: […], ref: […], over: […]})` |
| 3 | `state([mat(1), mat(2), mat(3)])` | `J-14: state 的 on 槽放了 3 个对象：一题一对象（关系用一对）。修法：逐个对象建状态，或把它们放进 over 槽当候选` ← 对了 |

**答案是第一个参数可以直接是列表。** M1 该把这一行补进签名。
顺带两条：内置函数的实参个数 `check` 不查（`len([1,2], 99, 100)` 静态通过），
而用户自定义函数查（`E-arity: f 要 1 个参数，这里给了 3`）。

### 8. 效应行不把 `cut` 算作 `judge`

我给一个只做 `handle(cut(r), …)` 的函数标了 `!{judge}`：

```
A-triage.jpp:9:1: W-effect: label 标了 judge 但函数体里看不到：多标不出错，只是预算会估高
```

这跟 M1 §二「判断是惰性的…到**刷新点**才一次发出，刷新点是 `cut`…」放在一起读会绊人：
真正发出调用的那个位置，效应行不认。M1 讲对了两件事，但没把它们放在一起说明白。
（行为本身合理——效应行跟的是 `judge(…)` 这个写法，不是调用发出的时刻。）

### 9. 三条 M1 说对了、我复核过的

- §4.2 `unsure_bound` 是常量不是判据：`{"n": 2, "n_unknown": 2, "union_bound": 2.0}`。**对。**
  （报文自己现在还加了一句 `independent_any: "1.0000（仅供参考，不可作判据；判据是 union_bound）"`，M1 没提。）
- §4.7 打错动作名查可逆性最快：`J-11: 动作 wrigt_json 未登记…本次登记了：read_json（可逆）、record_check（可逆）、write_json（**不可逆**）`。**对，而且确实是最快的查法。**

## 六、一句话评价

**判断这一层值得用，夹具这一层还在收你学费。**

真正把「模型判不准」当一等公民来写的部分——`judge` 惰性求值、`cut` 出口的四种去向必须处理、
未决责任不写就 `J-05` 拦你、不可逆动作要有可信守卫——这些在我写第一个程序的当天就帮我挡住了两次
我自己没意识到的疏忽，而且每次都告诉我该怎么改。当普通语言用（程序 B）也不别扭，
`loop`/`map`/`filter`/`fold` 加记录当映射表，够写一个真算法，一次写对。

代价在夹具。写 `.jpp` 本身几乎不用查文档，**写 `--fixtures` 那个 JSON 才是这门语言今天真正的门槛**：
认不得的字段静默吞掉、`responses` 不命中不报、报错让你照抄但照抄会错。
我六个探针里的五个全花在这儿。

所以我会说：**如果有 M1 这份文件，现在就能用它干活；没有的话我劝你先要一份。**
M1 把语法、内置签名和 `observations` 的 schema 这三块讲得足够准，我在这三块上一个探针没花、
一次字段名没猜——这是上一轮花掉 25 个探针的地方。它今天还替不掉的，是**夹具不命中时的排错**：
那五个探针不是 M1 讲漏了什么，是语言在那条路上不出声，任何文档都补不上。
（第六个探针是 `state` 的 `on` 槽怎么放多个对象，那一个 M1 补一行签名就能省掉。）
