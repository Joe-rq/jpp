## 1. 基本单元、关系、组合是否与 08 一致；谁偏离「只关于自己的逻辑」；谁是翻版

| | 基本单元 | 关系 | 组合 | 与 08 的偏差 |
|---|---|---|---|---|
| L1 | 守卫语句 + S 函数（§1、§4.2），即 g→S | 只有材料流，读数在语法上不可写（§4.3） | 顺序 / `if`·`select`·`switch` / `while`（§4.4） | 一致。缺 08 §2 的**多守卫同真时用选择题解非确定**（`if g₁→S₁ ▯ g₂→S₂ fi`）：L1 的 `select` 只在候选集上选，不在「多条启用的守卫命令」之间选 |
| L2 | 规则（Horn 子句），体是判/选/量字面 + `fn`（§1、§4.2） | 材料流（派生元组），一致 | 合取 = 顺序；**同头多规则 = 集合并**；`iterate` = 重复 | **偏离**：Datalog 的集合语义把 08 的「选择」组合解成「全部都成立」。同头多条规则、体内各有 `fn!`，同时满足时**都执行**（§4.4「`fn!` 按数据依赖定序，同键至多一次」不阻止不同键的多条都执行）；08 规定多守卫同真由选择题解决。L2 没有这一步 |
| L3 | Call 节点 + S 节点 + 线（§1、§2） | 线只传材料，读数不可接线（§4.3 第 1 条），一致 | 层 = 顺序；`fan`+`select` = 选择；`ring` = 重复 | 一致。同样缺「多守卫同真」的一般形式（只有候选集上的 `select`） |

**三套都把 08 的「选择解非确定」窄化成了「在候选集里选一个」。** 候选集选择是它的特例（S_i = 取第 i 个候选）。一般形式——几条守卫各绑不同的 S，同真时问一道选择题决定走哪条——没有任何一套提供。收敛稿必须补（§6）。

**谁偏离「语言只关于它自己的逻辑」：** 三套的核心文法都不含任务词。唯一可疑处：L3 程序里的 `budget cost <= $0.01`（§4.2）把钱写进程序——钱是宿主量，不是判断逻辑；可接受，但应是编译器核对项而非语法一等成分（否则「结构即成本」的承诺被程序员手写的预算替代）。

**谁是翻版（宪法第 1 条）：** 按「借的是表面还是语义」分：
- L2 借了 Datalog 的**语义**（分层否定、半朴素求值、集合语义、SCC 分层，§4.4）而不只是 `:-` 的写法。它登记了 R1–R5，但 R1 第四格「分层保留」没有回答第三格（非单调）带来的问题：分层否定的唯一模型保证依赖层内单调，Jev 非单调（P2、P4）时分层不再给出唯一模型，L2 照搬了保证已失效的机制。**翻版风险最高。**
- L3 借了硬件描述/数据流语言的**结构词汇**（`layer` `wire` `ring` `fan` `merge` `sink`），但**没有登记这一行**（§2.1 只登记了逻辑/物理算子分离；`layer = AQE 物化点` 引了宪法的查询规划器行）。同步电路的条件是「门延迟固定、时钟确定」，Jev 下一层延迟是 p95 有方差、调用可失败，条件变了，新机制（层耗时 = 最慢请求、层号由编译器重算）L3 写了但没按宪法格式登记。**缺登记，必须补。**
- L1 借了 Go/Python 的**语句形状**，登记了三行（§9.3），第三格都引了公理。翻版风险最低。

## 2. 引用了账本外事实、或把假设当推导的地方

| 设计 | 位置 | 问题 |
|---|---|---|
| L1 | §2「`select` K=2 且只问『哪个』→ 一道 noul」；§4.4「measure 档位数=2 → noul」 | **未测的等价假设**当下沉规则。E10 测的是 K=2 的 choice 可用，没测「二选一 choice ≡ 一道 noul」；两档 score ≡ noul 也没测（score 有锚、noul 无锚，读数分布形状不同）。应标假设并进账本 |
| L1 | §2 表「#13 成立条件（段落 K≤16，代码 K≤4 或逐候选 noul）」 | 与账本一致（E9b 后下调），但 L1 §4.4 [下沉] 行写「choice(K≤16 段落级)」没有写代码级 4 的上限，两处不一致 |

| L2 | §7 E77 `rule 候选(c) :- c in gen!(8, spec, top 1(接近(c) by 接近))` | 体内引用了自己头谓词的打分（候选依赖候选的 top 1），在 `iterate` 内但同一轮内自引，§4.4「每轮全量重求值」没有定义同轮自引怎么求；这是无定义处被当成可写 |
| L2 | §8 C8「满足（形式）」引 #19 | #19 在账本是「形式成立、未实现」，标注了状态，可接受 |
| L3 | §2.1「measure 档数 ≤3 且只要阈值时 → 一道是非题」 | 同 L1 的两档等价假设，未测 |

没有发现引用账本外「事实」的地方；越界的都是把**选择或假设写成了规则**。

## 5. 一致性反例（每套一个合法程序，语义矛盾或无定义）

**L1**：§4.4 [复合守卫]「要合取就嵌套 if，编译器把嵌套的同状态 if 合成一次请求，语义按强 Kleene 展开」。反例：
```
if a on m { if b on m { X } unsure { U_b } } else { Y } unsure { U_a }
```
读数 a=unsure、b=ignore。强 Kleene 的 a∧b = ignore（有 ignore 即 ignore），应走 Y。嵌套语义：a=unsure → 走 U_a，b 根本不参与。两条规则给出不同分支。**融合后 b 已经问了**（同状态一次请求），却按嵌套短路丢弃，与「按强 Kleene 展开」自相矛盾。修法：提供显式三值合取 `if a ∧ b on m`，语义 = 融合问全部、按 Kleene 合成；嵌套 if 保持短路语义，不再宣称等价。

**L2**：`iterate … variant … increasing` 要求变式**严格**单调，否则停止并出 unsure（§4.4）。反例即其探针 D41（§7）：
```
iterate bound 20 variant max(距离(s) by 距离) increasing { … }   # 距离 ∈ {远, 中, 近, 到}
```
四档刻度最多严格上升 3 次；第 4 轮起变式不可能再严格增加，循环在第 4 轮必停并出 unsure，`bound 20` 永远达不到。程序合法，语义使其不可能完成任务。修法：变式的进步判据改为「档位不下降 **且** (渲染状态，题) 键不重复」，或允许宿主计量变式（L3 的 `host` 变式）；严格单调只用于宿主整数变式。
（另一处无定义：E77 同轮自引，见 §2。）

**L3**：§4.3 第 5 条「每个语义操作的 `.unsure` 必须恰好被一条 `connect` 消费」。反例即其标准库 `Tournament`（§5.1）：
```
c.unsure -> merge next reg
next reg = c.pick ∪ members(c.unsure)
```
`c.unsure` 被 connect 消费一次、又被 `next reg` 表达式引用一次；按第 5 条是 E-unsure，标准库自身不通过类型检查。同样，D41（§7）里 `q = test "目标已达成？"` 的 `q.unsure` 没有任何 connect（只接了 `nxt.unsure`），按第 5 条是编译错。修法：把「恰好一条 connect」改为「至少一处消费，且消费点集合在编译期可枚举」；`members(c.unsure)` 算消费。
（另一处死规则：§4.4「含同伴的打分只允许 `.at`」与 §4.3 第 3 条「打分状态不得有 cands 槽」互斥，前者永不触发。）

## 6. 收敛建议

**以 L1 为骨。** 理由：它是 08 `g→S` 的直接实现，关系与组合与 08 一致（§1）；翻版风险最低（借的是语句形状，不是语义）；交互类与构造类任务（做→观察→判→定→做）写起来最直接，这正是能做域要扩的那一格（09 §8）；读数在语法上不可写，全局保证靠类型即可。

**从 L3 嫁接**（都是语言级保证或编译器产物，不是语法风格）：
1. 三种出口做成三种类型（`Outlet` / `Chosen[q,C]` / `Level[q,L]`）并作为唯一可接线的东西——L1 已有，按 L3 §4.3 补齐「同伴禁入打分状态」为类型规则。
2. `state(obj, cands, ctx, ref)` 四槽含候选槽与 `fan(K)`；K 上限按候选长度分档。
3. **校准按物理题型存**（§5.3）：题 id × 下沉题型 → 各自的线与验题。这是三套里唯一被注意到的必然推论，缺它 #8 就被下沉打破。
4. `jc lower` / `jc plan`：层、状态数、题数、钱、秒是**编译器输出**，不是语法。L3 的显式 `layer` 语法不要（它自评与调度打架）；预算作为编译器核对项。
5. `.unsure` 的消费检查（修正为「至少一处、可枚举」）。

**从 L2 嫁接**：
1. `judge` 声明的显式槽位（`on` / `ctx` / `over` / `anchors`）：程序员永远不拼字符串，状态由编译器按四槽构造（L1 用 `with` 拼状态，弱于此）。
2. 裂变的**按语义操作合回规则**（test exists=max；select 分块选再锦标赛；measure 出口计数）。
3. 融合后的账本键 =（渲染状态，题集）。
4. `not` 的定义（出口对调、非反问）与「跨候选集比较是类型错」的诊断措辞。
不嫁接 L2 的规则求值语义（集合语义与分层否定，见 §1、§3）。

**收敛稿必须新增的定义**（三套都没有或都错）：
1. **多守卫同真的选择构造**：`select among { g₁ → S₁ ; g₂ → S₂ ; … }`，同状态融合问全部守卫，多条 act 时由一道选择题（题式「比较」，候选 = 启用的命令的字面描述）定走哪条；只一条 act 直接走；全 ignore 走 else；含 unsure 且无 act 走 unsure。这是 08 §2 的原文，三套都漏。
2. **三值复合守卫的语义**：融合问全部子题，按强 Kleene 合成；与嵌套短路明确区分（L1 反例）。
3. **变式的进步判据**：档位不下降且键不重复；宿主整数变式可要求严格单调（L2 反例）。
4. **校准键 = 题 id × 物理题型**，下沉改变即换线（L3 §5.3）。
5. **两档 score ≡ noul、K=2 choice ≡ noul** 标为假设，进账本，未测前编译器不得据此下沉（L1、L3）。
6. **窗口常数是下界**（E10 措辞），编译器用下界做裂变阈值并在 `plan` 里标「待测上限」。
7. **HDL/数据流借用登记**一行（L3），**Datalog 分层否定登记的第四格重写**（L2）。
8. 钱与秒不进语法，只进编译器核对与干跑输出。

## 7. 补充：`10-组合代数-v0.md` 评审

**并（§3.1）七种是否穷尽。** 按「同一状态上出现哪些类型」分，{判, 选, 量} 的非空子集恰好 7 个，表是穷尽的。但表的「产物」列混入了三条**语义主张**而非枚举：判+选「先剔除再取索引」（融合是同时问，剔除是宿主后处理，措辞要改）；选+量「不一致 → ?」是**假设**（10 自己标了 E15，好）；选+选「众数或帕累托」是宿主聚合，属 §3.3 不属 §3.1。此外多重性（n 道判、n 道量）在类型子集里不可见，但语义上「n 道判」的 Kleene 合成与「2 道判」同型，不需要新行。**结论：穷尽，但要把语义主张与枚举分开。**

**接（§3.2）16 种有无遗漏或冗余。** 两处标「—」的格子其实有意义，应为 18：
- 位 → 刻度：一道判决定用粗刻度还是细刻度（「这是技术文档吗」→ 换技术评分锚），是「换刻度」的位形式。
- 索引 → 循环：选择题的候选集含「继续 / 停 / 升级」时，索引直接控制循环——这正是 08「决定」用法进循环的位置，也是 L3 D41 里 `test 目标已达成` + `select 下一步` 融合的那一步。
遗漏的**目标槽**：表的六个目标里没有**语境槽**（四槽之一）：一道判「这段是定义吗」→ 进语境槽；一道选「这 K 段里哪段是 a 的定义」→ 进语境槽；一道量「这段对读法的影响多大」→ 阈后进语境槽。补上后是 3 × 7 = 21 格。**人**（升级）不是目标槽，是 ? 的去向，10 处理正确。
冗余：位→材料「过/不过」与位→问题「问/不问」都是门，但目标不同（材料被丢 vs 材料留着但不问），不冗余。**结论：改为 21 格，两处「—」删掉。**

**七种题式与 08 三个位置是否一致。** 映射：守卫 ← 属性、关系（判）；解非确定 ← 比较、归类、解释、下一问（选）；变式 ← 程度（量）。一致。但 10 内部有一处不一致：§2 题式表里选的形式只有 4 种，§2 又说「选择题从逻辑上有七种」（候选、材料、标签、读法、动作、问题、假设）。后者是**按候选集里装什么分**，前者是按**题的形状分**；注意、消歧、决定都是「比较」题式换了候选集（材料、读法、动作）。要写明「题式 4 种 × 候选种类」，否则两个七会被当成一回事。另外 08 的「解非确定」在题式表里没有对应形——「哪条命令该走」是比较题式、候选集 = 启用的命令，应在表里加一行例子，与 §6 新增定义 1 呼应。

**能否成为收敛稿的核心定义（比 08 更细一层）。** 能，且应当。理由：
- 08 的三种组合（顺序、选择、重复）在 10 里分别是 接 表的「材料」列、「候选集 / 动作」列、「循环」列；08 的 S 是「动作 S」列；10 比 08 多出了「问题」「刻度」「语境」三个目标——**输出决定下一道题问什么、用什么刻度、带什么语境**，这是 08 没有、而二阶推导（C8）、换题细问、加锚全都需要的通道。08 只说「数字不流、材料流」，10 把「出口流向哪里」枚举完了。
- 三套设计都能落到 10 上：L1 的 `if / select / while` 是 接 表的（位→材料/动作）、（索引→候选集/动作）、（档→循环）三格；L3 的 `outlet -> target` 就是 接 表的一行一格；L2 的规则体是 并，聚合是 聚。收敛稿用 10 做语义核，用 L1 做表面语法，每条语句在 接 表里有一个格号，`? ` 的去向按列固定——这比三套各自的语义规则都小、都可数。
- 条件：(a) 按上面改成 21 格并写明每格是**推导**（来自 08）还是**选择**（如「? 在候选集格 → 再生成」是选择，要消融）；(b) 并 表去掉语义主张，E15 前「一致性检验」不进定义；(c) 题式表补「哪条命令」例，写明题式 × 候选种类；(d) §1 的「量管预览」保持 #24 假设标签，不进核心。
