# 宪法（Nature 2026-09-21 定，永久生效，每小时对照）

1. 联想可以用，但最难的是跳出联想。基于机制构建，不把它做成「一个什么什么东西」。
2. 借用别人的东西时必须先问：那个问题当年是在什么条件下被解决的；这些条件在 Jev 的公理下怎么不一样了；
   由此该发展出什么新的机制。只借解法不问条件的，不许进设计。
3. 一系列这样的机制累积起来，要完成过去做不出来的任务。每个小点的优化最终累积成巨大的优化。
4. 一切从本质出发：从逻辑底层、底层原理、底层代码出发。时刻牢记，时刻检查。

## 操作形式：借用登记表

每一项借用必须填这一行，缺一格不许用。

| 借的东西 | 当年解决的问题与条件 | 条件在 Jev 下怎么变了（引公理） | 由此发展的新机制 |
|---|---|---|---|
| LOTUS 逐行单独调用 | LLM 长上下文降质，且每次调用按题收费 | 状态收费、题免费（P5）；带主张材料 500 token 起带偏（P4） | 一状态多题一次问完；片段小、多分层 |
| Datalog 不动点求值 | 事实单调，加事实不推翻旧结论 | Jev 非单调，加材料可翻出口（P2、P4） | 有界迭代 + 只增账本；无进展键重复即停 |
| Dijkstra 守卫命令 | 守卫是布尔值，真假二分 | 守卫是校准的三值概率（P2，D2） | unsure 是一等出口，唯一去向是变字面或升级；变式用打分题 |
| 查询规划器（System R、Predicate Migration） | 代价与选择率都难估 | 代价 ≈ 状态数（P5），选择率是唯一未知 | 目标函数改为状态数与层数；层边界重规划；离线目录估选择率 |
| 验证器 / best-of-N（Cobbe、Lightman） | 验证器要训练，按候选逐个打分 | Jev 免训练、校准、一状态多候选相对判断（D1、E10） | 选择题锦标赛；置换取众数；unsure 触发再生成 |
| mRMR 特征选择 | 样本几百到几千，互信息可估 | 样本几十，互信息有偏 | 只借 D−R 形状；小样本退化为方差与一致率；条件于目标 |
| Kleene 三值逻辑 | 值离散，无噪声 | 值是过线后的出口，线附近有 δ（P2） | 迟滞；unsure 在每个算子签名里有去向 |
| AlphaGo 策略+价值+树搜索 | 封闭博弈，价值网络要训练，标量回归 | 开放任务，价值是校准档位（P13），策略是生成器 | 同一次调用给先验与价值；宁宽勿深；任务无关的闭环 |

新借用一律先填表，再进账本，再进设计。

## 附则（Nature 2026-09-21）
任何任务清单都只是检验任务无关性的探针，不是目标任务。不预定义「我们要做什么任务」，不为探针任务优化语言。
语言只关于它自己的逻辑；探针换一批，语言不该变。
| 数据库逻辑算子 / 物理算子分离 | 同一逻辑算子有多种物理实现，按代价模型选 | 物理实现是三种题型，其代价与偏置由实测决定（P5、P9、E9b、E10）；同状态多算子可零边际融合（P5） | 语义操作 test/select/measure 与题型分离；编译器按 K、长度、偏置下沉；判断融合与材料裂变 |
| SQL 三值 WHERE（反面） | 三值在 WHERE/CHECK 被隐式打成两值，三十年的坑 | 出口是校准三值且噪声在线附近（P2） | `partition` 显式三流/四流；`Set ∪ unsure 流` 是类型错（E11）；去向表每槽有固定去向 |
| `yield` 生成式（Python/C#） | 惰性序列，顺序语义 | 同层判断要可交换才能融合并发（P5） | `for … yield` 定义为纯映射，体内禁赋值（E7）；顺序用 `loop` |
| 资源预算 / 资源感知类型 | 编译期估算资源上界 | 成本几乎只取决于调用次数（P5），静态可估 | `budget` 必填；E12 最省计划超预算即拒；`jv plan` 逐语句报 |
| 燃料有界递归（Agda/Coq fuel） | 证明终止的技巧 | 非单调（P2、P4）使 fuel 从证明技巧变成语义必需 | `bound` 必填（E5）；耐心变式；键重复即停 |
| `Result`/`Either`（Rust/Haskell） | 失败是值，不是异常 | 「做」触世界会失败（E9b 30% 超时），失败必须进账本且能重放 | `Mat ⊎ fail`；槽含 fail → `failed` 出口；四流 |
