# 语言本质 v1 · 今晚推导的记录

日期 2026-09-20 晚。Nature 与总控对话推导所得。本文记录**结论和推导路径**，
不是规范，不是施工单。它取代 `04-语言规范-v0.md` 里的程序模型（单元盯表），
但沿用 v0 的原语层（三值出口、概率类型、Item、账本、校准线）。
后面的人先读这一份，再读 04，再读 01。

## 0. 一句话

判断要能出现在循环和递归里，像加法一样被成千上万次调用。程序的确定性部分
负责把上一批判断的数字变成下一批判断的材料和问题，Jev 只负责判断。
魅力在深度和广度，不在单次判断。

## 1. 为什么昨晚的东西不够

昨晚做的是触发式规则系统：一个单元一次调用，链的深度等于手写的单元数。
没有任何机制让「判断的结果」自动生成「新的判断」。所以它和一套写好的
调用套件没有本质区别。Nature 的原话：「你现在做的这个东西跟单纯调用式，
它是没有任何区别的。」

## 2. 三个基本操作

围绕 Jev 只有三件事，语言就是把这三件事做成任务无关的程序：

1. **投什么材料**（上一轮的数字决定下一轮塞哪段）
2. **问什么问题**（并行几乎免费：50 题的成本是 1 题的 1.04 倍，所以要把一段材料一次问干净）
3. **数字出来怎么反应**（数字如何作用于 1 和 2 的构造方式）

## 3. 技术事实（已测，约束设计）

- Jev 输入是文字，输出是数。「结果再判断」不能把数喂回去，中间必须有确定性
  代码做四件事：选、拆、拼、换问题。这四件事就是语言的控制结构。
- 钱和时间按**塞进去的材料**算，问题免费。铁律：每段材料进去一次就问干净，
  一轮里尽量少换材料。几千次判断的真实瓶颈是并发多少个片段。
- 带主张的无关文档超过约 500 token 就会带偏读数（E6）。片段要小，宁可多分几层。
- Jev 只做一跳、只看字面。多跳靠程序的层级，不靠提示词。
- 重跑不是逐位确定（噪声 δ 已量化），确定性由账本重放保证。

## 4. 对应的已知理论

- 三件事对应**谓词、查询、执行计划**。Jev 题是谓词，目标是查询，
  规划器按 Jev 的成本公式排执行顺序。数据库查询规划器是四十年的成熟技术，
  只是成本模型换成「材料收费，问题免费」。
- 组合算子四个：过滤、配对、聚合、递归。加谓词等于带递归的关系代数，
  表达力等于一阶逻辑加递归（Datalog）。完整性陈述：
  **凡能写成材料上一阶逻辑规则的判断，都能由一元二元 Jev 题组出来。**
- 最近的现有系统：斯坦福 LOTUS（2024，LLM 语义算子加成本优化）。
  差别三处：Jev 一状态多题免费；Jev 输出校准概率，可用三值和校准线严格过线；
  我们有账本重放。

## 5. 谓词表是二阶的

固定的通用谓词表（有观点、是定义……）是错的，换任务就没用。
任务无关的是**从目标推出谓词表的程序**，表本身每次不同。推导三步：

1. **前提**：目标成立材料必须先具备什么。一元，最便宜，永远第一层。
2. **区分**：海选加筛选。LLM 对目标生成上百个候选谓词，Jev 在样本材料上
   跑一遍，按熵（答案分得开）和两两相关（不同涨同跌）筛掉没信息的。
3. **关系**：目标是二元时推出关系谓词，只在幸存者的配对上跑。

推出的表再标通用性质：一元/二元、幸存率、成本。这些数字是规划器的输入。

## 6. 材料价值的本质：两个，不是一个

- **证据**：让目标判断动。判法是一元题「这段是否关系到 Q」。
- **语境**：自己不让判断动，但改变证据的意思（定义、约定、谁说的、是否引用）。
  判法是三元题「有了这段，那段的意思变不变」。语境对证据判，不对目标判。

前提是证据的退化情形（没前提的材料让 Q 永远为零）。
「不重复」不是本质，是经济性：影响成本，不影响对错。

一条漏洞：「让判断动」不能用放进去前后的差值来量，因为噪音也让判断动
（E6）。要用 Jev 自己的一跳判断「是否关系到 Q」。材料的价值靠判断定义，
不靠实验差值定义。

规划器三层顺序对任何任务都一样：先筛证据，再给证据配语境，最后问目标。

## 7. 深度

并行免费的是同一层内的题，每一层是一次往返，不免费。开新层的条件只有两个：
材料变了（幸存者、配对、合并），或问题变了（上一层的 choice 决定下一层问哪组）。
规划器规则：能挤进同一层的谓词全部挤进去，只在真依赖时开新层。
展开深度静态（编译期知道每层问什么），执行深度动态（每层筛掉多少）。

## 8. 闭环：整门语言是一个递归函数

选材料的动作和做判断的动作是同一种动作，只是问题换了：

```
判(Q, 材料):
    若 材料 小到能一次塞进状态:  return jev(Q, 材料)
    证据 = 过滤(材料, 段 => 判("这段有助于判断 Q 吗", 段))
    语境 = 过滤(材料, 段 => 判("这段改变证据的读法吗", 段 + 证据))
    return 判(Q, 拼(证据, 语境))
```

终止条件是物理的（一次状态约 500 token 带主张材料）。深度由材料量除以上限
自然长出。每层做的事一样：筛、配语境、拼、再问。人手做五十层做不完，
程序把重复固定下来，人只写最外层的 Q。这就是为什么必须是语言而不是提示词。

复杂判断是一棵树：叶子是 Jev 题；中间节点两种，确定性的逻辑/聚合（不花钱），
或对**拼出来的材料**再问的 Jev 题。

## 9. 最底层只剩三样

一道题、三值逻辑、四个算子（过滤、配对、聚合、递归）。其余全是标准库。
比 v0 又少一层。

## 12. 模块清单：每个从哪条推导来，各自的「好」是什么

原则：一个模块只替用户想掉一件事；它的标准必须可量、可验，不靠读着觉得好。
「为什么」一列指回本文前面的节号，后面的人能顺着看到推导。

|---|---|---|---|---|

## 13. 自检：哪些是 Jev 的逻辑，哪些被「文档判断」这类任务锁住了

Nature 的要求：设计只能来自 Jev 本身的逻辑，不能锁在某一类任务上。
今天是判断，明天是 computer use、编程、构建 Agent、复杂计算。逐条自检：

**只来自 Jev 的逻辑，任务无关（保留）：**
- 一切进入 Jev 的东西必须是文字状态；状态收费，问题免费；一跳、字面；
  噪声 δ；超界带偏；输出是数，数进不了 Jev，中间必须有确定性程序。
- 谓词推导（目标 → 谓词表，量熵和相关）：目标可以是「找矛盾」也可以是
  「登录表单是否出现」「这个函数是否会空指针」，推导程序同一套。
- 证据/语境二分：computer use 里证据是和目标有关的观察，语境是让观察读对的
  约定；编程里证据是相关代码，语境是类型定义和约定。二分不变。
- 规划器的成本公式、执行器的账本、校准、追溯：与任务内容无关。
- Choice 对应「决定做哪件」，Score 对应「打分排序」，unsure 对应「升级给人」。
  v0 已有，Agent 任务正好用上。

**被锁住的地方（要改）：**
1. 「料库」写成了「文件 → 片段」，这是文档任务。真正的一般形式是**状态源**，
   下一段材料有两种来路：**取**（从已有的东西里选，文档、代码库）和
   **做**（对世界执行一个动作，拿回新的观察：点一下屏幕、跑一次测试、
   调一个工具）。第 8 节的递归函数默认材料是固定语料，只写了「取」。
2. 四个算子（过滤、配对、聚合、递归）是关系代数，没有副作用。Agent 和
   computer use 必须有「做」。补第五个算子：**做**(动作) → 新状态。
   加上它，递归函数就是 观察 → 判（多题并行）→ 定（数字到决定，确定性）→ 做 → 观察。
3. 「选材器的召回检验」（丢掉的放回一部分看出口变不变）假设语料是固定的，
   对「做」出来的状态不适用，要另定：动作序列重放后观察一致。
4. 标准库里的例子（矛盾、重复）是文档目标。标准库本来就按任务分，不是核心，
   但核心文档里不该拿它们当唯一例子。

**修正后的递归函数：**

```
判(Q, 状态源):
    状态 = 取或做(状态源, 上一轮的数字)          # 取：选片段；做：动作后观察
    若 状态 小到能一次塞进:  return jev(Q, 状态)
    证据 = 过滤(状态, 段 => 判("这段有助于判断 Q 吗", 段))
    语境 = 过滤(状态, 段 => 判("这段改变证据的读法吗", 段 + 证据))
    return 判(Q, 拼(证据, 语境))
```

复杂计算的位置：Jev 不做算术。复杂计算 = 确定性宿主做算术和搜索，
Jev 在其中做启发式判断（这个分支值得展开吗、这两个约束冲突吗）。
语言就是「确定性宿主 + 判 + 自动批处理」，计算任务不需要额外原语。

**任务无关的验收方法（加到验收）：** 同一个递归函数分别写四个任务
（文档找矛盾、computer use 找一个设置项、代码找一个 bug、Agent 订一次行程），
比 diff。只允许两处不同：最外层的 Q，和状态源是取还是做。
第三处不同就是锁住了。

模块清单相应改动：1「料库」改名「状态源」，标准加「做」的一致性；
7「算子库」加第五算子「做」。

## 14. 修正第 13 节：材料只有一个类型，叫数据

Nature 纠正：料库不是「文件」，也不用分「取」和「做」两种来路。
无论是文本、二进制、机器码、屏幕、工具输出、还是上一轮判断的数字和日志，
**它就是数据，一个类型。** 和计算机里一切都是字节同理。

由此定下：
- 语言只有一个材料类型 `数据`。它有地址、有来源、有一个把它渲染成 Jev 能读的
  文字的方法。渲染按格式各写各的，类型只有一个。
- 「取」和「做」不是两种材料，是两种**产生数据的方式**，产出的类型相同。
  产生方式在语言里就是普通函数，不是原语。
- 判断的结果本身也是数据。这一条是递归能成立的根本：判断可以判断上一轮的判断，
  不需要任何特殊通道。
- 第 13 节的「状态源」改回「料库」，定义为：数据的集合，带地址，能渲染。
  第五算子「做」保留，它是产生新数据的算子，产出进料库。

模块 1 的标准改为：任何来源、任何格式的数据进入料库后同类型；同数据同地址
同渲染；渲染后的片段不超过界限；跨次运行无状态。

## 15. 「一切是数据」对其他模块的影响

逐个过一遍。结论：核心模块从十个缩到六个，两个模块降级为用这门语言写的程序，
一个模块并入料库；v0 的 Item 正是这个统一数据类型，直接沿用。

| 模块 | 影响 |
|---|---|
| 1 料库 | 就是 v0 的 Item 表：kind、body、about、supersedes、made_by、scope。Kind 从「类型」降为数据上的标签；类型只有一个。checker 的种类流检查保留为 lint，不再是类型检查。 |
| 2 判 | 签名变成 数据 × 问题 → 数据。问题本身也是数据。读数是数据，body 带 P_q 类型：跨题不可算，但可以作为下一轮的材料（渲染成文字，Jev 只判不算）。 |
| 3 谓词推导器 | **不再是核心模块。** 候选问题是数据，「这个问题对目标有信息吗」是判，熵和相关是聚合算子。它就是递归函数用在问题数据上，写成标准库程序。 |
| 4 选材器 | **不再是核心模块。** 证据筛选和语境筛选就是递归函数第二、三行，写成标准库程序。 |
| 5 规划器 | 成本按渲染后 token 算，不按「片段数」；依赖关系不用另建，就是数据的来源链（about/made_by）；计划本身也是数据，能被判、能被追溯。 |
| 6 执行器 | 日志和账本条目是料库里的数据，不另设存储；重放 = 按来源链重算。 |
| 7 算子库 | 五个算子全是 数据集 → 数据集，对一个类型封闭。这是「极简」的形式证明：一个类型、一道题、三值、五算子。 |
