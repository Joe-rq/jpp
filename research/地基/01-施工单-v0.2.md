## 2. 数据模型

所有哈希 = sha256 的前 16 个十六进制字符。JSON 序列化一律 `sort_keys=True, ensure_ascii=False, separators=(",", ":")`。

### 2.1 Item
```
id          = H(kind, body, about, supersedes, made_by, scope)
kind        : str            # 如 note.raw / note / mark / unsure / answer / ask / note.clean
body        : str | dict     # 正文
about       : id | None      # 标记、上交单、回答所指向的东西
supersedes  : id | None      # 新版本指向旧版本
made_by     : str            # unit:<name>@<ver> | pack:<name> | human | external
scope       : str            # 分区路径，根为 "/"；包为 "/<pack>/<instance_id>"
beat        : int            # 放上来的拍号（不进 id）
```
不可修改。`alive(item)` = 没有别的 alive item 的 `supersedes` 指向它。标记 body 固定为 `{"label": str, "unit": str}`。

### 2.2 Log（唯一真相）
JSONL 文件，只追加。每行 `{"seq": n, "t": event_type, ...}`。事件类型：
`run_start`（含 run_id、defs 指纹、model_version、模式 record|replay、参数）、`beat_start`、`ask`（view_fp、question_fps、cache_hit、request、response、cost）、`reading`（unit、item、view_fp、value、outlet）、`proposal`、`arbitration`（winner、losers、reason）、`action`（unit、hand、item、result_ids）、`item`（完整 Item）、`escalate`、`answer`、`guard`（哪道、参数）、`beat_end`（scope、new_items、calls、cost）、`run_end`（状态 quiet | waiting_on_human | guard_stop | budget_stop）。
`Table` 不单独存：`Table.from_log(log)` 折叠得到 `{id: Item}` 与 alive 集。快照可存可丢。

### 2.3 Ledger
SQLite 或 JSON 文件。键 `H(view_fp, question_fp, model_version)`；`question_fp = H(primitive, instructions, criteria, options/levels)`；值 = Jev 返回的该问题原始答案。若 E2 不过：键再加 `batch_fp`（同批问题 fp 的排序哈希）。

### 2.4 单元定义（YAML）
```yaml
unit: mark_promise
version: 1
watches:
  kinds: [note]
  prefilter: null                 # 可选：登记过的代码函数名，返回 bool
eye:
  type: jev                        # jev | code
  primitive: noul                  # noul | choice | score
  instructions: "这段话里，是否有人对另一个人许下了一个具体的、将来要兑现的承诺？"
  criteria: {true: "…", false: "…"}     # choice: {option: desc}; score: [level desc, …]
  # code 眼: fn: <登记名>，函数返回 "act" | "ignore" | "unsure" 或 (outlet, detail)
view: self                         # self | with_parent
hand:
  type: mark                       # mark | put | code | write | ask
  label: promise                   # mark
  # put:   kind: note.clean, body_template: "{body}"
  # code:  fn: <登记名>            返回 [Item 草稿]
  # write: instruction: "…", result_kind: note   写手产出取代原物
  # ask:   question: "…"
layer: correctness                 # safety | correctness | efficiency
priority: 10
exclusive_with: []                 # 互斥标记列表（mark 手）
probes: probes/mark_promise.yaml
```
验题文件：`- {view: "…", expect: act|ignore|<option>|<level_index>, source: builder}`。

### 2.5 包定义
```yaml
pack: tidy_note
inlets: [note.raw]
outlets: [note.clean, note.held]   # unsure 隐含
units: [clean_raw, mark_promise, …]
packs: []

```

### 2.6 单元运行态（`state/units.json`，随 run 存）
`{name: {status: draft|on_duty|suspended, gap, lines: {hi, lo, calibrated: bool}, calib_n, probes_pass}}`。

## 3. 算法

### 3.1 视野
`self` → 正文；`with_parent` → `{"current": body, "previous": supersedes 的 body}`。`view_fp = H(view_content)`。视野字符数上限由 E5 定，默认 6000 字符，超出截断并记 `guard: view_truncated`。

### 3.2 读数与出口
- Noul：`p = noul`。`act` 若 `p ≥ hi`；`ignore` 若 `p ≤ lo`；否则 `unsure`。
- Choice：`opt = argmax`，`p = probabilities[opt]`；同上三分；`act` 携带 `opt`。confidence 只记录。
- Score：`lvl = round(score)`，`p = probabilities[lvl]`；同上；`act` 携带 `lvl`。
- Code 眼：函数直接返回出口。
- 出口映射到动作：`act` → 执行手（choice/score 的手可按 `opt/lvl` 选模板，如 mark label 取选项名）；`ignore` → 无；`unsure` → 上交单。

### 3.3 验题闸门（上岗必要条件）
至少 3 道 expect=act、3 道 expect=ignore（choice 每选项 ≥2 道；score 每档 ≥2 道）。
- Noul：`gap = min(p | expect act) − max(p | expect ignore)`；`gap ≥ 0.20`（safety 层 0.30）才可上岗。
- Choice：所有验题 argmax == expect；`gap = min(p_expect) − max(第二高 p)` 记录。
- Score：所有验题 `|score − expect| ≤ 0.5`。
闸门不产出两条线。缝不足 → 单元停留 draft，名册标"缝不足"，**不得手调任何数**。

### 3.4 两条线（工作点）
每个单元一份校准集 `calib/<unit>.jsonl`：`{view_fp, p, label: act|ignore, source: human|builder_typical}`。
- `n < 20`：`hi = 0.65, lo = 0.35`，`calibrated=false`（safety 层 `hi = 0.75, lo = 0.25`）。
- `n ≥ 20`：`hi` = 使 `{p ≥ hi}` 中 label=ignore 的比例 ≤ ε_act 的最小 hi（在观测到的 p 值上扫描，默认 ε_act=0.05）；`lo` = 使 `{p ≤ lo}` 中 label=act 的比例 ≤ ε_ignore 的最大 lo（默认 0.05）。若 `hi ≤ lo`，取 `hi = lo = 中位数` 并标 `degenerate`。
- 停岗：校准集 ≥ 20 且 `{p ≥ hi}` 上错误率 > 2·ε_act，或 `{p ≤ lo}` 上漏放率 > 2·ε_ignore → `suspended`，名册亮红。
- ε_act / ε_ignore / gap 门槛 / 默认线是**全局参数**（`params.yaml`），契约实测只能改它们。

### 3.5 心跳（一个分区一拍）
```
dirty_body  = 本分区 alive 且正文新出现（本 run 内未被任何单元以当前 view_fp 判断过）的东西
dirty_mark  = 今晚不做（无 with_marks 视野）
pairs       = [(item, unit) for item in dirty_body for unit in on_duty+draft if unit.watches item.kind and prefilter(item)]
              去掉 once_key=(unit.name, unit.version, view_fp) 已存在的
group       = pairs 按 (item.id, view_fp) 分组
for each group:  code 眼直接算；jev 眼合并成一次调用（问题数上限由 E4 定，默认 40；超出按 unit 名排序切批）
                 先查账本，只问没问过的；response 逐问题写入账本
outlets     = 每对一个出口；draft 单元的 act 一律降级为 mark "would_act:<unit>"
proposals   = act 的动作提议
arbitrate   = §3.6
execute     = 胜出动作按 (layer_rank, -priority, unit.name, item.id) 排序执行，产出 Item 写入 Log
escalate    = unsure 生成 Item{kind: unsure, about: item, body: {unit, p, view_fp}}
guards      = §3.7
quiet       = 本拍无新 Item 且无待运行子包 → 分区结束；状态 quiet 或 waiting_on_human（人队列非空）
```
并发：Jev 调用可并发（上限由 E4 定，默认 6），但写 Log 的顺序严格按上面的排序，与返回先后无关。
包在心跳眼里与单元同接口：`observe(items) -> actions`；包的 observe 内部跑自己的心跳到安静，把 outlets 种类的 Item 和 unsure 复制到父分区。

### 3.6 裁决
冲突 = 两个提议 supersede 同一 item；或两个 mark 在彼此的 `exclusive_with` 里。
胜者：layer（safety > correctness > efficiency）→ priority 大 → 若仍平局：双方都不执行，生成 `unsure`，body 记 `tie`，并记 `guard: tie_conflict`。检查器把同层同优先级且可能 supersede 同种类的单元对报为定义错误。

### 3.7 保险
| 名 | 触发 | 动作 |
|---|---|---|
| once | once_key 已存在 | 跳过该对 |
| return_to_same | `H(sorted multiset of (kind, body) of alive items in scope)` 在本 run 出现第二次 | 分区停止，`unsure{kind: unsure, body: {guard: return_to_same, units: 两指纹之间动过手的单元}}` |
| runaway | 某版本链在本 run 超过 6 代 | 该链停止（其 alive 头不再配对），上交 |
| beat_budget | 分区拍数 > budget.beats（默认 30） | 分区停止，上交 |
| cost_budget | 全局 Jev 花费 > params.cost_usd（默认 1.0）或 write 调用 > params.write_calls（默认 40） | 全局停止，run_end=budget_stop |
每道保险有测试用关闭开关 `--disable-guard <name>`。

### 3.8 上交与人答
`unsure` Item 在本分区可被盯 `unsure` 的单元处理（code 眼，如 unsure_catcher）。分区安静时未被 `absorbed` 标记的 unsure 复制到父分区；根分区的 unsure 进人队列 `queue/<run>.json`。
`answer <run> <unsure_id> act|ignore`：写 `answer` 事件与 Item；立即按该出口执行原单元的手（在下一拍开头）；写一条校准集记录；重算该单元两条线；若触发停岗条件则停岗。**不写入验题集。**

### 3.9 包
`Pack.observe(inlet_items)`：新建实例分区 `/<pack>/<H(inlet ids)>`；复制 inlet Items（保留 id，scope 改为实例分区，作为新 Item 记入 Log）；运行子心跳到安静或保险；outlets 种类的 alive Items 与未吸收的 unsure 复制回父分区（scope 改回）。递归深度 > 4 → 拒绝实例化并上交。花费从全局池扣。

### 3.9b 第零步实测定下的参数（2026-09-20 夜，见 foundation/experiments/前提结论.md）
- `delta = {noul: 0.05, choice: 0.15, score: 0.15}`：同输入重复调用的读数噪声。**Jev 不是逐位确定的**，确定性只由 Log + Ledger 保证：一个 run 内第一次读到的数就是这个 run 的数，永不重问。
- 账本键不含批次（E2：并排不额外引入偏差，偏差就是 E1 噪声）。
- 单次调用问题数不设硬上限，默认 40 一批（E4：50 问耗时是 1 问的 1.04 倍）。
- 视野上限默认 6000 字符（E5：中性内容到 8000 token 中位漂移 ≤0.02）；视野里不得拼入另一份带主张的文档（E5：500 token 起即改变判断标的），今晚只有 self/with_parent 视野，天然满足。
- 问句默认中文；某单元缝不够先改句子，再试英文（E3）。
- 硬阈值优先用 noul；choice/score 的出口线加 0.15 迟滞，名册标注"噪声较大"。
- 版本钉 jev-1.13.0，响应 model 字段核对（E6）。

## 3.10 客户端与重放
`EyeClient(mode=record|replay)`：record 真调 HTTP（POST /v1/systemone，model 固定 jev-1.13.0，429/529 指数退避），response 写 Log 与 Ledger；replay 只从 Log 取（按 seq 顺序匹配 `ask` 事件），取不到即报错。
`Writer(mode)`：record 调 `claude -p --model haiku --output-format text` 以 stdin 传入 `instruction + "\n\n---\n" + view`；replay 从 Log 取。超时 90 秒记失败并上交。

## 7. 试验台 A（砍到今晚够用）
| 单元 | 眼 | 手 | 层/优先级 | 验什么 |
|---|---|---|---|---|
| clean_raw | code：kind==note.raw | code：去首尾空白，put 为 note | efficiency/1 | 接力起点 |
| mark_promise | noul：具体承诺 | mark promise | correctness/10 | 基本单元 |
| mark_date | code：正则含日期 | mark has_date | efficiency/1 | 代码眼 |
| route_kind | choice：请求/通知/抱怨/闲聊 | mark kind:<opt> | correctness/10 | Choice |
| urgency | score：不急/今天/马上 | mark urgency:<lvl> | correctness/10 | Score |
| soften_blame | noul：语气在指责对方 | write：改成陈述事实，事实不变，只改语气 | correctness/10 | 写手 |
| shorten | prefilter len>200 + noul：有明显重复内容 | write：压缩，不丢事实 | efficiency/6 | 写手，与 add_context 拉扯 |
| add_context | noul：不了解背景的人读不懂在说哪件事 | write：补一句背景 | efficiency/5 | 同上 |
| hold_private | noul：含证件号/卡号/住址等隐私（验题含敌意样本） | put note.held + ask | safety/100 | 安全层压过一切 |
| done_checker | code：note 无待处理且上一拍无人动它 | put note.clean | efficiency/0 | 交出 |
| unsure_catcher | code：同一单元本 run 上交 ≥3 次 | mark needs_rewording（about=unsure） | efficiency/0 | 盯 unsure |
| flipflop | code：正文以 "[A]" 开头→改为 "[B]"，反之亦然 | code | efficiency/1 | 只用于 S3 回到原样 |
| grow | code：每次在末尾加一个字 | code | efficiency/1 | 只用于 S3 改不停（关掉 return_to_same 后测） |
包 `tidy_note`：收 note.raw，交 note.clean / note.held，含除 flipflop/grow 外全部单元。
fixtures：≥12 条中文便条（含承诺、指责、隐私、超长重复、缺背景、两件事、干净的），另有 flipflop/grow 专用夹具。

## 8. 验收（独立验收 agent 执行，真实调用跑一遍 + 断网 replay 一遍；报告只有 PASS/FAIL）

**S1 单元与桌面**
- S1.1 `probe a_notes`：每个 jev 单元输出缝与状态；至少 4 个 jev 单元上岗；一个故意含糊的单元（验收者临时加）停在 draft 并显示"缝不足"。
- S1.2 三个出口各至少出现一次，Log 中可见 view_fp、p、outlet。
- S1.3 Item 不可修改：`Table` 无任何修改接口；改动只能是新 Item + supersedes（代码审阅 + 测试）。
- S1.4 删快照，从 Log 重建 Table，与运行时 Table 的 alive 集合与 id 集合逐一相同。
- S1.5 `core/` 不 import `testbeds/`。

**S2 并排、账本、确定性**
- S2.1 同一 note 上挂 ≥20 个 jev 单元（验收者复制单元定义改名）：Log 显示对该 (item, view) 只发出 ⌈20/上限⌉ 次调用；耗时 ≤ 单单元的 2 倍。
- S2.2 桌面不变再跳一拍：调用 0，花费 0。
- S2.3 replay 模式重跑：Log 事件序列（去掉时间与 seq）逐字节相同（回归工具，不是确定性证明）。
- S2.4 清空账本真跑第二次（**按第零步实测修订**：E1 测得 Jev 同输入重复调用 noul 读数 p99 偏差 0.05、最大 0.09，choice/score 最大 0.12–0.18，choice 选中项约 3% 会换）：报告两次运行所有 (unit, item) 的读数差分布与出口翻转数；过关线：noul 读数差 ≤0.09 的格子 ≥99%；出口翻转只允许发生在"读数距该单元任一条线 ≤δ"的格子上（δ：noul 0.05，choice/score 0.15），其余格子出口必须相同。翻转数原样写进报告。
- S2.5 打乱 defs 加载顺序：Log 相同。
- S2.6 choice、score、code 眼各有单元正确走出口。

**S3 手、接力、保险**
- S3.1 note.raw → note → 标记 → note.clean 至少三环接力，每环一拍，拍线可见。
- S3.2 一条有毛病的便条被 write 手改到安静，版本链完整，每代记录 unit 与 instruction。
- S3.3 flipflop 触发 return_to_same，分区停止，unsure 点名 flipflop。
- S3.4 关掉 return_to_same 后 grow 触发 runaway（>6 代）。
- S3.5 `--max-beats 3` 后停止并上交，不是异常退出。
- S3.6 含 write 的 run 可 replay，Log 相同。
- S3.7 ask 只挡被问的东西：队列有未答单时其他便条照常到 note.clean。

**S4 裁决、上交、校准**
- S4.1 三种冲突各一次：不同层高层胜；同层不同优先级高者胜；同层同优先级双方不执行并上交 tie。被裁掉的提议在 Log 可见。
- S4.2 `arbiter.py`、`outlet.py`、`calib.py` 中不存在跨单元比较读数（验收者审阅并书面确认）。
- S4.3 根分区 unsure 进入 queue；`answer … act` 后动作在下一拍执行，校准集 +1，两条线重算并记入 Log。
- S4.4 用 ≥20 条构造的校准记录喂一个单元，两条线按 §3.4 算出；构造使错误率超线时单元停岗亮红。
- S4.5 draft 单元只产生 would_act 标记，不动手。
- S4.6 契约第一版：对 fixtures + E3(b) 的 60 条真实便条跑 draft，输出每个单元的读数直方图与按读数分层的抽样清单（每段 ≤10 条）到 `reports/contract-sample.md`，供明早人标。今晚不设 97/60 过关线，只要求产物齐全。

**S5 包**
- S5.1 隔离：包内单元读不到父分区非 inlet 的 Item；父分区读不到包私有 Item（测试尝试并失败）。
- S5.2 替换不变（**验收后修订，见 design-issues.md DI-1**）：tidy_note 单独跑记录交出物；放进一个外层包再跑同样输入：同一 (unit, view_fp) 的出口相同；交出物按 (kind, body) 多重集合相同；含包的 run 可 record/replay。原文「交出物 id 集合相同」按 §2.1 的 id 定义结构性为假（scope、made_by 进 id 是 S5.1 隔离的前提），原判据保留为回归锁：两个 id 集合必须不相交。
- S5.3 `beat.py`/`pack.py` 无按层数分支；三层嵌套（root → wrapper → tidy_note）跑通；根的"上一层"是人队列，通过同一接口注入。
- S5.4 包内 unsure 出现在父分区，被父分区盯 unsure 的单元接住；无人接则到 queue。
- S5.5 递归下钻：一个包把长文切段后以自身 inlet 种类交给自己，深度 3 到达安静，第 5 层被拒并上交；全局花费池正确累计。

**S6 检查器（不阻塞）**
