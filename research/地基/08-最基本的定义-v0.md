# 最基本的定义 v0 · 为什么必须是语言、基本单元是什么、判断即执行

日期 2026-09-21 凌晨。Nature 提出四个问题：什么效果必须写成语言才能达到；基本单元、关系、组合
如何做到像数学一样与任务无关；什么技术搭配能 100+100=1000、三个 10000 而任两个不到；
以及「判断替代不了执行」是错的，判断绑定一个确定函数就是执行。本文只做定义与推导，不设计。

## 1. 什么效果必须是语言

库是人在设计时把固定的件拼好；语言是结构在运行时由数据自己长出来。只有三种效果非语言不可：

1. **自指**：判断的输出、问题、程序本身都能被判断、被生成、被执行。这要求它们是同一种一等值。
   库做不到，因为库的调用是不透明的；语言做得到，因为程序是数据（Lisp 的 code = data）。
   我们的二阶推导（用判断选问题）、锦标赛（用判断选程序的产物）都是自指。
2. **全局保证**：概率不跨题算、unsure 不被悄悄二值化、必终止、可重放。这些是对**所有可能的组合**
   成立的性质，只有类型系统加静态检查加运行时语义能保证。库拦不住误用。
3. **全局优化**：同状态全题一次问完、分层、选 K、并发，是对整个程序的调度决定，
   用户看不见。这要求程序作为整体可分析，也就是要有编译器。

结论：**判断产生并执行判断（自指），加对一切组合成立的保证，加整体优化**。这三样是语言的定义性效果。
组合做不到自指，也给不了保证。

## 2. 判断即执行：因果绑定

「判断替代不了执行」是错的说法。正确的说法：

```
守卫命令  g → S        g 是一道判断（三值、校准），S 是绑定的确定函数
语义      outlet(g) = act ⟹ S 执行；ignore ⟹ 不执行；unsure ⟹ 不得执行，必须细化或升级
```
判断是因，函数是果，绑定就是执行。E9 的教训重述为一条定律，而不是一个限制：

**字面化定律**：每道判断必须对面前的材料一跳可判。凡不是字面的，先由绑定的确定函数把它变成字面
（跑一次、取一次、算一次、渲染一次），再判。确定性部分的职责就是**替判断把世界变成字面**。
E9 里「这段代码正确吗」不是字面的，「跑示例后输出与预期一致吗」才是。语言不模拟运行时，
它把「值得跑」绑到「跑」，再把「跑的输出」交给下一道判断。

这套结构是 Dijkstra 守卫命令的形式：三种组合恰是它的三种：
- 顺序：S 的输出是下一道 g 的材料。
- 选择 `if g₁→S₁ ▯ g₂→S₂ fi`：多条守卫同时为真时经典语义是非确定选一条；
  我们用选择题**解决**这个非确定：哪条该走。这是选择题在语言里的位置。
- 重复 `do g→S od`：终止靠一个**严格递减的变式函数**。我们用打分题做变式：档位不再进步即停，
  这就是「无进展静态检查」的语义根据。这是打分题在语言里的位置。

所以三种题不是三种格式，是守卫命令三个位置各需要的东西：是非做守卫，选择解非确定，打分做变式。
原创在于守卫是校准的三值概率而不是布尔值：unsure 是「守卫既不真也不假」，
它的唯一合法去向是细化（让它变字面）或升级（问人）。最弱前置条件的证明规则要重新推，
这是 v3 红队后的工作。

## 3. 基本单元、关系、组合（任务无关）

- **基本单元**：`(g, S)`，一道校准判断加一个绑定的确定函数。v3 的 `Unit = Call ▷ β` 是 g 的部分，
  S 是「做」或纯宿主。判断没有绑定函数就只是读数，函数没有守卫就只是脚本。
- **关系**：只有一种，材料流：S 的输出成为下一个 g 的材料。没有别的通道，数字不流。
- **组合**：顺序、选择、重复，各由一种题解决。组合的组合是同一接口（材料集 → 材料集 ⊎ unsure）。
- **任务无关的理由**：以上没有一个词涉及任务。任务只提供 g 的文本、S 的具体函数、材料的来源。
  像数学只关于数，不关于算什么。验收：罗列 100 种互不相干的任务，每种写成一行 (g, S, 变式)，
  写不出来的就是锁住了（派 agent 做，见 §5）。

## 4. 搭配：1000 与 10000

按 Jev 的缺口推，不按别人的产品推。Jev 缺四样：不生成、不触世界、不算术、不记忆。
- **Jev + 生成器 = 1000**：生成器出候选，Jev 便宜校准地选。单独的生成一次一个不知对错；
  单独的判断只能在已有的东西里选。合起来是搜索。他人证据：验证器范式（研究/02）。
- **Jev + 执行器（做）= 1000**：执行把世界变字面，判断决定执行谁。单独的执行是脚本，
  单独的判断不接地。合起来是可审计的 Agent。
- **生成器 + 执行器 = 今天的 Agent**：没有校准的选择，靠昂贵的大模型裁判，无错误率。
- **三者 = 10000**：提出（生成）→ 接地（执行）→ 校准地判（Jev）→ 再提出。这是一个闭环，
  任两个都闭不上：缺生成不出新东西，缺执行不接地（E9 的 `sum(strings,'')`），缺 Jev 没有便宜的校准信号。
  没有一个单独的技术能做到「以校准错误率搜索真实世界中被验证的产物」。
- **第四样是人**：unsure 升级给人，人的答案进校准集，线自动更新。人只看边界案例，系统越用越准。
  这一样让 10000 随时间增长。

不做成别人的东西的判据：AlphaGo 是三者在一个封闭博弈里的实例；我们的东西是这个闭环本身，
任务无关，守卫是自然语言，接地是任意确定函数。借结构，不借产品。

## 5. 下一步（定义层，不是设计层）

1. 把 §2 的守卫命令语义写成形式规则（三值守卫的顺序、选择、重复各一条），红队打「unsure 的去向是否穷尽」。
2. 100 种任务的 (g, S, 变式) 一行表，找锁。
3. 三值守卫下的最弱前置条件：能否给组合后的程序算错误率上界（B 席的 1−(1−ε)^D 是它的粗版）。

## 6. 修订（据 设计/D 百任务压力测试）

- 写不出的东西加两类：**时延**（决策周期短于一层往返，P5 的 p95 ≈ 1 s）；**模态**（材料非文字且没有忠实渲染函数）。
  不动点与算术两类在 100 任务里各 0 条：算术由 S 算完再判，是字面化定律的直接结果。
- 字面化定律补全：`S : 世界 → 文字`。非文字模态经 S 有损，损失计入该题的错误率，由校准量出。
- 允许 `⊤ → S`（无守卫的纯确定段），不为每个 S 配无意义的 g。
- 校准状态加「待真值」：真值后到的题（预测类）先按验题上岗，真值到达后才算错误率。
- S 与 g 同级。100 任务里的难度多在「怎么把它变字面」，不在「问什么」。
- 适用域声明：语言只对**判断有信息增益**的任务有用；信号全在算术的任务（棋、排程、路径）Jev 多余。

## 7. 修订（据 设计/E 百计算机任务）

- 适用域再补一句：有精确算法的子问题交给 S，Jev 只判 S 的输出「说明了什么」。
  判断的信息增益 = 输出到结论之间没有确定算法的那一段。
- 时延锁细分：有离线批判定形式的不算锁，算「模式受限」；无离线形式的才是锁。
- 「待真值」的题集中在选型类（预测 + 事后回填），列为一个骨架。
- **S 的库比 g 的库更值钱**：100 条计算机任务里 S 只有不到 30 种（跑一次、diff、AST 抽取、日志切阶段、
  宿主算特征再渲染、K 邻居渲染、可访问性树……）。标准库先建 S 库，再建题库。
- 模态锁在计算机域只剩纯视觉两条；可访问性树与 OCR 把 UI 任务拉回文字。「模态有损计入错误率」成立。
