## 0. 一句话

这是一门**判断语言**：唯一的非确定运算是 Jev 的三种判断（是非、选择、打分），
其余全是确定性代码。程序由「一次请求加它的出口」组成，
用 if / switch / while 三种由判断驱动的控制流连接，加「做」触碰世界、加生成器出候选，
构成一门以自然语言写约束、目标和选择规则的**优化语言**，执行确定性、可重放、带校准错误率。

## 1. 最基本的单元（A §1）

```
Call = M × Q⁺              一个渲染后 ≤ 界限的状态 + 一批题（三种类型可混）
β    = ⟨outlet_q⟩          每题一座桥，线只来自校准
Unit = Call ▷ β : M → ⟨O_q⟩
O_noul = {act, ignore, unsure}   O_choice[C] = C ⊎ {unsure}   O_score[L] = L ⊎ {unsure}
```
不能更小：去状态则超界带偏（E5/E6）；去桥则读数是死数，无法分支也无法记账；
只留一种出口即昨晚的锁死。不能更大：它是成本单位、账本键、确定性边界三者的重合点。

## 2. 类型（A §2）

材料 `M` 一个类型（Item），Kind 是标签。读数三类：`R_noul[q]`、`R_choice[q,C]`、`R_score[q,L]`，
候选集 C 与刻度 L（含锚样例）是题的类型参数，参照因此进类型。
编译期拒绝：跨题算读数；跨候选集比 choice；跨刻度或异锚比 score；读数放到要材料的位置
（读数无渲染，概率不进 Jev）；score 无锚；线是字面量（只能 `calib(q)`）；出口缺 unsure 策略。
唯一允许跨材料算读数的地方：同题同刻度同锚的 score 可排序、可聚合期望。打分题的价值全在这里。

## 3. 控制流（A §3）

- `if noul`：三支必填。复合条件强 Kleene。`¬` 不是反问。
- `switch choice over C`：分支表恰好覆盖 C；候选顺序做记入账本的随机置换；两条线（最大概率、前二差距）不过即 unsure。
- `while score < ℓ bound n`：bound 必填。**无进展静态检查**：循环体不含「做」也不改状态 ⟹ 账本键不变 ⟹ 必不终止，编译期拒绝。这条只在「同键同读数」的账本语义下成立，是本语言独有。
- 集合 `for` 无顺序语义，同层独立单元由调度器合并（同状态一请求、异状态并发）；「做」按数据依赖定序，定不了序是编译错。

## 4. 内核与库（A §4，C §1）

**语言内核四样**：判（三出口）、做、有界循环、纯宿主；运行时两样：调度、账本。
**库第一层七算子**：过滤、选、序、配对、聚合、生成（= 做 writer）、升级（= 做 ask）。
它们全由内核组合得出，但作为标准形式发布，每个签名写死 unsure 去向。
**骨架五个**：筛、配对、分治、搜索、锦标赛（= 有界循环 + 选）。

**实现模块九个**（C §1.3，每个有「去掉即坏」的验收）：
料库、判、账、校准、算子、检查、规划器、执行器（内核 8）+ 标准库（骨架、推导、选材、参照）。
选材器、谓词推导器、追溯、生成器不是模块（分别并入标准库、标准库、料库+账、做）。

## 5. 计算模型与定律（B）

能写的：窗口有界、深度有界的一跳判断电路 + 生成候选上的有界搜索，由确定性宿主连线。
写不了的：需要不动点的自指规则；分解会改变语义的整体判断；生成器支持集外的解；需要算术的判断。
六种搜索（束、进化、分支限界、MCTS、二十问、弧一致）全部可写，成本按实测公式估（B §2）。

定律（B §3）：L1 成本轴是调用次数，同状态全题一次问完；L2 窗口 L 是深度的来源；
L3 层内全问、层间按 rank=(σ−1)/代价；L4 二元 ∝ N_s²/K，规划器第一职责压 N_s；
L5 时间 ≈ Σ 层 max(τ, 调用/35)；L6 宁宽勿深（错误 1−(1−ε)^D）；L7 搜索成本 = Σ 候选数。
「几秒几千次判断」成立边界：每次 ≥ 20 题、≤ 5 层、每层 ≤ 64 次调用。

原创十条（B §4.2，每条追溯一条已测事实）：调用次数为成本轴；二十问塌缩成一轮；
窗口常数生深度；选择吸收配对 N²→N²/K；有界迭代取代不动点；数字不进判；
概率性剪枝 unsure 不剪；打分做适应度不需训练且参照是一等材料；选材是字面前提不是元题；
选问题用选择题条件于目标。
借用（B §4.1）：半朴素分层、rank 公式、层边界重规划、强 Kleene 与 Mostowski 量词、
函数缓存、离线目录估选择率、mRMR 形状、验证器范式、AlphaGo 结构、经典搜索算法。

## 6. 校准分题型（C §3）

是非沿用 v0（hi/lo、δ 0.05、3+3 验题、缝 0.20）。
选择新增：最大概率线、前二差距线 ≥ 0.30（= 2δ）、置换 3 次一致率 ≥ 97%、每选项 3 题 + 「都不是」3 题。
打分新增：每档概率线、相邻档差 < 0.15 → unsure、参照指纹进账本键、每档 3 题、批不变性 ≥ 97%（E10 待测）。
δ 噪声下的重复次数（C §2.0）：均值漂移 noul 3 次、choice/score 23 次；翻转率 3%→13% 需 90 次。

## 7. 旧代码去留与建造顺序（C §4–5）

沿用 7（item/log/table/canon/ledger/eye/registry），改造 11，废弃 3（beat/arbiter/pack）。
九步约 $1.3：定义定稿 → 判+桥+校准 → 算子+检查 → 料库四槽+执行器 → 三骨架 → 规划器 →
分治与搜索骨架+推导与选材 → **实跑消融**（逐个关模块，每关一个至少一条 FAIL）→ 表面语法。

## 8. 三席不一致处与总控裁决

| 分歧 | A | C | 裁决 |
|---|---|---|---|
| 七算子是内核还是库 | 库（可由四样组出） | 模块之一 | **语言定义按 A**：内核四样；**实现按 C**：算子作为模块发布，因为它是用户写程序的第一层。两者不矛盾。 |
| 选择的置换次数 | 一次记账置换 | 3 次取多数 | 验题时 3 次（上岗门槛）；运行时默认 1 次记账置换，线不过即 unsure；E9 位置分布出来后再定是否默认 3 次。 |
| 桥的数量是否「最简」 | 三座 | 三座但存疑 | 三座。少于三座就丢掉分支或程度，B2 的消融在这里反过来：去掉一座就坏。 |
