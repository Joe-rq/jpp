# 语言规范 v0

日期 2026-09-20。本文定义语言；`01-施工单-v0.2.md` 定义实现。两者冲突以施工单为准，冲突处在本文以「[施工单优先]」标出。

这门语言的程序由**单元**和**包**的定义构成。程序不描述过程，描述条件与动作；求值由运行时按拍进行。语言的原语判断由 Jev 提供：一份文本状态加一条带类型的问题，返回校准概率。

## 1. 值与类型

### 1.1 原语判断的值域

```
Noul   : [0, 1]                       一个概率 p
Choice : {opt: [0,1]} , Σ ≈ 1         选项到概率的映射，另附 confidence（只记录，不参与语义）
Score  : {lvl: [0,1]} , Σ ≈ 1         档位到概率的映射，另附 score 期望与 confidence（只记录）
```
理由：三者都是分布，只是支撑集不同；语义只用分布，不用衍生量。

### 1.2 三值出口

```
Outlet ::= act | ignore | unsure
```
每次判断求值恰好得到一个出口。`unsure` 是一等值，可以流经程序的任何边界。理由：Jev 给的是概率，`unsure` 保留了它知道自己拿不准的信息。

### 1.3 读数类型规则

每个问题 q 定义一个独立类型 `P_q`。读数 `p : P_q`。

```
p₁ : P_q₁ , p₂ : P_q₂ , q₁ ≠ q₂  ⟹  p₁ + p₂ 、 p₁ < p₂ 、 p₁ = p₂  均为类型错误
p₁ : P_q  , p₂ : P_q            ⟹  p₁ < p₂ 合法
```
唯一合法的跨类型运算是 `outlet_q : P_q → Outlet`（用 q 自己的两条线）。理由：官方明说不同问题的读数各有零点，P(x)+P(¬x)≠1；类型系统把这条事实变成编译期错误。

### 1.4 种类与 Item

```
Kind ::= identifier ('.' identifier)*          如 note、note.raw、mark、unsure
Item  = { id, kind : Kind, body : Text | JSON, about : Id?, supersedes : Id?, made_by, scope }
id    = H(kind, body, about, supersedes, made_by, scope)
```
Item 不可变。修改表现为新 Item 且 `supersedes` 指向旧者。`kind` 是 Item 的类型，也是单元之间接线的唯一依据。理由：内容寻址使账本和重放可核对；按 kind 接线使单元可独立搬动。

## 2. 语句：单元

一个单元是一条守卫语句：

```
Unit     ::= name version Guard Eye View Outlets Hand Layer Priority Probes
Guard    ::= watches Kind+  prefilter Fn?
Eye      ::= jev Primitive Instructions Criteria | code Fn
Primitive::= noul | choice Options | score Levels
View     ::= self | with_parent                         # [施工单优先] with_marks、with_context 留空
Outlets  ::= lines(hi, lo)                              # 由校准集算出，不可手写
Hand     ::= mark Label | put Kind Template | code Fn | write Instruction Kind | ask Question
Layer    ::= safety | correctness | efficiency
Probes   ::= (view, expect, source)+
```

出口映射（对 Jev 眼）：

```
p ≥ hi → act ;  p ≤ lo → ignore ;  否则 → unsure
Noul  : p = noul
Choice: p = probabilities[argmax] ，act 携带 argmax
Score : p = probabilities[round(score)] ，act 携带该档
```
理由：三种原语用同一套两条线，语义只有一处。

YAML 具体语法与抽象语法一一对应（字段名同施工单 §2.4）：

```yaml
unit: mark_promise          # name
version: 1
watches: {kinds: [note], prefilter: null}      # Guard
eye: {type: jev, primitive: noul, instructions: "…", criteria: {true: "…", false: "…"}}
view: self
hand: {type: mark, label: promise}
layer: correctness
priority: 10
probes: probes/mark_promise.yaml               # Outlets 不在文件里：由校准集算出
```

## 3. 组合

单元之间没有直接引用，只通过桌面上的 Item 及其 kind 相连。由此只有四种组合。

| 组合 | 形式定义 | 代价 |
|---|---|---|
| 并排 | U₁…Uₙ 的 watches 含同一 kind | 0 拍；同一 (item, view) 上合并为一次调用 |
| 接力 | Uᵢ 的 hand 产出 kind k，Uⱼ 的 watches 含 k | 每环 1 拍 |
| 裁决 | 两提议 supersede 同一 Item，或标记互斥 | 0 拍；胜者由 (layer, priority) 决定，平局 → unsure |
| 包 | 一组单元 + 私有分区 + inlets/outlets | 外层 1 拍；内部照常计拍 |

包的签名：

```
Pack : inlets ⊆ Kind  →  outlets ⊆ Kind  ∪  {unsure}
```
包对外与单元同接口 `observe(items) → actions`。包可含包，可引用自身（递归），深度上限 4。理由：同接口使层数对使用者不可见，这就是「组合之后仍是一个单元」。

替换不变量：包的交出物只取决于 inlet 的内容（`view_fp`），不取决于它被放在哪一层。形式上：同一 (unit, view_fp) 的出口相同；交出物按 (kind, body) 多重集合相同。**不是** id 相同：id 含 scope 与 made_by，那是隔离的前提（见 design-issues.md DI-1）。

接力靠 kind 名自动成立，不需要连线。理由：连线是组合的敌人，靠名字接线使每个单元可独立造、测、换。

## 4. 操作语义

### 4.1 状态

```
Σ = ⟨ Log, Ledger, Units ⟩
Table = fold(Log)          桌面由流水账折叠得出，不独立存在
Ledger : (view_fp, question_fp, model_version) ↦ answer
```

### 4.2 一拍的小步规则（分区 s）

```
D  = { i ∈ alive(s) | ∃U. U watches i.kind ∧ (U, i.view_fp) ∉ once }         脏集
Pr = { (i, U) | i ∈ D, U ∈ on_duty ∪ draft, U watches i.kind, prefilter(U, i) }  配对
G  = Pr 按 (i.id, view_fp) 分组；每组的 Jev 眼合并为一次调用，先查 Ledger      求值
O  = { (i, U, outlet_U(p)) }                                                    出口
A  = { proposal | outlet = act } ，draft 单元的 act 降级为 mark would_act       提议
W  = arbitrate(A)  按 layer ＞ priority，平局双方不执行并生成 unsure            裁决
执行 W，顺序固定为 (layer_rank, −priority, unit.name, item.id)，产出写入 Log    执行
∀ (i, U, unsure) 生成 Item{kind: unsure, about: i}                              上交
guards: once / return_to_same / runaway / beat_budget / cost_budget             保险
本拍无新 Item 且无待运行子包 ⟹ 分区安静                                          安静
```
包的求值：inlet Items 复制入私有分区 → 子分区按上述规则跳到安静 → outlets 与未吸收的 unsure 复制回父分区；根分区的 unsure 进入人队列，人答产生 `answer` Item 并进入校准集。

### 4.3 定律

```
确定性  同一 Log 重放 ⟹ Log 事件序列逐字节相同（读数与写手产出取自 Log）
        run 内：同一 (view_fp, question_fp, model_version) 只求值一次，之后取 Ledger（Jev 本身不是逐位确定的）
        清空 Ledger 真跑 ⟹ 读数差 ≤ δ（E1 实测：noul δ=0.05 p99 / 0.09 max；choice/score 0.15），
        出口只在"读数距任一条线 ≤ δ"的格子上允许翻转，其余格子出口相同
批不变  eval(s, Q₁ ∪ Q₂) = eval(s, Q₁) ∪ eval(s, Q₂)      （E2 验证；不成立则 Ledger 键含批次）
深度    一个程序的深度 = 桌面被改写的拍数；无写手时可展平为一拍内的宽度
无恒等  不保证 P_q(x) + P_q(¬x) = 1，也不保证 Noul 与 Choice 可比（见 1.3）
```
理由：前三条来自 Jev 是纯函数且并行隔离；第四条来自官方明说的结构不变式缺失。

## 5. 静态语义

### 5.1 种类流向图

节点是 Kind；边 `k₁ → k₂` 当且仅当存在单元 watches k₁ 且 hand 产出 k₂。图不需运行即可从定义算出。

### 5.2 四项检查（`check`）

```
悬空产出    产出 k 但无人 watches k，且 k ∉ outlets ∪ 终点声明
无源之水    watches k 但无人产出 k，且 k ∉ inlets
未决冲突    两在岗单元同 layer 同 priority，且可能 supersede 同一 kind      → 定义错误
越权        draft 单元配了 mark 以外的手
```
[施工单优先] 总册的七项中，无闸的环、问错对象、视野过大三项留空。

### 5.3 排程

同一 (item, view) 的 Jev 眼合并为一次调用；问题数上限与并发上限由 E4 定；超出按 unit.name 排序切批。写 Log 的顺序与网络返回顺序无关。

### 5.4 上岗

```
编译期  验题闸门：≥3 act + ≥3 ignore；gap = min(p|act) − max(p|ignore) ≥ 0.20（safety 0.30）
        闸门只判断"句子被读成了我的意思"，不产出两条线
运行期  校准集 n < 20 ⟹ hi=0.65, lo=0.35，标 uncalibrated（safety 0.75/0.25）
        n ≥ 20 ⟹ hi = min{h | 错误率({p ≥ h}) ≤ ε_act}，lo = max{l | 漏放率({p ≤ l}) ≤ ε_ignore}
        错误率 > 2ε ⟹ suspended
```
理由：缝只能验措辞，工作点必须来自真实流的错误分布；两者分开，各有数据源。ε 与门槛是全局参数，契约实测只能改它们，不能改单个单元的线。

## 6. 标准形式

```yaml
# 筛（并排）
unit: keep_relevant ; watches: {kinds: [note]} ; eye: {type: jev, primitive: noul, instructions: "…"} ; hand: {type: mark, label: keep}

# 分（接力）
unit: route ; watches: {kinds: [note]} ; eye: {type: jev, primitive: choice, criteria: {ask: "…", inform: "…"}} ; hand: {type: put, kind: "note.{opt}"}

# 守门（并排 + 裁决）
unit: hold_private ; layer: safety ; priority: 100 ; hand: {type: put, kind: note.held}

# 修到安静（接力成环 + 保险）
unit: soften ; watches: {kinds: [note]} ; view: with_parent ; hand: {type: write, instruction: "…", result_kind: note}

# 拆—做—合（接力 + 代码眼）
unit: split ; hand: {type: code, fn: split_paragraphs}          # 产出 para
unit: merge ; watches: {kinds: [para]} ; eye: {type: code, fn: all_done} ; hand: {type: code, fn: merge}

# 复核（并排 + 接力）
unit: check_a ; hand: {type: mark, label: contra_a}
unit: check_b ; hand: {type: mark, label: contra_b}
unit: agree   ; eye: {type: code, fn: marks_disagree} ; hand: {type: ask, question: "两问不一致"}

# 递归下钻（包 + 接力）
pack: drill ; inlets: [doc] ; outlets: [doc.done] ; units: [cut_into_doc, mark_small] ; packs: [drill]
```

## 7. 语言决定与 Jev 事实的对应

| Jev 事实 | 语言决定 |
|---|---|
| 输入状态 + 带类型问题，输出概率，不生成文字 | 判断必须接一只手才能成为语句（§2） |
| 同一状态上的问题并行、隔离求值 | 并排代价为零；批不变定律（§3、§4.3） |
| 有依赖的调用必须串行 | 深度定律：深度 = 桌面改写次数（§4.3） |
| 同样输入读数有 δ 量级噪声（E1 实测），并排不额外引入偏差（E2） | run 内确定性由 Ledger 承担，重放由 Log 承担；出口线带 δ 迟滞（§4.1、§4.3） |
| 输出是校准概率 | 三值出口，`unsure` 一等值（§1.2） |
| 不同问题读数不可比 | 读数类型规则 P_q（§1.3）；裁决不比读数（§3） |
| 无关内容降低精度 | View 限定，Item 要小（§2） |
| 字面阅读、不算数、不多跳 | code 眼；一个单元一个判断；model 眼留位（§2、§8） |
| 对抗内容可带偏 | Item 一律当数据；safety 层验题含敌意样本（§5.4） |
| 版本可钉住 | Ledger 键含 model_version（§4.1） |

## 8. 有意留空

| 部分 | 为什么推迟 | 接口位置 |
|---|---|---|
| 表面语法 | 语法定了改不动；先用 YAML 写两个系统，重复十遍的写法再起名 | 定义文件是抽象语法的直接序列化 |
| model 眼 | 今晚没有需要多跳的判断 | `Eye ::= … \| model Instructions` 留位，返回同类型答案 |
| with_marks / with_context 视野 | 脏集的两级定义需先经实测 | `View` 枚举留位；脏集规则已按两级写出（§4.2） |
| 规则上桌 | 自我修改不是"能用"的前提 | 定义作为 `unit.def` / `pack.def` Item 上桌，元单元与普通单元同闸门 |
