## 0. 攻击方法与新任务

**(a) 探针之外的新任务（自造）**：「FAQ 去重合并」——一千段客服 FAQ，找出语义重复的组，每组合并成一条，无法确定是否重复的留人。
它有三样探针里没有的东西：二元关系要做**传递闭包**（a≈b、b≈c ⟹ 同组），需要宿主做并查集；合并是**生成**；组的规模事先未知。
三套各写一遍（§1.0 / §2.0 / §3.0），看哪套写不出或要改语法。

**(b)** 逐构造查 unsure 去向是否穷尽。**(c)** 每套找最短的成本失控程序。**(d)** 找与 P4、P9、E10 矛盾的语法或语义。**(e)** 查有无为探针改语言（宪法附则）。

## 1. L1 守卫命令式

### 1.0 新任务写法（写得出，但暴露两处）
```
program 去重FAQ(S: Set) -> Set {
  q 重复 = select "这 K 段里哪些与 a 说的是同一件事？"      # select 只返回一个候选：多选写不出 → 只能逐候选 test
  q 同事 = test "这两段说的是同一件事吗？"
  let 边 = {}
  for a in S { for b in neighbors(a, S, 16) {
      if 同事 on state(a, b) { 边 = 边 + {(a,b)} } else {} unsure { 边 = 边 + {(a,b) with "unsure"} } } }
  let 组 = union_find(边)                                   # 纯 S
  let 出 = {}
  for g in 组 { let c = do gen(1, "把这组合并成一条", table(g)); 出 = 出 + {c} }
  return 出
}
```
暴露：① `select` 只能选一个，"哪些"这种多选关系判断没有语义操作，只能退回 K 道 test（K 邻居本来正是 select 的「选材料」用法，06 §6）；② `for` 体内改外层变量 `边`（见 A1-1）。

### A1-1 `for` 无顺序语义与体内改外层变量矛盾，确定性主张在 15 条探针里有 9 条不成立（§4.4 [for]、§7）
**反例。** 7.1：`for e in 错 { select … { 归因 = 归因 + {e with b}; 错 = 错 - {e} } … }` 在遍历 `错` 的同时删 `错` 的元素；7.2、7.3、7.4、7.6、7.8、7.10、7.14 都在 `for` 体内 `出 = 出 + {…}`。§4.4 说「体内语句对每个元素独立求值；无顺序；同层独定判断并发」，又说「桥之后全是纯函数；调度顺序不影响结果」。集合累加在数学上可交换，但 7.1 的「边遍历边删」不是；且语言没定义 `for` 体内对外层变量的写是折叠还是竞争。
**怎么才能对。** `for` 体只许产生每元素的值，由语言定义的确定折叠收集：`let 出 = for m in S yield …`（集合并）与 `partition`（三条流）；体内对外层变量赋值是编译错。7.1 改为两段：先 `for` 收集 (e,b) 对，再宿主求差。

### A1-2 `while … < 最低档` 永不执行：15 条里 5 条的循环体一次都不会跑（§4.2 whilestmt、§4.4 [while]）
**反例。** `levels ::= IDENT ("<" IDENT)+  # 低到高`，`while q on m < 档` 语义是「出口低于该档时执行体」。7.1 `while 剩余 … < 无`、7.5 `< 一`、7.7 `< 零`、7.10 `< 零`、7.11 `< 零`：目标档都是**最低档**，没有任何出口低于它，体永不执行，程序直接 `return 归因`（空集）。作者本意是「直到降到最低档」。
**怎么才能对。** 把 `while` 定义为 `while q on m > 档`（高于目标档时继续）或提供 `until q on m == 档`；变式方向（递减/递增）写进语法并由编译器检查目标档与方向一致。顺带解决 §9.1 第 4 条：允许 `while host size(x) > 0 bound n` 的宿主变式，打分变式只在「多少」不可由宿主算时用。

### A1-3 融合规则与 P4/A7 矛盾：把多条规则塞进同一状态（§7.14 注、§4.4 [融合]）
**反例。** 7.14 注：「同一段上的多条规则由编译器合成一次请求：一状态 |规则| 题」。但程序写的是 `state(段, r)`，每条规则 r 各是一个状态；要合成一次请求，语境槽必须装下全部规则——规则是带主张的文本，P4：500 token 起带偏，而且每条题看到的不再是「这条规则」而是「全部规则」，对象绑定（A7）被破坏。融合的定义是「同一渲染状态」，7.14 的状态彼此不同，注解与语义规则自相矛盾。
**怎么才能对。** 融合只对渲染文本逐字节相同的状态成立，写死；规则要进同一状态只能进**题面**（每条规则一道题、题面含规则文本），语境槽不放。编译器对「语境槽含多份带主张材料」报 W-P4。

### A1-4 成本失控的最短程序（3 行）与无预算构造
```
for a in S { for b in S { if 矛盾 on state(a,b) { } unsure { } } }
```
N² 状态，语言没有 `budget`，只有命令行 `--budget $`。7.1 的 `select 哪块 over 块` 在一份 2,000 块的 diff 上下沉为 2,000 道 noul × 错误数，同样无声。
**怎么才能对。** `program` 头部 `budget calls ≤ n, cost ≤ $` 必填或有默认；`jv check` 对可静态估计的笛卡尔积报 W-cost 并要求显式 `allow`。

### B1 类（必改）
- B1-1 7.5 用了未声明的题 `回归`；7.11 的 `全过_候选` 声明在代码块外。程序不自洽。
- B1-2 `escalate` 在 `for` 体内（7.3、7.8）：「程序在此挂起或返回 unsure（由调用者决定）」——一条 row 升级就挂起整个程序？应定义为每元素升级并继续，升级集合随返回值一起交出。
- B1-3 `refine e` 在 `for` 体内重入「当前守卫」，但当前守卫是 `select 哪块 over 块 with e`，细拆的是 e 不是候选集；对 `refine col`（7.6）在已抽 100 样例后再拆列，拆不动 → 规则「细拆到单段仍 unsure → escalate」触发，但「单段」对列无定义。给每种 Mat 定义可拆性或让 `refine` 只对 `Set` 生效。
- B1-4 `do` 函数失败（超时、非零退出、崩溃）没有出口：`let r = do run(c, cwd)` 只能成功。见 §4 共同盲点 1。
- B1-5 §7.16 说「同一组语句」但 `switch` 只在分类探针出现、`refine` 只在两条出现——不是问题；问题是 `参照.错误数` 这类锚样例集在参照库里并不存在，程序引用了不存在的东西。参照库要随程序声明或标「待建」。

### (e) 探针优化检查：通过。语法未为探针改动；`table()`、`refine`、`with` 是通用的。

## 2. L2 声明式目标

### 2.0 新任务写法（写得出，代价是把闭包塞进 iterate）
```
source faq = file("faq.txt") as seg
fn neighbors(a, S, k) -> set seg      fn merge!(G) -> seg      fn union_find(E) -> set group
judge 同事(a, b) : test = "这两段说的是同一件事吗?" on a ctx b
rule 边(a, b) :- seg(a), b in neighbors(a, faq, 16), 同事(a, b).
rule 组(g) :- g in union_find(边).            # 闭包交给纯 fn；用规则递归写要进 iterate 且要变式
rule 合并(m) :- 组(g), m = merge!(g).
goal 合并(m) unsure escalate.
```
暴露：① `g in union_find(边)` 把一个**派生关系**当参数传给 fn——文法里 fn 的参数是材料，不是关系；是否允许未定义；② 「哪些与 a 重复」同样只能 test，`select` 单选。

### A2-1 两条构造类探针（E77、D7）与 D41 违反设计自己的分层规则，且为 D41 发明了 `prev_scene`（宪法附则）（§4.4、§7）
**反例。** E77：`rule 候选(c) :- c in gen!(8, spec, top 1(接近(c) by 接近)).`——体内聚合 `top 1(接近(c) …)` 的 `c` 就是本规则正在派生的 `候选(c)` 上的候选，聚合与被定义谓词在同一层；§4.4 明说「not 与聚合要求分层（不得递归穿过）」。D7 同构且 `by 失败少` 引用了不存在的谓词。首轮 `top 1` 对空集求值无定义。D41 的 `prev_scene`「由运行时绑定为上一轮场景」是文法里没有的东西，只为一条探针存在——宪法附则「不为探针任务优化语言」被违反。
**怎么才能对。** `iterate` 的轮次是显式层：允许 `候选@prev`（引用上一轮关系，时态 Datalog 的写法），首轮 `@prev` 为空并有 `init` 规则。`prev_scene` 删除，D41 写成 `rule 场景(s) :- 场景@prev(p), s = act!(下一步(p)).` 并给 `init 场景(scene0).`。这样三条构造探针都合法，且语法是通用的。

### A2-2 成本在语法里不可见且规划器的「拒绝坏计划」没有判据（§9.1 自认，但没给修法）
**最短失控程序（1 行）。** `rule 重复(a,b) :- seg(a), seg(b), 同事(a,b).` → N² 状态；E85 `rule 升级破坏(d,v) :- upgrade(d,v), 破坏(run_tests!(upgrade!(repo,d,v)))` 对 `upgrade` 关系的**每个**元组各跑一次升级加测试。文法没有 `budget`；「规划器要好到能拒绝坏计划」不是设计。
**怎么才能对。** `goal … budget calls ≤ n, cost ≤ $, layers ≤ d` 必填；规划器规则写死：估算超预算 → 拒绝并打印最贵的规则；二元规则必须经 `pair_select` 模板或显式 `allow pairs`。

### A2-3 三值函数谓词在规则体里的求值顺序与副作用不相容（§4.4 fn!、§2 R3）
**反例。** E85：一条规则体里 `破坏(run_tests!(upgrade!(…)))`，求值是「集合一次」（set-at-a-time）——对全部 (d,v) 绑定同时执行两层副作用，再判。E22：`不稳定(t)` 的 `on summary(rerun!(t,5))` 对每个 t 各跑 5 次重跑，`goal … unsure refine summary(rerun!(t, 20))` 再跑 20 次——`refine` 只重问一次，之后仍 unsure 的元组去哪没写。`fn!` 的失败（超时、非零退出）无定义。且「同键至多执行一次」的键是参数的哈希，`rerun!(t,5)` 第二轮 iterate 时键相同 → 不再重跑，程序员以为跑了。
**怎么才能对。** `fn!` 的返回类型是 `M ⊎ fail`，`fail` 元组进 unsure 流并带原因；`refine` 后仍 unsure 的元组按 `goal` 的第二策略处理（语法 `unsure refine e then escalate`）；`fn!` 在 `iterate` 内的键加轮次号，除非显式 `memo`。

### B2 类
- B2-1 E42 `k != 正常`：`CMP` 只对同一 `measure` 谓词合法，choice 值与标签常量的 `!=` 在自己的类型规则下是错。加「choice 值与其候选集内常量可相等比较」一条。
- B2-2 E45 `bisect(commits(repo), 退化, c)`：以谓词名作参数的高阶原子，文法没有；且 bisect 隐含 log N 层的 `bench!` 串行，在一个原子里看不见层数。模板要有展开定义并在 `jl plan` 展开。
- B2-3 `variant max(接近(c) by 接近)`：跨候选取 max 依赖打分偏序，δ 0.15 下常并列，「不严格单调即停」会让多数 iterate 在第 2 轮停。变式改用宿主计量（失败数）或定义「非降即继续，连续 2 轮不升才停」。
- B2-4 `refine` 只重问一次的规则与 `keep/drop/escalate` 是并列策略，但实际是「先 refine 再什么」的序列；语法要允许策略链。
- B2-5 材料与谓词的可比性：`一致(c)` 的验题在何种材料上做没写；同一题面用于不同 `source` 种类时共用线（见 §4 共同盲点 4）。

### (e) 探针优化检查：不通过（`prev_scene`），见 A2-1。

## 3. L3 电路数据流

### 3.0 新任务写法（写得出，宿主表达式不够用）
```
circuit DedupFAQ(in S: Set[M]) -> out merged: Set[M] {
  budget layers <= 3, cost <= $0.5
  layer L1 {
    st = state(obj: S, cands: fan(S.neighbors(S, 16), K=16))
    q  = select "这 K 段里哪一段与 a 说的是同一件事？"@dd among cands on st   // 单选：一段最多认一个重复
  }
  q.unsure -> sink escalate
  wire groups = S.union_find(pairs(q.pick))          // pairs、union_find 都不在 hostexpr 里，只能是 sfn
  out merged = S.gen_merge(groups)
}
```
暴露：① `select` 单选，多重复只能多轮；② `hostexpr` 只有 `∪ \ ⊕ first size owner members`，写不出 `pairs`、并查集、按对象归组，所有探针都在偷用未声明的宿主函数（见 A3-1）。

### A3-1 宿主语言的边界没有定义：15 条探针用了至少 9 个文法之外的宿主函数（§4.2 hostexpr、§7）
**反例。** 45：`slow(half)`、`timings(half)`；77、D7：`fails(runs)`、`fails(reps)`；17：`owner(q.act)` 在列表里但 `sents \ owner(…)` 的语义（owner 返回什么）没写；13 的 `q.pick` 是 `Map[M,M]` 还是 `M`（obj 是集合时逐元素向量化，pick 应是 Map），`out blame: Map[M, M]` 与 `Tournament` 里 `first(R.reg)` 的类型不接。`hostexpr` 的文法只允许六个运算，程序却依赖任意宿主函数，而且这些函数不是 `sfn`，不进账本键、不受「effect none 抽样核对」约束。
**怎么才能对。** 二选一：宿主表达式只保留集合代数，其它一律 `sfn … effect none`（进账本、可核对）；或定义一个封闭的纯宿主子语言（映射、过滤、按键归组、计数）并给出文法。探针里的 `slow/timings/fails` 改为 `sfn`。

### A3-2 `fan` 与 `select` 的语义在多组时未定义，13 与 45 两条探针结果类型错（§2 fan、§4.4 出口）
**反例。** 13：`cands: fan(hunks, K=8)`，40 块 diff → 5 组；每组一次 `select` 出一个 `pick`——一条错误得到 5 个「罪魁」。§2.1 只说超窗裂变时「select 变成两层锦标赛」，显式 `fan` 多组时是每组一个 pick 还是自动锦标赛没写；`out blame = q.pick` 的类型因此不确定。45 同样：`fan(S.summaries(slow(half)), K=8)` 多组，`next reg = q.pick ∪ members(q.unsure)` 把多个组的 pick 并起来当候选，与 `until <= 1` 的二分逻辑不符——而且 45 的算法本身错了：性能回归定位应对中点做 `test`（bench 快慢），不是对 K 个摘要做 `select`「哪个改了热路径」。
**怎么才能对。** `select … among fan(S, K)` 定义为：K 组各选一，再对胜者递归到一个（隐式 Tournament），出口 `pick : M`；要「每组一个」用 `select_each`。45 重写为 `ring` 内 `S.bisect_mid` + `test`。

### A3-3 下沉规则自相矛盾，K=8 的段落级候选同时命中两条相反的规则（§2.1 表）
**反例。** 表中 `select` 行：「段落级候选且 K≤16 → (a) 一道选择题」与「长候选（代码级）**或 K>4** → (b) K 道是非」。段落级、K=8：前者说 (a)，后者说 (b)。45 注说「摘要是段落级，K=8 → 一道选择题」，D41 说「动作短 → 一道选择题」，13 说「K=8>4 → 8 道是非」，三处各按自己理解。
**怎么才能对。** 规则按优先级写：先看候选长度（代码级 → (b) 或 K≤4 (a)），再看 K（段落级 K≤16 (a)，K>16 裂变为锦标赛）；`jc lower` 打印命中的规则号。

### A3-4 `.unsure` 「恰好一条 connect」与探针写法冲突；`.ignore` 有时显式丢有时隐式丢（§4.3 第 5 条、§7）
**反例。** 45：`q.unsure -> merge next reg` 之外，`next reg = q.pick ∪ members(q.unsure)` 又消费了一次 unsure——两条消费，违反「恰好一条」；`merge next reg` 与 `next reg = …` 两种机制并存无定义。87 写 `q.ignore -> sink drop`，其余 12 条 `ignore` 都不接，是隐式丢弃——研究 §5.2 的 SQL 教训正是「有的地方显式有的地方隐式」。
**怎么才能对。** 三条出口线都必须接（`sink drop` 可作默认但要在 `jc check` 报 W-drop），或语言定义 `test` 的 ignore 默认接 `drop` 并写进语义；`merge next reg` 删除，只保留 `next reg = expr`。

### B3 类
- B3-1 22：`state(obj: table)` 是整张 n 次重跑结果表当一个对象，题「同一用例…不一致？」对整表只出一个出口，`out flaky = q.act` 要么整表要么空；应 `obj: S.rows(table)` 逐行。42 的 `ctx: S.window(log, 3)` 对所有行是同一个窗口，不是每行的上下文。13 的 `ctx: log` 把整份编译日志（带主张、常超 500 token）塞进每个状态，P4。
- B3-2 `q.act -> out done = q.outlet; stop`（D41、77、D7）不在 `connect`/`target` 文法里。
- B3-3 `budget` 可省略；省略时 `pair(A,B)` 的 N² 无上限。改为必填或默认 `calls ≤ 1000`。
- B3-4 `Tournament` 的 `until <= 1` 与 `variant host size(reg) decreasing`：整组 unsure 时 `members(q.unsure)` 使 size 不减 → 第 1 轮后停并出 unsure，等于「一次平局就放弃」；应允许 unsure 组再置换重问一次再放弃。
- B3-5 `sfn effect none` 「编译器抽样重跑核对」是运行时抽查不是编译期；且对 `ocr`、`a11y_tree` 这类不逐位确定的 S 会误报。纯性由声明承担，核对降为 warn。

### (e) 探针优化检查：基本通过；`stop` 与 `out … = …; stop` 的写法是为环内提前退出临时加的，应进文法或删掉。

## 4. 三套共同的盲点

1. **S 失败没有出口。** `do`/`fn!`/`effect world` 都只有成功返回。E9b 实测写手并发 12 时 30% 超时。三套都会在第一次超时处崩掉或静默。怎么才能对：S 返回 `M ⊎ fail(原因)`，`fail` 走 unsure 流并入账；重试策略是 S 库的事，不是语言的事。
2. **升级给人的流量没有控制。** E9b unsure 率 6/14，E9 4/30。一千段材料按 20% unsure 就是二百次升级；三套都把 `escalate` 当 O(1) 汇。怎么才能对：`escalate` 带预算与去重（同键只问一次），超预算的 unsure 转 `keep` 并标注；人答回流后同题同材料的其它 unsure 自动复用。
3. **新题没有线就不能跑，三套都没有冷启动路径。** 每条探针声明 2–3 道新题，按 v0/C 的闸门每题要 3+3（选择每选项 3 + 都不是 3）验题才有线；15 条程序里没有一条能在第一天运行。怎么才能对：题的校准状态加「冷」：无验题时用保守默认线（hi 0.75 / lo 0.25）并强制所有出口带「未校准」标记，累计 20 条人答后自动上岗；这正是 08 §6「待真值」的推广。
4. **校准与材料种类脱钩。** 三套的线都挂在题面（L1 题名、L2 judge 名、L3 `@id`）上；同一题面「这段有观点吗」在笔记上校准、在代码注释上使用，线不适用。怎么才能对：校准键 =（题面，对象槽种类，语境槽种类）；换种类是新题。
5. **状态渲染格式未定义。** 四槽渲染是账本键、P4 窗口、对象绑定三件事的共同基础，三套都写「渲染带槽标记」但没给格式；渲染器一改，全部账本与校准作废。怎么才能对：渲染格式进规范并版本化，版本号进账本键与校准键。
6. **多对象同状态没人用。** E8：每次调用固定开销 271 token 占小片段的 77%；B 席 L2 定律「一状态装 w 个材料各问一题」；E10 证明 16 段候选同状态可行。三套都是「一对象一状态」，把最大的一块成本留在桌上，也没有人提出对 noul 做多对象同状态的实验。怎么才能对：加 E15——同一状态放 w 段各挂一道 noul，对比逐段单状态的读数差与成本；成立则融合规则扩展为「同层同题不同对象可合状态（在窗口内）」。
7. **并发上限与状态大小相关未进任何设计。** E10 附带发现并发 16 加大状态触发 SSL EOF；三套都按 32 并发算时间。
8. **多选关系判断没有语义操作。** 新任务暴露：`select` 三套都是单选；「这 K 段里哪些与 a 相关」只能 K 道 test。06 §6 说选择题是「注意力」，注意力常是多头的。要么加 `select_many`（下沉为 K 道 noul 或一道多选题——Jev 文档未说明是否支持多选，标待查），要么明说不支持。

## 5. 结论

| 设计 | A 类 | 一句话 |
|---|---|---|
| L1 | 4 | `for` 无序与体内改变量矛盾；`while < 最低档` 使 5 条探针的循环永不执行；多规则融合违反 P4；无预算构造 |
| L2 | 3 | 构造探针非分层且为 D41 发明 `prev_scene`（违附则）；成本不可见且规划器无拒绝判据；`fn!` 的失败、重问、键与副作用不相容 |
| L3 | 4 | 宿主语言边界未定义（探针偷用 9 个函数）；`fan`+`select` 多组语义缺失且 45 算法错；下沉规则自相矛盾；unsure 双消费与 ignore 隐式丢 |

三套没有一套能原样进规范。共同盲点里 1、3、4、5 是「不改就跑不起来」的，6 是「最大一块钱没省」，8 是新任务直接打出来的表达力缺口。

## 6. 补充攻击：`10-组合代数-v0.md`

### 6.1 七种题式之外：至少两种归不进去，一种归进去了但违反自己的写题规则

**第八种：子集（多选）。** 「这 K 段里**哪些**与 a 说的是同一件事」「这批候选里哪些可行」。输出是 C 的子集，不是索引也不是位。
§2 的「比较」是单选（Jev choice 分布和为 1 → 一个胜者，D1），「归类」是每个 x 一个标签，「属性」是逐个判。多选可以**下沉**为 K 道属性题，
但那是物理实现；语义上它是独立题式，正如「比较」也能下沉为 K 道判却仍被列为题式。§1 把「选管注意」定义成「哪段关系到 a」，注意天然是多头的——
本轮新任务（§0）三套设计都写不出「哪些」，就是这一格空着的直接后果。

**第九种：充分性（材料对题）。** 「这份材料包含回答 Q 所需的信息吗」。它是材料与**问题**之间的关系，不是材料与材料（关系题）、也不是材料的属性。
它驱动的是 ? 的两个去向（细拆还是升级）：材料不足 → 取更多材料；材料够但仍 ? → 升级。没有它，? 的去向只能按格子写死（见 6.3）。
E7 测的元题「有助于判断 Q 吗」偏弱，但「材料里提到了 Q 问的那个东西吗」是字面的，可测。

**「解释」题式违反写题规则第 1 条。** 「哪个假设 h 最能解释 x」要求 Jev 做「若 h 则 x」的推理，是两跳；E9 的 `sum(strings,'')` 已证 Jev 不模拟。
怎么才能对：解释题写成字面形式「x 的文字里出现了 h 描述的原因吗」（每个 h 一道属性题，或一道多选），溯因由宿主按出口组合。
题式表里「解释」应改名「提及（h 在 x 里有无字面痕迹）」，溯因是骨架不是题式。

### 6.2 接的十六种：两格误标为「—」，且十六种其实是三种映射 × 六种槽

- **索引 → 循环** 不是空格：`select "接下来做什么" over {继续, 停, 升级}` 是 Agent 循环最自然的控制（E9b 的搜索类探针都需要），比「档不进步即停」更直接。
- **位 → 刻度** 也不是空格：「材料带主张吗」为 act 时换细刻度、为 ignore 时用粗刻度（E10 锚数与漂移的关系正好给这条依据）。
所以 18 格全有意义；「16 种有意义」少算了两种。

更要紧的是这张表把**映射种类**与**目标槽**乘在了一起当原语。位→材料（门）、位→动作（执行/不执行）、位→循环（继续/停）是同一个东西：守卫 `g → S`，只是 S 落在不同槽。
真正不同的映射只有三种：**门**（位决定做不做）、**路由**（索引决定做哪个）、**阈/序**（档决定做多少、先做谁）——恰是 08 的守卫、解非确定、变式。
语言若提供 16 个组合子（门、取、路由、分支、换刻度、分派、阈、换题、保留、缩放、分配、变式……）是 API 爆炸，程序员要记 16 个名字学 3 件事。
怎么才能对：语言提供 3 种映射 × 6 种槽的**正交**写法（`gate(b) → 槽`、`route(i) → 槽`、`rank(ℓ) → 槽`），表只作文档，不作原语。
另有第七个槽表里没有：**参照槽**——索引→参照（选出的最好样例成为下一道量题的锚）、档→参照（某档的典型样例入锚库）是真实且常用的映射（E10 锚每档一条，锚从哪来？就从这里来）。

### 6.3 ? 的固定去向：两个反例，一个出错、一个死循环

**出错（材料格 → 细拆再判）。** 找矛盾：`关系("这两段相反吗") on (a, b)` 出 ?。按表，材料格的 ? 固定「细拆再判」：把 a 拆成句子 a₁…aₙ，逐句与 b 配对。
矛盾在段落层（a 的结论与 b 相反，但 a 的每一句单独都只是铺垫），拆后每对都 ignore，聚合「存在」= ignore，程序输出「无矛盾」。
固定去向把一个 ? 变成了一个**确定的假阴性**，比 ? 更糟。P4/A7 的对象绑定在这里反向起作用：拆分改变了对象。
怎么才能对：材料格的 ? 先问充分性（6.1 第九种）：材料够 → 升级；材料不够且可拆 → 细拆；拆后仍 ? → 升级，不得聚合成确定值。

**死循环（候选集格 → 再生成；刻度格 → 加锚）。**
```
loop bound 20:
  cands = gen(8)                       # 候选集
  x = select "哪个满足规格" over cands  # ? 的固定去向：再生成
```
? 的原因若是**题面歧义**而非候选质量（E9b 的 unsure 多属此类），再生成 20 轮候选都是 ?，烧 160 次生成到 bound 才停，账本里全是 ?。
刻度格同理：? 固定「加锚」，E10 已证 3–5 锚后漂移收敛（5→10 只差 0.07 档），真正处在两档之间的对象加多少锚都是 ?，加到状态超窗报 E-window。
动作格「不执行」在搜索里更隐蔽：`while 距离 < 到 { select 下一步 …; ? → 不执行 }`，不执行则场景不变、变式不动、「不进步即停」触发——**一次 ? 就终止整个搜索**，输出 ?。
怎么才能对：每格的去向不是一个，是**有序的两个**：第一去向失败（键重复或再 ?）后必须换到第二去向（升级或换题），且第一去向带独立的小上限（默认 2 次）。

### 6.4 「选与量不一致 → ?」在 δ 0.15 下会把两到四成样本判成 ?

推算（引 E1、E10）：量题配置内重跑 argmax 档一致率 0.97–1.00，但**跨配置**（3 锚对 5 锚）一致率只有 0.75，同题跨对象的档位本就有约 25% 的不稳定；
选题 argmax 翻转约 3%。K=8 候选、3–5 档：多个候选共享最高档是常态，「选中者不在最高档」只在选中者被噪声压低一档（约 10–25%）或另一候选被噪声抬高一档时发生；
两者相加，估计 20–40% 的样本触发不一致。若一致性检验把这些全判 ?，选题的可用率直接掉到六成。
而且选与量的判据往往不同（「哪个最好」对「多紧急」），不一致是多准则的正常现象，不是错误信号。
怎么才能对：不一致只在**同一判据**下定义；判 ? 的条件改为「选中者比最高档低 ≥ 2 档」（超出 δ 相邻档）或「选题 p_max 未过线」；
E15 预注册：不一致样本的错误率显著高于一致样本才启用，且 ? 率 ≤ 15%，否则这条检验降为日志信号不进语义。

### 6.5 一句话
题式：至少加「子集」与「充分性」，「解释」改成字面形式；接：三映射 × 六槽（加参照槽）而不是 16 个组合子，18 格都有意义；
? 去向：每格两个有序去向带小上限，材料格先问充分性；一致性检验：同判据、差两档、E15 先测再进语义。
