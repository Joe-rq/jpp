## A. 致命（规范必须改）

### A1. 规范自相矛盾：E1 说「判断没有值」，§3.1 说「出口是 Mat 的子类型」，§9 有 3 条探针把判断当值用
**反例。** §3.3 E1：「判断没有值：守卫只能出现在 if/select/switch/while/choose 或组合子里」。
§9.4：`return for r in log_stage(log) yield 类别(on: r)`；§9.6：`yield 类型(on: sample(col,20), ctx: header(col))`；§9.14：`yield 符合(on: 段, ctx: r)`。
三条都把 `call` 放在 `yield` 的值位。按 E1 是编译错误，按 §3.1（出口 ⊂ Mat）是合法的。同一份规范两条规则互斥，探针站在 §3.1 一边。
**后果。** 若判断真无值，`class` 题的分类结果没有任何合法的落地方式（`switch` 只能分支不能收集），9.4/9.6 写不出；若有值，E1 与 E4 的边界要重画。
**怎么才能对。** 判断**有值且值是出口**（`Outlet3 / Chosen / Level`，都是 `Mat` 子类型，可 yield、可入集合、可入账本），E1 改为：
「读数没有值；出口是值。守卫位只接受出口值或 call。」E4 保留（守卫位禁数值与概率）。§4.7 的聚合子作用在出口集合上，正好闭合。

### A2. §2 文法解析不了 §9 的 15 条程序：至少七类构造不在文法里
逐条解析结果（行号按 §9 代码块）：
| 构造 | 出现 | 文法状态 |
|---|---|---|
| 元组绑定 `let (a, b, c) = partition …` | 9.2/9.3/9.7/9.8/9.10/9.12 | `let ID = expr` 无元组；`partition` 的三流无法接住 |
| 赋值 `候选 = before(…)`、`史 = 史 with …`、`repo = apply(…)`、`观 = a11y(…)` | 9.5/9.7/9.11/9.13 | 只有 `let`，没有赋值语句；§4.5 说 `loop` 可写外层变量，却没有写法 |
| `do run(…)` 作表达式 | 9.3/9.5/9.7/9.9/9.11/9.13 | `do` 只在 stmt 位（`"do" call`），不在 expr |
| 宿主条件 `if host size(对) > 0` | 9.7 | `if` 只接 `call`；`>` 不在 expr；`host` 只在 variant 里。宿主布尔分支整个缺失 |
| 位置参数 `take(哪块, 块, e)`、`dispatch(下一步, actions(观), 观 with 目标)` | 9.1/9.11/9.13 | `call ::= ID "(" args? ")"` 的 `args` 非终结符**未定义** |
| 未绑定的迭代变量 `partition 出现(on: 句, …) over split(…)`、`on: row`、`on: d`、`on: f.signature` | 9.2/9.3/9.8/9.10 | `partition` 没有绑定元素变量的语法，`句/row/d/f` 从哪来无定义 |
| 一等题的调用 | §3.1 `Q` 一等值；§6.4 `route` 返回 `Q` | `call` 要求首项是 `ID`，Q 类型的表达式**无法被调用**；`route/retitle` 的返回值用不了 |
另有：`msg.parent`、`f.signature`、`f.docstring` 访问 `Mat` 没有的字段；`range(n)` 产 Int 集合但 `for ID in expr` 要 `Set[Mat]`；`return "破坏" with diff(…)` 是 `Str with Mat`，`with` 在 §9 里同时当集合并、打补丁、字符串拼接、流合并四种意思，无类型规则；`import` 在 §9 开头声称共用却没有一条探针写它。
**后果。** 「A2 像 C++ 说清」判满足不成立：这份文法写不出自己的示例程序。
**怎么才能对。** (1) 加 `let "(" ID ("," ID)* ")" "=" expr` 与 `ID "=" expr`（仅 `loop` 体内合法，`for` 体内报 E8）；(2) `do call` 进 expr（返回 `Mat ⊎ fail`）；(3) 加宿主布尔：`if host expr block else block`（无 unsure 支，因为不是判断）；(4) 定义 `args ::= expr ("," expr)*`；(5) `partition` 改为 `partition ID in expr where call`，元素变量显式绑定，`for … yield` 同理已有 ID；(6) `call ::= (ID | "(" expr ")") "(" slotargs ")"` 让 Q 值可调用；(7) `with` 拆成 `∪`（集合/流）、`patch`（S 库函数）、字符串不许 `with`；(8) `Mat` 的字段访问只许经 S 库函数（`parent(m)`、`signature(f)`），或在 §3.1 定义 `Mat` 的可选字段表。

### A3. §9 里至少五条探针违反规范自己的 E10（escalate 无预算），且升级超预算后的「保留并标注」在程序出口处静默丢标
**反例一。** 9.3、9.7、9.9、9.11、9.15 都有 `escalate` 或 `unsure -> escalate`，`budget` 里都没有 `escalate <= n`。按 §3.3 E10「`escalate` 无预算」是编译错误。规范的示例过不了规范的检查。
**反例二。** §4.10：超预算的 unsure「转为保留并标注」。9.2 `return 未见 with 疑`、9.8 `return 不符 with 疑`、9.10 `return rank(严重, 变) with 疑`：返回类型 `Set`，`疑`（unsure 流）并入后没有任何类型标记；下游拿到一个 `Set`，分不出哪些是 ignore 哪些是 unsure。这正是 §0 原则 6「没有静默二值化」禁止的事，发生在程序边界。§2 的 `type` 只有 `⊎ fail`，没有 `⊎ unsure`。
**怎么才能对。** (1) `budget escalate` 缺省为 0，`escalate` 语句在预算 0 下是编译错误（E10 已写，探针改对）；(2) 程序类型加 `⊎ unsure`，`Set` 与 unsure 流合并只许经 `mark_unsure(流)` 得到 `Set[Mat ⊎ unsure]`，`with` 混合两流是类型错（新 E11）；(3) 超预算 unsure 只能进返回值的 unsure 分量或 `drop`，不能进 `Set`。

### A4. §4.2 打分变式「档位不下降且键不重复」在 δ 0.15 下会早停，且「键不重复」可被无意义改动绕过
**早停。** E1/E10：score 档位重跑 argmax 一致率 0.97–1.00（配置内），相邻档差 < 0.15 判 unsure；而 §3.3 又规定「相邻档视为并列」。若「不下降」按严格档位比，噪声把 3 读成 2 的一轮就退出，每轮约 3–10% 的假退出，10 轮循环有 26–65% 的概率在真正收敛前停；若按并列比，则「不下降」恒成立，判据失效。两种读法都不对。
**绕过。** 循环体每轮 `史 = 史 with 新东西`（9.7 就是这样），渲染状态每轮都变，键永不重复，循环跑到 `bound` 为止，「不进步即停」一次也不触发。键重复检测只能抓「什么都没改」，抓不住「改了没用的」。
**怎么才能对。** 变式用**迟滞 + 耐心**：连续 `patience`（默认 2）轮档位不上升即停（上升定义为 ≥ 1 档且超出相邻并列）；键重复仍作为「什么都没改」的快速退出。宿主变式保持严格单调。这两个参数进 `while` 语法：`while q(…) improving patience 2 bound n`。

### A5. §5.1 下沉表的条件「段落级 / 代码级」无人判定；§5.3 分块选再锦标赛把 P9 首位偏置逐轮相乘
**条件不可判。** 下沉表按「段落级候选 K ≤ 16 / 代码级候选 K ≤ 4」分支，但规范没有任何地方定义谁给候选打「段落级/代码级」标签；`Kind` 是标签不是类型（§3.1），S 库渲染器是否必须给 kind 未规定。E10 与 E9b 的区分量其实是**候选渲染 token 数**（约 100 对 300+），不是种类。
**偏置相乘。** §5.3：K > 16 时「分组 + 锦标赛」。P9/P17：choice 首位偏置 23–33%（置换后仍有残余）。r 轮锦标赛，每轮独立残余偏置 b，胜者正确的概率约 (1−b)^r；b = 0.10、r = 3 → 0.73；且 §6.5 「unsure 组晋级前二」使下一轮候选数不减反增。与此同时 P17 已证 K 道 noul 取 argmax 在长候选上 14/14 优于 choice 12/14，而同题的 noul 读数跨状态可比（v0 §1.3 同 q 合法），一层即可全局 argmax，不需要锦标赛。
**怎么才能对。** (1) 下沉条件改为可测量：`avg_tokens(候选)` 与 K，阈值来自校准库（E10：≤ 120 token 且 K ≤ 16 用 choice；> 250 token 用 noul-argmax；中间待测）；(2) 锦标赛只在「噪声可接受且 N 大到 noul 一层超预算」时才选，`jv lower` 必须打出两种方案的预估调用数与偏置估计，默认 noul-argmax；(3) 锦标赛的 unsure 组晋级规则要带上限（晋级总数 ≤ 上一轮的一半），否则不收敛。

### A6. 题式数与组合子签名两处内部不一致：§6.2 说「七 + 二」、§9.16 引 设计/F 说「全部落在九种题式内」，而 F 只分了七种；组合子用位置参数，题用具名槽
**题式。** 设计/F 的结论是七种（下一问改名决定后 188/188），没有 `subset` 与 `enough`。§9.16 把「九种」归功于 F 是引错。更实质的问题：`enough` 的字面形式「材料里提到了 Q 问的那个东西吗」是 `attr`（对象 = 材料，语境 = 题面），`subset` 是 `attr` 在集合上的向量化（§5.1 自己也下沉为 K 道 noul）。它们是**题模板**不是**题式**；把它们列为题式，与 §0 原则 3「语义操作与题型分离」相抵：题式应按判据分，不按物理形状分。
**签名。** §6.4 `take(q, C, ctx)`、`dispatch(q, A)`、`allocate(q, S, plan)` 用位置参数；题的调用用 `on/ctx/over/ref`。9.1 `take(哪块, 块, e)` 里 `e` 是**对象**（编译错误那一条），却落在 `ctx` 位；9.11 `take(最可能, do gen(…), spec)` 里 `spec` 是语境。同一个组合子的第三参在两条探针里意思不同。`allocate` 的 `plan` 无类型无语义；`rescale`、`retitle` 无返回类型。
**怎么才能对。** (1) 题式定为七种（属性、关系、比较、归类、提及、程度、决定）；`subset`、`enough` 进 §6.2 的**模板**，各注明「= 属性的向量化 / = 属性以题面为语境」；(2) 组合子接受**部分应用的题调用**：`take(哪块(on: e, over: 块))`，组合子只补去向，不再承担槽；(3) `allocate`、`rescale`、`retitle` 补完整签名或从 v1 删去，列入 §12。

## B. 标准与表述必须改

### B1. `choose` 的仲裁题 `cmp` 用「命令的字面描述」做候选：是决定题式，且描述无处书写
「多条守卫同真时由一道 cmp 决定走哪条」——候选是「启用命令的字面描述」，判据是「走哪条更好」，这是前瞻判据，按 设计/F 是 `decide` 不是 `cmp`。文法里 `choose` 的分支没有描述字段，描述从哪来无定义。修法：`choose { g₁(…) "描述" -> B₁ ; … }`，仲裁题下沉为 `decide`，描述是程序员写的字面材料。

### B2. §4.6 `then` 链的作用域与递归未定义
「第一去向上限 2 次」是每题、每循环、还是每程序？`refine` 产生的子判断各带自己的计数，细拆深度只受材料大小限制；N 段全 unsure 时升级 N 次直接撞预算，然后落入 A3 的静默丢标。修法：计数按（题，对象来源链根）计；`refine` 的子判断继承父计数；升级请求按对象去重后计入预算。

### B3. `partition` 内的 `do` 失败（`fail`）走哪条流未定义
9.7 `partition 成功(on: do run(c, cwd), …) over cmds`：`run` 超时返回 `fail`（E9b 30%），此时对象槽是 `fail` 不是 `Mat`，判断无法渲染。`fail` 进 unsure 流（§3.1）还是进 ignore 流？修法：`fail` 进第四流 `failed`，`partition` 返回四元组或 `fail` 单独由 `on_fail` 子句接住。

### B4. §5.4 规划器目标与 `budget` 冲突时的行为未定义
最小（层数，钱）计划超出 `budget` 时：拒绝？裁剪？降级下沉？规范只说 `jv plan` 比对。修法：`jv check` 阶段静态可估的部分超预算即 E12（新），报「最省计划 $x > 预算 $y，可放宽 K/加一元筛/减 bound」；动态部分运行时到预算即停并把剩余对象标 `bound`。

### B5. 宪法登记表缺项：`partition` 三流、`for … yield`、`budget`、`bound` 燃料循环、`fail` 和类型
这五个构造都是借的：三流分区（SQL 三值 WHERE 的教训反面）、`yield`（Python/C#）、资源预算（资源感知类型系统）、燃料有界递归（Agda/Coq 的 fuel）、`⊎ fail`（Rust `Result`/Haskell `Either`）。`00-宪法.md` 登记表没有它们，第三格「条件在 Jev 下怎么变」没写。修法：补五行；`bound` 的第三格是「非单调（P2/P4）使 fuel 从证明技巧变成语义必需」。

### B6. §6.5 把 `derive`、`preview` 列为「骨架（用 Jv 写）」，但账本里它们是假设 #19（未实现）、#24（未测）
方法 09 规定设计只许引用公理/推导/成立的条目，假设要标状态。§6.5 只给 `preview` 标了 #24，`derive` 没标。修法：两条移到 §12 或在 §6.5 标「[假设·未验]，不随 v1 交付」。

### B7. §10 四条「满足」名不副实
- A2「像 C++ 说清」：A2 文法缺口 → 部分。
- A4「三种题都用并深挖」：`subset` 的物理形式待查（§12）、档 = 2 未测 → 部分。
- C11「九种题式、七种选法可写」：选问题（决定于题集）要调用 Q 值，文法写不出（A2 第 7 行）→ 部分。
- B1「五种语句」：§2 `stmt` 有 14 个候选式，关键字 32 个 → 自评「清晰优雅」的依据不成立，改「待红队」。
另 B7「沿用 设计/C §2」：C §2 的标准按九模块写，本规范以 E/W 代码重组，对应表没有 → 部分。

### B8. 渲染格式 `[JVR 1]` 装不下 `subset` 与多条语境
`[候选 k=…]` 只为 `select`；`subset` 下沉为 K 道 noul，对象是谁？（K 个对象各一状态 → 与「一状态一对象」一致，但格式里无表达）；`[语境]` 可空但多条语境（定义 + 约定 + 谁说的）的顺序与分隔未定，顺序影响读数（P4）。修法：`[语境 n=…]` 编号且按来源链排序；`subset` 明写为 K 个 `[对象]` 状态。

### B9. `select` 默认置换 2 次「取众数」：2 次无众数
两次置换 argmax 不同时无众数可取，规范没说是 unsure 还是补第三次。E10 用的是 3 次。修法：默认 2 次，不一致自动补第 3 次，仍不一致 → unsure；写进 §4.2。

### B10. 三个合法但语义不成立的程序（§3 类型规则漏网）
1. `q 深 : degree[低 < 高] anchors A` —— 文法允许两档（`("<" ID)+`），§5.1 说档 = 2 未测且不下沉，编译器对它做什么无定义。
2. `while 有观点(on: 段) improving bound 3` —— `improving` 要求 measure，`有观点` 是 attr；文法 `variant ::= call "improving"` 不检查题式。
3. `select 类别(over: {}) as x { … } unsure -> escalate` —— 空候选集合法，语义无定义（unsure？E？）。
修法：E13 变式题式必须是 degree；E14 候选集静态为空报错、动态为空走 unsure；两档 degree 报 W-2level 并按 noul 下沉的假设标注「未测」。

## 通用性：三个探针外的任务

1. **商务谈判助理**（观察对方报价 → 决定 {接受, 还价, 拒绝} → 生成还价 → 发送）：`decide` 于动作集 + `dispatch` + `do gen` + `while 满意度 improving`。**写得出**，但三处撞 A2：需要赋值（历史）、`do` 作表达式、宿主布尔（回合数上限之外的「对方已接受」）。
2. **翻译抽检**（哪些句翻错、错得多严重、生成修订）：`subset` 于对齐句对 + `degree` + `do gen`。**写得出**，句对需要宿主 `zip` 后作对象，`rel(on: 译句, ctx: 源句)` 更自然；`subset` 按 A6 是模板不是题式，写法无差别。
3. **万级记录去重**（相似记录合并）：先宿主分块（哈希/长度）再 `rel` 配对 + `exists`。**写得出**，W-cost 与 `allow pairs` 起作用；但「合并」需要写回记录集——又是赋值与 `loop`。
结论：语言层没有新锁，锁全在文法（A2）；一旦 A2 修好，三条都能在 12 行内写完。未为探针优化语法（宪法附则通过）。

## 结论

A 类 6 条：判断有无值的自相矛盾（A1）；文法写不出自己的示例（A2）；示例违反自己的预算规则且程序边界静默丢 unsure（A3）；打分变式早停与可绕过（A4）；下沉条件不可判与锦标赛偏置相乘（A5）；题式计数与组合子签名内部不一致（A6）。
每条都有修法且不需要新实验，除 A5 的中间 token 区间（E10 补测）与 A4 的耐心参数（E14 顺带测）。
建议：按 A1–A6 修出 v1.1 后再红队一轮文法（用 15 条探针 + 本轮 3 条新任务做解析测试，解析器先于解释器）。
