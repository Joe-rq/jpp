## A. 致命问题（设计必须改）

### A1. 第 8 节的递归函数不终止：过滤不保证材料变小（§8、§13、§12 模块 6）
**反例一（退化）。** 材料是 60 段全在讨论同一主题的论文，每段都有观点，Q =「有矛盾吗」。第二行「这段有助于判断 Q 吗」对 60 段全部 act（每段都有观点，都可能参与矛盾），证据 = 材料；语境 ⊆ 材料；拼(证据, 语境) 的大小 ≥ 原材料。回到第一行，材料没变小，再判一遍，无限循环。
**反例二（内部爆炸）。** 第三行的状态是「段 + 证据」。证据一旦超过 500 token，内层调用 判("这段改变证据的读法吗", 段+证据) 走的不是「一次塞进」分支，而是再对「段+证据」做过滤。它的证据集合包含整个原证据（问的就是「改不改变证据的读法」，证据当然和 Q' 有关），材料同样不缩小。递归在第三行内部就发散，和外层无关。
**根因。** 文档写「深度由材料量除以上限自然长出」，这是把**拆分**的性质安在了**过滤**头上。过滤只能在材料里有无关部分时缩小材料；对同质材料它是恒等映射。终止靠的必须是结构上的缩小：拆（分治后各自判再聚合）或配对（N 段变 N² 个 ≤ 界限的对）。
**推论。** 旗舰例子「矛盾」本身就跑不通这个函数：矛盾是二元的，两段相隔 40 段的话必须出现在同一个状态里才判得出，过滤加拼永远不会把它们单独放到一起，只会把所有观点段拼成一个超界的大块。
**修法。** 递归函数改为按 Q 的**元数**选骨架：一元 Q → 过滤后逐段判再聚合；二元 Q → 一元前提过滤 → 配对 → 逐对判 → 聚合；全局 Q（「这篇是否自洽」）→ 分治：拆成 ≤界限的块，各块判，把各块的**出口**（不是读数）渲染成摘要再判。三种骨架每层都严格减小状态大小，终止可证。§12 模块 6「必然终止（物理界限）」改为「每层状态 token 数严格递减，由骨架保证」。

### A2. 「整门语言是一个递归函数」不成立：四任务伪码除 Q 外至少六行不同（§8、§13 验收法）
四份伪码和逐行 diff 见附录。除最外层 Q 外，不同的行：①终止条件（大小 / 找到或步数耗尽 / 测试通过 / 订单落地）②缩小结构（过滤 / 分治+配对 / 结构索引 / 生成候选再打分）③「定→做」一步（文档任务没有；另外三个都有 choice → 动作映射）④语境的来源（Jev 判 / 屏幕历史 / AST 调用关系，确定性工具算，不用 Jev）⑤记忆（computer use 与 Agent 要记已访问状态防绕圈，文档任务不要）⑥不可逆动作闸门（订票要 unsure → 人，其它不要）。
**结论。** 按第 13 节自己定的验收标准（「第三处不同就是锁住了」），第 8/13 节的函数锁在「固定语料上的一元过滤」这一种任务上。任务无关的东西比它更小：**判 + 五算子 + 账本 + 校准**是内核；「递归函数」是内核之上的一个标准库骨架，而且是四个骨架（筛、配对、分治、搜索）中的一个。
**修法。** 第 8、9 节改口：最底层是一道题、三值、五算子；标准库提供四个任务无关的骨架，每个骨架的验收是「换任务只改 Q 和料库来源」。四任务 diff 验收保留，但改成对**各自骨架**做 diff。

### A3. 选材的核心一跳题是元问题，Jev 实测在这类题上弱（§6、§8）
**问题。** 「这段有助于判断 Q 吗」要求 Jev 推理「什么会影响另一个判断」，不是字面一跳。E7 已测：隐式双重判断的缺口 −0.05，结论是「元单元需要模型眼」。整门语言的选材建立在一种已测偏弱的题型上，而且没有任何验题闸门覆盖它。
**修法。** 选材不用元问题，用第 5 节推导出来的**字面前提谓词**：矛盾的前提是「这段有观点吗」，不是「这段有助于判断矛盾吗」。这样第 5 节和第 8 节合一，第 8 节的第二行就是第 5 节的第一步。元问题只允许出现在推导器的编译期，产物必须过验题闸门才能当谓词用。

### A4. 谓词推导的熵/相关筛选是无监督的，筛出来的是「会变的」不是「有用的」（§5、§12 模块 3）
**反例。** 代码库 10,000 个函数，真有 bug 的 3 个。随机样本 200 个函数上，「这个函数会空指针吗」几乎全 ignore，熵 ≈ 0，被砍；「这个函数超过 30 行吗」答案分得开、和别的题不相关，熵高，被留下。筛选选中了和目标无关的谓词，砍掉了唯一有用的。目标越稀有，这个筛法错得越厉害，而稀有目标（矛盾、bug、违规）恰是最值钱的。
**根因。** 熵和两两相关只量谓词自己的分布，不量它和目标的关系。要量「有用」必须有目标侧的信号：样本上的标签，或至少一个已经能判目标的代理。
**修法。** 推导器的筛选改为**条件于目标**：（a）样本要带标签（人标或已有的正例集合，稀有目标要**分层抽样**把正例抽够）；（b）按谓词对目标的区分力筛（正负样本上读数分布的距离），熵和相关只做第二道去冗余；（c）没有标签时只允许保留「前提」类谓词（逻辑必要条件，由规则给出，不由熵给出）。没有标签的谓词表在名册上标「未验证」。

### A5. 「结果是数据，可以再判」会把数字塞进 Jev；Jev 不会算、不会比（§14、§15 模块 2）
**问题。** 第 14 节说「判断的结果本身也是数据，判断可以判断上一轮的判断，不需要特殊通道」。渲染后进入状态的是「P=0.83」这样的字面。Jev 官方明说不做算术；E7 测的隐式判断缺口就是这类题。而「一切一个类型」意味着编译器**没有办法**阻止程序把读数渲染进状态，v0 §1.3 的 P_q 类型规则（跨题不可算）在「一个类型」下无处挂靠。
**修法。** 分清递归需要的两件事：（i）用上一轮的**数字**在确定性代码里选下一轮的材料和问题——这是递归成立的全部理由，数字不进 Jev；（ii）把上一轮的**结果**当材料给 Jev 看——只允许渲染**出口**（act/ignore/unsure 或选项名、档位名），禁止渲染概率。类型上：材料一个类型，读数是另一个类型且没有渲染函数，唯一的桥是 outlet_q。第 14 节「一个类型」改为「一个**材料**类型」，第 15 节模块 2 补这条限制。

### A6. 递归算子在非单调判断上没有不动点（§4、§12 模块 7）
**问题。** 「带递归的关系代数 = Datalog」的表达力结论依赖谓词单调（加事实不会让已推出的结论消失）。Jev 判断不单调：E5/E6 实测加材料会让读数上飘或下落，出口可翻。三值下的 Datalog 语义（Fitting/良基语义）也要求单调。没有单调性，递归求不动点可能振荡——这正是 v0 用「改不停」保险兜底的现象，说明它在昨晚的系统里已经出现过。
**修法。** 递归不定义为不动点，定义为**有界迭代**：每层材料严格变小（A1 的骨架）或步数有上限；出口一旦落地进账本就不因后来的层改写（单调化：账本是只增的）。表达力主张改为「有界深度的一阶查询」，不引用 Datalog 不动点定理。

### A7. 证据/语境二分漏了「参照」，且证据没有绑定判断对象（§6）
**反例一（参照）。** Q 是 score 题「这条待办有多紧急，1–5 档」。给 Jev 看三条已知档位的样例，或看同批其它待办，会改变读数的刻度。样例既不「让 Q 动」（它不是关于这条待办的），也不「改变证据的意思」（待办还是那个待办），它改变的是**问题的刻度和参照类**。choice 题的选项集合、排序题的同批候选同理。这是第三类，叫参照。
**反例二（对象绑定）。** Q =「A 段是否承诺 X」。B 段自己承诺了 X，B 对 Q「有帮助」（它显示 X 是本文会承诺的东西），按第 8 节被当证据拼进状态。E5 已测：带主张的材料 500 token 起就把判断的真实标的带偏——Jev 会把 B 的承诺读成 A 的。第 8 节的「拼」把目标段和证据段混成一块字面，正好重现 E5 的失败模式。
**修法。** 材料价值三类：证据、语境、参照。状态渲染必须**结构化标出对象**（哪段是被判的对象、哪段是证据、哪段是参照），证据题改为「这段是否关系到**对 A 的**判断」，且对象段永远单独占位。

## B. 标准与表述必须改

### B1. 「问题免费」只在时间上成立，token 上不成立（§2、§3、§12 模块 5）
E4 v2 实测：同一 300 token 状态挂 1/10/50/200 题，input_tokens = 570/1048/2530/8080，每题约 37.7 token；耗时 0.876/0.797/0.910/1.069 s。时间近似常数，token 线性。200 题时问题占 93% 的 token。钱的公式是 状态数 ×（状态 token + 37.7 × 题数），不是「按材料算」。规划器成本模型改为这条；「一段材料一次问干净」在钱上不是免费的，只是便宜（$0.042/Mtok 下 200 题 ≈ $0.0003）。

### B2. 「几秒几千次」取决于并发上限，而并发上限未测（§0、§3）
实测：单请求 0.8–1.1 s，与题数几乎无关；实验并发只跑到 6，且遇到过 429/529 要退避（EXPERIMENTS.md 第 5 行）。推算：一层 = p95 延迟 ≈ 1.1 s；6 并发 × 200 题 ≈ 1,200 题/秒，「5 秒几千次判断」只在**状态数 ≤ 30、层数 ≤ 5** 时成立。若判断数按状态算，1,000 段 ÷ 6 并发 × 0.9 s ≈ 150 s，不是几秒。需实测：最大在飞并发数（429 出现点）、持续 RPS、延迟 p50/p95 随状态大小（500/2000 token）的曲线、单请求题数上限（200 已过，1000 未测）。层的耗时是该层所有状态的**最大**延迟，尾延迟决定一切，中位数没用。

### B3. 语境要先于证据，不是先证据后语境（§6 末句）
「本文的 X 指狭义 X」这句定义决定哪些段算「关于 X 的观点」，即决定谁是证据。先筛证据再配语境会把靠定义才算证据的段漏掉。顺序改为：问题语境（定义、约定，相对 Q 选）→ 证据 → 证据语境（谁说的、是否引用）→ 参照 → 问目标。

### B4. 三值算子的 unsure 传播没有定义，聚合和否定各有一个洞（§12 模块 7）
- 过滤：unsure 段去哪？进下游算 in 则成本爆，算 out 则召回掉。必须是**第三条流**，下游对它的处理（细拆再判 / 升级）由骨架定。
- 聚合「存在」：全 unsure → unsure（Kleene）；「全部」：任一 ignore → 假；计数：给区间 [act 数, act 数 + unsure 数]；top-k：偏序，k 内含 unsure 时结果标 unsure。这些要写成定义并有测试。
- 否定：v0 §1.3 已定 P(x)+P(¬x)≠1，所以「非 Q」不能用 1−p，也不能简单换出口。「非」要么是另一道题（自己的两条线），要么是出口对调并明确标注它不等价于反问。二者选一写死。
- 做：有副作用，代数律（两次过滤 = 一次合取过滤）只对不含「做」的子表达式成立，标准里要限定。

### B5. 选材召回检验在 δ 噪声下要约 90 次重跑才能测到 10 个百分点的召回损失（§12 模块 4）
基线翻转率 3%（choice 实测），要在单侧 α=0.05、功效 0.8 下分辨翻转率 3% 对 13%，需 n ≈ 90 次「放回后重判」。钱不多（几分），但它只测**整体**召回，测不到「一段决定性材料被丢」这种针尖失败——随机放回 10% 的片段，命中一根针的概率每次 10%。标准改为两条：（a）整体：90 次分层放回，翻转率不高于基线 + ε；（b）针尖：对标注过的决定性片段做**穷举**放回，出口必须变。

### B6. 规划器「状态数最少」和 500 token 界限、和延迟直接冲突（§12 模块 5）
状态数最少的解是把片段合并成少数大状态，正好撞界限（E5）。延迟 = 层数 × p95 + 状态数 ÷ 并发，钱 = B1 公式。目标函数改为：在「每个状态 ≤ 界限」约束下，按（层数，钱）字典序最小，或按用户给的时间预算最小化钱。

### B7. 料库标准「1MB 重建 < 1 s」「同数据同渲染」被格式锁住（§12 模块 1、§14）
PDF 扫描件、截图要 OCR，1 秒做不到；OCR 也不是逐位确定的。账本键必须建在**渲染后的文本**上，不能建在源字节上，否则同一张截图两次渲染得到两个键。标准改为：渲染结果进账本，同渲染文本同键；重建时限按格式分档报告，不给统一数字。

### B8. 「前提永远第一层」对交互任务不成立（§5 第 1 步）
computer use 的第一层是一次「做」（截屏），没有材料可以过滤前提。改为「前提是第一个**判**层」，其前可以有做。

### B9. Kind 降为标签后，v0 的四项静态检查失去依据（§15 模块 1）
悬空产出、无源之水靠 Kind 流图判定。降为 lint 可以，但要明说：语言不再保证「每个产出有人看」，这条保证转由骨架的聚合步承担（每个中间结果必须被某个聚合消费）。

## C. 建议

### C1. 旗舰例子换骨架，先量再写语法
「矛盾」按 A1 的二元骨架写：前提过滤（有观点）→ 配对 → 逐对 Jev（每对一个状态，同状态挂「相反」「同主题」「同一命题」三题）→ 聚合。试验台 A 约 40 段，若 15 段有观点，配对 105 个状态，6 并发约 18 s、约 $0.005。预注册：前提幸存率、对数、层数 3、往返 ≈ 105/并发。

### C2. 需实测的量（建议一次实验，预算 $1 内）
并发上限与 429 出现点；持续 RPS；延迟 p50/p95 对状态大小（300/500/1000/2000 token）；单请求题数上限；「这段有助于判断 Q 吗」元题与字面前提题在同一批标注段上的区分力对比（A3 的证据）；读数渲染成「P=0.83」再判与渲染成出口再判的差异（A5 的证据）。

### C3. 把内核写成一页形式定义
类型两个（材料、读数），桥一个（outlet_q），算子五个各带三值传播规则，骨架四个各带终止证明。这一页就是 v1 的规范，比第 8 节的函数更小也更真。

### C4. 保留 v0 的「改不停」「回到原样」保险
A6 说明非单调是 Jev 的性质不是 v0 的实现问题，这两道保险在新程序模型里仍然需要。

## 附录一：四任务伪码（按第 13 节函数如实写，不美化）

### T1 文档找矛盾（Q = 「a 与 b 矛盾吗」，二元）
```
判(Q, 料库):
    材料 = 取(料库)                                   # 全部段
    若 材料 ≤ 界限: return jev(Q, 材料)               # 40 段 ≈ 6000 token，不成立
    证据 = 过滤(材料, 段 => jev("这段有观点吗", 段))   # 一元前提；A3：不用元题
    对 = 配对(证据)                                   # 需要，第 8 节没有
    结果 = 逐对 jev({相反, 同主题, 同一命题}, 对)      # 每对一个状态
    return 聚合_存在(结果)                            # 需要，第 8 节没有
终止：配对后每个状态 ≤ 2 段，一层到底。
```

### T2 computer use 找一个设置项（Q = 「设置项 X 在当前屏幕上吗」）
```
判(Q, 料库):
    已访 = {}                                         # 记忆，T1 没有
    循环 直到 步数 > 上限:                             # 终止条件是步数，不是大小
        屏 = 做(截屏)                                 # 每层先做，B8
        若 jev(Q, 屏) == act: return 屏               # 找到即停
        语境 = 已访 的出口摘要                         # 语境来自历史，不是 Jev 判
        下一步 = jev_choice("该点哪个入口", 屏 + 语境)  # 定：choice → 动作，T1 没有
        若 下一步 ∈ 已访: 升级(unsure)                 # 防绕圈
        做(点击(下一步)); 已访 += 下一步
    return unsure
```

### T3 代码找一个 bug（Q = 「函数 f 会空指针吗」）
```
判(Q, 料库):
    候选 = 过滤(取(料库).函数, f => jev("f 解引用了可能为空的值吗", f))  # 一元前提
    对每个 f ∈ 候选:
        语境 = AST.调用者(f) ∪ AST.类型定义(f 用到的类型)   # 语境由确定性索引给，不是 Jev
        读数 = jev(Q, f + 语境)                            # 对象段单独占位，A7
        若 读数 == act: 证 = 做(写测试并运行(f))             # 「做」出现在取任务里
                       若 证.失败: return f
    return ignore
终止：候选有限，每个 f 一次验证。
```

### T4 Agent 订一次行程（Q = 「这个方案满足约束吗」，构造型）
```
判(Q, 料库):
    约束 = 取(料库).用户要求                            # 语境（相对 Q）
    候选 = 做(查航班与酒店(约束))                        # 生成候选，T1–T3 没有
    合格 = 过滤(候选, c => jev(Q, c + 约束))
    排序 = 聚合_topk(合格, c => jev_score("综合满意度", c + 约束 + 参照(合格)))  # 参照，A7
    选中 = 排序[0]
    若 jev("下单不可逆且金额大吗", 选中) != ignore: 升级(人)   # 不可逆闸门，其它任务没有
    return 做(下单(选中))
终止：候选有限；不可逆动作前必经人。
```
