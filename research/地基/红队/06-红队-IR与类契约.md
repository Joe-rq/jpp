## A. 致命（IR 定义必须改）

### A1. 构建器「先建图再执行」与宿主原生控制流不相容；文档同时承诺了两者（§6、§4.1、J-05、J-07）
**反例。** §6 说「`@jv.program` 内的调用不立即执行，先建图，检查器跑 J 规则，规划器跑 pass，再解释执行」。但 §6.1 六条程序全部用 Python 原生 `match e: case jv.Act(): …`、`if len(cands) == 1: break`、`if (对 := [...]): return` 对**效应结果**做分支。建图时 `e` 是尚未求值的图节点，Python 的 `match`/`if` 在建图那一刻就要一个真值，图里没有——这正是 JAX 必须提供 `lax.cond` 而禁止对 tracer 做 `if` 的原因。两条路只能选一条：
- **静态建图**：分支必须写成 `jv.match(e, {Act: …, Ignore: …, Unsure: …})` 这类组合子，宿主 `if/match` 只能作用于非效应值。代价：§0「宿主自带一切控制流」缩水，§6.1 的六条程序全部重写；J-05 的「match 穷尽性」要自己实现（Python `match` 本无穷尽检查）。
- **即时执行**：逐语句求值，效应结果立即可用，宿主控制流原样可用。代价：§4 的提升 pass「跨 if 分支也提」不可能（分支还没走到）；J-07 的整程序符号成本只能逐层估；§4.6「计划期拒绝超预算」变成运行期截断。
文档两头都要：§4.1 提升跨分支（要静态图）+ §6.1 原生 match（要即时执行）。
**怎么才能对。** 选**即时执行 + 层边界前瞻**（与 DECISIONS 早前「层边界重规划」一致，也与 AQE 的粒度一致）：解释器逐语句跑，每到一次 `judge` 不立即发，收集到「下一个依赖其出口的语句」为止（同一直线段内的全部 judge 自动同层融合）；提升只在直线段内做，跨分支不做；预算在每层开始时按已知规模核，超即停并记 `Unsure(budget)`；J-05 在 IR 层实现：每个 `Exit` 值带「已消费」标记，程序返回前有未消费的 unsure 即报。把这个选择写进 §6 第一段，并把「跨 if 分支提升」从 §4 删掉或标为「需静态建图，暂不做」。

### A2. 类契约把 jev-1.13 的性质当成了类性质，且没有「档案与契约冲突时」的规则（§1）
**反例。** C1「状态是文字或 JSON」——清单 G3 明说不只文本，未来模型可收图像；这是 D1 对当前 API 的描述。C2「三种输出结构、概率和恒为 1、从不产生集合」——D1/D2 是 jev-1.13 文档，一个能输出「都不是」或输出开放集的下一代模型会违反它。C6「模型不做算术、不做计数」——这是当前模型的缺陷，不是类定义；一旦模型会算，契约条款直接为假。C9「题近乎免费」是这家厂商这一版的计价与架构（P5 实测），却是融合 pass 与整个成本模型的根据。C10「一状态一判断对象」来自 E16 对这一版的证伪。
更严重的是缺规则：档案字段填了与契约相反的值（如 `arithmetic_capable: true`、`questions_free: false`）时，编译器做什么？§1 只说「引未测字段报错」。
**怎么才能对。** 把 §1 拆成两栏：**类不变量**（真的对「校准判断传感器」这一类成立的：状态 + 题 → 分布；跨题不成恒等式；结果记版本；线只从校准来；读数经桥离开）与**类假设**（C1、C2、C5、C6、C8、C9、C10、C12 各对应档案一个布尔或数值字段：`text_only`、`fixed_output_types`、`one_hop`、`arithmetic_capable`、`window_bounded`、`questions_free`、`multi_object_crosstalk`、`assertion_susceptible`）。每个 pass 与 J 规则声明它依赖哪些假设字段：融合依赖 `questions_free`，裂变依赖 `window_bounded`，J-01 的「不做算术」依赖 `arithmetic_capable=false`，J-14 依赖 `multi_object_crosstalk`。档案字段为反值时对应 pass 关闭、规则降 warn，程序不改——这才是 C11「换版本程序不改」的实现，而不是口号。加一节「版本变化必重测」：列出每条假设由档案哪一项测（SCHEMA 已有，契约里要引）。

### A3. `fit` 是绕过 J-01/J-04 的后门（§2.4、J-01、J-04）
**反例一（跨集合）。** `fit(m, judge(state(over=C1), q)[0], judge(state(over=C2), q)[0])`：两个 select 读数来自不同候选集，J-04 说不可比；`fit` 的签名是 `[Reading]`，没有指纹，检查器不会拦。训练时 C1、C2 碰巧对齐，运行时不对齐，Score 无意义。
**反例二（身份拟合）。** `FitRef{trained_from: 3 条, features: [q1, q2]}`，模型是「r1 + r2」：只要注册表接受 n=3 的训练，程序员就用 fit 写出了被 J-01 禁止的跨题相加。「只能训练产生」在类型上不可判——注册表是数据，不是类型。
**反例三（双重使用）。** `fit` 的 `error_rate` 与后续 `cut` 的 `CalibRef.conformal_quantiles` 在同一标注集上算出来（文档没禁止），保形覆盖保证失效（数据泄漏）。
**怎么才能对。** (a) `fit` 的输入类型带指纹：`features: [(calib_key, slot_fingerprint_kind)]`，运行时读数的指纹必须与训练时同类，否则 J-04 报错；(b) `FitRef` 加最小 n（按特征数，例如 ≥ 20 × 特征数）与「训练集 id ≠ 保形集 id」的注册约束，注册表拒绝不满足的记录，检查器只认注册表签名；(c) 明文：`fit` 的输出是分数不是概率，必须 `cut(…, CalibRef)` 才能出口，且该 CalibRef 的集合不得与 `trained_from` 相交（注册时校验）。

### A4. 跨程序缓存键会把不同判断当同一判断（§2.2）
**反例一（槽绑定）。** 缓存键用 `materials_hash(state)`。若它是材料集合的哈希（文档没说是槽结构哈希），则 `state(on=A, ctx=[B])` 与 `state(on=B, ctx=[A])` 材料相同、`slot_kinds` 相同（都是 on+ctx）、题面相同 → 同键。但对象绑定不同，读数不同（P4/A7 正是为此）。
**反例二（置换）。** 缓存键不含 `perm_seed`。choice 读数随置换而变（P9，首位 2–3×）；命中缓存会把另一置换下的读数当本次读数，众数统计被污染。
**反例三（渲染版本）。** 校准键含 `render_version`，缓存键不含。渲染器升级后旧读数继续命中。
**反例四（模型子版本）。** `model_version` 是别名时（官方 models.md 别名会动，审核 §3.2-8）同键不同模型。
**怎么才能对。** 缓存键 = `(canon_json(state) 含槽结构, q_text_hash, phys, render_version, model_id 解析后的不可变 id)`；choice 的缓存值是「按 perm_seed 索引的读数集合」，命中时只复用同 seed 的，众数在集合上算；账本键与缓存键的差别只剩 `run_seq` 与程序点，文档要写成一张对照表。

### A5. 宿主纯性在 Python 里不可判，J-11 与重放承诺（C7、§4.7）建在它上面（§2.8、J-11）
**反例。** `for m in mats: jv.judge(jv.state(on=m, ctx=[pick_ctx(m)]), q)`，其中 `pick_ctx` 是普通 Python 函数，内部 `random.choice` 或读 `time.time()` 或读环境变量。§2.8 说「纯性由 IR 判：不含六种效应即纯」——IR 看不见 Python 函数体，只看见一个不透明调用。结果：状态随运行变，账本键变，重放不命中，「逐字节重放」失效；调度 pass 以为可并发融合，实际每次状态不同。
**怎么才能对。** 三选一并写死：(a) 宿主函数须用 `@jv.pure` 声明，运行时抽查（两次调用比对哈希）降 warn，违规记账并禁用该函数的融合；(b) 所有进状态的材料必须来自 IR 形式或字面量，宿主函数只能变换 Mat（`jv.transform(f, mats)` 记入账本，重放取账本）；(c) 沙箱执行宿主代码，禁 random/time/env。建议 (b)：与「材料不可变、来源链」一致，成本最低。

### A6. taint 的产生规则缺失，J-08 无法执行（§2.1、§2.5、§2.6、J-08、J-14）
**反例一。** `gen(prompt, ctx=[untrusted 网页])` 产出的候选是什么 taint？未定义。注入句可以从网页经生成器进入候选，再经 select 进入 `do`——J-08 只看「出口所在状态的 taint」，候选若被标 trusted 就放行。
**反例二。** `do(run, code)` 的输出 taint？执行不可信代码的输出应是 untrusted，文档没说；J-08 的「trusted 证据」若来自这种 `do`，就是用不可信的东西为不可信的东西作证。
**反例三。** 两个不可信来源（网页 A、网页 B）都判「安全」，`Act ∧ Act`——「不得单独放行」在这里怎么判？两个不可信合取不等于可信，但规则只写了「须与 trusted 证据合取」，没写「多个 untrusted 合取仍 untrusted」。
**怎么才能对。** taint 是效应的输出属性：`gen` 输出 taint = ∨(ctx.taint)；`do` 输出 taint 由动作声明（沙箱执行给 `untrusted-derived`，仓库/测试框架输出给 trusted，读网页给 untrusted）；`ask` 输出 trusted；`cut` 输出继承状态 taint。J-08 改为：放行 `do` 的守卫表达式中至少一个合取项来自 taint=trusted 的状态，且 untrusted 项的数量不改变这一要求。J-14「ctx 只收 trusted」过严（大多数任务的语境本来就来自网页/日志），改为「ctx 收 untrusted 时状态 taint=untrusted，进 J-08 路径」。

### A7. 默认路径与最新实测不一致：`enough`、select 先验（§5、§8）
**事实。** §5 handler 库写「`refine` 的判据用字面前提题，不用元题（`enough` 待 E-ENOUGH）」，§8 #1「E-ENOUGH 待跑」。E-ENOUGH 已跑：`enough` AUC 0.81 / 0.81（不是 P7 那类），但**可排序不可过线**（代码域读数全 > 0.5，默认线判 100% 够）。§5 的 select 策略只写到 E9d 的「先验绑测试证据」，E9e 的三条（期望值交给执行 + 判、按输出聚类降 K、先验绑通过数）与「投票基线在漏放高时退化」未进。
**怎么才能对。** §5 handler：`insufficient` 的判据 = 推导器生成的字面前提题过线；`enough` 只作排序（谁最缺先细拆谁），作门须域标注扫线。§5 select 策略加：候选先按执行输出聚类（同输出一簇）再选簇，K 降为簇数；先验绑通过数而非读数差；投票基线的适用条件（漏放 ≤ 0.3）。§8 #1 改「已测，落地为排序信号」。

## B. 定义与标准必须改

### B1. 形式数目自相矛盾：标题「六形式」，正文七个（§2）
`state/judge/cut/gen/do/ask` 六个 + `fit`（§2.4「第二个读数消费者」）。要么 `fit` 是库（一个注册表驱动的纯函数，输出仍要 `cut`），要么形式是七个。建议：`fit` 是**桥库**，不是形式；IR 形式六个，桥两座（`cut` 内核、`fit` 注册表库）。

### B2. `ask` 的 `Pending` 挂起没有 IR 表示（§2.7）
挂起时宿主局部变量（Python 栈）不在账本里。恢复 = 从头重跑并按账本重放——这要求 A5 成立且 `do` 全部命中账本；文档没写「恢复即重放」这条语义，也没写 `Pending` 在 `match` 里是不是一个必须处理的 case（J-05 只提 Unsure）。写明：`Pending` 是程序级出口，程序整体挂起；恢复 = 重放执行；`ask` 的结果到达后作为账本条目参与重放。

### B3. 提升 pass 的目标函数会为了少一层而多花钱（§4.1、§4.6）
「（层数，钱）字典序最小」+「跨分支提升」= 只要能少一层，任意多的推测调用都合法。若 A1 采纳即时执行则此条自然消失；若保留静态建图，目标要改为「层数 × τ + 钱 / 预算权重」或「推测调用数 ≤ 预算余量」。

### B4. unsure 乘性公式既非上界也非下界（J-10）
`1−(1−u)^k` 假设独立。同一材料上的题 unsure 正相关（材料难则全难）时真实率低于公式；题互补时高于公式。作为「超预算即报」的门，方向不定。改为：有标注集时用经验联合 unsure 率；没有时用联合界 `Σuᵢ` 作保守上界，并标「独立假设估计」为参考值。

### B5. 裂变对文字表示的回退与下沉对「未测」档位的行为（§4.3、§4.4、J-15）
- 裂变按 `profile.window.<repr>`：文字材料若 JSON 化后仍是一整段带主张文字，窗口应取文字槽的 500 而非 JSON 的 1,800（E-JSON-hi 测的是**语境槽**里的干扰，不是对象槽里的长文）。写明：对象槽内单段材料的窗口按 `text_slots`，槽间干扰按 `json_slots`。
- J-15「引未测字段即错」会让 120–250 token 候选的 select 在编译期直接失败（档案该格未测）。改为：未测格取保守物理形式（K-noul）并报 W-untested，不阻塞。

### B6. C3 的措辞比 J-04 用到的弱（§1）
C3「同题同状态可比」是恒真；排序需要的是「同题**跨状态**（同锚、单独渲染）可比」，这是 E10 的实测条件，也是 J-04 的依据。改 C3。

### B7. 没有持久料库，跨程序的 Mat 在哪（§2、§5）
v1 有料库，12 号只剩读数缓存。跨会话记忆（谈判 agent、长期监控）、延迟真值回填（§7「期限过了没」要回来找当初那份材料）都需要持久的 Mat 存储与来源链。`core/log.py`、`table.py` 沿用了，但 IR 没有对应形式或库声明。加 §5 一行「料库：只增 Mat 存储 + 来源链 + 地址；`do(file/http)` 与 `gen` 的输出默认入库」。

### B8. 账本头缺预算与档案版本，重放可分叉（§2、§4.7）
handler 路径依赖 `budget`（`budget` 耗尽走 `Unsure(budget)`）与档案（下沉、窗口）。两次运行 budget 不同 → 路径不同 → 「逐字节重放」为假。账本头记 `budget`、`profile_hash`、`retry_seq` 策略。

### B9. 三个自造任务的写法（构建器）
- **会议纪要找无负责人的承诺**：`test` 逐段 + `subset`（谁是负责人）——可写；但「subset」在 §2 不是 op（只有 test/select/measure），§5 说它是题式。写成 K 道 test，可以，但 `Reading` 元组的向量化出口 `Map[候选, Exit]` 没有 IR 类型。补 `judge` 对 `over` 槽的向量化返回类型。
- **视频会议字幕对齐讲者**：`do(asr)` → 段 → `select`（哪位讲者）——可写。
- **多轮谈判 agent（跨天）**：需要跨程序记忆与 `ask` 挂起恢复——B2 与 B7 两处缺口同时命中，当前写不出「恢复后继续上一轮」。
结论：写不出的是「跨程序持久状态」一类，不是判断类。

### B10. 文档缺「清单 A0–G5 对照」与「宪法四条对照」一节
前几版规范都有 §10 对照表，12 号没有。按宪法「时刻检查」，每版必须带。补上，并对 A0（通用）、G3（不为一个版本）、G4（发挥长处）三条重点写：G4 在 12 号里只有 `fit` 与代价比线两处，「判断向量作为一等数据」（DECISIONS 已定）没有进 IR 类型（`Reading` 元组没有向量操作）。

## C. 建议

### C1. LLM 生成构建器代码最可能写错的模式（自举风险）
```python
e = jv.judge(s, q)                       # 忘了 [0]，拿到元组
if e == jv.Act: ...                      # 类型比较而非 isinstance/match
r1 > r2                                  # 比较读数（J-01 会拦，但错误信息要指向「用 cut」）
for c in cands: jv.do(run, c)            # 期望并发，实际依赖前次结果时被串行化且不知道
jv.gen(p, ctx, n=4, retry_seq=0)         # 循环里常量 retry_seq（J-13 拦）
jv.cut(r, calib="perf.慢了")             # 传字符串而非 CalibRef（J-03 拦，但报文要说「用 jv.calib()」）
```
诊断报文要按这六种模式各给一条修法，自举时的检查器输出直接回喂生成器。

### C2. `Reading` 元组加最小向量操作
只允许两种：同题跨运行的均值/众数（§5.1 合法项一），同题同锚跨对象的偏序（合法项二）。以方法形式挂在 `Readings` 类型上，其余运算不存在。这是「判断向量一等」的最小落法。

### C3. 边界声明
加一句：Jv 不是概率编程语言，无联合分布可推断，读数不是后验（研究 04 §7-6）。

### C4. 宪法登记表核对
`研究/04` §7 的六行提议是否已进 `00-宪法.md`（保形、IFC、Haxl、决策论、DSPy、PPL）——父会话已加保形/CodeT/JAX/效应系统四行，IFC 与 DSPy 两行未见，补。

| G4 发挥长处 | fit、代价比线、乘性预算 | 判断向量未进类型（B10） |
| F 锚点 | 可运行 0 | 不变 |
| 宪法 2 借用 | 登记表 | IFC、DSPy 未登记（C4） |

结论：六形式的方向对（H 独立推到同处），但 12 号在三处把「愿望」写成了「定义」：建图与原生控制流（A1）、宿主纯性（A5）、契约的版本无关（A2）。这三处不定，J 规则与重放承诺都悬空。其余 A 类是键与规则的漏洞，改了就好。
