# 十个主体，一次模糊意图：J++ 的第一个应用案例

一个人说：“最近创业很累……我也不知道我需要什么，只想有一会儿不用自己撑着。”程序把这段话分别交给八个接收方，与各自的上下文结合判断。它提名了一位心理咨询师，并通过一位奶奶的转介，找到没有参加初始广播的司机。

接着，“发出意图的人 + 奶奶 + 司机”组成一份新的候选材料，再与其他人的上下文结合。真实 JEV 运行提名了一位社群组织者和两位愿意体验的创业者。司机从“时间未确认”变为“周六可以提供体验”后，这三个后续候选变为可以进一步讨论小规模尝试。投资人的相关性仍未确定，保留在未决候选中。

这展示了[通爻构想](first-problem-towow.zh-CN.md)的一个小切片：**意图遇见本地上下文，产生候选；候选本身成为下一段计算的材料。**

## 直接运行

在仓库中安装后：

```sh
python -m pip install -e '.[dev]'
jpp towow
```

默认用仓库附带的真实 JEV 响应录制，重新执行相同的 J++ 程序。无需密钥，无网络请求，也不产生费用。它不是重新做模型推理，也不是按人物名字返回预设匹配；录制客户端只对完全相同的请求返回已保存的模型回答。

打开生成的 `run-data/towow/index.html`，会播放约 50 秒的七步动画：意图 → 遇见上下文 → 转介 → 形成组合 → 继续发现 → 条件变化 → 组合方法。每一步只突出当前变化，配简短文字说明；支持暂停、调速、上一步、下一步和跳步。点击人物可查看本地上下文与真实判断，未确定的投资人候选仍保留。系统开启“减少动态效果”时默认不自动播放。运行数据在同目录的 `report.json`。

The self-contained viewer now tells the recorded story in seven animated steps, with playback, pause, speed control, step navigation, and clickable evidence. Reduced-motion preferences are respected. Animation timing is for explanation; measured model timings remain separately labeled. No additional model calls occur in the viewer.

也可以下载仓库中的[完整交互页面](demos/towow/index.html)到本地打开。页面内嵌了本次真实运行的记录，显示的是录制时的耗时；浏览页面本身不会调用模型。

要重新做真实推理，先按现有 JEV 后端的方式配置 `~/.typesafe-key`：

```sh
jpp towow --live --out run-data/my-towow
```

此命令会向 TypeSafe/JEV 发送案例资料并产生费用。程序设置共享的 0.10 美元估算调用预算；成本采用当前适配器配置的单价，账单以服务商为准。不要把密钥放进案例 JSON 或 Git。要修改十个人的上下文，复制 [towow-people.json](../src/jpp/data/towow-people.json)，然后运行：

```sh
jpp towow --live --scenario my-people.json --out run-data/my-towow
```

修改过的请求不能借用旧录制冒充新判断。新增人物 ID 或大幅改变人数时，CLI 计算可以扩展，当前十人图的布局需要相应修改。

## 这段程序怎样使用现有 J++

[源码](../src/jpp/towow.py)将三个方法组合成一个方法：

```python
METHOD = (
    discover
    .then(expand_relays)
    .then(extend_combinations, name="towow_discovery")
)
```

每个方法都是现有 `jev_compose.component`。它们构造 `Request` 和问题值，通过 `batch_observe` 把独立判断交给 `foundation.jv`。同一接收方的多个问题合并请求，不同接收方的请求由已有运行时并发执行。案例没有修改内核。

每个请求只包含当前信号或候选，以及一个接收方的上下文；不会把十个人的全部资料塞进每个问题。奶奶是否有值得读取的联系人由模型判断；联系人的地址从案例数据读取，再进入相同的判断方法。程序没有 `if person == "grandma"` 之类的匹配分支。

候选材料由实际提名产生，保留成员、服务材料和可用性。后续判断分别问“内容是否相关”和“接收方是否愿意尝试或讨论”。已经得到的可用性与这些结果，由普通代码做三值逻辑组合。候选未就绪时，也能先被其他主体发现。

未知没有变成否定。相关性未确定的对象保留在输出中；页面用灰色关系线区分，后续条件也不会因此自动成立。所有模型提名仍标记 `provisional`：本案例使用现有运行时的冷校准处理方式，没有为这些新问题伪造校准集。

## 一次真实运行的结果

2026-09-20，`jev-1.13.0`，十个虚构主体，在开发者本机运行。完整记录见 [live-report.json](demos/towow/live-report.json)，原始请求与响应见 [towow-recording.json](../src/jpp/data/towow-recording.json)。

| 执行 | 实测时间 | 新增模型请求 | 复用的判断 |
|---|---:|---:|---:|
| 首次完成三个阶段 | 5.215 秒 | 16 | 0 |
| 相同输入再次运行 | 0.063 秒 | 0 | 32 |
| 只更新司机的资料 | 2.047 秒 | 8 | 16 |

一次请求可以包含多个问题。首次运行涉及 32 个语义判断：首轮 16 个，转介目标 2 个，构型对其他七个主体 14 个。司机更新后，首轮 16 个判断仍被复用；司机与其下游构型重新计算。程序本身会重新走过组件，缓存复用由现有运行时完成，不代表已经实现自动增量依赖引擎。

另取**完全相同的首轮八个请求体**，先真实顺序调用，再真实并发调用：

| 执行方式 | 实测时间 |
|---|---:|
| 顺序，1 个工作线程 | 7.847 秒 |
| 并发，8 个工作线程 | 1.042 秒 |

本次观察到约 **7.53 倍**的墙钟时间差。这个对照单独测量首层请求调度，不是整段程序的加速比，也不是相对于另一种语言的优势。测试顺序固定，网络与服务端缓存未控制；16 个读数中 5 个完全相同，最大读数差为 0.05，不能宣称模型回答逐位一致。运行对照的命令是：

```sh
jpp towow --live --benchmark --out run-data/my-benchmark
```

已发布这次运行及其对照的估算费用合计 **0.00113223 美元**。包含此前第一版尝试，本轮开发累计估算 **0.00229744 美元**，低于获准的 0.10 美元预算。

第一次尝试把内容关联、互补价值与可执行条件描述得过宽，冷校准策略下没有提名后续对象。我们随后拆分问题、用普通代码组合条件，并保留未知；没有降低判断阈值来追求想要的输出。[开发记录](demos/towow/development-note.json)保留这次修改的起因。因此当前案例是经过开发调试的展示样例，不是盲测准确率报告。

## 这个切片推进了什么

已经能运行的是：接收方本地判断、转介展开、三方候选继续参与发现、独立请求并发、同输入记录复用，以及保留局部未知。源码中的几个方法可以像其他 J++ 组件一样继续组合。

这里仍使用三个有限阶段、一台机器和短小的虚构上下文；首层广播到八个已知接收方，尚未解决大网络如何选路。它没有生成商业计划、执行合作或进行心理诊断，也没有把分散存储当作加密。

更大的构想仍然保留：让进行中的计算持续暴露结果，让多个方法订阅、复用这些结果，进而更新可发现表示与传播路径。这个 demo 让候选在条件尚未齐备时先进入后续计算；任意持续流、自动依赖更新和分布式网络，需要继续扩展语言和运行系统。

测试包括转介撤除、联系地址撤除、未知保留、局部更新与缓存复用，以及离线录制不访问网络。结构测试中的确定性回答只验证这些机制，不作为模型能力证据；真实模型的证据是另外保存的请求、响应与运行记录。
