# 下一组案例：从人物上下文找回已知关系

状态：2026-09-20 已定位原实验与数据，尚未进行新的真实人物 JEV 调用。216 人合成案例已经完成实测；本文件约定下一组真实来源案例的比较方式。

## 找到了用户记得的实验

通爻 `experiments/real_data/analysis/step2_multisource_v2/EXPERIMENT_REPORT.md` 记录：原始实验为 98.65%，恢复数据后的 2026-04-03 实验为 893 / 972 = 91.87%。恢复版本包含 325 份公开来源资料：178 位学术作者、101 位 GitHub 用户、46 位创业人物。

972 条标签分为：599 条共同论文关系、316 条同 GitHub 组织关系、33 条同创业团队关系，以及 24 条人工挑选的跨来源种子关系。最后一类单独报告，不算已证实发生的合作。同组织也不必然意味着两个人实际协作过。

旧 91.87% 是“任一方向进入提名集合即命中”，每人最多重排 160 人，报告总提名 26,164 条，平均约 80.5 人。它不是前十召回率，不能直接和 216 人案例的 Recall@10 比大小。当前保留了逐关系命中 JSON，但缺少完整提名排序和原 D1-D5 输出，因而旧值作为历史记录，不能伪造它在相同 K 下的结果。配套 Markdown 表还有零命中与 JSON 不一致的情况，需保留此说明。

本地准备时另外发现：现存规范化资料中缺少一个原关系端点，对应 9 条边；当前可匹配的关系为 963 条。原 972 分母保留为历史口径，新评估必须明确排除原因，不能悄悄改变分母。

## 本次要实际比较什么

保持 325 个主体及资料版本固定，已知关系仅进入评估器。比较本地词面检索、本地向量检索、J++ 语义判断，以及这些组件的组合。先冻结输入和方法再运行，保留全部结果。

所有方法均报告 Recall@1/5/10/20、提名总数、每个主体的候选数及分来源结果。两端任一进入对方前 K 的无向关系召回，与每个主体各自的有向召回分别报告，不混用分母。无已知边不能当作真实负例，暂不计算完整 precision；新关系的质量需要后续匿名独立评阅。

时间分成资料准备、索引构建、第一次发现、新意图/新资料更新和相同输入复用；费用区分一次性资料处理和每次发现。旧系统的索引后匹配本来就不调用大模型，因此不能预设新方法更便宜。

## 怎样更接近陌生发现

原资料中存在共同论文标题、共同摘要、公司名等可直接提示关系的内容。先做“关系恢复”基线，随后单独做隐藏直接线索的干预。删除标题或名字后若仍保留共同论文摘要，不能宣称已经没有泄漏。

严格的陌生发现测试需要用目标合作发生前、或者与目标合作无关的资料构造上下文，再把后来真实发生的合作作为保留标签。现存学术资料有部分主要由目标论文生成，不能靠改名就得到这种测试；需要另取独立的先前资料。这个版本的成功标准是：在固定候选数量下找回更多关联，或保留相同找回比例时显著减少候选与判断成本。
