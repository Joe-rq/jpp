这一次要验证的，是“发现还能继续参与发现”
只做一轮判断时，程序可以找到心理咨询师。沿奶奶的联系人继续计算，原本没有收到消息的司机才会出现。把林、奶奶和司机组合成新材料以后，社群组织者和另外两位创业者才有机会针对这项具体可能表达关联与参与意愿。你可以关闭相应组件，检查这些结果是否真的消失。


撤掉联系地址是另一个关键检验：模型即使认为奶奶知道人，也不能凭空补出一条可执行路径。司机可用性则影响另一件事——能否进一步讨论尝试。它不应把投资人的未知变成肯定，也不应让最初未改变的判断全部重新调用。这些区别都能在运行结果和导出的记录里检查。


J++ 带来的可复用部分
首轮发现、转介展开、组合再发现都是同一种组件，它们通过 .then(...) 接在一起，组合以后仍然是一种方法。这个实验台调用同一份源码，开关实际改变组合及输入，而不是由页面写死人物结果。现阶段可以验证的是这套组件怎样改变发现结果、怎样复用判断；它仍是一个经过开发的十人案例，不是未知真实人群上的准确率证明，也不是与所有匹配算法的胜负比较。


浏览器的 Python 程序读取的是完整匹配的已录制回答，所以这里支持的是明确列出的条件变化。它不会把任意新语料伪装成已经推理过。当前浏览器执行使用顺序调度，显示的毫秒数只计算本地重放；真实 JEV 的并发时间对照在图谱讲解页保留。
