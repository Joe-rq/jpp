一个想法，能否长出
新的合作关系？

同一套 J++ 发现程序，接收不同的意图、判断问题和组合规则。它从 216 个合成主体的上下文中提出候选，让组合继续接受判断，也允许上一次的组合成为下一次发现的输入。

这是实际 JEV 计算的公开回放，页面操作不调用模型。人物来自旧实验的合成资料；示例中的贡献方向由应用配置提供。这里交付的是可替换规则、可续接的发现应用接口；输出是待确认的提议。

读取意图…

先输入局部上下文，判断可能提供什么贡献；再输入成员组成的候选方案，判断贡献能不能接起来。已有组合可以成为新的输入，原始成员资料与之前未决的判断继续保留。

正在读取实际运行记录…

同一个意图，怎样找到不同贡献

圆点是合成主体。不同贡献的候选分别亮起，随后连成接受复核的组合。动画只回放已记录的计算，不表示模型正在运行。

合作提议

为什么这比一张推荐名单多了一步

两个人分别拥有能力，并不自动意味着他们愿意或能够合作。这个程序将成员资料、贡献和原始想法一起交给下一次判断，保留不能确定的部分，并给出开始讨论前还需要确认的问题。关掉组合步骤时，程序只返回单人候选；打开以后，才会产生这些可继续处理的提议。

通爻研究里的目标更进一步：接收方依自己的上下文提出关系，发送方不必预先知道该找谁；候选组合还能继续改变发现。当前这一版先实现可替换的提名与组合接口、组合续接和观察复用。示例配置由开发者编写；自动形成局部算子、网络传播与大规模动态路由仍是后续工作。

自己运行与改写

命令行程序可以用录制回答复现，也可以在自己的调用预算内改写输入并运行。每个提议都保留成员、分工、输入资料、暂定判断与待确认条件，方便其他程序接着使用。应用复用 J++ 已有的组合运行时，正式独立语言仍沿 Rust 路线建设。
