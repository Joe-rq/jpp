Harness 的世界A world compiled from the Harness ledger

这是把一个真实运行了三个月的 Agent 系统——Harness，约 89 万条事件——的账本，用 J++ 编译成可看的三维世界的第一批骨架。J++ 在里面做的事：生成器为每类对象提候选，JEV 逐个对象挑身体；为每个任务挑结构、材料、颜色、顶；为每一步挑工序。数量（规模、层数、开窗）由代码照实算，物理先决条件由世界强制。五页都是真机运行：判断次数与费用在页面右下角。

This compiles the ledger of a real Agent system that ran for three months — Harness, about 890,000 events — into a viewable three-dimensional world with J++. What J++ does inside it: a generator proposes candidates for each object class, and JEV picks a body for each object, then picks structure, material, color and roof for each task, then picks a procedure for each step. Quantities (scale, floor count, window openings) are computed by code as recorded; physical preconditions are enforced by the world itself. All five pages are live runs: judgment counts and cost sit in the bottom-right corner of each page.

判断分工的两次实证Two tests of what should be judged versus decided by code

把只有闸门检查项的 CommitAccepted 交给 JEV 判「修根因还是绕过」，1,460 条里 1,379 条给出同一个答案。这批材料本身只有闸门检查字段，没有给判断留下可区分的证据。

Handing CommitAccepted events that only carry gate-check fields to JEV, asking it to judge "fixed the root cause or worked around it": 1,379 of 1,460 came back with the same answer. The material handed to JEV carried only gate-check fields — no evidence that could tell the two answers apart.

把颜色、顶当抽象选项直接问 JEV，48 座里 41 座选了青灰。修法：代码能定的用代码判；需要 JEV 判的，让生成器先为每个候选写一句「什么样的任务适合它」，判断器才有证据可依据，而不是在裸选项里凭空选。

Asking JEV to pick color and roof as bare abstract options, 41 of 48 buildings came back the same blue-gray. The fix: let code decide whatever code can decide; where JEV must judge, have the generator first write one sentence per candidate on what kind of task it fits, so the judge has evidence to work from instead of choosing among bare labels.
