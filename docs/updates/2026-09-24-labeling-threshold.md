# Cutting the labeling threshold from 160 examples to about 60, without loosening the safety bound / 把标注门槛从 160 条降到约 60 条，安全边界不放松

2026-09-24. Research-workspace design, offline analysis against existing data, and a ruling; the certification-method change is decided but not yet built.

## English

The [previous update](2026-09-24-live-trial-lines.md) describes a looser "trial" certification tier that lets a new question become usable after roughly 60-100 labeled examples instead of a full formal certification. This update is about why the formal number was 160 in the first place, and how much of that number turned out to be avoidable rather than necessary.

**Taking the number apart.** The 160-example requirement is not one thing; it's four multiplied together. A one-sided statistical bound needs about 22 zero-error examples to certify a 10% error tolerance with 90% confidence -- that part is a direct consequence of the safety target and isn't up for negotiation. Certifying both directions of a threshold (the false-accept side and the false-reject side) doubles it to 44. Protecting against a specific form of multiple comparisons -- checking many candidate threshold positions against the same labeled sample and reporting whichever one happens to look best -- was handled by splitting the labeled pool into two halves, one to pick a candidate threshold and one to verify it, which doubles the requirement again to a structural floor of 88. The actual number, 160, came from a further practical accident: the code split that pool in half using a fixed pseudo-random seed, and for the specific mix of examples tested, that particular seed happened to produce a lopsided split -- one of the four resulting groups was smaller than the statistical minimum, so the whole pool had to be inflated until every group cleared the bar. Roughly half of the gap between 88 and 160 was this seed accident, not a real requirement.

**What replaced the doubling.** Splitting the pool into a "pick" half and a "check" half is one valid way to guard against selecting a good-looking threshold from the same sample used to certify it, but it isn't the only one in the statistics literature this project draws on. An alternative -- used in this project's family of methods for producing statistically valid risk guarantees around model predictions -- checks a fixed, pre-declared sequence of candidate thresholds one at a time, from strictest to most permissive, and stops at the first one that fails, without ever splitting the sample. Because the sequence of candidates is fixed before any labels are looked at, this controls the same error-budget-across-many-checks risk that the split was protecting against, without paying the 2x split cost. Tested offline against every labeled dataset already collected in this project (zero additional API cost, since it only reuses existing labels), this cut the formal-certification requirement from 160 to about 60 examples for straightforward questions, and produced a usable (if narrower) line for one semantically ambiguous question type that the split-sample method could never certify at any sample size. The looser trial tier dropped from 60-100 examples to about 32. A companion "sequential" variant lets labeling happen in batches, with certification stopping as soon as enough evidence has accumulated rather than committing to a fixed count in advance.

**Where the pre-registered predictions did not hold.** All of the above was checked against predictions written down and submitted before the analysis ran, so a clean-looking result could not be assembled after the fact. One prediction did not hold: for the semantically ambiguous question type that the old split-sample method could never certify at any sample size, the offline test had predicted the fixed-sequence method would fail to produce a usable line there too; instead it produced a narrow line covering about 78% of the labeled range. A separate check on the new method's statistical validity appeared to fail at one specific combination of sample size and threshold; tracing it found the failure was an artifact of how that particular check is scored at small sample counts, not a validity problem -- recomputed as a joint probability, the actual rate was 2.3%, within the target bound. Separately, when the certification-method ruling itself was written up, a prediction that skipping the correction for checking many candidate thresholds against the same batch of labels would push the false-certification rate above the target bound did not hold either: the measured rate without that correction was 4.5%, still under the 10% bound (the corrected version measured 1.8%-2.4%) -- about twice as high, not over the line.

A synthetic test aimed at the sequential batch-labeling variant found a real problem before the method was ruled on: judging a candidate threshold from only part of its eventually-labeled examples could certify a candidate whose true overall error rate was 25% every time, if the labels available for that early judgment were not a representative random sample of the full set. One research run's stratified-labeling variant had avoided this only because of an incidental tie-breaking rule, not by design. This is now written into the method as an explicit requirement: a candidate threshold can only be judged sequentially once its available labeled examples have arrived in an unbiased random order; when labeling starts from both ends of a distribution at once, a candidate outside the first labeled batch has to wait for that batch to finish before it can be judged.

A third, unrelated finding surfaced a real specification gap, not a live vulnerability in deployed code: the written rule for letting a certified line extend to a new but similar-looking style of input required only 10 reviewed examples -- a weaker bar than even the new trial tier. The fix -- extending a line's scope now requires the same tiered evidence as certifying it in the first place -- is a ruled decision; it has not been implemented.

**Status.** The certification-method change (fixed-sequence by default, sequential as an option, plus the scope-extension fix) is a ruled decision, written into the design record; none of it has yet been implemented in the calibration code, so live-backend runs today still use the older split-sample method and its higher example counts. The next live test is expected to reuse the 80 labeled examples already collected for the live trial-line test and check whether they now clear the formal bar under the new method.

## 中文

[上一篇更新](2026-09-24-live-trial-lines.md)介绍了一档更松的「试用」认证——约 60–100 条标注就能让一道新题可用，不必等到完整的正式认证。这一篇讲清楚正式认证的门槛为什么原来是 160 条，以及这个数字里有多少其实是可以避免的、不是必须的。

**把这个数字拆开。** 160 条这个要求不是一件事，是四件事相乘。一条单侧统计边界，要认证到 10% 错误容忍、90% 置信度，需要约 22 条零错样本——这一部分是安全目标的直接推论，没有商量余地。同时认证阈值的两个方向（假放行一侧、假拒绝一侧）把它翻倍到 44。防范一种特定形式的多重比较——在同一批标注样本上检验很多个候选阈值位置，挑一个看起来最好的报出来——现行做法是把标注样本池切成两半，一半用来挑候选阈值，另一半用来验证它，这又把要求翻倍到 88 条的结构下限。实际用到的 160 这个数字，来自进一步的实践意外：代码用一个固定的伪随机种子把样本池切成两半，而针对实测用的那批具体样本，这个种子恰好切出了一个不均匀的分组——四个组里有一组小于统计最小值，于是整个池子要不断加大，直到每一组都过线。88 到 160 之间的差距，大约一半就是这个种子的偶然，不是真正的要求。

**用什么取代了这次翻倍。** 把样本池切成「挑选半」和「验证半」是防止「用同一批样本挑出一条好看阈值」的一种有效办法，但不是这个项目所依据的统计文献里唯一的办法。一种替代方案——属于本项目引用的、给模型预测产出统计有效风险保证的那一族方法——按一个预先固定的候选阈值序列，从最严到最松逐个检验，第一次不通过就停，全程不切分样本。因为候选序列在看任何标签之前就已固定，这样能控制住同样的「多次检验累积误差」风险——正是切分要防的那个风险——却不用付切分带来的两倍代价。用项目里已经收集的全部标注数据做离线核对（零额外费用，因为只是复用已有标签），这把普通问题的正式认证门槛从 160 条降到约 60 条，还给一类语义模糊的题型产出了一条可用（虽然较窄）的线——用切分样本的方法，这类题型不管标多少条都认证不出来。更松的试用档门槛从 60–100 条降到约 32 条。一个配套的「序贯」变体让标注可以分批进行，一有足够证据就停，不必事先定死条数。

**预注册预测哪些没有成立。** 以上全部结论都是在分析运行之前先写下并提交预注册预测、再跑分析检验的，就是为了不让一个好看的结果是事后拼凑出来的。有一条预测没有成立：对那类旧的切分样本方法不管标多少条都认证不出来的语义模糊题型，离线测试原先预测固定序方法在这类题上同样得不到可用线；实际结果是得到了一条窄线，覆盖标注范围的约 78%。另一处，新方法的统计有效性核对在某个具体的样本量与阈值组合上一度显得没通过；追查后发现这是那项核对本身在小样本下的度量方式造成的假象，不是有效性真的出了问题——按联合概率重算，实际失守率是 2.3%，在目标边界之内。此外，在认证方法的裁定文本写成时，另一条预测——「同一批标注上检验多个候选阈值若不加多重比较校正，假认证率会超过目标边界」——也没有成立：实测不加校正时假认证率是 4.5%，仍低于 10% 的边界（加了校正的版本是 1.8%–2.4%），大约高出一倍，没有越过边界。

针对序贯分批标注这个变体的一次合成测试，在这项方法被正式裁定之前，抓到了一个真实问题：如果用来做提前判定的标注不是最终全部标注里有代表性的随机子集，只凭一道候选阈值最终会标到的样本里的一部分做判定，可能把一条真实总体错误率高达 25% 的候选阈值每一次都判定通过。研究运行里的一次分层标注变体之所以躲过了这个问题，只是因为并列判定时一条偶然的平局规则，不是方法设计本身避免的。这一点现在被写进方法本身，作为一条明确要求：候选阈值只有在它现有的已标注样本按无偏随机顺序到达时，才能做序贯判定；如果标注从分布两端同时开始，不在首批标注范围内的候选阈值，要等首批标完才能被判定。

第三项发现与标注条数无关，揭出的是一个真实的规格缺口，不是已上线代码里的漏洞：现行写下的规则允许一条已认证的线只凭 10 条复核样本就扩展到一种新的、看起来相近的材料风格——这个门槛比新的试用档还松。修法——扩展一条线的适用范围，需要与首次认证同一档次的分级证据——是一项已裁定的决定，尚未实现。

**现状。** 认证方法的改动（默认改用固定序检验，序贯作为可选项，加上范围扩展的修法）是一项已裁定并写入设计记录的决定；其中没有一项已经在校准代码里实现，所以今天的真机运行仍在用较旧的切分样本方法与它更高的样本量要求。下一次真机测试预计会复用已经为真机试用线测试收集的那 80 条标注，检验它们在新方法下是否已能过正式线的门槛。
