# From "every new question is undecided" to a usable live run: trial-grade calibration lines / 从「新题一律未决」到真机可用：试用档校准线

2026-09-24. Built in the research workspace; the code is on the same-day sync branch `sync/2026-09-24-architecture`, pending review before it is pushed and merged into this repository's `main`.

2026-09-24。研究工作区已经造出并实测；代码在同日同步分支 `sync/2026-09-24-architecture` 上，待审核后推送并合入本仓库 `main`。

## English

Once the real JEV backend was wired in (documented in the [2026-09-23 update](2026-09-23-constructs-and-calibration.md)), a specific problem blocked every new program: any question without a certified calibration threshold came back `Unsure(cold)` -- correct in the sense that the language refuses to guess a threshold, but useless in the sense that a program chaining two layers of judgment never reached its second layer, because the first layer never produced a decided outcome to hand it. Getting a threshold certified at the project's existing safety bar took on the order of 160 labeled examples for a straightforward question and 200-plus, not guaranteed, for a more semantic one. That is a real barrier for a first-time user: write a ten-line program, then go label 160 examples before it produces a single decided answer.

**The design.** A second, looser certification tier was added: a "trial line," certified at a wider error tolerance than the standard ("formal") line -- enough to route a program's control flow (accept/ignore/still-undecided) but explicitly barred from authorizing an irreversible action. The distinction already existed for other weak evidence sources (a hand-supplied placeholder line used only in test fixtures behaves the same way); this extends the same idea to statistically certified-but-thin evidence. Every decided outcome in a run report now records which grade of line backed it -- formal, trial, borrowed from a related question template, fixture-only, or none -- so a reader auditing a run's output can see exactly how much evidence stands behind each decision, and that record survives replaying the run from its log with zero new backend calls.

**A live test.** Eighty short constructed customer-service dialogues (unrelated to any earlier test data) were labeled by construction along two dimensions -- whether a refund was being requested, and whether the tone was heated -- and run once against the live backend to collect readings, then imported as calibration evidence. Both questions' readings matched their constructed labels on all 80 examples; neither cleared the bar for a formal line (each fell a few examples short of the ~22-per-side zero-error requirement), but both cleared the looser trial bar. A two-layer test program that chains these two questions -- unresolvable before, because the first layer never decided -- got all 14 of its outcomes decided on the live backend for the first time, and for the first time reached its second layer live. A companion program that tries to write a file based on the first question's outcome was correctly blocked: because the backing line was trial-grade, not formal, the language's credibility gate refused to authorize the file write, and no file was written. Total cost for this test was under two-tenths of one US cent.

**What this does and doesn't show.** Both questions tested were close to literal (a refund request and a heated tone are usually stated plainly), so this is not yet evidence that a genuinely ambiguous, middle-of-the-distribution question behaves the same way; that test is still open. The calibration and the test material were also similar in style to each other, so this run did not exercise the separate safeguard that keeps an out-of-style material from borrowing a line it wasn't certified on. A self-review after the initial implementation caught one real gap before it shipped: a trial-grade recertification attempt could, under the original logic, silently overwrite an already-suspended formal-grade line and then get treated as formal-grade evidence -- exactly the kind of authorization creep the credibility gate exists to prevent. That was closed (trial recertification now refuses to touch a record that already carries any formal-grade certificate) and a regression test was added for it before the feature was considered done.

## 中文

接通真实 JEV 后端之后（见[2026-09-23 的更新](2026-09-23-constructs-and-calibration.md)），一个具体问题挡住了每个新程序：没有认证校准阈值的题一律回 `Unsure(cold)`——从「语言拒绝瞎猜阈值」这个角度看是对的，但从「链式两层判断的程序永远走不到第二层」这个角度看毫无用处，因为第一层从来产不出一个已决结果交给第二层。按项目既有的安全门槛认证出一条线，普通问题要约 160 条标注，偏语义的问题要 200 条以上且不保证能过。对第一次用的人这是道实实在在的墙：写十行程序，先去标 160 条例子才能得到第一个已决答案。

**设计。** 新增了一档更松的认证等级：「试用线」，用比标准（「正式」）线更宽的错误容忍认证——够给程序的控制流（接受/忽略/仍未决）分派路由，但明确不许用它放行不可逆动作。这个区分已经用在别的弱证据来源上（只在测试夹具里用的手写占位线就是这样处理）；这次把同样的思路延伸到「统计上认证过但证据量薄」的情形。运行报告里每个已决出口现在都记录它背后的线属于哪个等级——正式、试用、从相关题式借来、只有夹具、或没有线——读者审查一次运行的输出时能确切看到每个决定背后站着多少证据，且这条记录只凭账本重放、零新后端调用就能复现。

**一次真机测试。** 80 段构造出来的客服对话短文（与此前任何测试数据都不重复）按两个维度构造好真值——是否在要求退款、语气是否激烈——先真机跑一遍拿到读数，再作为校准证据导入。两道题的读数在全部 80 条上都与构造真值一致；两道题都没过正式线的门槛（每侧零错都差几条没到约 22 条的要求），但都过了更松的试用线门槛。一个链式两层的测试程序（此前无法运行，因为第一层从不产出已决结果）在真机上第一次得到全部 14 个已决出口，也第一次在真机上走到了第二层。另一个基于第一道题结果尝试写文件的配套程序被正确拦下：因为背后的线是试用档而非正式档，语言的可信度关卡拒绝授权这次写文件，文件确实没有被写出。本次测试总费用不到千分之二美元。

**这证明了什么、没证明什么。** 两道被测的题都接近字面（要不要退款、语气激不激烈，通常说得很直白），所以这还不能证明一道真正模棱两可、读数落在分布中段的题会有同样表现——那项检验还没做。校准材料与测试材料风格也相近，所以这次运行没有触发另一道独立防线——防止风格不同的材料借用一条它未经认证的线。实现完成后的一次自查在上线前抓到了一个真实缺口：按最初的逻辑，一次试用档的重新认证可能悄悄覆盖一条已经被标记停岗的正式档线，随后被当作正式档证据使用——这正是可信度关卡本该防的那种授权蔓延。该问题已修（试用档重新认证现在遇到任何已带正式档证书的记录都不会去碰它），并在功能定稿前补上了回归测试。
