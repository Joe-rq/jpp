# 百人案例：执行前确定的比较方法

日期：2026-09-20。以下数据选择和比较规则在本轮真实 JEV 调用前确定。

本次从通爻原仓库历史提交 `6b4230453ecf7c02e8ae86bedfd97eb695b23a7a` 恢复完整的黑客松 118 份、技能交换 107 份合成档案。相同 alias 的资料合并，得到 216 个主体，全部参与计算。档案中的名称、经历和任职声称均为合成角色设定。选择这两套数据是因为它们直接描述协作和能力交换；未按本轮模型结果挑选人物。

同时保留旧 `field_poc/test_queries.py` 的全部 20 条查询，涵盖直接匹配、同义改写、需求与能力互补、跨领域模糊意图。模型输入只有查询、补充上下文和一个主体的档案，不包含预期命中名单。源文件哈希、合并关系和缺失的预期人物保存在 `towow-population.json`。历史 `EXP-008_profiles.json` 是旧检索 Top-10 候选的汇集，因此本次从完整原始池恢复数据。

J++ 为每个主体构造同一份本地材料，再构造 20 个独立问题。运行时可以合并共享材料的问题并并发处理主体。总计 216 × 20 = 4,320 个判断。之后通过第二个组件汇总各意图的候选和对照。真实调用的费用上限为本次追加 0.08 美元，连同本会话此前的 0.00229744 美元，低于已批准的 0.10 美元总预算。程序记录实际费用；超限不会自动追加预算。

对照使用同一主体池、同一查询和补充上下文的 BM25：中文二字词、英文及数字词，`k1=1.5`、`b=0.75`。它是明确可复现的词面检索参照，不代表所有向量检索、所有语言或所有推荐算法。旧实验在不同主体池上的结果不拼接到本次比较中。

J++ 按现有运行时 `ReadingsVec.order()` 的读数层级排序，同层按 alias 固定排序，取前 10；保留完整层级，展示边界并列情况。旧 `expected_hits` 是不完整的预期名单，命中数只表示找回了多少旧名单中的人物；不在名单里的人不自动算错。19 条查询有名单，1 条无名单；`anti_hits` 全部为空，不能据此估算假阳性率。保留原 `min_hits`、当前池中缺失的人物，以及每条查询的结果，不以调整门槛消除失败。

本次要检查：完整方法能否处理百人以上、多个不同意图；是否会找到词面参照未排进前十的已有预期人物；哪些查询退步；相同输入重跑能否复用判断。查询和档案都来自旧开发实验，因此结果属于旧样本上的可复现实验，不能称为未见数据上的准确率证明。转介与组合的因果干预仍由十人实验台单独展示，两种证据不互相替代。

## 看到第一轮结果后的开发修订

首次真实运行保存在 `demos/towow/population/live-report.json`，未经改写。原排序命中旧名单 33 次，BM25 命中 43 次。检查发现部分意图的读数层级包含 200 多人，按 alias 截取前十会将高相关候选排出名单。

随后新增 `rank_candidates` 组件：先按现有语义出口分成候选、未知、未提名三组，每组内部按同一个 BM25 排序。这是查看开发数据后的改进，不是预注册的盲测结果。它不读取预期名单，也不修改模型读数或判断门槛；相同真实回答被离线复用，无新增模型调用。改进输出另存为 `analysis.json`，同时保留语义层级排序、BM25、组合排序三种结果，供别人检查和继续复现。
