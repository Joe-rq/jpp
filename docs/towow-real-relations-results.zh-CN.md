# 325 个主体：从上下文找回关系

这个案例把通爻旧实验的公开来源职业资料，接入现有 J++ 的判断、组合、相对排序与复用能力。打开[关系对照页面](https://towow-ai.github.io/jpp/demos/towow/real/)，可以选择任意主体，切换方法和候选数量，查看亮起的关系以及双方实际资料。图谱展示已完成的真实计算，浏览时没有新的付费调用。

## 比较的是同一件事

325 份档案对应 963 条可核对的旧标签，其中 939 条来自共同论文、同一开源组织或创业团队，24 条是人工挑选的跨来源种子关联。原始 972 条中有 9 条涉及现存规范化资料中缺失的人，未纳入新分母。

方法只读取职业上下文，关系标签只在评估时使用。每个主体分别提出前 1、5、10、20 个候选；一条旧关系只要任一方向找到即算命中，完整结果也保留有向召回和逐关系类别统计。未被旧名单标注的关系不能当成错误，因此这里不把召回率称为准确率。

同一批处理后的资料上，MiniLM、BM25 和等权 RRF（k=60）提供本地检索基线。J++ 首先判断 RRF 前二十候选，再展开到全部 324 个其他主体。多候选请求使用固定四级刻度；接受的等级降序排列，未确定单独保留，同级保持原检索顺序。

首轮前十结果与本地融合持平后，我们追加现有 `ReadingsVec.order()` 的对照：每对上下文单独回答同一个问题，将读数变成相对偏序，并列保留 RRF 顺序。同一批独立配对回答另按“已接受等级”排序，隔离排序操作本身的影响。原始结果全部保留。这是根据开发结果改进方法的实验，不是盲测。

## 实际结果

完整七组结果、各类关系命中和每个主体的排序见[可下载结果](demos/towow/real/results.json)。全量扫描并没有自然带来提升：本地融合在前十找回 675 条，前二十等级排序同为 675 条，全部 324 人等级排序降至 596 条。模型的语义关联刻度与旧关系标签不是同一目标；粗等级和未确定项的排序策略可能损失原检索的信息。

相对排序找回 **697／963（72.38%）**，相比 RRF 的 **675／963（70.09%）** 增加 2.28 个百分点。同一批独立配对回答按接受等级排序仅找回 677 条。相对 RRF，新方法新增找回 52 条，同时丢失 30 条，净增 22 条；页面两组均可逐对查看。

| 方法 | 前 1 命中 | 前 5 命中 | 前 10 命中 | 前 20 命中 |
|---|---:|---:|---:|---:|
| MiniLM | 168 | 485 | 670 | 825 |
| BM25 | 169 | 496 | 673 | 824 |
| 本地融合 RRF | 173 | 494 | 675 | 830 |
| J++ 等级排序，候选 20 | 166 | 492 | 675 | 830 |
| J++ 等级排序，候选 324 | 131 | 418 | 596 | 719 |
| 独立配对，接受等级排序 | 138 | 468 | 677 | 830 |
| 独立配对，J++ 相对排序 | 183 | 515 | 697 | 830 |

提升主要来自共同论文关系（522 → 542），同组织关系为 120 → 122，同团队仍为 33；24 条跨来源种子关联均未命中。去除这 24 条人工种子后，来源支撑的关系为 697／939。有向前十命中仅从 1182／1926 提升至 1185／1926，说明无向指标的改善也包含提名在两端之间的重新分布，不能据此声称每个主体都明显变好。

语言负责把可替换的方法接起来、保存每次计算并运行对照。这里证明了一次具体组合在当前数据上的改善，尚未证明泛化、更低成本或更高速度。七组结果和逐对得失均保留，后续应在未参与方法开发的数据上复验。

## 历史结果与计时怎样读

旧报告恢复运行的 893／972 = 91.87%，是在 26,164 条有向提名中统计，平均每人约 80.5 个候选。它不能直接和这里每人前十的结果比较。当前缺少旧运行的完整排序与 D1-D5 输出，保留这个历史记录，不虚构同 K 重跑。详细来源说明见[实验规则](towow-real-relations-plan.zh-CN.md)。

本地 MiniLM 模型加载约 2.23 秒、资料编码约 9.55 秒、全部向量搜索约 0.070 秒；BM25 全部检索约 5.74 秒。首次前二十运行中途恢复，记录中的约 3 秒是恢复与录制读取时间，不能当成 JEV 推理速度。随后全量扩展约 687 秒，复用了前二十判断，也不能冒充完全冷启动。相对排序另保留独立配对的实际端到端时间。所有计时均为本机一次运行，未做稳定性或吞吐压测。

独立配对的相对排序运行耗时 175.796 秒，组织了 6,500 个候选判断，资料内容去重后实际发送 5,353 个请求，新增估算费用 $0.153491。真实来源实验共录制 10,022 个请求，累计估算 $1.447708；加此前十人与 216 人实验约 $1.489203，在授权的 $5 内。当前语义复核比本地检索慢且增加了 API 费用，不能称为速度或成本优势。

费用来自逐请求的 token 计价估算，并非服务账单。原始请求和回答公开为压缩录制，无认证头或密钥。重复输入从记录或语言运行账本读取，不需要重新支付；本地离线重放可验证同样的结果。

## 重现

安装本仓库后，下载页面的 `data.json`、`retrieval.json` 和 `recording.jsonl.gz`。解压录制到 `run/recording.jsonl`，使用同一份资料和排序：

```sh
python -m jpp.towow_real --data data.json --retrieval retrieval.json --out run --limit 20 --mode order
python -m jpp.towow_real --data data.json --retrieval retrieval.json --out run --limit 324
```

默认离线，没有 API 调用。`--live` 才使用本机配置的 JEV 密钥并支付新调用；`--budget` 是该运行目录中累计录制费用的上限。完整实验报告另以 [reports.json.gz](demos/towow/real/reports.json.gz) 提供。输入生成与本地检索脚本分别为 `scripts/prepare_towow_real.py` 和 `scripts/benchmark_towow_real.py`。

## 接下来怎样测试陌生发现

职业资料仍含共同论文内容、公司等直接线索，所以这次衡量的是已有关系恢复。严格的陌生发现应以合作发生前或与目标合作无关的资料为输入，将后来发生的合作留作独立标签。现存有些档案主要来自目标论文，仅删除姓名和标题不够。

对新候选的评阅还应与已知关系恢复分开：用不知道方法来源的评阅者，按实际可行的共同方向、互补资源与行动条件判断候选价值，再记录联系后的结果。这会回答“发现了值得合作的陌生人吗”，而不只是“重新找到了共同论文或共同组织”。
