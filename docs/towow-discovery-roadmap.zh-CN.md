# 用 J++ 继续推进通爻网络发现

后续进展：[可续接的发现应用与固定名额对照](towow-discovery-iteration.zh-CN.md)。来源配额没有改善最终排序；已经实现可替换任务配置、提议作为下一轮输入及观察复用。接收方自行形成算子、转介披露与动态图传播继续沿本路线推进。下文保留当时的诊断与计划。

沿用当前[正式语言路线](adr/0001-rust-kernel.md)：Rust 单一内核与独立 `.jpp` 源码正在建设，已发布的 Python 实现继续用于行为对照和实验。本轮只增加应用诊断与研究记录；后续组件需保留输入、问题、输出的稳定样例，供 Rust 实现接入和核对，不另行扩大正式 Python 内核。

## 当前主要问题不是训练集大小

325 人案例没有训练或微调 JEV，也没有学习新的检索模型参数。我们使用现成模型、问题刻度和组合方法做推理与评估。这些人物资料是测试输入，不是模型训练集。

扩大人数主要能检验干扰、容量与成本；增加不同类型的意图和合作关系，才能检验发现能力。后续的校准样本用于判断读数何时值得信任，与训练基础模型是不同工作。现在先找清楚候选、问题和组合机制的瓶颈，再决定是否需要训练。

## 本轮新诊断：先让值得计算的双方相遇

在已公开的同一批资料上，J++ 相对排序前十找回 697／963 条标签。剩下 266 条中，133 条两端都没有进入对方的 RRF 前二十；另外 133 条已进入至少一端的候选池，但没有被最终前十保留。前者要改召回，后者要改判断与排序。

| 每人候选数 | 候选池覆盖的旧关系 | 其中 24 条跨来源种子关系 |
|---:|---:|---:|
| 10 | 675 | 0 |
| 20 | 830 | 0 |
| 40 | 913 | 0 |
| 80 | 947 | 8 |
| 160 | 956 | 17 |

这里是候选池覆盖，也就是后续排序能达到的上限，不是最终前十效果。24 条人工种子关系最近的一端也排在第 47 名，最远为第 264 名。因此，再准确的“前二十复核”也无法找出它们。它们是待评阅的关联假设，不等同于已确认的真实合作。

保持每人二十个名额，一个不使用关系标签的探索性改动是：保留前十六个 RRF 候选，另取四个不同资料来源的候选，去重后补齐二十个。跨来源覆盖变为 7／24，但总覆盖从 830 降到 797：新增 7 条，失去 40 条。探索名额增加到八个，跨来源覆盖变为 10／24，总覆盖降到 734。这个改动没有接受 JEV 复核，不能当成新方法已胜出。

它给出的设计依据是：相似性排序会占满名额，互补与转介需要有机会进入计算。资料来源配额只是诊断工具；科研、开源、创业这些标签并不等于合作方向，不能直接成为最终路由规则。

## 下一轮只先解决候选入口

下一轮问题是：**在相同的二十个候选名额和相同模型预算下，能否把更有价值的互补对象送到 J++ 面前，并保留最终前十？**

固定当前 RRF → 相对排序作为基线。先试一个明确的候选生成变化：相似候选与互补探索候选组成同一个池；探索名额采用预先固定的分配，不根据当前标签逐条调节。来源配额作为便宜对照，真正的探索路径按当前意图的“缺少什么、能提供什么、能转介什么”组织，而非永久的职业分类。

同一池中的每个候选先用现有问题与 `.order()` 复核，隔离候选生成的影响。记录总前十召回、跨来源候选与最终命中、实际新增和丢失的关系、每次发现的调用及耗时。当前 325 人是开发集；在它上面挑选方法后，用新的意图和人物组检查迁移效果。资料中的相同文本有 54 个重复项差额，相关人物和同一项目/论文组应整体分配到开发或评估侧，避免随机拆边造成信息串联。

这个开发轮的推进标准是：相同二十个名额，跨来源种子候选覆盖至少达到已观察的 7／24，并且经 J++ 复核后仍有非零最终命中；同时公开总前十相对 697 的得失。它是筛选机制的标准，不是对真实陌生合作的成功承诺。若只是挤掉大量原有有效结果，就调整入口策略；不靠扩大扫描人数把成本藏起来。确认有值得保留的取舍后，才进入未参与设计的材料。

## 随后按问题推进三个能力

**让判断表达关系的方向。**“两个人像不像”“A 能否补足 B 的需要”“A 能否把问题转交给 C”应分别判断。两个人都在找司机很相似，但不能直接互相提供司机服务。旧困难负例和供需世界卡可以检验这个区别。先改变问题表达并做小批独立评阅，再考虑学习参数；不要把模型的分数直接当合作成功概率。

**让组合成为新的输入。**从局部候选中产生一个含成员、可能贡献和未满足条件的合作假设，再把这个假设送给其他接收方。保留它对原始材料的引用。仅当它带来新事实、新候选或新的可检查条件时继续展开。第一项对照可以关闭转介或关闭组合，看哪些可行候选因此消失；组合对象是提议，不代替参与者同意。JEV 负责判断，需要生成新方案时可接生成模型或确定性模板，不要求 JEV 单独承担生成。

**让进行中的计算改变后续发现。**复用旧网络的版本事件与按需传播。主体的新资料、尚未解决的问题、关系读数和中间组合都可以触发可发现性更新。首先检验一个主体改变状态后，哪些新路径出现、哪些旧路径失效，系统付出了多少更新工作。持续变动不意味着每秒全网重算；比较定时全量、事件触发和带少量探索的路由，在同一更新流上看发现延迟、漏失和成本。

这三项依次接到候选入口之后，不同时重建三个完整系统。NAC、向量检索、JEV 判断和图传播都是可替换组件；通用的组合与状态机制留在 J++，业务特定的协作判据放在应用层。

## 每轮留下别人能接着用的东西

每轮只围绕一个具体改变，保存输入说明、可运行的方法、与上一版的对照、费用和时间，以及值得保留或放弃的结论。可复用部分实现为组件，接回案例入口；旧失败留在对照里。下一次开发还记录“新增方法花了多久、改了哪些组件、多少控制逻辑直接复用”，把语言带来的研发效率纳入结果。过去一小时与一两天的比较是用户回忆，不能当作已经控制变量的效率测量。

当前已完成：历史资产核对、零费用诊断、候选入口的一个离线探索对照，以及这份接续计划。尚未实施：新候选池的付费复核、旧世界卡接入、组合递归和动态图路由。本轮 API 新增费用为 0。
